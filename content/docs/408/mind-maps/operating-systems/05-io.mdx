## I/O设备分类

- 特性分类
  - 人机交互类
    - 如：打印机、显示器、键盘、鼠标
    - 交互速度较慢，一般是以字节为单位交换的
  - 存储设备
    - 如：磁盘、磁带、光盘
    - 交互速度快，一般以多字节组成的一个块来进行交换的
  - 网络通信
    - 如：网络接口、调制解调器
    - 速度居中
- 传输速率分类
  - 低速设备
    - 几B到几百B/s
    - 键盘、鼠标
  - 中速
    - 几千B到几万B/s
    - 打印机
  - 高速
    - 兆B/s
    - 磁盘、U盘
- 信息交换分类
  - 块设备：
    - 单位：
      - 以数据块为单位存取
        - 可寻址、支持随机存取
    - 随机：
      - 可寻址，可随机存取
    - 例如：
      - 磁盘
  - 字符设备：
    - 单位：
      - 字符
        - 不可寻址、不可随机存取，使用中断驱动
    - 随机：
      - 不可寻址
    - 例如：
      - 打印机
    - 批注：因为其传输的基本单位是字符
- IO应用程序接口
  - 字符设备接口
    - 例如：键盘、打印机
    - 输入输出：get、put指令
      - IO设备内部用一个字符缓冲区
    - 控制：in-control指令
  - 块设备接口
    - 交换数据块、例如：磁盘
    - 通常使用DMA的IO方式
  - 网络接口
    - 网络通信接口、例如socket
  - 阻塞IO
    - 阻塞IO是调用IO的时候，阻塞进程

## I/O控制器

- I/O接口
  - I/O控制器
    - 设备控制器
- I/O内部
  - 机械部件
    - 看得见摸得着的实体
  - 电子部件
    - 藏起来的电路板
- I/O控制器组成
  - <img src="/images/408-mind-maps/os-0122.png" alt="I/O控制器组成" width="240" height="143">

    - 由图可知：
    - 1\. 一个I/O控制器，管理多个IO设备
      - 一个I/O设备中，也可以连接多个I/O控制器（多通路IO系统）
    - 2\. 每个I/O控制器中可以有多个(相同或不同的)寄存器。
    - 3\. 一个I/O控制器中有一个I/O逻辑，负责接受和识别CPU的命令，通过这个I/O逻辑，可以使这个I/O控制器管理的设备和CPU能够进行交互
    - 4\. I/O逻辑把命令发送到对应的接口处，由接口处的线来进行数据、控制的发送。同时也可以获得设备发来的状态
      - 这里的I/O逻辑到设备的接口模型和CPU到I/O控制器的模型基本一致
- I/O控制器功能
  - CPU无法直接控制I/O设备中的机器部件，所以I/O设备中还要有一个电子部件来作为中介
  - 又称：
    - 设备控制器
  - 功能：
    - 接受和识别CPU命令
      - 把CPU的命令：例如read/write，放到【控制寄存器】中，同时通过【控制线】告知I/O设备发送了命令
    - 向CPU报告设备状态
      - 【状态寄存器】，表示空闲忙碌
    - 数据交换
      - 读写数据都放到【数据寄存器】
    - 地址识别
      - 把逻辑IO寄存器地址翻译为物理地址，通过【地址线】进行传输
    - 概要：【数据寄存器】 【控制寄存器】 【状态寄存器】 【地址线】 【控制线】
      概要范围：[接受和识别CPU命令](#focus=%E6%8E%A5%E5%8F%97%E5%92%8C%E8%AF%86%E5%88%ABCPU%E5%91%BD%E4%BB%A4)、[向CPU报告设备状态](#focus=%E5%90%91CPU%E6%8A%A5%E5%91%8A%E8%AE%BE%E5%A4%87%E7%8A%B6%E6%80%81)、[数据交换](#focus=%E6%95%B0%E6%8D%AE%E4%BA%A4%E6%8D%A2)、[地址识别](#focus=%E5%9C%B0%E5%9D%80%E8%AF%86%E5%88%AB)

- I/O 端口
  - 设备控制器中可被CPU直接访问的寄存器

## I/O控制方式

- 程序直接控制
  - 图：
    - <img src="/images/408-mind-maps/os-0068.png" alt="图：" width="170" height="220">

      - CPU不停的进行轮询测试
  - CPU干预：
    - 非常大
  - 读写单位：
    - 字 word
      - NOT 字节byte（因为读取的单位是按数据总线的位数决定的）
  - 数据流向：
    - I/O控制器 -&gt; CPU -&gt; 内存
- 中断驱动方式
  - 图：
    - <img src="/images/408-mind-maps/os-0118.png" alt="图：" width="113" height="220">

      - CPU中断去做其他事情
  - CPU干预：
    - 不高，可以切换到其他进程
  - 读写单位：
    - 字
  - 数据流向：
    - I/O控制器 -&gt; CPU -&gt; 内存
  - 何时检查中断：
    - 在指令周期的末尾的时候进行检测
  - 中断时，CPU：
    - 保存在执行程序的上下文，然后去执行中断处理程序
- DMA方式
  - 图：
    - <img src="/images/408-mind-maps/os-0131.png" alt="图：" width="240" height="218">

  - DMA控制器的组成：
    - <img src="/images/408-mind-maps/os-0153.png" alt="DMA控制器的组成：" width="240" height="94">

      - 四个寄存器的作用：
      - DR：
        - Data Register，用于暂存设备和内存交换的数据
      - MAR：
        - Memory Address Register，指明内存的起始地址
      - DC：
        - Data Count，存在本次要传送的字数（或字节数，都可以）
      - CR：
        - Command Register，用于接受CPU发来的命令
  - CPU干预：
    - 很低
      - CPU指明内存的哪个部分和磁盘的哪个部分需要进行数据交换
  - 读写单位：
    - 一个块
  - 数据流向：
    - 内存 &lt;-&gt; I/O
  - 缺点：
    - 一次只能读一个/多个连续块
    - 读写多个离散的块很麻烦
  - 例如：
    - 磁盘
- 通道方式
  - 通道技术是一种硬件机制
    - 在计组中有学，例如有通道三总线模型等等
  - 将众多指令直接编写在通道文件中，CPU交付于I/O处理，I/O将指令执行完成后再通知CPU
  - 又称为
    - I/O处理机
  - CPU干预：
    - 最低
  - 读写单位：
    - 多组连续的块 = 一组离散的块
  - 数据流向：
    - 内存 &lt;-&gt; I/O
  - 通道分类（拓展）
    - 字节多路通道
      - 大量的低速、中速I/O设备
    - 数组选择通道
      - 少量的高速I/O设备
    - 数组多路通道
      - 大量的高速I/O设备
  - 通道控制设备控制器，设备控制器控制设备
    - DCT、COCT、CHCT、SDT
  - 批注：\*
- 总结：中断时机
  - 程序直接控制方式
    - 没有中断：CPU定期轮询检查I/O操作是否完成
  - 中断控制方式
    - 中断发生的时机：每完成一个字的读写（CPU完成的读写），I/O控制器向CPU发出一个中断信号
  - DMA控制方式
    - 中断发生的时机：CPU向DMA控制器指明读写操作相关参数，每完成一整块数据的读写（DMA完成的读写），DMA控制器向CPU发出中断信号
  - 通道控制方式
    - 中断发生的时机：CPU向通道指明通道程序在内存中的地址，通道执行完通道程序后，通道向CPU发出中断信号

## 高速缓存和缓冲区

- 磁盘高速缓存
  - Disk Cache
  - 概念：
    - 将一个指令又存在内存中，又存在磁盘中
  - 作用：
    - 提高I/O的速度，访问更高效
      - 例如进程的指令既在磁盘中，也在内存中，同时还在CPU一级二级cache中
  - 形式：
    - 1\. 在内存中【单独开辟空间】，大小固定
    - 2\. 把未利用的内存空间作为【缓冲池】，供请求分页和IO共享
- 缓冲区
  - 目的：
    - 1\. 缓和CPU和I/O的速度矛盾
    - 2\. 减少CPU中断频率
    - 3\. 解决数据粒度不同
      - 例如CPU一次产生一个块，I/O一次只能读一次char
    - 4\. 提供CPU和I/O的并行
  - 实现方法：
    - 使用硬件缓冲区，成本太高，一般不用
    - 采用内存缓冲区
      - 采用缓冲技术
  - 需要缓冲的例子：
    - 鼠标、键盘
      - 若有更高优先级的进程到来，鼠标点击事件不应被丢失，则放在buffer中
    - 多任务的磁盘驱动器、磁带驱动器
    - 图形卡
      - 图形学开篇，使用双缓冲来实现图像更换
  - 若无特殊说明，缓冲区大小为一个块
  - 高速缓存和缓冲区的对比
    - <img src="/images/408-mind-maps/os-0042.png" alt="高速缓存和缓冲区的对比" width="240" height="66">

  - 预读 + 滞后写
    - 预读：读区域A的时候，把A的下一块也同时读入到buffer中
    - 滞后写：在需要把A写回时，先不写回，先挂载到buffer中，直到这块buffer需要使用再写回

## 设备的分配和回收

- 三种分类：
  - 独占
    - 打印机
  - 共享
    - 磁盘
  - 虚拟
    - SPOOLing技术
- 数据结构：
  - DCT：
    - 一个DCT表就表征一个设备，表中内容就是设备的各个属性
    - 称为：
      - Device Control Table 设备控制表
    - 内容：
      - 设备类型type
      - 设备标识符: deviceid
        - 唯一id
      - 设备状态：等待/空闲
      - 指向控制器的指针
        - 用来找该设备对应的I/O控制器
          - 父级指针
      - 重复执行次数或时间
        - I/O设备会在自己发现执行失败了很多次以后才会认定为I/O失败
      - 设备队列的队首指针
        - 指向正在等待该设备的【进程队列】
          - 如果一个进程想要使用这个设备，那么就把该进程的PCB插入到该设备对应的DCT的设备队列中
  - COCT：
    - 用来管理众多DCT，因为【一个控制器会管理多个设备】
    - 称为：
      - Controller Control Table 控制器控制表
    - 内容：
      - 设备标识符: controllerid
      - 设备状态：等待/空闲
      - 指向通道的指针
        - 父级指针
      - 控制器队列的队首指针
      - 控制器队列的队尾指针
      - 概要：指向正在等待该控制器的【进程队列】
        概要范围：[控制器队列的队首指针](#focus=%E6%8E%A7%E5%88%B6%E5%99%A8%E9%98%9F%E5%88%97%E7%9A%84%E9%98%9F%E9%A6%96%E6%8C%87%E9%92%88)、[控制器队列的队尾指针](#focus=%E6%8E%A7%E5%88%B6%E5%99%A8%E9%98%9F%E5%88%97%E7%9A%84%E9%98%9F%E5%B0%BE%E6%8C%87%E9%92%88)

        - 如何插入的不做深究
  - CHCT：
    - 用来管理众多COCH的，一个通道管理很多个控制器
    - 称为：
      - Channel Control Table 通道控制表
    - 内容：
      - 设备标识符: channelid
      - 设备状态：等待/空闲
      - 控制器队列的首地址
        - 孩子节点，找到第一个相连的控制器
      - 通道队列的队首指针
      - 通道队列的队尾指针
  - SDT：
    - 整个系统只有一个SDT表，管理所有物理设备
    - 称为：
      - System Device Table 系统设备表
    - SDT是一个表，每一个设备就占一个表项（前面的同理）
    - 内容：
      - 设备类型
      - 设备标识符
        - 物理设备名
      - DCT
      - 驱动程序入口
  - 设备分配的步骤：
    - 1\. 根据进程请求的【物理设备号】去查SDT的【设备标识符】，获得对应DCT
      - 如果请求的是【逻辑设备号】，就去查SDT的【设备类型】
    - 2\. 找到DCT，如果设备忙碌(【设备状态】)就挂到等待队列，如果不忙碌就获得该设备
      - 将该逻辑设备的&lt;逻辑设备名、物理设备名、驱动程序入口地址&gt;加入到LUT表中
    - 3\. 根据DCT去找【父指针】，找到COCT，控制器忙碌就挂，不忙就用
    - 4\. 根据COCT去找【父指针】，找到CHCT，忙挂闲用
    - 只有上述四个步骤都分配完成才算成功
      - 使用【物理设备号】请求不如【逻辑设备号】好
  - 概要：配图
    概要范围：[SDT：](#focus=SDT%EF%BC%9A)

    - <img src="/images/408-mind-maps/os-0082.png" alt="数据结构：" width="240" height="160">

- 设备分配策略：
  - 设备分配方式：
    - 静态分配
      - 作用：
        - OS一次性分配该作业需要的所有设备、控制器、通道信息
      - 死锁：
        - 不会”死锁“，破坏了”请求保持“
    - 动态分配
      - 作用：
        - 通过进程需求来提供设备
      - 死锁：
        - 有可能”死锁”
  - 设备分配算法：
    - 先请求先分配
    - 优先级高优先
- 逻辑名到物理名的映射：
  - LUT：
    - 名称：
      - 逻辑设备表
    - 表项：
      - 逻辑设备名、物理设备名、驱动程序入口
    - 单用户：
      - 每个设备都在这个LUT中，不运行出现相同的逻辑设备名
    - 多用户：
      - 每个用户在登录时，系统会给用户【创建一个进程和一个LUT】，这个LUT会放入到PCB中

  - SPOOLing：
    - spooling技术本质上是添加了一个消息队列+异步执行+完成回调，可以让一个独占资源变成共享资源的一个功能

- SPOOLING技术
  - <img src="/images/408-mind-maps/os-0092.png" alt="SPOOLING技术" width="240" height="145">

    - 共享打印机：
      - 当系统同意其打印时：有用户（输出进程）开辟一个空闲磁盘区
      - 步骤：

## 磁盘调度算法

- 考频：高

    - 批注：注意：今年将①和②时间统称为寻找时间
- 可以优化的
  - 延迟时间
    - 平均：
      - 1/2r
    - 有关：
      - 磁盘空闲空间分配程序
        - 是否错位编号
          - 程序规定的分配方式是直接分配相邻块（每次读取的旋转时延为一整圈）
          - 若是相邻一个分配（每次读取的旋转时延为一个簇）
      - 物理结构
        - 是连续分配还是链接分配
        - 连续分配：可以只转圈
        - 链接分配：可能需要换柱换盘块
    - 数据处理时间的影响：
      - 会影响间隙大小，其实影响不大
  - 寻道时间
    - 有关：
      - 磁盘调度算法
- 调度算法
  - FCFS算法
    - 根据进程请求访问磁盘的先后顺序进行调度
    - 优点
      - 公平、简单
    - 缺点
      - 平均寻道距离大，I/O较少可以使用
  - SSTF算法
    - 调度处理的磁道是与当前磁头所在磁道距离最近的磁道
    - 优点
      - 性能比FCFS好（贪心算法）
    - 缺点
      - 可能出现“饥饿”现象
  - SCAN算法
    - （电梯调度算法）
    - 磁头【当前移动方向】上选择与当前磁头所在磁道距离最近的请求作为下一次服务的对象
    - 优点
      - 性能好，不会有“饥饿”
    - 缺点
      - 不利于远离磁头一端的访问
    - LOOK调度
      - 不用扫到两端，扫到最左/最右的磁盘请求就行
  - C-SCAN算法
    - 回返时直接快速移动至起始端而不服务任何请求
    - 优点
      - 磁道请求公平
    - C-LOOK调度
      - 同理
  - 磁臂黏着
    - 只有FCFS没有，如果在算法访问某个磁道时，这个磁道又进行了请求，就会一直被访问
      - 很诡异，记住就行
  - 概要：若无特殊说明，默认采用LOOK而不是SCAN（C-LOOK / C-SCAN）
    概要范围：[SCAN算法](#focus=SCAN%E7%AE%97%E6%B3%95)、[C-SCAN算法](#focus=C-SCAN%E7%AE%97%E6%B3%95)

- 错位编号
  - 同一盘面
    - 同一盘面，物理地址相邻的扇区，在磁盘中应交错存放（留一些处理时间给磁头）
  - 不同盘面
    - 同柱面不同盘面的扇区错位编号，可以缩短连续读写两个相邻盘面的时间

## 固态硬盘SSD

- 基于闪存的存储器
  - 存储介质：NAND颗粒
- 读写速度比较：
  - AS SSD Benchmark 实测（顺序 / 4K 随机读写）

    |项目|机械硬盘|860 EVO（SATA3）|970 EVO Plus（M.2 NVMe）|
    |---|---|---|---|
    |连续读|165.92 MB/s|513.21 MB/s|2974.60 MB/s|
    |连续写|159.01 MB/s|487.98 MB/s|2145.97 MB/s|
    |4K 读|0.68 MB/s|42.25 MB/s|61.62 MB/s|
    |4K 写|1.96 MB/s|128.04 MB/s|200.74 MB/s|
    |访问时间（读）|15.019 ms|0.030 ms|0.033 ms|

    - 机械硬盘的随机读写尤其慢：磁头寻道和旋转延迟是主要开销

    - （硬件茶谈）
- 组成：
  - 闪存翻译层 + 多个闪存芯片 <img src="/images/408-mind-maps/os-0033.png" alt="闪存翻译层 + 多个闪存芯片" width="240" height="142">

    - 读写单位
      - CPU下令要读取一个块的内容
      - SSD的读取单位：一个页
        - SSD接受到这个块的地址
        - SSD的闪存翻译层把它翻译为SSD中对应的数个页的地址
        - SSD把这些页的数据发到IO总线上，返回CPU
      - 具体大小：机械磁盘的一个块大小可能在1KB；SSD的一个页大小是512B~4KB，一个块中有32~128个页
    - 批注：市面上的厂家的SSD都有一个缓存
- 读写原则：
  - 读：以一个页为单位来读 ✅
  - 写：以一个页为单位来写
    - 擦除：以一个块的单位来擦除
    - 擦除方法：先把要写那页的整块复制到另一块，然后再擦除原来那块
      - 复制过后，在闪存翻译层中会建立新的： ‘逻辑地址’ —— ‘物理地址’ 的转换关系
    - 擦除的缺点：
      - 擦除多了会造成磨损
- 平均磨损
  - 静态平均：
    - SSD在进行擦除后的数据迁移的时候，会让寿命比较老的闪存块担任“读”的责任，让新的闪存块担任“写”的责任
  - 动态平均：
    - 在SSD写入新数据的时候，会优先选择磨损次数少的块进行写入
  - 概要：静态平均的效果比动态平均效果更好
    概要范围：[静态平均：](#focus=%E9%9D%99%E6%80%81%E5%B9%B3%E5%9D%87%EF%BC%9A)

- 考频：低
  - 无
