- 编译
  - 编译的步骤：
    - 源代码文件 .c
      - 预处理 -&gt; .i
        - 编译 -&gt; .s
          - 汇编 -&gt; .o
            - 链接 -&gt; .exe
            - 概要：ci,so,exe
              概要范围：[链接 -&gt; .exe](#focus=%E9%93%BE%E6%8E%A5%20-%3E%20.exe)

  - 编译后产生的目标模块地址都是从0开始的相对地址
- 链接
  - 概念
    - 由链接程序把库函数和目标模块连着一起
      - 库代码也需要新分配空间
  - 静态链接
    - 程序运行前，把目标模块、库文件链接成同一个完整的装配模块，后不再拆开
  - 装入时动态链接
    - 程序在装入内存时，边进行装入边链接
    - 易于修改和更新，便于共享
  - 运行时动态链接
    - 程序装入时不进行链接，运行时才链接（动态链接库DLL）
    - 在执行过程中未被用到的目标模块，都不会被调入内存和被链接到装入模块上
    - 优点是能加快程序的装入过程， 还可节省大量的内存空间。
- 装入
  - 概念
    - 从逻辑地址更改到物理地址
  - 绝对装入
    - 代码中的逻辑地址与物理地址相同，编译时装入（只适用单道程序）
  - 可重定位装入 （静态重定位）
    - 程序执行之前，完成逻辑地址和物理地址的转换，运行时内存不移动也不再申请空间。
  - 动态运行时装入 （动态重定位）
    - 运行时才进行逻辑地址到物理地址的转化
    - 整个系统中只设计一个重定位寄存器，所有进程共享使用
  - 概要：只有装入到连续地址空间中，不能修改
    概要范围：[绝对装入](#focus=%E7%BB%9D%E5%AF%B9%E8%A3%85%E5%85%A5)、[可重定位装入 （静态重定位）](#focus=%E5%8F%AF%E9%87%8D%E5%AE%9A%E4%BD%8D%E8%A3%85%E5%85%A5%EF%BC%88%E9%9D%99%E6%80%81%E9%87%8D%E5%AE%9A%E4%BD%8D%EF%BC%89)

  - 概要：不连续空间，装入部分代码即可运行，动态分配内存
    概要范围：[动态运行时装入 （动态重定位）](#focus=%E5%8A%A8%E6%80%81%E8%BF%90%E8%A1%8C%E6%97%B6%E8%A3%85%E5%85%A5%EF%BC%88%E5%8A%A8%E6%80%81%E9%87%8D%E5%AE%9A%E4%BD%8D%EF%BC%89)

## 覆盖和交换

- 覆盖和交换
  - 覆盖：
    - 把内存分为固定区 + 覆盖区
      - 经常活跃的部分放在固定区中
      - 即将访问的段放在覆盖区中，其他放在外存
    - 固定区就是不可被覆盖的
    - 用于单一连续存储管理
  - 交换：
    - 换出：把处于等待状态的程序从内存移到辅存，就可以把内存空间腾出来
    - 换入：把准备好竞争CPU进程从辅存移动到内存
      - 中级调度
        [查看关联主题：第二章 进程管理](/docs/408/mind-maps/operating-systems/02-processes)

    - 不同状态的进程 能否交换：
      - 创建态，可以
        - 即创建态 -&gt; 挂起态
      - 死锁，可以
        - 非常好
      - 处于临界区，不行
        - 因为这片临界区的访问会一直阻塞，直到该被挂起的进程重新恢复
      - 正在IO操作，不行
        - 如果是A进程Input阶段，则可能造成新的B进程交换后，输入设备覆盖掉了B进程的指令
- 可重入程序：
  - 法一：共享使用同一块存储空间
  - 法二：通过动态链接的方式将所需的程序段映射到相关的进程中
    - 最大的优点：减少了程序段的调入调出
- 考频：低
  - 无

## 连续分配

- 连续分配和非连续分配：装入
- 内部、外部碎片
  - 程序使用的空间、程序申请的空间、内存总空间
  - 内部碎片：程序申请空间 - 程序使用的空间
  - 外部碎片：内存总空间 - 程序申请空间
- 单一连续分配
  - 一个内存空间只给一个进程使用
  - 优点：
    - 简单、无外部碎片、采用覆盖技术
  - 缺点：
    - 单用户、单任务、有内部碎片、利用率低
- 固定分区分配
  - 分区大小相同
    - 将内存空间划分为若干固定大小的区域
  - 分区大小不同
    - 划分为多个小分区、适中中分区、少量大分区
  - 分区说明表
    - （分区号） \| 大小/KB 、始址/KB、状态

      **分区使用表**

      |分区号|大小 / KB|起址 / KB|状态|
      |---:|---:|---:|---|
      |1|12|20|已分配|
      |2|32|32|已分配|
      |3|64|64|已分配|
      |4|128|128|未分配|

      **空间分配情况（地址向下递增）**：OS 从 0 开始；作业 A 从 20 开始；作业 B 从 32 开始；作业 C 从 64 开始；128～256 为未分配区。

  - 优点：
    - 多道程序设计、无外部碎片
  - 缺点：
    - 程序太大，分区装不下
    - 主存利用率低，很多内部碎片
    - 没有内存共享能力
- 动态分区分配
  - <img src="/images/408-mind-maps/os-0061.png" alt="动态分区分配" width="240" height="74">

  - 记录存储内存使用情况
    - 内存分区链、内存分区块
    - 分区表
      - (分区号) \| 大小/KB、始址/KB、状态
  - 分配回收
    - 动态分区分配算法
      - 首次适应
        - 找到第一个满足的就行
          - 最好的
      - 最佳适应
        - 找到最小满足的一个（排序）
      - 最坏适应
        - 找到最大满足的一个（排序）
      - 邻近适应
        - 首次适应 + 指针不回溯
    - 回收（4种）
      - 紧凑技术
      - 分区前面有一块
        - 改前一块的大小
      - 分区后面有一块
        - 改后一块的大小 + 始址
      - 分区前后都有
        - 合并前后两块，改大小
      - 分区前后都无
        - 新增一块
  - 分配流程：
    - 系统在初始化后除操作系统占据一部分内存外，其余部分都是【自由空间】。作业申请内存时候，OS分配一个大小相当的内存过去，将作业创建为进程，在作业运行完毕后，在释放内存
      - 申请内存阶段就是装入阶段

## 非连续分配

- 概念
  - 页、页表、页框、页帧、块、页面、内存块、物理块、物理页面、页表项、段、段表、段表项
    - 对应关系
      - 进程的
        - 页、页面
      - 内存的
        - 页框、页帧、块、内存块、物理块、物理页面
      - 外存的
        - 块、外存块
      - 其他的
        - 页表、页表项、段表、段表项
  - 非连续分配：
    - 把主存空间划分为大小相等且固定的块，块相对较小，作为主存的基本单位。每个进程也以块为单位进行划分，进程在执行时，以块为单位逐个申请主存中的块空间。
- 分页存储
  - 基本分页存储管理
    - 原理
      - 把内存划分为数个大小相同且固定的块、块相对较小、作为主存的基本单位
      - 页面和内存块的完全大小相同
      - <img src="/images/408-mind-maps/os-0017.png" alt="原理" width="188" height="220">

    - 转换
      - 内存总大小为 4GB, 内存块大小为4KB, 所以内存中一共可以有 2^20个内存块，内存块编号为0 ~ 2^20 - 1
        - 由此可知【页表项中的块号】至少需要20bit来存储，即至少需要3B来存储（如果需要填充为B）
    - 数据结构
      - 逻辑地址
        - 页号、偏置值
          - 硬件划分
          - 链接后产生的
          - 使用2^n B来设计页面大小，很方便快捷
          - 按字节寻址 -&gt; 偏置值W的bit数就为 n
      - 页表寄存器（PTR)
        - 页表始址、页表长度
      - 页表项结构
        - （页号）块号
          - 页号并不占用存储空间
    - 基本地址变换机构： 得到一个逻辑地址，操作流程

## 虚拟内存

- 考频：超高
  - 11\*2、12、13、14\*2、15\*2、16\*2、19、20、21\*2、22\*2、09大、10大、12大、15大、17大、18大、20大
- 为什么使用虚拟内存
  - 若同时运行的进程太多，则需要很多的内存，当一个程序没有内存空间可用时，那么它甚至无法运行。 所以，在物理上扩展内存相对有限的条件下，应尝试以一些其他可行的方式在逻辑上扩充内存。
- 虚拟内存的空间大小约束
  - 实际容量 ≤ 内存+外存
    - 硬件硬性要求
  - 最大容量 ≤ 计算机地址位数容纳的最大容量
    - 例如32位地址系统，虚存最大为2^\{32\} B
  - 概要：需要两种都满足
    概要范围：[实际容量 ≤ 内存+外存](#focus=%E5%AE%9E%E9%99%85%E5%AE%B9%E9%87%8F%20%E2%89%A4%20%E5%86%85%E5%AD%98%2B%E5%A4%96%E5%AD%98)、[最大容量 ≤ 计算机地址位数容纳的最大容量](#focus=%E6%9C%80%E5%A4%A7%E5%AE%B9%E9%87%8F%20%E2%89%A4%20%E8%AE%A1%E7%AE%97%E6%9C%BA%E5%9C%B0%E5%9D%80%E4%BD%8D%E6%95%B0%E5%AE%B9%E7%BA%B3%E7%9A%84%E6%9C%80%E5%A4%A7%E5%AE%B9%E9%87%8F)

- 虚存的好处和缺点
  - 好处：使用了外存空间扩充了内存空间，通过一定程度的换入换出使得整个系统在逻辑上能够使用一个远远超出其物理内存大小的内存容量
  - 缺点：虚拟内存技术调换页面时需要访问外存，会导致平均访存时间增加，若使用了不合适的替换算法，则会大大降低系统性能
- 虚拟内存的基本概念
  - 传统存储管理方式
    - 一次性
      - 程序一次性全部装入内存
        - 程序大，运行不了
        - 程序多，并发度低
    - 驻留性
      - 程序直至运行结束才会被换出内存
  - 局部性原理
    - 时间局部性
      - 某条指令被执行，不久会再被执行
    - 空间局部性
      - 访问了某条指令，其相邻的代码/指令也会很快被访问
  - 虚拟存储器的定义和特征
    - 特点：
      - 分内余外
        - 部分装入内存，其余留在外存
      - 内需调入
        - 程序执行过程中，所访问的信息不在内存，需要OS把信息调入到内存中
      - 空闲调出
        - OS将内存中暂时不需要的内容换出到外存
    - 多次性
      - 作业无须运行时全部装入内存，可以分多次完成装入
    - 对换性
      - 作业无须常驻内存，可以在运行过程中换入换出
    - 虚拟性
      - 逻辑上扩充内存的容量
  - 虚拟内存技术的实现
    - 要建立在
      - 非连续分配的情况下
    - 三大虚拟内存实现方式
      - 请求分页存储
      - 请求分段存储
      - 请求段页式存储
      - 概要：与非请求模式的区别：采用了虚拟内存的技术，不需要把页/页面全部都先放入内存中，而是在运行中检测到缺页再去外存中读取
        概要范围：[请求分页存储](#focus=%E8%AF%B7%E6%B1%82%E5%88%86%E9%A1%B5%E5%AD%98%E5%82%A8)、[请求分段存储](#focus=%E8%AF%B7%E6%B1%82%E5%88%86%E6%AE%B5%E5%AD%98%E5%82%A8)、[请求段页式存储](#focus=%E8%AF%B7%E6%B1%82%E6%AE%B5%E9%A1%B5%E5%BC%8F%E5%AD%98%E5%82%A8)

    - 需要的四个硬件支持
      - 一定的内外存

- 页面分配策略
  - 调入页面的时机
    - 预调页
      - 根据局部性原理，一次调入若干相邻的页
      - 成功率不高，进程首次调入时，由程序员指定预调页
    - 请求调页
      - 运行时进行调页
  - 从何处调用页面
    - 外存结构
      - 对换区 + 文件区
        - 对换区是连续分配
        - 文件区是离散分配
    - 系统有足够对换区
      - 直接 内存 ↔ 对换区
    - 系统没有足够对换区
      - 不会被修改的：文件区 → 内存
      - 会被修改的：对换区 ↔ 内存
    - Unix方式
      - 首次都是 文件区 → 内存
      - 其余 对换区 ↔ 内存
      - <img src="/images/408-mind-maps/os-0116.png" alt="Unix方式" width="240" height="175">

  - 驻留集大小
    - 驻留集：
      - 分配给进程的物理块大小（OS概念）
    - 固定分配 VS 可变分配
      - 固定：每个进程的驻留集刚开始就确定
      - 可变：每个进驻留集是可变的
    - 局部置换 VS 全局置换
      - 局部：缺页时，进程先自己进行页面置换，OS不干预。根据进程的缺页率，OS再进行空闲块分配的
      - 全局：进程缺页，OS直接送一块
        - 如果没有空闲块，就选择”未锁定”的页面置出外存
    - 联合：
      - 固定分配局部置换
        - 驻留集大小不变，自己内部置换
      - 可变分配全局置换
        - 驻留集大小可变，缺页就给你新的
      - 可变分配局部置换
        - 最好，灵活调配，缺页率高就给新的，低就拿走
  - 批注：页框分配
- 页面置换算法
  - OPT
    - 最佳置换算法
    - 无法实现、找最长时间不被访问的块置换（作为算法的评价标准）
  - FIFO
    - 先进先出
      - 队列类算法
        - 会出现Belady异常：总分配的内存物理块（内存块）数增加，导致缺页率也会增加
    - 实现简单，性能差
    - 与首次适应进行区分

  - CLOCK
    - 简单CLOCK（NRU算法）
      - 只使用访问位
        - 第一轮扫描的时候，把访问位为0的换出，边扫描边把访问位全部置为0。进行第二轮扫描
    - 改进CLOCK置换算法
      - 使用访问位 + 修改位
        - 优先淘汰没有被修改过的页面
        - 四级访问：
          - （书中的P用的A来表示）
          - P = 0，M = 0
            - 未访问，未修改
          - P = 0，M = 1
            - 未访问，有修改
              - 本次扫描结束后把所有的P都改为0，然后重复扫描
          - P = 1，M = 0
            - 访问过，未修改
          - P = 1， M = 1
            - 访问过，修改过
          - 概要：如果会搜到这里，P其实已经更改为0了
            概要范围：[P = 1，M = 0](#focus=P%20%3D%201%EF%BC%8CM%20%3D%200)、[P = 1， M = 1](#focus=P%20%3D%201%EF%BC%8C%20M%20%3D%201)

- 抖动 &amp; 工作集
  - 抖动定义
    - 刚换出的马上要换入主存，刚换入的马上要换出
    - 产生原因：
      - 某个进程频繁访问的页面数目高于可用的物理页面帧数
    - 解决办法：
      - 工作集
  - 工作集W和时间t和工作窗口大小delta
    - 基于局部性原理，OS实时跟踪进程，用最近访问过的页面来确定工作集。例如在t1时刻，工作集窗口大小为5，窗口内的页面是2, 3, 5, 3, 2，此时工作集为\{2, 3, 5\}
      - 随后操作系统为进程分配【 &gt; 工作集的驻留集】大小，就会保证不抖动
      - 拓展：
        - 有些OS会根据工作集来设计页面置换算法，根据进程近期访问的页面来确定换什么页面
  - 工作集和驻留集关系
    - 工作集  &lt; 驻留集
- 内存共享、内存映射文件
  - 页框分配：
    - 即页面分配策略，连续、非连续分配
  - 内存映射文件：
    - mmp, Memory-Mapped File
    - 通过内存映射，使得多个进程的某一个虚拟进程地址区域对应内存中同一个物理地址区域
  - 虚存性能因素：
    - 缺页率是影响虚存性能的最主要因素
    - 提高性能的办法
      - 设置好页面大小
        - 太大会增加内部碎片
        - 太小会使得缺页率高、页表过长
      - 设置好工作集、驻留集
      - 设置好LRU、CLOCK置换算法
      - 提高程序的局部性
    - 概要：TLB、Cache命中率都没有这么主要
      概要范围：[缺页率是影响虚存性能的最主要因素](#focus=%E7%BC%BA%E9%A1%B5%E7%8E%87%E6%98%AF%E5%BD%B1%E5%93%8D%E8%99%9A%E5%AD%98%E6%80%A7%E8%83%BD%E7%9A%84%E6%9C%80%E4%B8%BB%E8%A6%81%E5%9B%A0%E7%B4%A0)
