# 4.2 文件操作：逐一分辨名称、句柄、数据

## 创建与打开
- 创建文件：在父目录中建立**名称到文件对象**的目录项，并初始化必要元数据
- 不必为**空文件**预先分配与未来最大长度相等的磁盘空间
- `open(path, flags, mode)`：路径解析、权限核验、创建打开文件描述和进程 fd 表项
- 已存在文件的 `open` 不等于复制所有目录内容到内存；元数据/目录项可能经缓存按需加载
- `open` 返回的是**当前进程的 fd**，不是全局唯一文件ID

## 读、写与文件偏移
- `read(fd, buf, count)`：从当前偏移读取至多 `count` 字节；成功后常推进文件偏移
- `write(fd, buf, count)`：向文件写入数据；返回可能是实际写入字节数，不能假定一定完整
- 文件I/O首先利用**进程fd→打开文件对象**，通常无需每次重新遍历目录路径
- page cache/缓冲缓存可减少物理I/O；遇到文件I/O等待不等于必然发生“虚拟内存缺页异常”
- 随机定位 `lseek`：调整当前打开文件偏移，本身一般不搬移数据块；某些非可定位对象不支持

## 截断与关闭
- `truncate`/`ftruncate`：改变文件逻辑长度；缩短通常回收尾部数据块，但不保证**所有属性都不变**
- `close(fd)`：释放该进程的一项 fd 引用；关联打开文件对象在**最后引用**消失后才可回收
- `close` 不是“关闭操作系统中所有指向该 inode 的打开项”
- 部分系统调用可能产生延迟写错误；持久化语义通常需要进一步考虑 `fsync` 等同步机制

## 删除名称与释放物理内容
- `unlink(path)` 删除一个目录项，硬链接数减1
- 当**硬链接数为0 且最后打开引用也消失**时，类 UNIX 模型才最终释放对应文件数据
- 目录删除与普通文件删除的接口/空目录要求因系统而异；不能通则“非空目录一律可直接 delete”
- 已打开文件被 `unlink` 后，已有 fd 仍可能读写，直到关闭最后引用

## 性能优化与代价
- 预读/顺序预取提高顺序访问效率，错误预测会浪费I/O带宽
- 延迟写合并多次写入；可能扩大崩溃前未落盘数据的损失窗口
- 缓冲/页缓存加速重复读；**命中缓存不代表数据已永久存储**
- 连续或成组分配可改善空间局部性，但动态增长和外部碎片仍须权衡
