# 2.1 进程与 PCB：静态程序如何成为动态执行

## 核心定义
- **程序**：静态的指令与数据描述，可作为多个进程的可执行映像来源
- **进程**：程序在某个数据集合上的一次执行过程，是动态的活动
  - 408教材：进程是**资源分配的基本单位**；在支持内核级线程的系统中，线程是CPU调度的基本单位
- **进程实体**：程序段、相关数据段、PCB 等组成的实体
  - PCB描述某时刻的执行现场与资源状态；不是“进程实体=PCB”
- 动态性、并发性、独立性、异步性、结构性
  - 动态性：创建、运行、等待、终止；**进程最基本的特征**
  - 异步性：不同进程推进速度不可预知，需要同步协调

## PCB = 内核管理进程的依据
- 标识：PID、父PID、UID及权限等
  - **PID是数值标识；PCB是进程存在的唯一标志和管理信息集合**
- 状态与调度：就绪/运行/阻塞、优先级、队列指针、计时信息
- 现场：PC、PSW、通用寄存器、栈指针等保存值
- 资源：虚拟地址空间、打开的文件、I/O和相关资源清单
- 组织：就绪队列、阻塞事件队列，可使用链表或索引结构
- PCB通常由内核创建、维护，进程结束后回收；具体实现可分散于多个内核数据结构

## 进程之间的共享与隔离
- 相同可执行程序可同时产生不同进程
  - 各进程分别有自己的PID、PCB和逻辑地址空间
  - 代码所在的只读**物理页**可以被多个进程共享；可写页通常隔离
- 父子进程：例如 `fork` 后，初始虚拟映像可能相同，并通过**写时复制 COW**共享物理页
  - “不同进程一定拥有不同虚拟地址数值”错误：虚拟地址相同，映射到的对象可能不同
- 同一进程的多个线程共享代码段、堆、打开文件等
  - 每个线程独有PC、寄存器现场、线程栈和线程状态

## 易错结论与自测
- PCB属于管理数据结构，不等于用户程序的代码区
- 临界区是访问共享资源的**代码段**；临界资源是同一时刻不能被并发使用的资源
- 打开同一程序两次，**不能**仅凭“程序段相同”推断它们共享私有数据
- 思考：两个进程代码段映射到同一个只读物理页，为什么依然是两个进程？
