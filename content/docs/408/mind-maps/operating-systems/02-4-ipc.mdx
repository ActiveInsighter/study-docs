# 2.4 进程通信 IPC：共享数据不等于已同步

## 共享存储
- 两个进程将某些虚拟地址映射到**同一底层共享对象**
- 通信方式：通过共享存储区直接读写；适合大量数据交换
- 优点：减少重复拷贝；缺点：共享内存**不自动解决互斥和同步**
- 常搭配：互斥锁、信号量或条件变量维护一致性
- 教材分法：基于共享数据结构的低级共享、基于共享存储区的高级共享

## 消息传递
- 通过`send/receive`等原语传递结构化消息，内核/运行时帮助交换
- **直接通信**：明确指定发送/接收进程或通信端点
- **间接通信**：通过邮箱、端口、消息队列等中间对象
- 同步发送/异步发送、阻塞接收/非阻塞接收是**独立维度**
- 一条消息可以被复制或搬运，不意味着两个进程分享了可随时读写的同一物理页

## 管道通信
- 匿名管道常见于有亲缘关系进程；命名管道可用路径名发现
- 标准管道通常是**单向字节流**；双向通信一般使用两个管道或其他双向通信机制
- 缓冲区满：阻塞式写可能等待；缓冲区空且写端未全部关闭：阻塞式读可能等待
- **读端看到EOF**的关键：缓冲区已读空，且所有写端关闭
- 多个读者可以竞争读取同一管道字节：**不是“管道只能有一个读进程”**
- 管道通常没有独立消息边界，读取会消耗相应字节

## 通道 / 管程 / 管道勿混
- **通道**：I/O体系中的设备控制处理机构，可执行I/O程序
- **管道**：IPC通信机制，承载字节流
- **管程**：封装共享数据和操作的高级**同步抽象**
- 题目陷阱：消息传递的“直接”是**直接指定收件方**，不等于一定共享地址空间
