# 3.19 抖动：不是“缺页一次”就叫抖动

## 工作集 Working Set
- 给定时刻 $t$ 与窗口长度 $\Delta$，工作集 $W(t,\Delta)$ 为最近窗口内**被访问过的不同页面集合**
- 例：最近5次引用 $2,3,5,3,2$ → 工作集 $\{2,3,5\}$，工作集大小为3
- 每个进程的工作集会随执行阶段变化，体现时间局部性和空间局部性

## 工作集和驻留集的关系
- **工作集**是近期访问页集合，**驻留集**是当前已装入物理内存的页集合
- 二者既非定义相同，也非始终满足简单固定大小关系
- 若长期无法容纳活跃工作集，则缺页率通常会显著升高
- 有效驻留集大小接近或覆盖工作集是降低抖动的目标之一，并非绝对保证“不缺页”

## 抖动 Thrashing 的因果链
- 多进程争抢有限页框 → 活跃页面反复被淘汰 → 很快又重新缺页调入
- CPU大量时间用于处理缺页和I/O，真正执行有用指令的比例下降
- 若错误地继续提高多道程序度，可能让物理页框更紧张、吞吐继续恶化

## 调控策略
- **工作集策略**：估计所需活跃页框，在内存不足时减少并发驻留进程数
- **页故障频率 PFF**：基于缺页率高低动态增减进程可用页框
- 暂停/换出一部分进程，给剩余进程更足够的活跃驻留页
- 更好的局部性、合适页大小、合理页面置换，也可降低调页压力

## 纠错辨析
- 缺页率高不一定是置换算法差，也可能是工作集突然扩张或页框过少
- TLB未命中率高不等于抖动：TLB未命中通常只需访问页表
