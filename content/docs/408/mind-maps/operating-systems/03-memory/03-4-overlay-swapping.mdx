# 3.4 覆盖与交换：两种不同的内存节省技术

## 覆盖（Overlay）
- **同一进程**把不同时期才用到的模块放进同一覆盖区
- 常见划分：固定区保留关键执行部分，覆盖区复用给互不同时执行的模块
- 常需要程序/装载器预先规划模块的覆盖关系
- 多用于早期存储受限环境；不能把覆盖与虚拟内存自动调页完全等同

## 交换（Swapping）
- 通过把进程映像的部分或全部驻留状态移到后备存储，回收物理内存
- **换出**可使进程进入挂起态；**换入**后若事件已满足才有条件参与CPU竞争
- 中级调度在传统教材语境中负责对换/挂起与恢复
- 现代OS通常以按页换出为主，也可能有匿名页交换、文件页丢弃后重读

## 哪些情况不能一概而论
- I/O正在直接访问进程物理内存时，不可把所依赖的页任意迁移或回收
  - 常用**锁定/固定页（pin）**、I/O缓冲或DMA映射协调
- 进程执行临界区并不意味着**所有页面绝对不能换出**；核心问题是保证锁的进展性和所需内存可用
- **死锁进程不因“换出”就自动解锁**；持有的互斥资源、等待关系可能不变
- 创建态、就绪态等能否直接挂起要看教材状态模型，不能把“创建→挂起”当通用必经路径

## 408 对照
- 覆盖：单位是同一进程内部的程序模块；交换：单位通常是进程或页面驻留内容
- 交换与**页面置换**不等同：前者可以是整体换出，后者是缺页等触发的换页
