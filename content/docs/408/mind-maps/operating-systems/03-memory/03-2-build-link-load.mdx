# 3.2 编译—链接—装入：地址何时确定

## 从源程序到进程映像
- 典型 C 工具链：源文件 → 预处理 → 编译成汇编 → 汇编成目标文件 → 链接成可执行映像 → 装载运行
- 目标文件通常含：代码、数据、符号、重定位信息；不应笼统说“全都从零开始绝对寻址”
- 链接解决**模块间符号引用和重定位**，装入负责把映像建立到运行地址空间
- <img src="/images/408-mind-maps/os-0085.svg" alt="编译、链接、装入三个阶段" width="760" height="300">

## 三种链接时机
- **静态链接**：运行前把需要的目标模块与库代码合成可执行文件
  - 优势：部署独立；代价：可执行体积可能增大、公共库更新需重新链接
- **装入时动态链接**：程序装入阶段解析、连接需使用的模块
- **运行时动态链接**：运行过程中按需装入并解析模块，例如通过动态链接器接口
  - 按需装入可节约资源，但不能保证每个库函数只在首次调用才装载
- 动态库节省**磁盘或物理内存**的效果依共享映射和使用情形，不是“肯定更少”

## 三种装入/重定位
- **绝对装入**：装入位置在生成地址时已确定，适用于地址布局固定的简单系统
- **可重定位装入（静态重定位）**：装入时依据起始位置一次性修改需重定位的引用
  - 运行后一般不靠此方案再动态改变该地址映射
- **动态运行时装入（动态重定位）**：程序执行访问时进行地址翻译
  - 可通过基址/界限寄存器或分页 MMU 完成；**不等于只能连续分配**
  - 每次进程切换可更新当前地址空间对应的转换状态
- “整个系统只有一个重定位寄存器供所有进程永久共享”不准确；是**CPU当前运行上下文**中激活的转换状态

## 高频考法
- 链接与装入不能混淆：链接处理模块关系，装入建立运行映像
- 静态重定位后的程序挪动通常需要重新处理地址；动态重定位可以更新映射
- “运行时链接”与“按需调页”彼此独立，前者是模块加载，后者是页驻留管理
