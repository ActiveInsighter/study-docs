# 3.11 分段存储：以程序的逻辑单元为边界

## 为什么分段
- 一个程序可按代码、数据、堆栈或其他逻辑模块划为长度不同的**段**
- 逻辑地址是二维的：$(s,d)$，其中 $s$ 为段号、$d$ 为段内位移
- 段通常反映程序的逻辑结构，便于按段共享、独立保护和增长
- 与页对比：**段长可变，页长固定**；段式管理更易产生外部碎片

## 分段地址转换
- 段表寄存器提供段表始址与段表长度
- 第一层判断：段号 $s$ 是否越界
- 读第 $s$ 个段表项，取得段基址 $B_s$ 和段长 $L_s$
- 第二层判断：$0\le d<L_s$
- 合法时物理地址 $E=B_s+d$
- <img src="/images/408-mind-maps/os-0111.svg" alt="段表、段长越界校验与段基址加偏移" width="730" height="370">

## 算例和访存
- 段表第2项：基址8192B，长度500B
- 逻辑地址 $(2,100)$ → 合法，物理地址8292B
- $(2,500)$ → **越界**：最大合法偏移为499B
- 段表位于内存、无快表：读段表1次 + 读目标数据1次，共2次主存访问

## 共享和保护
- 同一只读代码段可映射到多个进程地址空间
- 不同段可设置读/写/执行权限；共享可写数据仍需并发同步
- “分段一定物理连续到整个进程”错误；只要求**单段内部**在该模型中连续
