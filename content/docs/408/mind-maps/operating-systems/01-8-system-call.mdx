# 1.8 系统调用：受控访问内核

## 触发流程
- 应用准备系统调用号与参数（寄存器/栈/内存，依ABI）
- 执行**系统调用入口指令**（`syscall`、`svc`、`ecall`、`int`等，依架构）
- CPU通过受控入口切换权限，内核验证参数/权限并分派对应服务
- 内核执行操作、填写返回值/错误码、执行受控返回；应用继续运行或因阻塞暂时不运行
- **图示**：<img src="/images/408-mind-maps/os-01-mode-entry-clean.svg" alt="系统调用与异步中断在模式切换上的异同" width="740" height="276">

## 系统调用与普通函数
- **普通函数调用**：通常在同一权限级执行，通过普通跳转/返回完成；不必进入内核
- **系统调用**：由硬件受控入口授权执行内核服务，通常涉及权限转换与安全检查
- **库函数 ≠ 系统调用**：`strlen`完全可留在用户态；`fread`会处理用户态缓冲，必要时再发起`read`
- 系统调用**不意味着每一次必须陷入磁盘**：内核可在缓存中完成，或操作根本与I/O无关

## 典型分类
- 进程控制：创建/终止/等待、线程等相关服务
- 文件/设备：打开、读写、设备控制
- 内存：映射、解除映射、保护页权限
- 通信：管道、套接字及其他IPC
- 获取时间/身份/属性：部分功能可使用用户态快速路径，但仍有受控内核接口

## 易错判断
- `printf`是**库函数**，不是所有平台上直接对应一条单一系统调用
- 提交系统调用的**入口指令在用户态发出**，服务代码通常在内核态执行
- 若`read`需要等待数据：内核可将当前进程阻塞并调度别人，返回时间延后
- **没有发生进程切换的系统调用仍发生了权限切换**；不可混为一谈
