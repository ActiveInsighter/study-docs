# 1.11 进程的典型虚拟地址空间

## 逻辑映像（示意，不等于所有平台固定布局）
- **代码段 text**：可执行机器指令，通常可执行、不可随意写；多个进程可能共享只读映射
- **只读数据**：字符串常量及只读常量对象的典型存放区，具体编译器布局可能不同
- **已初始化全局/静态数据**：典型在`.data`
- **未初始化或零初始化全局/静态数据**：典型在`.bss`，不必把大量0逐字节存入磁盘映像
- **堆 heap**：动态分配（如`malloc/new`），管理策略依运行库与OS
- **栈 stack**：调用帧、局部自动变量、返回地址等，**并非所有局部变量必然存在物理栈槽**（优化/寄存器）
- 还可能存在共享库、内存映射文件、线程栈、内核映射区等

## 三个常考区分
- **虚拟地址**：进程使用的逻辑位置；**物理地址**：实际内存位置；由地址转换机制关联
- **虚拟连续** ≠ **物理连续**：分页允许相邻虚拟页映射到不相邻的物理页框
- **地址空间大** ≠ **当前全部驻留RAM**：按需调页使多数虚拟页可暂未装入

## 对照小例
- `int g = 7;`：典型已初始化静态存储数据区
- `static int c;`：典型BSS/零初始化区
- `char *p = malloc(100);`：`p`本身若为自动局部变量通常在栈/寄存器，**指向的100字节在堆**
- `const char *s = "abc";`：指针本身依其存储期，字符串字面量通常在只读区域
- 注意：这些是常见编译器/操作系统布局，C语言标准**不强制规定.data/.bss的实际段名**
