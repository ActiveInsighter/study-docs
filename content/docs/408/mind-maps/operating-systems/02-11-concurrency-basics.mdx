# 2.11 并发控制：互斥与同步不是同一件事

## 同步、互斥与竞态
- **互斥**：同一时刻最多一个执行流访问特定临界资源
- **同步**：建立必要的先后/协作关系，如“先生产再消费”
- **竞态条件**：执行结果依赖不可控的指令交错顺序
- 例：两个线程各执行`count = count + 1`，无保护可能丢失更新
  - 读取 → 运算 → 写回是多个步骤，并非普通意义上的原子操作

## 临界资源与临界区
- 临界资源：同时被并发使用会破坏正确性或只能独占的资源
  - 共享链表、打印设备等可成为临界资源
- 临界区：进程/线程访问该资源的**程序段**
- 一次典型循环
  - 进入区：申请访问许可
  - 临界区：对共享对象进行操作
  - 退出区：释放许可
  - 剩余区：与该共享对象无关的其他代码

## 四个实现要求
- **空闲让进**：无人使用时应允许有意进入者进入
- **忙则等待**：已有线程在临界区，其他请求者不得同时进入
- **有限等待**：在合理条件下，申请者等待不应无限期延长
- **让权等待**：无法进入时尽量让出CPU，避免长时间忙等
  - 自旋锁一般无法满足让权等待，但可保证互斥

## 三类常考反例
- 无锁更新共享计数器 → 不满足互斥，可能丢更新
- `turn`严格交替但对方迟迟不进入 → **违反空闲让进**
- 两线程先置位后等待另一线程撤销 → **死等**，违反进展性
