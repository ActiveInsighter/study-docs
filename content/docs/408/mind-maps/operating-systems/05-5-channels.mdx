# 5.5 通道控制方式与四种I/O模式对比

## I/O通道的地位
- **通道**：专门执行I/O指令序列的处理部件（教材抽象）
- CPU启动通道程序；通道解释/执行通道命令，控制设备控制器工作
- 可管理多步、多个块甚至多设备协同操作，大幅减少CPU逐项干预
- 经典层级：CPU → 通道 → 设备控制器 → 设备

## 经典通道类别
- **字节多路通道**：按字节分时交替服务多个低速设备
- **数组选择通道**：选定一台设备后连续传送较大数据组
- **数组多路通道**：兼顾多个高速设备和成组数据传送
- 真实硬件会存在设备队列和独立的I/O处理器，不必把教材三类强制套入现代NVMe

## 四种方式对照
- 程序查询：CPU持续询问状态、参与数据搬运；等待成本最高
- 中断驱动：CPU不再持续忙等，但传统传送仍由CPU参与
- DMA：CPU配置+结束处理，中间由DMA负责主存/设备的数据搬运
- 通道：CPU启动通道程序，通道执行更复杂的I/O任务
- 总规律：**CPU对数据搬运和设备细节的直接干预逐渐减少**；不代表每个系统都具备四层

## 中断触发区分
- 查询方式：依靠轮询，不要求设备完成中断
- 中断驱动：就绪/完成等事件可发中断，频度由设计决定
- DMA：常按一次编程的传输或描述符组完成通知
- 通道：通道程序完成或遇到异常后通知CPU
