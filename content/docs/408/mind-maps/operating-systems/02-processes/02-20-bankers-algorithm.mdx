# 2.20 银行家算法：安全状态是“有路可走”

## 五个核心量
- `Available[j]`：当前可用的j类资源实例数
- `Max[i,j]`：进程i声明的最大需求
- `Allocation[i,j]`：已分配给i的资源量
- **`Need = Max - Allocation`**：还能申请的最大剩余量
- 安全性测试临时向量：`Work=Available`、`Finish[i]=false`

## 安全性算法
- 找一个未完成的进程i，满足 `Need[i] ≤ Work`（逐资源类型比较）
- 假想i可全部完成并归还占有资源：`Work += Allocation[i]`，记`Finish[i]=true`
- 重复直到全部`Finish=true` → 有安全序列，系统安全
- 若找不到可完成者且有人未完成 → **不安全**
- 安全序列不是当前真实调度顺序，也不是一定只有一个

## 经典三资源例题
- 假设可用资源`Available=(3,3,2)`
- 五个进程的 `Allocation / Need`
  - P0：`(0,1,0) / (7,4,3)`
  - P1：`(2,0,0) / (1,2,2)`
  - P2：`(3,0,2) / (6,0,0)`
  - P3：`(2,1,1) / (0,1,1)`
  - P4：`(0,0,2) / (4,3,1)`
- 一条安全序列 **P1 → P3 → P4 → P0 → P2**

## 请求判定与陷阱
- 收到 `Request[i]` 必须先验证 `Request≤Need` 且 `Request≤Available`
- **试分配**后运行安全性算法，安全才真正批准；否则回滚试分配
- 对上述状态，假定P4请求`(3,3,0)`：虽不超过Need且Available，试分配后`Work=(0,0,2)`无进程可完成 → **不安全，拒绝**
- 不安全状态**不等于**已经死锁；可能后续有进程主动释放资源
