# 2.3 进程控制原语：创建、撤销、阻塞、唤醒

## 创建和终止
- 创建典型触发：系统启动、用户请求、作业入内存、父进程创建子进程
- 创建过程：分配PID/PCB → 分配/建立地址空间等资源 → 初始化PCB → 加入就绪队列
  - **资源不足不一定“进入阻塞态”**：创建可延迟或失败，依系统与原因区分
- 终止触发：正常退出、异常终止、被其他进程请求强制结束
- 终止过程：停止执行 → 保存退出信息/通知等待者 → 回收资源 → 按机制回收PCB
  - UNIX类系统：子进程可能先成为**僵尸进程**，待父进程`wait`回收剩余记录
  - “终止一个进程必终止全部子孙进程”不是普适法则

## 阻塞和唤醒
- 阻塞：运行进程因等待事件而**主动**请求睡眠（或内核使其等待）
  - 保存现场、更新状态、移入**对应事件**等待队列
  - 不能误写“放入就绪队列”
- 唤醒：I/O完成、V操作释放资源、条件被满足等
  - 在等待队列移除PCB → 标为就绪 → 加入就绪队列
  - 唤醒通常**不等于立即获得CPU**；若触发抢占，则可迅速分派
- 阻塞/唤醒相互配对的事件语义比“哪个进程调用API”更重要

## 调度、分派与上下文切换
- 调度程序：选择**下一个**运行主体；分派程序：执行交接
- 典型上下文切换
  - 保存当前PC/寄存器/状态 → 记入PCB/TCB → 切换地址空间等（若需要）
  - 恢复下一线程/进程寄存器和栈 → 从其断点继续执行
- 同进程不同线程切换：通常不用切换整个地址空间
- 用户态↔内核态切换：**不必然发生进程切换**
  - 系统调用可以返回原进程；中断也可以返回被中断进程

## 408易错与概念边界
- “广义调度”可含选择和上下文切换；不同教材术语略异，做题依题设
- 原语的逻辑动作应不可被并发破坏；并非所有步骤都由一条机器指令完成
- `fork/exec/exit/wait` 是UNIX类进程管理常见接口，不能把具体系统调用名称等同所有OS的实现
