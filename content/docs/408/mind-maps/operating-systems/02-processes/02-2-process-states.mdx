# 2.2 进程状态：为什么就绪不等于阻塞

## 三态与五态模型
- 核心三态
  - **运行态**：获得CPU并执行
  - **就绪态**：运行所需资源具备，只等CPU
  - **阻塞态**：等待I/O、同步信号等事件，**即使有CPU也不能继续**
- 五态增加：创建态与终止态
- 事件触发
  - 就绪 → 运行：**调度/分派**
  - 运行 → 就绪：时间片用完或被更高优先级任务抢占
  - 运行 → 阻塞：主动等待I/O或P操作阻塞等
  - 阻塞 → 就绪：等待事件完成/被唤醒；**不会直接转运行**

## 七态增加两种挂起
- **就绪挂起**：已具备运行条件，但进程主体暂不在可运行的内存集合中
- **阻塞挂起**：既等待事件，又已挂起
- 典型转换
  - 阻塞 → 阻塞挂起：阻塞进程被换出
  - 阻塞挂起 → 就绪挂起：等待事件在挂起期间完成
  - 就绪挂起 → 就绪：换入内存
  - 就绪 ↔ 就绪挂起：因内存压力/换入而变化
- *注意*：挂起机制的实现因OS而异；考试通常按教材七态图分析

## 必背的转移限制
- “运行 → 阻塞”是**主动等待条件**，不是I/O设备“通知CPU时间片用完”
- “阻塞 → 就绪”由等待事件满足产生，后续还需被调度
- 就绪的进程如果没有CPU，不能称为阻塞
- 缺页可能触发阻塞等待页面调入；**TLB未命中并不一定导致阻塞**
- 正在运行的进程被换出时如何表示，要按题目采用的状态模型回答

## 三步判别题
- 问题1：某进程申请读磁盘，数据未就绪 → **运行→阻塞**
- 问题2：磁盘读入完成但CPU正在运行其他进程 → **阻塞→就绪**
- 问题3：某进程已被换出，等待事件完成 → **阻塞挂起→就绪挂起**
