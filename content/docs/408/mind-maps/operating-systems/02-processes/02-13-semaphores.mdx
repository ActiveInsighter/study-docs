# 2.13 信号量：P/V 让资源数量与事件有了秩序

## 信号量的两个操作
- `P(S)` / `wait(S)`：申请一个许可或等待事件
- `V(S)` / `signal(S)`：释放许可或宣告一个事件完成
- P、V**必须具备原子性**；它们是进程同步原语，可由内核/运行库实现
- 计数信号量初值为可用资源数；二值信号量常设为0或1

## 整数与记录型区分
- **整数型（忙等实现）**：`wait`在不可用时循环检查，可能不让权
- **记录型（含等待队列）**：
  - `P`: `S.value -= 1`；若新值`< 0`，把调用者放入等待队列并阻塞
  - `V`: `S.value += 1`；若新值`≤ 0`，从等待队列唤醒一个等待者
  - 在这种教材定义下：`S.value < 0`时，`-S.value`可表示等待者数量
- 注意：不是每一次P都阻塞，也不是每次V都唤醒

## 三种典型用法
- **互斥**：初值`mutex=1`，每段临界区前P、后V
- **同步**：初值`done=0`；A完成动作后`V(done)`，B执行前`P(done)`
- **前驱关系**：对有向无环图的每条边`U → V`设置一个初值0的信号量
  - U执行完对每条出边V一次；V开始前P其全部入边
  - 多个入边要各自P，不能漏一个前驱

## PV顺序最容易错
- “先P互斥锁、再P资源信号量”可能**拿着锁睡眠**，导致生产者/消费者死锁
- “信号量=0一定已经有人阻塞”错误：零值只是可用许可为0
- 如果只规定“事件A发生后B才能开始”，通常令同步信号量初始值0
