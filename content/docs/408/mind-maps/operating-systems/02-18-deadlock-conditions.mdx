# 2.18 死锁的四个必要条件

## 先辨清三个现象
- **死锁**：一组进程相互等待，均无法推进；通常存在不可满足的资源等待环
- **饥饿**：有进程长期得不到服务，但系统其他部分可能一直在推进
- **活锁**：各参与者持续改变状态/重试，却没有完成有用工作
- 死锁和饥饿都可能导致长期等待，但形成机理不同

## 四个必要条件（Coffman条件）
- **互斥条件**：至少存在一个不可共享的资源
- **请求并保持**：进程持有部分资源，同时等待新的资源
- **不可剥夺**：进程未释放前，资源不能被系统强制取回
- **循环等待**：进程形成等待环路$P_1→P_2→…→P_1$
- 四者全部成立只是**可能导致死锁的条件**；不能直接反推“已死锁”

## 资源分配图 RAG
- 请求边：**进程 → 资源**；分配边：**资源 → 进程**
- 一类资源仅1个实例：存在等待环往往即可判定死锁（在标准RAG模型假设下）
- 资源有多个实例：存在环**不一定**死锁
- 没有环则在标准可再利用资源模型中可排除资源死锁

## 审题必看
- 资源是**可抢占**CPU时间片还是**不可抢占**打印机？适用策略不同
- 原有请求是否是“正在等待”，还是未来可能请求？二者不同
- 一个进程一直没有CPU可能是调度饥饿，不一定是资源死锁
