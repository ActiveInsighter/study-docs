# 4.1 文件：名称、内容和元数据分层

## 文件是什么
- **文件**：操作系统以名称和元数据组织、管理的一组持久化信息
- 用户侧：**按名存取**，无需直接记住磁盘扇区或分配表位置
- 系统侧：路径名 → 目录项/文件标识 → 文件元数据 → 数据块
- 文件可表示普通数据、目录、设备等；设备文件并不意味着“设备本体存在磁盘文件内容中”
- **持久化**是常见文件语义；不能推出每一次 `write` 返回即完成物理持久写入

## 文件的两层信息
- **数据内容**：普通文件的字节流或记录集合
- **元数据**：大小、类型、权限、时间戳、位置/块映射、所有者、链接数等
- **目录项**：名称与文件身份的映射；在 inode 模型中是“文件名 → inode号”
- 文件名在**同一目录中**通常不能重复；不同目录允许同名
- **文件描述符 fd**：进程持有的已打开文件引用，既不是路径名，也不是跨进程唯一的 inode 编号

## 逻辑组织与物理存储必须分开
- 无结构文件：文件系统通常将数据看作字节序列
- 记录式文件：按记录组织；记录可以由应用或专门文件系统管理
- 逻辑结构：决定如何理解与定位记录
- 物理结构：决定文件数据占用哪些**磁盘块**及块如何串接
- 相同字节流文件可采用连续、链接、索引、extent 等不同分配方法

## 文件类型与典型属性
- 普通文件：文本、二进制可执行文件、媒体内容
- 目录文件：维护名字到文件实体的关联
- 特殊文件：字符设备、块设备、管道、套接字等，具体支持依操作系统
- 创建/修改/访问时间语义、精度和更新条件依文件系统实现
- 访问控制关联进程身份与文件权限，不由“进程优先级高”决定

## 408小测
- 两个不同路径能否指向同一文件？**可以，硬链接**
- 文件重命名是否一定要重写全部数据块？**不需要**
- 文件物理块是否必须连续？**不需要**
