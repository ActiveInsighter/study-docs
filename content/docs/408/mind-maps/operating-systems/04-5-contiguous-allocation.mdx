# 4.5 文件物理结构：连续分配

## 核心映射
- 文件的盘块号按物理位置连续；目录可保存 `起始块号 start + 块数 length`
- 文件逻辑块号 j（从0开始） → 物理块号 `start + j`
- 支持顺序、随机读；随机读在**已定位块号**时无需沿链逐块遍历
- <img src="/images/408-mind-maps/os-0140.svg" alt="文件连续分配示例及目录起点与长度" width="790" height="484">

## 优点与条件
- 数据顺序排列、寻道/机械磁盘移动开销通常较低（尤其是大文件连续读）
- 块定位简单；元数据开销相对少
- 不能笼统说“访问速度永远最快”，还受到页缓存、设备、并发访问等影响
- 当前文件逻辑第 j 块越界时，即便磁盘物理位置存在块 `start+j` 也不可擅自读取

## 缺点与增长
- 需要足够大的**连续空闲区域**，磁盘空闲块总数足够也可能无法分配
- 文件增长受紧随其后的空间限制，可能移动文件或重新分配
- 连续分配可能导致**外部碎片**；预留空间也可能浪费
- “只有连续分配产生碎片”不严格：其它块/簇与extent系统也可能有内部浪费或空闲空间分散

## extent（区段）改进
- 将文件组织为多个 `(start,length)` 连续区段，而非要求所有数据属于**单个**区段
- 每个extent内保持顺序局部性；文件追加可增加新区段
- extent 数增多会提高映射元数据与碎片管理复杂度

## 408计算
- 若文件从盘块80开始，长度25块，则逻辑块0→80，逻辑块24→104
- 块大小4KiB，文件10240B → 最少占用3个数据块；第三块仅用2KiB（按块分配存在内部浪费）
