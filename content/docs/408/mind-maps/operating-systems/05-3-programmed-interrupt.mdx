# 5.3 程序查询与中断驱动I/O

## 程序直接控制：PIO/查询方式
- CPU发命令 → 反复读状态 → 等待就绪 → 通过CPU完成数据读写
- 等待期间持续占用CPU查询时间；实现简单、硬件要求低
- 数据常经控制器数据寄存器与CPU寄存器再进主存
- <img src="/images/408-mind-maps/os-0068.svg" alt="程序查询方式的轮询控制流程" width="560" height="520">

## 中断驱动方式
- CPU发命令后可运行其他任务；设备需要处理时发出中断请求
- 内核进入中断处理：识别来源、读状态、搬运或安排后续数据处理、唤醒等待者
- 避免忙等，但多次中断有现场保护与调度开销
- <img src="/images/408-mind-maps/os-0118.svg" alt="中断驱动I/O的控制过程" width="560" height="520">

## 数据传送与CPU干预
- 传统**PIO**：CPU参与每次数据搬运；中断驱动可以仍然由CPU搬数据
- 中断并不自动改变数据通路；DMA才可让设备/控制器直接与主存交换
- 数据宽度取决于设备、寄存器、指令和总线，不能统一规定为“字”
- CPU处理外部中断通常在可响应的指令边界；不意味着全部设备必须“每字一次中断”

## 四个典型陷阱
- 查询方式也可能在合适场景优于中断：短操作、低延迟忙等
- 中断处理期间不是“所有进程上下文都要切换”；先区分中断现场与进程切换
- 发出中断 ≠ 用户程序立刻获得结果：驱动/调度/唤醒仍有工作
- 设备完成通知与一次传输的数据粒度由实际设计决定
