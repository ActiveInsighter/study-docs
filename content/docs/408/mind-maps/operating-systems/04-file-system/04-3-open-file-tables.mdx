# 4.3 文件在内存中的三层引用

## 三层结构不要混淆
- 进程**文件描述符表**：`fd → 打开文件描述`，还可含描述符标志
- 系统**打开文件描述/文件对象**：当前偏移、打开状态标志、引用计数、底层文件引用
- 文件的**inode/元数据对象**：文件大小、权限、数据块映射、硬链接数等
- 不同进程的同一个数字 `fd=3` **完全可能指向不同文件**
- <img src="/images/408-mind-maps/os-04-open-tables-clean.svg" alt="文件描述符、打开文件描述、inode 三层结构与共享偏移" width="860" height="487">

## 三种打开方式的偏移区别
- **独立调用两次 `open`**：通常得到两个独立打开文件描述 → 文件偏移独立
- **同进程 `dup`**：两个fd可指向同一打开文件描述 → **共享文件偏移**
- **`fork` 继承fd**：父子进程表项可共享既有打开文件描述 → 共享偏移
- 硬链接：不同路径指向同一inode，**不自动说明**不同打开实例共享偏移
- 对一个文件 `open` 多少次与它的**硬链接计数**是不同指标

## 打开/读/关的典型链路
- `open("/a/b")`：目录路径解析与权限检查 → 取得文件对象 → 分配进程fd
- `read(fd, …)`：查进程 fd 表 → 打开文件描述 → inode/数据页 → 文件缓存或块设备
- `close(fd)`：释放 fd → 引用计数递减 → 必要时销毁打开文件描述
- 别将“文件系统表”简单视为只保存磁盘起始地址；还可能保存偏移、模式、引用等状态
- <img src="/images/408-mind-maps/os-0145.svg" alt="进程打开文件表与系统打开文件表" width="810" height="375">

## 数值小题
- P执行 `open(A)` 获得fd3；`dup(3)` 获得fd4，fd3读5字节 → fd4下次读取从**偏移5**开始
- P再执行 `open(A)` 获得fd5 → fd5从自身初始偏移开始，通常**与fd3/4独立**
- P再创建硬链接B→A，不会让 `fd5` 与 `fd3` 自动共享偏移
