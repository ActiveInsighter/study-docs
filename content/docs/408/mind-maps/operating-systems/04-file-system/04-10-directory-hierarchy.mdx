# 4.10 目录组织：名字唯一性的作用域

## 单级目录
- 所有文件共享同一目录；文件名全局唯一，搜索简单但多用户易冲突
- 适用极简系统，不适于复杂分类与权限管理
- <img src="/images/408-mind-maps/os-0099.svg" alt="单级目录结构" width="660" height="212">

## 两级目录
- 主文件目录 MFD → 用户文件目录 UFD → 文件
- 不同用户可使用同名文件；但缺乏灵活多层分类
- 传统两级模型共享能力弱，实际系统可另加链接共享机制
- <img src="/images/408-mind-maps/os-0026.svg" alt="主文件目录与用户文件目录" width="720" height="220">

## 树形目录
- 每个目录可包含子目录和文件；便于按层分类、按路径定位
- 绝对路径从根开始；相对路径以当前工作目录等基准解析
- `.` 指向当前目录、`..` 指向父目录；根目录相关处理依文件系统定义
- 访问 `/a/b/c` 一般需对路径每级执行查找/权限检查
- <img src="/images/408-mind-maps/os-0018.svg" alt="树形多级目录结构" width="740" height="310">

## 无环图目录 DAG
- 不同目录可共享子对象，形成具有多条入边但**无环**的目录结构
- 使用硬链接共享文件时，目录项数增加、inode硬链接计数增加
- 对目录硬链接通常受限以避免形成环；符号链接可造成路径循环，需要解析保护
- **共享链接数**不是“当前有多少进程访问文件”
- <img src="/images/408-mind-maps/os-0158.svg" alt="共享结点构成的无环图目录示意" width="730" height="495">

## 目录操作
- `mkdir` 创建子目录；`rmdir` 通常只删除空目录（不考虑特殊递归工具）
- `opendir`、`readdir` 用于遍历目录项，不等于“必须把所有FCB一次读入RAM”
- `rename` 改名字/位置，不是创建硬链接；跨文件系统移动可能需要复制+删除
- [上一节：目录与FCB](/docs/408/mind-maps/operating-systems/04-file-system/04-9-directory-fcb-inode)
