# 2.21 死锁检测：等待图与多实例矩阵

## 图模型的边和方向
- `P → R`：进程请求资源实例；`R → P`：资源实例已分配给进程
- **每类资源仅一个实例**时，等待图有环可作为死锁判据
- 某类资源多实例时：资源分配图**存在环仅是必要而非充分条件**
- <img src="/images/408-mind-maps/os-0162.svg" alt="多实例资源分配图教学示意" width="520" height="398">
- **注意原图标题中的“找安全序列”**：资源分配图必须与请求量、实例数配合判定，不可只看画面是否有圈

## 多实例检测算法
- `Available`：当前可用量；`Allocation`：各进程当前占有量
- `Request`：各进程**当前未满足请求量**；不是银行家算法的未来最大`Need`
- 初始`Work=Available`；对尚持有资源的进程令`Finish=false`
- 寻找`Request[i]≤Work`的进程，假想满足其请求并使其完成
  - `Work += Allocation[i]`，把它标为完成；重复
- 无法找到可继续者时，未完成进程即为检测出的可能死锁集合（按模型假设）

## 死锁解除措施
- 撤销一个/多个死锁进程：释放资源；牺牲对象要考虑已完成工作和优先级
- 可剥夺资源则采用资源剥夺 + 回滚；不能剥夺的设备需谨慎处理
- 周期检测可能带来性能开销；检测频率与资源冲突概率权衡

## 快速区分四个词
- **安全状态**：存在进程完成序列
- **不安全状态**：可能导致死锁，但不是已经死锁
- **死锁状态**：一组进程形成不可解等待
- **死锁检测**：识别当前请求是否阻塞到无法推进；**银行家算法**是分配前的死锁避免
