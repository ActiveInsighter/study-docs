# 7.4 分块查找 · 块内与索引

## 基本组织：块间有序，块内可无序
- 将记录划分成若干块，索引记录每块的**最大关键字**（或范围界）及首位置
- 要求各块满足区间有序：前一块所有关键字 **小于等于** 后一块所有关键字（重复值的策略须约定）
- 块内不必排序；因此普通块内查找通常用**顺序扫描**
- 先依据有序索引定位目标块，再扫描块内记录
- <img src="/images/408-mind-maps/ds-0165.svg" alt="按块索引组织的记录表与索引最大关键字" width="720" height="248">

## 分块索引怎么查
- 索引层：顺序查找或折半查找；后者要求索引可随机访问并按块界有序
- 成功 ASL：$ASL_{成功}=ASL_{索引|成功}+ASL_{块内|成功}$
  - **简单相加成立的前提**：概率模型、索引比较次数与块内比较次数已分别正确加权
- 失败 ASL：需分辨“索引层就失败”和“索引定位到块后块内失败”
  - **不能无条件写** $ASL_{失败}=L_i+(L_s+1)$：具体由边界和失败概率决定
- 设 n 条记录均匀分 b 块，每块 s=n/b 条、且索引线性扫描
  - 等概率成功时近似 $ASL\approx (b+1)/2+(s+1)/2$
  - 在 b 和 s 均可取整数且 n 固定时，使 b 与 s 相近，可把比较次数降低到 $\Theta(\sqrt n)$
  - 如果索引二分，索引层是 $O(\log b)$，块内顺扫是 $O(s)$

## 示例（严格按实现计数）
- 块1：[9, 2, 7]，索引 max=9；块2：[18, 12, 15]，索引 max=18
- 查 12：索引依次比 9、18，共2次；进入块2扫描 18、12，共2次 → 4次
- 查 11：索引比 9、18 共2次；块2扫描完3条，共3次 → 5次失败
- 查 25：若索引越界即失败，未必还需扫描最后一块

## 与别的存储方式对比
- 全局有序的顺序表：可直接折半，$O(\log n)$
- 分块查找：只需**块间有序**；块内无序利于局部插删
- B+ 树可以理解为**多级有序索引 + 叶层顺序数据**，但实现细节不同
