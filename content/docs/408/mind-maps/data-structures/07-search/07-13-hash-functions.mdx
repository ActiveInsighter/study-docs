# 7.13 散列表 · 散列函数

## 基本机制
- 散列函数 $H(key)$ 把关键字映射到表地址，例如 $0,\ldots,m-1$
- 不同关键字**可能映射到同一原始散列地址**，称为**同义词**；若争用存储位置则发生冲突
- 散列不是排序：**不能直接按散列地址得到关键字有序序列**
- 查找流程：计算原始 H → 依据冲突策略检查桶/探测序列 → 比对真实 key

## 常见散列函数
- **直接定址**：$H(key)=ak+b$；在地址空间足够且映射无冲突时适用，可能浪费大量空间
- **除留余数**：$H(key)=key\bmod p$；p 常选适当素数，通常 $p\le m$
  - “离表长最近的素数”是常用选法，**不是任何输入分布均最优的定理**
  - 若地址表长度 m、取模 p 小于 m，则地址 p…m−1 不直接成为初始落点
- **数字分析**：分析关键字某些数位的分布，抽取差异大的部分
- **平方取中**：取关键字平方结果中间若干位，减少固定高/低位规律影响
- **折叠法**：将长关键字分段叠加处理，再缩到合法地址范围

## 装填因子
- $\alpha=n/m$，n 为已存记录数、m 为散列表**槽位或桶**数量
- 对开放定址法通常要求 $0\le\alpha<1$ 才保证还有空槽可插入
- 链地址法可允许 $\alpha>1$，表示平均每桶不止一条记录
- 对相同散列函数和冲突策略，$\alpha$ 越高，探测/链平均长度通常越大
- **冲突数量不会改变给定的 n、m 与装填因子**；只有插删、扩缩容等会改变它

## 冲突与容量
- $H(a)=H(b)$ 对不同 key 叫原始地址相同；开放定址探测后也可能被**原始地址不同**的记录挡住
- 散列表是否高效还取决于函数、键分布、碰撞处理、负载和缓存
- “哈希函数完全消灭冲突”：一般不成立，除非特殊**完美散列/已知固定集合**条件
