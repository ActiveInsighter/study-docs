# 8.12 基数排序 · 分配 / 收集

## 不是比较排序
- 将关键字拆成若干位（十进制个位、十位、百位等）
- 每一趟按一位的取值分配到 r 个桶，再按桶顺序收集
- 它依靠**数字位/字符位结构**，不通过通用“两两大小比较”来决定所有记录次序
- 设 n 条记录、每个关键字 d 位、基数 r：处理开销通常为 $\Theta(d(n+r))$

## LSD：从低位到高位
- 先个位、后十位、再百位……每趟使用**稳定**分配与收集
- 后处理的高位应作为更高优先级；稳定性保留之前低位的排序结果
- 例：`[170,45,75,90,802,24,2,66]`
  - 个位稳定收集 → `[170,90,802,2,24,45,75,66]`
  - 十位稳定收集 → `[802,2,24,45,66,170,75,90]`
  - 百位稳定收集 → `[2,24,45,66,75,90,170,802]`

## MSD：从高位到低位
- 按最高位把记录分桶，**各桶内部**再按下一位递归分桶
- 与 LSD 不同，MSD 只需要在各桶内部进一步细分；不可把所有桶重新无条件全局收集排序
- 最高位宽度、负数/符号位、变长字符串结尾标记需有合理的大小顺序定义

## 空间复杂度与稳定性前提
- 用 r 个链接桶的队头/队尾指针且**重用原有记录结点**：额外桶指针空间 $O(r)$
- 若采用稳定数组计数和拷贝分配：通常需 $O(n+r)$ 额外空间
- **不能一概宣称基数排序只用 O(r) 空间**，应看实现
- LSD 必须每趟稳定，才能以低位→高位正确合成字典序
- 输入关键字不便拆位、r 过大或 d 随 n 很大时，基数排序未必占优
