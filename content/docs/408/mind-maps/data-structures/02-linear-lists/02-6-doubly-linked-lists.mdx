# 2.6 双链表 · 双向链接与修改

## 结点结构
- 结点：`prior` 指向直接前驱、`next` 指向直接后继
- 声明示意：`struct DNode { ElemType data; struct DNode *prior, *next; };`
- 从任意结点可按前驱或后继方向遍历
- 普通非循环双链表：首数据结点 `prior` 通常是 `NULL`（无头结点时）

## 双向一致性不变量
- 若 `p->next == q`，通常要求 `q->prior == p`
- 若 `p->prior == q`，通常要求 `q->next == p`
- 每次插入和删除均维护两个方向
- 读写一个方向后，别忘了更新另一方向的关联

## 在已知 p 后插入 s
- 保存原后继 q：`q = p->next`
- `s->next = q; s->prior = p`
- `p->next = s`
- 若 `q != NULL`，则 `q->prior = s`
- 已知 p 时，指针更新 $\Theta(1)$
- 必须检查尾插时 q 为空的情形

## 删除已知数据结点 p
- 保存 `a = p->prior; b = p->next`
- 若 `a != NULL` → `a->next = b`
- 若 `b != NULL` → `b->prior = a`
- 若有头指针或尾指针，还需维护对应边界变量
- 最后释放 p（采用匹配的内存释放方式）
- 已知 p 时可用 $\Theta(1)$ 时间完成连接修改

## 带头结点和带尾哨兵
- 头结点简化表头插入和删除
- 尾哨兵可进一步简化尾部边界条件
- 注意哨兵结点**不是逻辑数据元素**
- 不同教材的头尾结点设计不同，判断空表要先确定定义

## 循环双链表
- 带头结点的循环双链表：`head->next` 指向首元素或 head
- `head->prior` 指向尾元素或 head
- 空表：`head->next == head && head->prior == head`
- 某元素的后继指针可能指向头结点而不是 `NULL`
- 已知 p 时双向循环链表的连接修改无需一般非循环表的末端 `NULL` 分支

## 复杂度与易错
- 已知结点：沿 prior/next 前进一步 $\Theta(1)$
- 按位访问仍需定位，一般最坏 $\Theta(n)$
- 相比单链表：额外指针域，换取前驱访问便利
- “双链表支持任意下标 O(1) 访问” → 错
- “修改 `next` 就足够” → 错
