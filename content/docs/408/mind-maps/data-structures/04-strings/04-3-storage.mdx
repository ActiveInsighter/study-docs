# 4.3 串的存储 · 顺序、堆分配、链式

## 定长顺序存储
- 使用固定容量的数组：`char ch[MAXLEN+1]`、`int length`
- 教材式 1 基示例：`ch[1..MAXLEN]` 保存有效字符，`ch[0]` 可不使用
- 有效串长由 `length` 单独记录，与物理数组长度不同
- 读取第 i 个字符可 **O(1)** 定位
- 缺点：预先确定最大长度；拼接超长可能截断或失败
- 数组大小要足以覆盖**合法访问的全部下标**，不要用 `char ch[MAXLEN]` 却直接访问 `ch[MAXLEN]`

## 四种长度/结束方案
- **方案一**：字符连续存储，长度存额外独立变量
  - 无需遍历即可取得长度
- **方案二**：在 `ch[0]` 存长度，真正字符从 `ch[1]` 开始
  - 用单个字符单元保存长度可能存在取值范围限制
- **方案三**：字符从 `ch[0]` 开始，结尾放 `\0`
  - C 风格字符串常见；求长需要扫描，且结尾标志占额外容量
- **方案四**：`ch[0]` 留空，字符从 `ch[1]` 开始，长度另存
  - 便于与教材 1 基字符位序直接对应；**不是 C 字符串的强制约定**

## 动态堆分配顺序串
- 使用指针保存一片动态申请的连续字符空间
  - 示例抽象结构：`char *ch; int length; int capacity;`
- 可在空间不足时扩容；扩容可能重新申请并搬移原字符
- **随机访问依然 O(1)**（已知地址且下标合法）
- 追加操作的均摊代价依扩容策略而定，不代表所有插入都 O(1)
- 注意：堆分配不等于“链式存储”

## 块链存储
- 用链表结点存一个或多个字符；每结点带 `next` 指针
- 单字符结点：结构简单但指针额外开销大
- 多字符结点：每结点含 `ch[k]`，提高空间利用率
  - 尾结点可能不满：剩余字符位可能采用特殊填充符或独立记录长度
- **按下标定位通常 O(n)**：必须沿链遍历，除非另设索引
- 有利于局部拼接、插删；操作代价取决于是否已定位目标结点
- <img src="/images/408-mind-maps/ds-0014.svg" alt="单字符结点与多字符块链两种串的链式存储" width="600" height="317">

## 存储对照
- 顺序串：地址连续，访问第 i 个字符直接定位
- 链串：不要求结点地址连续，需保留链接字段
- 定长顺序：容量固定；堆分配顺序：容量可动态调整
- `\0` 作为结尾标志的串不能把任意包含零字节的数据当普通 C 字符串处理
- 另存 `length` 并不要求在结尾同时放置 `\0`，具体看实现约定

## 408 高频易错
- 串是**逻辑上连续的字符序列**，不强制要求所有实现物理连续
- `length=6` 表示有效 6 个字符，数组长度和实际申请量可能更大
- “链式存储的空间利用率总是更高”是错误判断
- “C 风格字符串长度包含 `\0`”是错误判断
- `char*` 是实现工具，不应直接替代抽象数据类型定义
