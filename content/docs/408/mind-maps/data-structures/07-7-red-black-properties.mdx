# 7.7 红黑树（RBT） · 五条不变式

## 红黑树仍然是 BST
- 采用严格关键字顺序约定时，中序遍历递增
- 结点具有颜色属性：红色或黑色
- **根为黑色**；在合法实现里可将根变黑而不改变 BST 顺序
- 每条缺失孩子指针对应的**NIL 外部叶均为黑色**（不存真实关键字）

## 不变量（口诀：左根右，根叶黑，不红红，黑路同）
- 左子树关键字小于根、右子树关键字大于根
- 根结点为黑、所有 NIL 外部叶为黑
- 红结点的两个孩子必须为黑，因此**红结点不能有红孩子**
- 任一结点到其所有后代 NIL 的路径含**相同数量黑结点**
- **黑高** $bh(x)$：从 x 向下、**不计 x 自身**的路径上黑结点个数，计入 NIL（具体课程可另约定）
- <img src="/images/408-mind-maps/ds-0109.svg" alt="红黑树黑高和NIL叶示例" width="720" height="400">

## 高度性质与证明骨架
- 不出现相邻红结点 → 根到 NIL 的路径上红结点数不超过黑结点数
- 同一根的所有路径黑结点个数相等，因此最长内部路径长度不超过最短路径的两倍（近似按内部层计）
- 对 n 个真实内部结点：按边数计的高度有 $h\le2\log_2(n+1)$
- 最坏查找、插入与删除时间为 $O(\log n)$，与 AVL 同阶
- **红黑树不是严格 AVL**：某个结点的左右子树高度差可以超过 1

## 示例判断
- <img src="/images/408-mind-maps/ds-0129.svg" alt="检查根颜色、红红相邻和黑高的红黑树候选图" width="720" height="469">
- 检查顺序：先验证 BST 顺序，再验证根/NIL 颜色与红红，最后逐条路径数黑结点
- **NIL 和真实叶结点不是同一个概念**；把真实叶结点一律涂黑不是红黑树要求
- 插入完仍允许出现红色真实叶，只要其 NIL 孩子黑且其他规则满足

## 红黑树与 AVL
- AVL 更严格平衡，查找层数往往更小，旋转维护可能更多
- 红黑树允许更多形态，在许多工程负载中有较好的插删维护成本
- “红黑树插入删除一定比 AVL 快”：**不是算法定理**，还受数据与实现影响
