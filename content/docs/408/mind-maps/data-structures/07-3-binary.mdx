# 7.3 折半查找（二分查找）

## 适用条件
- 数据按目标比较规则**有序**，并能高效随机访问某个中间位置
- 典型：已排序数组；**普通单链表不适合高效二分**，定位中点需要遍历
- 对重复关键字：普通二分只保证找到**其中一个**，不保证首个或最后一个

## 算法：闭区间写法
- 初始 `low=0, high=n-1`
- `while (low<=high)`；`mid=low+(high-low)/2` 避免 `(low+high)` 溢出
- 相等返回 mid；`key<a[mid]` → `high=mid-1`；否则 `low=mid+1`
- 退出时 `low>high` 表示失败；若求插入位置，`low` 即 lower_bound 型边界（实现时需按比较规则定义）
- 单次关键字比较的语义需统一，不能把代码里 `==` 与 `<` 两个判断不加说明地算成“2次查找比较”

## 判定树与 ASL
- 每次比较的 mid 形成**折半查找判定树**，成功结点对应真实记录
- 失败：落入 $n+1$ 个外部区间；其树形深度受 n 和取中点策略影响
- 若记录出现概率等同：$ASL_{成功}=\frac1n\sum_{i=1}^n \mathrm{depth}_{比较}(i)$
- 例 $n=7$：成功结点分布在比较深度 1、2、3 层，个数 1、2、4
  - $ASL_{成功}=(1+2\times2+4\times3)/7=17/7$
  - 8 个失败区间均经过 3 个内部结点，若**不计最终空指针比较**则失败 ASL=3
- 不满的判定树需逐个统计外部结点深度，而非一律 $\lfloor \log_2n\rfloor$

## 性能与题型
- 查找最好 $O(1)$；最坏比较次数 $O(\log n)$，额外空间迭代 $O(1)$
- 若每次取下中点 `floor((low+high)/2)`，偶数长度时中点偏左
- **不同取中点约定产生不同判定树**；画树和 ASL 题必须统一
- 折半查找只在输入已排序时有效；如果先排序，需将排序成本单独计算

## 408 常考陷阱
- “能随机访问就能二分”：**还要有序**
- “二分查找的每个失败外部节点一定同层”：错，非满树常在相邻层
- “折半判定树可直接看成任意 BST”：错，其形态受取中点规则限制
