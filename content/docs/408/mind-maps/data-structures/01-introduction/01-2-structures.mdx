# 1.2 数据结构的三要素

## 总框架
- **逻辑结构**：元素之间在抽象层面的关系
- **存储结构**：如何在计算机存储空间中表示
- **数据运算**：在数据上定义和实施的操作
- 考点：分析时分开，实际设计中相互制约

## 逻辑结构：线性
- 特征：除首尾外，各元素通常有唯一直接前驱和直接后继
- 线性表：有序的一对一关系
- 栈：只能在一端插入、删除
- 队列：一端入队，另一端出队
- 串：元素为字符的线性序列
- 注意：**顺序表是线性表的一种存储实现**，不等于“线性结构”的全部

## 逻辑结构：非线性
- 集合：元素同属集合，通常不强调其他次序关系
- 树：具有层次关系；非根结点有唯一双亲
  - 典型：文件目录树、表达式树
- 图：结点之间可建立任意边关系
  - 有向图、无向图
  - 可以表示多对多关系
- 注意：**二叉树也是非线性结构**，不因其可数组存储而变成线性结构

## 存储结构：顺序与链式
- 顺序存储
  - 逻辑相邻元素用相邻的存储单元表示
  - 常见：数组实现的顺序表
  - 优点：支持按下标访问；局部性通常较好
  - 局限：插删时可能需要移动元素；容量变化受实现策略影响
- 链式存储
  - 结点地址可不连续，通过指针表示逻辑关系
  - 常见：单链表、二叉链表
  - 优点：结点插删时无需整体搬移元素（定位仍可能有代价）
  - 局限：指针空间、定位时间、访存局部性

## 存储结构：索引与散列
- 索引存储
  - 建立索引项（关键字或位置 → 记录地址）
  - 需要额外索引空间
  - 访问性能取决于索引组织及维护开销
- 散列存储
  - 散列函数将关键字映射到地址或桶
  - 冲突需要解决：拉链法、开放定址法等
  - 平均访问可很快，**最坏情况不保证常数时间**
- 分类提醒：索引、散列与顺序/链式可组合，不必互斥

## 逻辑与存储：独立又相关
- **逻辑结构不依赖于具体物理地址**
- **同一逻辑结构可采用多种存储方法**
  - 线性表 → 顺序表 / 链表
  - 二叉树 → 顺序存储 / 二叉链表
  - 图 → 邻接矩阵 / 邻接表
- 不能反推：**“地址连续”不等于“逻辑一定是线性结构”**

## 数据运算
- 定义：插入、删除、查找、修改、遍历、排序等
- 运算的**定义**依赖逻辑结构及 ADT 语义
- 运算的**实现代价**取决于存储结构和算法
- 例：在线性表的第 i 个位置插入
  - 顺序表：定位快，但通常需要移动后续元素
  - 链表：定位第 i 个结点可能需要遍历；已知前驱时改链较快

## 典型判断
- “顺序存储一定是线性结构” → 错
- “链式存储一定不支持快速插入” → 需看是否已知目标位置
- “哈希存储没有冲突” → 错
- “改变存储结构一定改变逻辑结构” → 错
