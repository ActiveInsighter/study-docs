# 7.2 顺序查找 · 哨兵与有序表

## 普通无序表
- 从表的一端逐个检查关键字，直到匹配或所有元素都检查完
- 不要求有序，也能适用于链表、顺序表
- 成功等概率：$ASL_{成功}=(1+2+\cdots+n)/n=(n+1)/2$
- 失败比较次数：**扫描全部 n 个真实记录**，$ASL_{失败}=n$
- 时间：成功/失败最坏均为 $O(n)$；额外空间 $O(1)$

## 哨兵优化的精确含义
- 教材常用 $a[0]$ 做哨兵：把目标 key 放到哨兵，指针从 n 逆向扫描
- `while (a[i].key != key) --i;`：无需在每一步另判 `i>0`
- **失败时会比较到 a[0]**，若把哨兵关键字比较也算入，失败为 $n+1$ 次
- 哨兵只是实现优化，**不是必须使用 `unsigned int` 的理由**
  - C/C++ 语境下 `int` 大小与取值范围由平台决定，不固定为 16 位
  - 表中逻辑记录依然为 n 个；不能把哨兵当作第 0 个有效记录

## 有序顺序表可提前停止
- 升序扫描时若当前 key 大于目标值，后续更大，可立刻宣告失败
- 查找成功的比较顺序与普通表相同：等概率 $(n+1)/2$
- 查找失败：有 $n+1$ 个可能插入空隙，扫描比较次数与空隙位置有关
  - 定义失败位于第 j 个空隙（j=0…n），若**每次只统计与真实记录的关键字比较**：$c_j=\min(j+1,n)$
  - 当 $n\ge 1$，若空隙等概率：$ASL_{失败}=\dfrac{\sum_{j=0}^{n}\min(j+1,n)}{n+1}=\dfrac{n(n+3)}{2(n+1)}$
  - **有序顺序查找的失败 ASL 不能直接套 n 或 n+1**，要根据实现与失败概率

## 例：有序表 10、20、30
- 查找 25：比较 10、20、30，3 次后首次遇到大于目标的记录
- 查找 5：只比较 10，一次失败；查找 40：比较全部 3 条后越界失败
- 4 个失败区间长度分别为 1、2、3、3，等概率 $ASL_{失败}=9/4$

## 易错纠正
- “失败必为 n+1”：仅当实现把哨兵比较计入才对；普通全扫为 n
- “顺序查找只能在无序表上做”：错，有序表也可顺序查找并提前停
- “顺序查找必须顺序存储”：错，链表也能做
