## 软件分类

<a href="/images/408-mind-maps/co-0085.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0085.svg" alt="软件分类" width="48" height="48" loading="lazy" /></a>

- 软件分类
  - 系统软件
    - 操作系统（OS）、数据库管理系统（DBMS）
      - 操作系统是大型系统软件
      - 区别DBMS和DBS：
        - DBS是数据库系统，DBS是OS【引入了数据库以后的系统】，一般由数据库、数据库管理系统、数据库管理员、应用系统组成，是【应用软件】
        - DBMS是位于用户和OS之间的一层【数据管理软件】，是【系统软件】
        - DBS没了操作系统依然可以正常运行，故为【应用软件】。DBMS是用于把DBS和硬件进行交互的软件，故为【系统软件】
    - 语言处理系统、分布式软件系统、网络软件系统、标准库系统、服务型程序等
  - 应用软件
    - 文本处理
    - DBS（数据库系统）
  - 其他软件
    - 编译程序
      - ：语言处理软件
    - 连接程序
      - ：服务型程序
    - 概要：不属于应用软件
      概要范围：[编译程序](#topic-d8edbd5d-67b5-4b9d-b898-0a7efe4ee99d)、[连接程序](#topic-c0fe3b40-c430-4725-a31b-338f0a475696)

- 语言分类
  - 机器
    - 二进制
  - 汇编
    - 二进制的易读形式
  - 高级
    - 【预处理】是把头文件中的引用代码段插入到程序文件中
    - 【编译】生成的就是【汇编程序】
    - 【汇编】生成的就是【机器程序】
    - 编译的步骤：
      - 源代码文件 .c
        - 预处理 -&gt; .i
          - 编译 -&gt; .s
            - 汇编 -&gt; .o
              - 链接 -&gt; .exe
              - 概要：ci,so,exe
                概要范围：[链接 -&gt; .exe](#topic-d561a878-5d99-48e5-a13e-fe9f8788a6cf)

    - 编译后产生的目标模块地址都是从0开始的相对地址
  - 翻译、编译、解释、汇编：
    - 翻译\[过程\]：
      - 高级语言一步步转为机器语言
    - 编译程序：
      - 高级语言一步到位直接转为机器语言
    - 解释程序：
      - 高级语言一条条解释为机器语言后执行
        - 如python
    - 汇编程序：
      - 汇编 -&gt; 机器

  - 预处理阶段：
    - 预处理器（cpp）对源程序中以字符#开头的命令进行处理。
      - 例如将#include 命令后面的.h文件内容插入程序文件。输出结果是一个以.i为扩展名的源文件hello.i
  - 编译阶段：
    - 编译器（ccl）对预处理后的源程序进行编译，生成一个汇编语言源程序hello.s
      - 汇编语言源程序中的每条语句都以一种文本格式描述了一条低级机器语言指令 。
  - 汇编阶段：
    - 汇编器（as）将hello.s翻译成机器语言指令，把这些指令打包成一个称为可重定位目标文件的hello.o
      - 它是一种二进制文件，因此用文本编辑器打开会显示乱码。
  - 链接阶段：
    - 链接器（Id）将多个可重定位目标文件和标准库函数合并为一个可执行目标文件，或简称可执行文件。
      - 本例中，链接器将hello.o和标准库函数printf所在的可重定位目标模块printf.o合并，生成可执行文件hello最终生成的可执行文件被保存在磁盘上。

## 计算机性能指标

<a href="/images/408-mind-maps/co-0247.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0247.svg" alt="计算机性能指标" width="48" height="48" loading="lazy" /></a>

- 机器字长
  - 机器进行一次整数运算时所能处理的最大二进制位数
  - 和指令字长、存储字长的区别：
    - 指令字长是设定的一条指令的长度范围
    - 存储字长是指存储器存储数据的最大长度
- 数据通路带宽
  - 数据总线一次所能并行传送的信息的位数
  - 此处的”数据通路宽度“是指“外部数据总线”的宽度，即CPU与其他部件相连的线的根数
- 主存容量
  - 主存储器能够存储信息的最大容量，即：（ 字数 x 字长 ）
  - MAR反应存储单元个数
    - 16bit -&gt; 系统有2^16个存储单元
    - 和PC长度一致
  - MDR反应存储单元字长
    - 32bit -&gt; 一个存储单元中有32bit
  - 地址有多少个
    - 按字节寻址：2M 个
    - 按字寻址：64K 个
  - 概要：2M bit / 256MB大小
    概要范围：[MAR反应存储单元个数](#topic-cc4c8c08-fbd4-447c-a9c8-e7cb8c8963b5)、[MDR反应存储单元字长](#topic-a8c867d4-d2ff-490f-801b-959109bcc57a)

- 运算速度
  - 吞吐量
    - 系统能在单位时间内处理请求的数量
      - CPU的速度很大程度上受限于主存，故吞吐量主要取决于主存的存取周期
  - 响应时间
    - 用户向计算机发送了一个请求，到系统对该请求做出响应并获得所需结果的等待时间
  - CPU时钟周期
    - 节拍脉冲，主频的倒数
    - 执行指令的每一个动作至少需要一个时钟周期
  - 主频
    - 计算：时钟周期数 ➗ 时间
    - 机器内部主时钟的频率，单位为Hz
  - CPI
    - Clock cycle per instruction，每条指令所需的时钟周期数
      - 一个系统/程序的CPI是平均下来的CPI
  - CPU执行时间
    - CPU时钟周期数/主频
      - (指令条数 x CPI)/主频
  - MIPS
    - Million instructions per second，每秒执行多少百万条指令
      - 公式



        $IPS\times 10^{-6}$

    - 公式



      $IPS = I/S = \frac{I}{S} =  \frac{C}{S} \div \frac{C}{I} = 主频 \div CPI$

      - 配图

        <a href="/images/408-mind-maps/co-0220.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0220.svg" alt="MIPS" width="240" height="177" loading="lazy" /></a>

  - FLOPS
    - FLoating-point Operation Per Second，每秒执行的浮点运算数
    - K/M/G/T/P/E/Z + FLOPS
      - 对应的10的次方数：K - 3. M - 6. G - 9. T - 12. P - 15. E - 18. Z - 21.
        - KMG, TP, EZ
- 基准程序
  - 跑分程序，存在一定的缺陷
- 考频：中
  - 10-14、17、20-22

## 定点数的表示

<a href="/images/408-mind-maps/co-0242.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0242.svg" alt="定点数的表示" width="48" height="48" loading="lazy" /></a>

    - 指针、表示地址
- 定点数
  - 小数点位置是固定的
    - 即小数点前面和后面的位数是固定的
  - 定点小数
    - 配图

      <a href="/images/408-mind-maps/co-0032.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0032.svg" alt="定点小数" width="240" height="79" loading="lazy" /></a>

      - 只表示正的、负的小数
  - 定点整数
    - 配图

      <a href="/images/408-mind-maps/co-0244.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0244.svg" alt="定点整数" width="240" height="76" loading="lazy" /></a>

      - 只表示正的、负的整数
- 浮点数 --- 小数点位置是不固定的
- 有符号数
  - 原码
    - 形式
      - 第一位为符号位，其余位为数值位，要么表示小数要么表示整数
    - 表示范围
      - 整数
        - 整数
          - 存在 +0 和 -0，所以正负数对半分



            $-(2^n-1) \leq x \leq (2^n - 1)$

      - 小数
        - 纯小数
          - 小数的表示是离散的，正负对半分



            $-(1-2^{-n}) \leq x \leq (1 - 2^{-n})$

    - 作用
      - 最容易理解的表示方式
      - 原码相加运算不成立哦
    - 举例：
      - 整数
        - x1  = +1110
          - \[x1\]原 = 0, 0001110
        - x2 = -1110
          - \[x2\]原 = 1, 0001110
      - 小数
        - x1  = +0.1101
          - \[x1\]原 = 0.1101000
        - x2 = -0.1101
          - \[x2\]原 = 1.1101000
  - 反码
    - 形式
      - 从原码转化而来，如果原码为正，反码不变。如果原码为负，则反码的数值位是原码的取反
    - 表示范围
      - 和原码完全一致
    - 作用
      - 作为”原码 -&gt; 补码“的中间态
      - 若是想通过反码得出十进制，则先转为原码再转为十进制
    - 举例：
      - 整数
        - x1  = +1110
          - \[x1\]反 = 0, 0001110
            - \[x1\]原 = 0, 0001110
        - x2 = -1110
          - \[x2\]反 = 1, 1110001
            - \[x2\]原 = 1, 0001110
      - 小数
        - x1  = +0.1101
          - \[x1\]反 = 0.1101000
            - \[x1\]原 = 0.1101000
        - x2 = -0.1101
          - \[x2\]反 = 1.0010111
            - \[x2\]原 = 1.1101000
  - 补码

    - 形式
      - 正数的补码：不变<br>负数的补码：反码 + 1
        - 负数：原码转为补码的技巧是【尾数】取反再+1
      - 注意：
        - 补码中只存在一个 0
          - +0 的补码： 0 0000 000
            - -0 的补码：【 1 0000 000按位取反再+1 】<br>-&gt; 【0 0000 000】和+0 一致了
          - 1 0000 000是无法通过原码变化获得的，故规定在整数中表示 -2^n，在小数中表示 -1
          - 概要：因为1 0000 000 = 0 0000 000按位取反 + 1，但是 +0 是正数，没有这个运算规则
            概要范围：[1 0000 000是无法通过原码变化获得的，故规定在整数中表示 -2^n，在小数中表示](#topic-ab1a3251-e2d7-403f-85aa-cc5c3473dfda)

        - 原码 -&gt; 补码：（负）按位取反 + 1<br>补码 -&gt; 原码：（负）按位取反 + 1
          - 为什么：
            [参考链接](<https://blog.csdn.net/m0_37433111/article/details/107938663?utm_medium=distribute.pc_relevant.none-task-blog-2%7Edefault%7EBlogCommendFromMachineLearnPai2%7Edefault-1.essearch_pc_relevant&depth_1-utm_source=distribute.pc_relevant.none-task-blog-2%7Edefault%7EBlogCommendFromMachineLearnPai2%7Edefault-1.essearch_pc_relevant>)

          - 按位取反 + 1 的快速做法：从右往左，遇到第一个 1 右边的所有bit不动，把这个1左边的全部数值位bit取反
    - 表示范围
      - 整数
        - 没有 -0 了，负数可以到 -2^n 了



          $-2^n \leq x \leq 2^n - 1$

          - 原码范围：
            - 存在 +0 和 -0，所以正负数对半分



              $-(2^n-1) \leq x \leq (2^n - 1)$

      - 小数
        - 没有 -0 了，负数可以到 -1 了



          $-1 \leq x \leq 1 - 2^{-n}$

          - 原码范围：
            - 小数的表示是离散的，正负对半分



              $-(1-2^{-n}) \leq x \leq (1 - 2^{-n})$

    - 作用

      - 补码相加减的运算是成立的
        - 所以在现代语言(例如C++)中都是采用的补码来表示数
      - 一切加减法都可以写作两个补码数相加
    - 举例：
      - 整数
        - x1  = +1110
          - \[x1\]补 = 0, 0001110
            - \[x1\]原 = 0, 0001110
        - x2 = -1110
          - \[x2\]补 = 1, 1110010
            - \[x2\]原 = 1, 0001110
      - 小数
        - x1  = +0.1101
          - \[x1\]补 = 0.1101000
            - \[x1\]原 = 0.1101000
        - x2 = -0.1101
          - \[x2\]补 = 1.0011000
            - \[x2\]原 = 1.1101000
  - 移码
    - 形式
      - 移码 = 补码首位取反
    - 表示范围
      - 和补码一致
    - 作用

      - 使用移码计算机可以直接通过【按位比较的方式】来比较两个数的大小



        |真值（十进制）|8 位补码|8 位移码|
        |---:|---|---|
        |-128|10000000|00000000|
        |-127|10000001|00000001|
        |-126|10000010|00000010|
        |-3|11111101|01111101|
        |-2|11111110|01111110|
        |-1|11111111|01111111|
        |0|00000000|10000000|
        |1|00000001|10000001|
        |2|00000010|10000010|
        |3|00000011|10000011|
        |124|01111100|11111100|
        |125|01111101|11111101|
        |126|01111110|11111110|
        |127|01111111|11111111|

        省略号表示原图略去的中间数值。移码表示的数较便于按编码大小比较；其编码由 8 位补码的符号位取反得到。

- 带标记加法器
  - 标志位的生成
    - PSW用来存放两类信息：
      - 一类是体现当前指令执行结果的各种状态信息，称为状态标志，如有无借位进位（CF位）、有无溢出（OF位）、结果正负（SF位）、结果是否为零（ZF位）、奇偶标志位（PF位）等；
        - 另一类是存放控制信息，称为控制状态，如允许中断(IF位)，跟踪标志（TF位），方向标志(DF)等。有些机器中将PSW称为标志寄存器FR（Flag Register）。
  - 配图

    <a href="/images/408-mind-maps/co-0137.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0137.svg" alt="带标记加法器" width="225" height="220" loading="lazy" /></a>

    - ZF：
      - F输出全为0，ZF = 1



        $ZF = \overline{F_n + \dots + F_2+F_1}$

    - OF：
      - 溢出位，是给【有符号数】用的，有符号数溢出则OF = 1，不溢出 OF = 0



        $OF = C_n \oplus C_{n-1}$

        - 最高位进位 ⊕ 次高位进位
        - 符号位发生了改变就说明溢出
    - SF：
      - 给【有符号数】的，正数为0，负数为1



        $SF=F_{n}$

    - CF：

## 定点数的移位运算

<a href="/images/408-mind-maps/co-0052.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0052.svg" alt="定点数的移位运算" width="45" height="46" loading="lazy" /></a>

- 逻辑运算
  - 与、或、非三大基本运算
- 逻辑移位
  - 不管数的类型，一律添 0
  - 作用：
    - 用于拆分和定位一个二进制中对应区间bit的数值，例如可以通过逻辑移位获得24bit RGB二进制数的R、G、B分别的数值
- 算术移位
  - 原码
    - 正数负数，一律添 0
  - 反码
    - 正数全 0，负数全 1
  - 补码
    - 正数全 0，负数左 1 右 0
    - 概要：注意：是左边添 1，右边添 0
      概要范围：[正数全 0，负数左 1 右 0](#topic-603a962c-a94e-4c81-9f4f-3699f66e8f0b)

      - 王道：左移（在右边）添0，右移（在左边）添1
  - 算术移位的精度：
    - 往右移动会丢失精度
      - 例：0011(3) 右移一次 0001(1)，而 3 ÷ 2 = 1.5
    - 往左移动可能出现严重误差
      - 例： 1000(-8)  左移一次 0000 (0), 出现严重误差
  - 作用：
    - 算术位移可以模拟乘法运算



      ```text
      -2 × 7：使用 8 位补码进行示意
      1111 1110 × 0000 0111
      → -2 左移 0 次（×1）、1 次（×2）、2 次（×4）再相加
        1111 1110 + 1111 1100 + 1111 1000
      = 1111 1010 + 1111 1000
      = 1111 0010
      = -14
      ```

    - X：被乘数
    - 概要：X \* MQ = ( ACC, MQ )

      - 最开始ACC是0，然后通过多次加法+移位把低位移动到了MQ中，ACC中存放的是高位。
  - X \* MQ
    - X是被乘数，MQ是乘数
      - 前放X，后放MQ
        - （X\*Y）
  - 【原码乘法】<br>符号另算。多次累加，通过MQ最后一位来判断是否让ACC加X，每次都让右移，最后结果ACC为高位，MQ为低位

        - ACC有n+1位，MQ也有n+1位
    - 加法规则：
      - MQ的最低位为0，则ACC = ACC + 0
      - MQ的最低位为1，则ACC = ACC + X
    - 移位规则：
      - 统一采用逻辑移位（只补0）
        - 因为是原码，所以逻辑算术移位没区别
    - 运算流程：
      - 已知运算 x \* y，x为负，y为正
        - 其中x和y的符号位为一位，数值位为n位
      - 0\. 确定最终符号位为 1，把【x的符号改为0】
        - 符号位的计算：对两个数的符号位进行异或运算即可
      - 1\. 把x存入X寄存器中，把y存入到MQ寄存器中，清空ACC
        - 此时，MQ的最低位就应该是被乘数X应该进行操作
      - 2\. 进行加法，进行移位
        - 此时的右移有两个作用：
          - A. 使得MQ的最低位指明了下一次需要进行操作<br>B. 下次一次的加法是和上一次的结果“错位”相加
      - 3\. 重复 1~2 的步骤 n 次。<br>最后的结果就是(ACC, MQ)中，其中MQ的最末位舍弃，ACC的第一位改为符号位
        - ACC的全部 + MQ的前n位
        - x \* y 最后的结果最多为 2n 位，MQ和ACC都是n+1位寄存器，MQ的最末位舍去
    - 采用的是原码一位乘法，还有二位乘法，不拓展了

      - 2\. 根据加法和移位的规则进行加法运算
      - 3\. 重复 1~2 的步骤n次
      - 4\. 对3的结果再进行一次加法运算
      - 5\. 最后的结果就是(ACC, MQ)

      - 补码除法在商的时候根据ACC和X的符号进行判断
        - 如果ACC和X的符号不同，则商0
          - (ACC, MQ)左移一位，+ X
        - 如果ACC和X的符号同号，则商 1
          - (ACC, MQ)左移一位， - X

## 浮点数

<a href="/images/408-mind-maps/co-0171.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0171.svg" alt="浮点数" width="48" height="48" loading="lazy" /></a>

- 考频：高
  - 09-15、18、20-22、17大
- 通常表示方法
  - 公式



    $N =(-1)^S \times R^E \times M$

    - 其中 R为基数（即R进制），E和M都是有符号定点数。E称为阶码，M称为尾码
    - E为定点整数，M为定点小数
    - 其中E和M可以用补码或原码来表示
      - 注意计算十进制值的时候补码为负要转为对应真值在写值
  - 一般格式

    <a href="/images/408-mind-maps/co-0004.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0004.svg" alt="一般格式" width="240" height="75" loading="lazy" /></a>

  - 尾数规格化
    - 原码
      - 浮点数的尾数部分的最高位一定是“有效数”位
        - 负数： 1, 1 ....
        - 正数：0, 1....
    - 补码
      - 浮点数的尾数部分最高位和符号位一定不同
        - 负数：1, 0 ...
        - 正数：0, 1....
    - 尾数、阶码规格化
      - 例如 原码 ( M = 1,011 ，E = 0, 000 0010 )，则应该变为：( M = 1,110 ，E = 0, 000 0001），M左移了，E对应减小
        - 尾数左移：左归
        - 尾数右移：右归
  - 计算
    - 在进行加减计算中，采用双符号位进行计算，可以挽救很多溢出
      - 例如：符号位 00 和 符号位 00 相加的结果是 0 1，则可以把尾数右移一位，阶码 +1 来进行挽救
- 浮点数的运算
  - 对阶
    - 首先把两个浮点数的阶码对齐，以小阶向大阶看齐
  - 尾数求和
    - 尾数按定点数的加减法进行运算
  - 规格化
    - 尾数 &gt; 0时，规格化为00.1xxxx<br>尾数 &lt; 0时，规格化为 11.0xxxx
    - 概要：补码
      概要范围：[尾数 &gt; 0时，规格化为00.1xxxx<br>尾数 &lt; 0时，规格化为 11.0xxxx](#topic-4a70a692-e8df-4c7b-abea-3b50a61e633f)

  - 舍入
    - "0"舍"1"入法：
      - 尾数右移，如果被【移除的最高位】为 0，那么就舍去。如果被【移除的最高位】的是 1，那么就让尾数 + 1
        - 10100
          - 右移3次：
            - 10 + 1 = 11
          - 右移1次：
            - 1010
        - 此时+1后可能还需要进行规格化
    - 恒置为"1"法：
      - 尾数右移，不管如何移动，尾数最末位一定为 1
  - 溢出判断
    - 双符号时
      - 如果阶码出现了“01”，说明出现了上溢，进入中断处理
      - 如果阶码出现了“10”，说明出现了下溢，按 0 处理
  - 一般考试的运算是不会计算IEEE754模式的
    - 计算只有09选择题考了
- IEEE 754

  - 一般格式
    - &lt;符号位、阶码、尾数&gt;
      - 【符号位】 1 为负，0为正
      - 【阶码】部分使用特殊的移码计算



        $偏置值 = 2^{n-1} - 1$

        - 之前的移码（改符号位）：1,000 0001 + 1000 0000 = 0,000 0001
        - 直接在补码那里进行加法运算，例如：1, 000 0001 + 0111 1111(偏) = 0000 0000
      - 【尾数】用原码表示，且隐藏最高位的1

## 存储器特点

<a href="/images/408-mind-maps/co-0015.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0015.svg" alt="存储器特点" width="48" height="48" loading="lazy" /></a>

- 分类：
  - 按作用：
    - 高级缓冲存储器
      - 【即Cache】，位于CPU和主存之间，使CPU能更快速的使用到里面的数据（Cache中的数据是主存中的副本，而缓冲区不是）
    - 主存储器
      - 【即主存/内存】，存放计算机运行时需要的大量的数据，CPU可以直接与其进行访问，也可以和cache交换数据
    - 辅助存储器
      - 【即辅存/外存】，不能与CPU进行直接信息交换
  - 按存储介质：
    - 磁表面（磁盘磁带）、磁心存储器半导体存储器（MOS存储器）、光存储器（光盘）
  - 按存取方式：
    - 随机存取
      - RAM、ROM（只读存储器）
    - 串行访问存储器
      - 对存储单元进行读写时，根据其物理位置的先后进行寻址
      - 例如顺序存取（磁带）
  - 按信息可保存性：
    - 易失型（RAM断电后丢失）
    - 非易失性（ROM断电后不丢失）
    - 破坏性读出（DRAM芯片）
    - 非破坏性读出（SRAM芯片、DISK）
  - 其他
    - DAM直接存取存储器
      - 磁盘
- 性能指标：
  - 存储容量：
    - 存储字数 \* 字长
    - 公式



      $2^{MAR位数} * MDR位数$

      - MAR位数：
        - 地址总线个数
      - MDR位数：
        - 数据总线个数
  - 单位成本：
    - 每位价格 = 总成本 / 总容量（bit)
  - 存储速度：
    - 存取时间：
      - 启动一次存储器到最终完成操作所经历的时间
    - 存取周期：
      - 存取时间 + 恢复时间
        - 又称：连续读或者连续写所允许的最短时间间隔
    - 主存带宽：
      - 数据传输率，表示每秒从主存进出信息的最大数量

## SRAM、DRAM

<a href="/images/408-mind-maps/co-0017.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0017.svg" alt="SRAM、DRAM" width="48" height="48" loading="lazy" /></a>

- 考频：低
  - 12、14、15、22
- SRAM
  - Static Random Access Memory
  - 存储元：<br>（几个MOS)
    - 双稳态触发管，6个MOS

      <a href="/images/408-mind-maps/co-0003.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0003.svg" alt="双稳态触发管，6个MOS" width="240" height="168" loading="lazy" /></a>

      - 了解即可
  - 优点：
    - 速度快，但是【集成度低、功耗大、用来组成高速缓存存储器】
    - 不需要进行刷新
  - 批注：Cache
- DRAM
  - Dynamic Random Access Memory
  - 存储元：
    - 栅极电容
  - 采用技术：
    - 地址复用技术
  - 优点：
    - 集成高、价格低、容量大、功耗低
  - 在工作时存储器内容不会发生改变（即会进行刷新，所以内容不会发生丢失）
  - 现在DRAM被称为SDRAM（例如DDR3，DDR4）
  - 刷新：
    - 每次刷新多少存储单元：
      - 【基础版】一次刷新一整行

        <a href="/images/408-mind-maps/co-0010.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0010.svg" alt="【基础版】一次刷新一整行" width="240" height="219" loading="lazy" /></a>

        - 例如有20根地址线，则一共对应有1024 \* 1024根选通线。
        - 刷新顺序：从上到下选n个。每次刷新一行
      - 【行列存储版】把地址分布改为行地址+列地址的存储方式

        <a href="/images/408-mind-maps/co-0148.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0148.svg" alt="【行列存储版】把地址分布改为行地址+列地址的存储方式" width="240" height="120" loading="lazy" /></a>

        - 例如有20根地址线，则有1024根行选通线，1024根列选通线 = 2048根选通线。
        - 刷新顺序：从左到右，从上到下。每次选n个一起刷新
    - 刷新周期：
      分组说明：题目没说刷新时间，那就是2ms；对应：[一般取2ms刷新一次](#topic-c66901c9d27948ed1a1489ad67)

      - 一般取2ms刷新一次
    - 刷新算法：
      - 集中刷新：
        - 在一个刷新周期内，在一个固定时间，停止其他操作，把【所有】的存储单元都进行刷新。
        - “死时间”、“死区”
      - 分散刷新：
        - 把每行的刷新分散到各个工作周期内，每个存储周期前半部分用于正常读写，后半部分用于刷新【某一行】（这一行是CPU安排的）
        - 加长了系统的存取周期
      - 异步刷新：
        - 即：集中刷新 + 分散刷新
        - 将刷新周期除以行数，得到两次刷新操作之间的时间间隔 t，则每隔时间t进行一次刷新，刷新【一行】
    - 注意：
      - 透明度：
        - 对CPU透明，不依赖外部的访问
      - 刷新单位：
        - 一行，行地址由CPU自行生成
      - 选片：
        - 不需要选片，对存储器中所有芯片都进行刷新

## 只读存储器ROM

<a href="/images/408-mind-maps/co-0152.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0152.svg" alt="只读存储器ROM" width="48" height="48" loading="lazy" /></a>

  - 不易失、断电不丢失、结构简单、位密度高

- 类型：
  - MROM：
    - 中文：
      - 掩模式ROM(Mask)
    - 特点：
      - 厂商按照要求再生产时直接写入，写入后任何人无法改变内容
      - 可靠性高、便宜、灵活性差
  - PROM：
    - 中文：
      - 一次可编程ROM(program)
    - 特点：
      - 可以实现一次编程（用户可以使用专门的设备），一旦写入，不可改变
  - EPROM：
    - 中文：
      - 可擦除可编程ROM(Erase Program)
    - 特点：
      - 可以多次修改，编程次数有限，写入时间过长
      - UVEPROM紫外线擦除，(E^2)PROM电擦除
  - Flash：
    - 中文：
      - 闪速存储器
    - 特点：
      - 是EPROM的改良，擦除重写速度更快（写比读慢），Flash只用单个MOS，故位密度比RAM高
  - SSD：
    - 中文：
      - 固态硬盘
    - 特点：
      - 由控制单元和Flash组成，读写速度快，低功耗，价格高

  - 引导块
  - 位置：
    - 主板上的ROM的BIOS芯片里
  - 计算机系统中，OS保存在硬盘上，其内存储器应该采用：RAM + ROM

  - 连续编址

    - 磁带（OS）

- 字扩展
  - 原因：芯片的字长和CPU已经满足了，可是CPU的地址总线上还是有很多根没有充分利用。故可以通过在地址中设置片选信号来增加地址数目

    - 法一：线选法，CPU每一根多的地址线就连接着对应的芯片的CS。【这样CPU多了N根线，就可以多连接N个芯片】

      - 地址空间不连续
    - 法二：译码片选法，CPU的每一根对应的地址线都连接一个非门和一根线，这样可以控制两个芯片。【所以CPU多了N根线，可以多连接2^N个芯片】

      - 译码片选法连接多个芯片(此处选择了A13,A14，所以A15无论是多少都不会改变A0-A14的地址映射）
      - 这样就把4个8K \* 8位的芯片通过【字扩展的方法】扩展为了32K \* 8位的芯片

    - RAID （独立冗余磁盘阵列）是指将多个独立的物理磁盘组成一个独立的逻辑盘，数据在多 个物理盘上分割交叉存储、并行访问，具有更好的存储性能、可靠性和安全性。
    - • RAID0：无冗余和无校验的磁盘阵列。
      - 把连续多个数据块交替地存放在不同物理磁盘的扇区中，几个磁盘交叉并行读写，扩大了存储容量，提高了磁盘数据存取速度，但没有容错能力
    - • RAID1：镜像磁盘阵列。
      - 使两个磁盘同时进行读写，互为备份，若一个磁盘出现故障，可从另一磁盘中读出数据。
      - 但容量减少一半
    - • RAID2：采用纠错的海明码的磁盘阵列。
    - • RAID3：位交叉奇偶校验的磁盘阵列。
    - • RAID4：块交叉奇偶校验的磁盘阵列。
    - • RAID5：无独立校验的奇偶校验磁盘阵列。

      - 读写单位
        - CPU下令要读取一个块的内容
        - SSD的读取单位：一个页
          - SSD接受到这个块的地址
          - SSD的闪存翻译层把它翻译为SSD中对应的数个页的地址
          - SSD把这些页的数据发到IO总线上，返回CPU
        - 具体大小：机械磁盘的一个块大小可能在1KB；SSD的一个页大小是512B~4KB，一个块中有32~128个页
      - 批注：市面上的厂家的SSD都有一个缓存
  - 读写原则：
    - 读：以一个页为单位来读 ✅
    - 写：以一个页为单位来写
      - 擦除：以一个块的单位来擦除
      - 擦除方法：先把要写那页的整块复制到另一块，然后再擦除原来那块
        - 复制过后，在闪存翻译层中会建立新的： ‘逻辑地址’ —— ‘物理地址’ 的转换关系
      - 擦除的缺点：
        - 擦除多了会造成磨损
  - 平均磨损
    - 静态平均：
      - SSD在进行擦除后的数据迁移的时候，会让寿命比较老的闪存块担任“读”的责任，让新的闪存块担任“写”的责任
    - 动态平均：
      - 在SSD写入新数据的时候，会优先选择磨损次数少的块进行写入
    - 概要：静态平均的效果比动态平均效果更好

- Cache的替换算法
  - 直接映射：
    - 冲突直接覆盖
  - 组相联和全相联
    - RAND --- 随机算法
      - 随机确定一个替换的块
    - FIFO --- 先进先出算法
      - 将最早调入的行调出
      - 会出现Belady异常、抖动
    - LRU --- 最近最少使用算法
      - 堆栈类算法，在每个cache中添加一个“counter位”
        - 2^n 路组相联，就需要n bit的计数位
      - 举例

        <a href="/images/408-mind-maps/co-0026.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0026.svg" alt="举例" width="240" height="71" loading="lazy" /></a>

        - 使用counter计数来模拟堆栈的实现，阴影数值越小，说明越新进入Cache
        - counter的值是有范围的 0 ~ 2^n-1，不会超过
    - LFU --- 最不经常使用算法
      - 每行都添加一个counter位，在一段时间内，每被访问一次，counter++。换出时把counter最小的换出
        - 没有遵循局部性
        - counter的大小未知
  - 批注：与OS的请求分页置换算法一致
- Cache的写策略
  - 原因：Cache存储的是主存内容的副本，当Cache内容进行变更时，需要使得Cache和主存的内容保持一致
  - 写命中
    - 全写法/写直通法
      - 把数据同时写入Cache和主存
      - 当需要进行替换时，可以不做其他操作，直接进行替换操作
      - 优化【CPU对主存的访问次数过多】：
        - 写缓冲
          - 在Cache和主存中加入一个写缓冲，CPU写数据到写缓冲中，写缓冲再自行控制将数据写入主存
    - 写回法
      - CPU只对Cache进行修改
      - 在Cache的每一行中添加一个脏位
        - 如果要进行Cache块置换的时候，如果发现该行的脏位为 1，则需要把该Cache块写回内存
  - 写不命中
    - 写分配法
      - 每次写不命中，都先把这个数据块写入到Cache中，然后把数据修改到Cache中，设置脏位为 1
    - 非写分配法
      - 每次写不命中，只写入主存，不进行调块
  - 通常搭配
    - 【全非】全写法 + 非写分配法
      - 写命中同时写回Cache和内存，写不命中只写回内存
    - 【回写】写回法 + 写分配法
      - 写命中只写入Cache并修改脏位，写不命中则把块调入到Cache中，并只修改Cache
    - 多级Cache的混合搭配
      - 配图

        <a href="/images/408-mind-maps/co-0021.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0021.svg" alt="多级Cache的混合搭配" width="240" height="44" loading="lazy" /></a>

        - CPU -&gt; Cache -&gt; L2 Cache
          - 采用的是全写法 + 非写分配法（因为有写缓冲）
        - Cache -&gt; L2 Cache -&gt; DRAM
          - 采用的是写回法 + 写分配法
      - 离CPU越远，容量越大，速度越慢
        - Cache 存 L2 Cache 的复制<br>L2 Cache 存 DRAM 的复制

- 虚存 和 Cache
  - 相同处
    - 都提高了系统性能，两者都有容量、价格、速度等的梯度
    - 都把数据分成了若干块，虚存的块更大(页面大小) ，Cache的块更小(内存块大小)
    - 都有地址映射、替换算法、更新策略
    - 都运用了局部性原理
  - 不同处
    - Cache解决系统速度问题
      - 虚存解决主存容量问题
    - Cache纯硬件实现，对所有程序员都透明
      - 虚存对系统程序员不透明
    - Cache不命中对速度影响没有虚存不命中的影响那么大
      - Cache不命中：读内存
      - 虚存不命中：读外存
    - Cache不命中时，CPU直接访问主存
      - 虚存不命中时，只能先把硬盘的数据调入内存，再与CPU通信
    - 概要：Cache - 空间换时间；虚存 - 时间换空间。

## 指令格式

<a href="/images/408-mind-maps/co-0271.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0271.svg" alt="指令格式" width="48" height="48" loading="lazy" /></a>

- 基本格式
  - 操作码 + 地址码（op + add）
  - 字长
    - 指令字长
      - 指令字长【可变】
      - 一条指令的总长度
      - 指令字长与机器字长无固定关系，可以使单字长、半字长、双字长
    - 机器字长
      - CPU一次运算所能处理的位数
    - 存储字长
      - 一个存储单元的位数
    - 概要：固定
      概要范围：[机器字长](#topic-e9286ad6-c894-4af5-a5b2-da874217bebe)、[存储字长](#topic-b258be78-ade9-45de-be3f-90c41f50b474)

- 指令分类：
  - 零地址指令
    - OP
    - 无操作数
      - 可用于不需要操作数的指令：空操作、停机、关中断
    - 有操作数
      - 用于堆栈计算机，把两个操作数从栈顶和次栈顶弹出，运算后再压回去
  - 一地址指令
    - OP A1
    - 单操作数
      - 只有目的操作数的单操作数，OP(A1) -&gt; A1
        - 三次访存：取指令，取A1，写回A1
        - 例如 ++, --, 取反，求补
    - 双操作数
      - (ACC)OP(A1) -&gt; (ACC)
        - 两次访存：取指令，取A1
    - 系统32位，若OP为8位，则A1可以寻址16M
  - 二地址指令
    - OP A1 A2
      - 操作码、目的、源
    - (A1)OP(A2) -&gt; A1
      - 四次访存：取指令，取A1，取A2，写回A1
    - 系统32位，若OP为8位，则可以寻址4K
  - 三地址指令
    - OP A1 A2 A3
    - (A1)OP(A2) -&gt; A3
  - 四地址指令
    - OP A1 A2 A3 A4
    - (A1)OP(A2) -&gt; A3，A4为下一条指令的地址
- 定长操作码：
  - 操作码有n bit，则一共有2^n个指令
- 扩展操作码：

    <a href="/images/408-mind-maps/co-0318.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0318.svg" alt="扩展操作码：" width="188" height="220" loading="lazy" /></a>

## CPU的功能、基本结构

<a href="/images/408-mind-maps/co-0144.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0144.svg" alt="CPU的功能、基本结构" width="45" height="45" loading="lazy" /></a>

- 具体功能
  - 指令控制
    - 完成取指、分析指令、执行指令
  - 操作控制
    - 一条指令由若干操作（微指令）组合实现，CPU管理产生每条指令的操作信号
  - 时间控制
    - 对各种操作加以时间上的控制
  - 数据加工
    - 对数据提供算术和逻辑运算
  - 中断处理
    - 对计算机运行过程中的异常情况和特殊情况进行处理
- CPU的基本结构
  - 运算器
    - 运算器是计算机的数据加工中心
    - 组成部分
      - 算术逻辑单元ALU
        - 进行算术/逻辑运算
      - 暂存寄存器
        - 用于暂存从主存读来的数据
          - 例如ACC需要R0和R1的数据，就先把R0读入到暂存寄存器，然后把R1和暂存寄存器中的数同时写入到ACC中
      - 累加寄存器ACC
        - 一个通用寄存器，用于存放ALU运算的结果，也可以作为运算的输入端
      - 通用寄存器组
        - A
          - 累加器EAX
        - B
          - 基地址EBX
        - C
          - 计数ECX
        - D
          - 数据EDX
        - 变址ESI、EDI
        - 堆栈基EBP
        - 堆栈顶ESP
        - 概要：32位：E\_\_X<br>低16位：\_\_X<br>\_\_X的高8位：\_\_H<br>\_\_X的低8位：\_\_L
          概要范围：[D](#topic-4fdb9992-2be2-4acb-abfa-6c937b471f3b)

        - 概要：这两个寄存器不能乱用
          概要范围：[堆栈顶ESP](#topic-3aed7745-7ae4-497e-859f-51d555d48467)

      - 程序状态字寄存器PSW
        - 由OF、ZF、SF、CF组成
      - 移位器
        - 对操作数或运算结果进行移位的运算
      - 计数器CT
        - 控制乘除运算的操作步数
  - 控制器
    - 基本功能：执行指令，每条指令的执行由控制器发出的一组微操作实现
    - 组成部分：
      - PC程序计数器
        - 指出下一条指令在主存中的地址
        - CPU根据PC的内容去主存取指令
        - PC具有自增功能
      - IR指令寄存器
        - 保存当前执行的那个指令
      - 指令译码器
        - 对操作码字段进行译码，向控制器提供操作信号
      - MAR存储器地址寄存器
        - 存放要访问的主存单元的地址
      - MDR存储器数据寄存器
        - 存放向主存写/从主存读的数据
      - 时序系统
        - 用于产生各种时序信号，由统一时钟(CLOCK)分频得到
      - 微操作信号发生器
        - 根据IR、PSW、时序信号产生的控制整个计算机系统所需的各种控制信号
        - 分为：
          - 组合逻辑型
          - 存储逻辑型
  - 计算机可以划分为：
    - 控制部件
      - 控制器：
        - PC、IR、MAR、MDR、ID、时序、微操作信号发生器(CU的第一步)
    - 执行部件
      - 运算器：
        - ALU、ACC、Reg(寄存器组)、X(暂存寄存器)、PSW、CT、移位器
      - 存储器
      - 外围设备
  - 内存寄存器
    - 用户透明（不可编程）
      - MAR、MDR、IR
    - 用户不透明（可编程）
      - &lt;Reg&gt;、PSW、PC

  - 10、16

## 【数据通路】的功能、基本结构

<a href="/images/408-mind-maps/co-0183.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0183.svg" alt="【数据通路】的功能、基本结构" width="45" height="45" loading="lazy" /></a>

- 数据通路的功能
  - 数据通路：数据在功能部件之间传送的路径
  - 数据通路部件：通路上的部件
    - 如ALU、通用寄存器、状态寄存器等等
  - 执行/功能部件：在数据通路中专门进行数据运算的部件
- 数据通路的基本结构
  - CPU内部单总线方式
    - 各个部件对于总线的使用是独占的，同一时刻只能两个部件进行数据交换（一个in，一个out）
    - 配图

      <a href="/images/408-mind-maps/co-0273.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0273.svg" alt="CPU内部单总线方式" width="115" height="220" loading="lazy" /></a>

        <a href="/images/408-mind-maps/co-0103.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0103.svg" alt="CPU内部单总线方式" width="108" height="220" loading="lazy" /></a>

        - 其中所有的寄存器的in out控制命令全是由CU发出的
        - 寄存器之间的数据流动
          - 例如：PC -&gt; MAR<br>1. (PC) -&gt; Bus -&gt; MAR， \[ PCout有效，MARin有效 \]<br>2. (PC) + 1 -&gt; PC
        - 主存和CPU之间的数据传送
          - 例如：从主存读取指令<br> 1. (PC) -&gt; Bus -&gt; MAR，\[ PCout，MARin有效 \]<br>2. 1 -&gt; R，(PC) + 1 -&gt; PC<br>3. MEM(MAR) -&gt; MDR，\[ MARoutE MDRinE 有效 \]<br>4. (MDR) -&gt; IR，\[ MDRout，IRin \] 有效
            - MARoutE 和主存交互
            - MDR in/out E 和主存交互
        - 执行运算

(MDR) -&gt; Bus -&gt; Y，\[ MDRout Yin 有效 \]<br>5. (ACC/R0) + (Y) -&gt; Z，\[ACCout/R0out Zin有效，CU发送加法指令\]<br>6. Z -&gt; ACC/R0，\[Zout ACCin/R0in有效\]
            - 这里的Y是一个暂存寄存器，因为单总线同时只能有一个数据流向。如果设置多总线，则可以不用该暂存寄存器
        - 例题：ACC (R0), R1
          > 备注：
          > 翻译一下就是((R0)) + (R1) -&gt; (R0)，把R0内的地址间接寻址一次，然后和R1中的内容进行相加，最后存回到R0对应的地址中（为什么这里最后是(R0)而不是((R0))，因为如果只是向R0中写数据，就只写-&gt;R0就可以了）
          >
          > 【故一共有三个阶段：取指阶段、间址阶段、执行阶段】
          > 【  1. 取指阶段】
          > (PC) -&gt; Bus -&gt; MAR,  PCout MARin
          > 1 -&gt; R, (PC) + 1 -&gt; PC
          > M(MAR) -&gt; MDR, MARoutE MDRinE
          > (MDR) -&gt; IR, MDRout IRin

          > (R0) -&gt; Bus -&gt; MAR, MARin R0out
          > 1 -&gt; R
          > M(MAR) -&gt; MDR, MARoutE MDRinE
          > (MDR) -&gt; Y, MDRout Yin
          > 【 3. 执行阶段】
          > (R1) + (Y) -&gt; Z, R1out Yout ALU发出加法控制信号
          > (Z) -&gt; MDR, Zout MDRin
          > 1 -&gt; W
          > MDR -&gt; M(MAR), MDRout MARinE

## 硬布线

<a href="/images/408-mind-maps/co-0129.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0129.svg" alt="硬布线" width="46" height="45" loading="lazy" /></a>

- 只能适用于RISC架构，执行速度超级快，扩展起来很复杂
- 四大机器周期
  - FE 取指周期、IND 间址周期、EX 执行周期、INT 中断周期
- 微指令的内容
  - 特点一：每个周期中有多个微操作/微指令，很多微操作/微指令是可以并行的完成的（特别是多总线结构的时候）
    - 三个原则
      - 原则一：微操作的先后顺序不得随意更改
      - 原则二：被控对象不同的微操作尽量安排在一个节拍内完成
      - 原则三：占用时间较短的微操作尽量安排在一个节拍内完成并【允许有先后顺序】
        - 时间较短：不用访问主存
    - 例如：取指周期
      - 配图



        取指周期的微操作安排：

        |节拍|微操作|先后约束|
        |---|---|---|
        |$T_0$|① $PC\to MAR$；② $1\to R$|启动访问|
        |$T_1$|③ $M(MAR)\to MDR$|①②之后，存储器空闲时完成|
        |$T_1$|⑥ $(PC)+1\to PC$|①之后，可与③安排在同一节拍|
        |$T_2$|④ $MDR\to IR$|③之后|
        |$T_2$|⑤ $OP(IR)\to ID$|④之后，可安排在同一节拍内串行完成|



        - M(MAR) → MDR 从主存取数据，用时较长，因此必须一个时钟周期才能保证微操作的完成
        - MDR → IR是CPU内部寄存器的数据传送，速度很快，因此在一个时钟周期内可以紧接着完成 OP(IR)。
      - 多个不涉及主存的数据传输可以在一个时钟周期内完成
    - 批注：微指令产生微操作信号

## 微程序

<a href="/images/408-mind-maps/co-0317.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0317.svg" alt="微程序" width="45" height="45" loading="lazy" /></a>

- 引用了软件的思想
  - 把程序运行的【指令划分为多个微指令】，然后在CPU中再套娃一层CPU
    - 也可以称为【机器指令是多个微指令的封装】
    - 微指令 = n \* 微操作
      - 微指令是微程序独有的概念
    - 微程序、微程序组、微指令、（微操作、微命令）
      - 微程序：实现一条机器指令的程序
        - 耗费一个指令周期
      - 微程序组：一条机器指令在不同机器周期执行一个微程序组
        - 耗费一个机器周期
        - 例如指令A的取值、间址阶段有不同的微程序组
      - 微指令：
        - 多个微操作的合集，是微程序的‘代码’
          - 代码
      - 微操作、微命令：
        - 微命令是微操作的控制信号；微操作是微命令的执行过程。 \[ 例如（PC)-&gt;MAR \]

      - 五段式流水线
      - MIPS架构(RISC)的经典模型
      - 每个阶段的时间设置为一样，以最长的时间看齐，所以每个阶段的末尾都添加了【锁存器】，用来存储产生的结果，以确保可以准时发出
    - Cache分为：
      - 指令Cache
      - 数据Cache
      - 概要：这样访问Cache的指令和数据是可以并行进行的
        概要范围：[指令Cache](#topic-06421cee-1c95-4a5f-82f9-973b7da34505)、[数据Cache](#topic-d1979d5a-4e9c-4049-990b-8150e57b7223)

      - FE 取指阶段
        - 访问指令Cache，把指令存到锁存
        - 如果存在立即数，就把立即数放入到 Imm 锁存器中
      - ID 译码阶段
        - 把操作数从寄存器组中取出，放入到AB锁存器中
          - 在RISC中所有的指令操作数都只来自于寄存器
      - EX 执行阶段
        - 在ALU中进行运算，把运行结果然后到锁存器
      - M 访存阶段
        - 把运行结果写入到数据Cache中
      - WB 写回阶段
        - 把运行结果写回到寄存器中

- 举例说明五种类型指令：
  - 运算类指令
    - ① IF取指 ② ID译码&amp;取值 ③ EX 执行 ④ 空过  ⑤ WB 写回寄存器

      <a href="/images/408-mind-maps/co-0119.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0119.svg" alt="① IF取指 ② ID译码&amp;amp;取值 ③ EX 执行 ④ 空过 ⑤ WB 写回寄存器" width="240" height="98" loading="lazy" /></a>

      - 运算类指令：
        - IF：根据PC从指令Cache中取指令到IF段的锁存器中
        - ID：取IF中的op操作数到ID段锁存器
        - EX：运算，结果放入EX锁存器
        - M：空段
        - WB：将运算结果写回指定的寄存器
      - Rs是源操作数，Rd是目的操作数
      - 指令举例
        - ADD Rs, Rd
          - (Rs) + (Rd) → Rd
        - ADD #996, Rd
          - 996 + (Rd) → Rd
        - SHL Rd
          - (Rd) &lt;&lt;&lt; 2 → Rd
      - RISC运算只有Reg参与，没有M阶段
  - LOAD指令
    - ① IF取指 ② ID译码&amp;取值 ③ EX 执行 ④ M 访存  ⑤ WB 写回寄存器

      <a href="/images/408-mind-maps/co-0045.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0045.svg" alt="① IF取指 ② ID译码&amp;amp;取值 ③ EX 执行 ④ M 访存 ⑤ WB 写回寄存器" width="240" height="101" loading="lazy" /></a>

      - LOAD指令：
        - IF：根据PC从指令Cache中取指令到IF段的锁存器中
        - ID：将BR基址寄存器的值放到A，将偏移量放到Imm
        - EX：运算，得到有效的地址 A + Imm
        - M：从数据Cache中取数据，放到锁存器
        - WB：将运算结果写回指定的寄存器
      - 指令举例
        - LOAD Rd, 996(Rs)
          - (996+(Rs)) → Rd
        - LOAD Rd, mem
          - (mem) → Rd
      - RISC处理器中只有“LOAD”和“STORE”指令才能访问主存
  - STORE指令
    - ① IF取指 ② ID译码&amp;取值 ③ EX 执行 ④ M 访存  ⑤ 空段

      <a href="/images/408-mind-maps/co-0155.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0155.svg" alt="① IF取指 ② ID译码&amp;amp;取值 ③ EX 执行 ④ M 访存 ⑤ 空段" width="240" height="100" loading="lazy" /></a>

      - STORE指令：
        - IF：根据PC从指令Cache中取指令到IF段的锁存器中
        - ID：将BR基址寄存器的值放到A，将偏移量放到Imm，将要存的数放到B
        - EX：运算，得到有效的地址 A + Imm，把B的值放进去
        - M：从数据Cache中取数据，放到锁存器
        - WB：空段
      - 指令举例
        - STORE Rs, 996(Rd)
          - Rs → (996+(Rd))
        - STORE Rs, mem
          - Rs → (mem)
  - BRANCH指令
    - ① IF取指 ② ID译码&amp;取值 ③ EX 执行 ④ M/WrPC（目标PC值写回PC）  ⑤ 空段

      <a href="/images/408-mind-maps/co-0196.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0196.svg" alt="① IF取指 ② ID译码&amp;amp;取值 ③ EX 执行 ④ M/WrPC（目标PC值写回PC） ⑤ 空段" width="240" height="108" loading="lazy" /></a>

      - 转移类指令：通常采用相对寻址
      - BRANCH指令：
        - IF：根据PC从指令Cache中取指令到IF段的锁存器中
        - ID：将需要比较的两个数放到锁存器A，B；偏移量放入到Imm
        - EX：运算，比较两个数
        - M：将目标PC值写回PC
          - 也可以成为WrPC段，比M耗时短，安排在M段时间内完成
        - WB：空段
          - WB阶段一般修改通用寄存器
      - 偏移量：例如 beq Rs, Rt, #996 就是<br>【 (PC) + 4 + (996 \* 4) -&gt; PC 】
      - 指令举例
        - beq Rs, Rt, #off
          - 如果(Rs) == (Rt)，则(PC) + 指令字长 + (#off \* 指令字长) → PC
          - 否则：(PC) + 指令字长 → PC
        - bne Rs, Rt, #off
          - 如果(Rs) != (Rt)，则(PC) + 指令字长 + (#off \* 指令字长) → PC
          - 否则：(PC) + 指令字长 → PC
  - JMP指令
    - ① IF取指 ② ID译码&amp;取值 ③ EX/WrPC ④ 空段  ⑤ 空段

      <a href="/images/408-mind-maps/co-0237.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0237.svg" alt="① IF取指 ② ID译码&amp;amp;取值 ③ EX/WrPC ④ 空段 ⑤ 空段" width="240" height="114" loading="lazy" /></a>

      - 转移类指令：通常采用相对寻址
      - 把PC的操作安排在EX里面完成，WrPC
        - 因为PC越早写入，越能够避免控制冲突
      - JMP指令：
        - IF：根据PC从指令Cache中取指令到IF段的锁存器中
        - ID：偏移量放入到Imm
        - EX：（计算PC值？）把PC值写回PC中
          - WrPC
          - 咸鱼PPT中说不需要ALU，不用计算，这里存疑
        - M：空段
        - WB：空段
      - 指令举例
        - jmp #off
          - (PC) + 指令字长 + (#off \* 指令字长) → PC
      - WrPC段越早完成越能避免冲突，也可以在WB端修改PC
- 指令流水线的分类
  - 根据流水线使用级别的不同
    - 【部件功能级】流水线
      - 把复杂的运算组成流水线
      - 例如：ALU执行浮点的运算，可以把求阶差、对阶、尾数相加、结果规格化四个部分组装成流水线
      - 批注：更细一层
    - 【处理机级】流水线
      - 把指令的执行组成流水线
      - 例如：把指令的取值、分析、执行、访存、写回分为5个部分形成流水线
      - 批注：【一个处理器中的不同部件】<br>跑【一个指令不同阶段】
    - 【处理机间】流水线
      - 每个处理机完成某一类型的任务，然后把任务结果存在与下一个处理器共享的存储器中
      - 批注：【多个处理器】跑【一个任务】
  - 根据流水线完成的功能不同
    - 单功能流水线
      - 只能用于某个特定的任务：例如浮点运算流水线
    - 多功能流水线
      - 可以用于多个任务：例如指令流水线
  - 动态&amp;静态
    - 静态流水线
      - 同一时间内，流水线的各段只能按同一种功能的连接方式工作
    - 动态流水线
      - 指在同一时间内，当某些段正在实现某种运算时，另一些段却正在进行另一种运算。
        - 这样对提高流水线的效率很有好处，但会使流水线控制变得很复杂。
    - 例子：动态 --- ALU又可以做除法又可以做加法
  - 线性&amp;非线性
    - 线性流水线
      - 从输入到输出，每个功能段只允许经过一次，不存在反馈回路。
    - 非线性流水线
      - 存在反馈回路，从输入到输出过程中，某些功能段将数次通过流水线，这种流水线 适合进行线性递归的运算。
    - 例字：非线性 --- 只有加法指令的ALU，运行乘法需要多次EX，IF ID EX EX EX ...  EX M WB

    - 一个指令对多个数据流进行处理，一般为【数据级并行技术】。由一个指令控制部件，多个处理单元组成
      - 例如一个CPU多个ALU

      - 概要：例如一个程序中的for处理循环数组，可以同时处理完16个下标的数据
        概要范围：[一条指令中的多个数据是存在不同的地址中的，那么该条指令的执行的数据运算可以并发进行](#topic-d11864f4-79f1-43c2-8e88-620dd0ef1555)

## 总线定义

- 定义：
  - 一组能为多个部件分时共享的公共信息传送线路
- 特点：
  - 分时
  - 共享
- 设备：
  - 主设备
    - 获得总线控制权的设备
  - 从设备
    - 被主设备访问的设备，只能响应来自主设备的控制
- 特性：
  - 机械特性
    - 尺寸、形状
  - 电气特性
    - 传输方向 + 与数字有关的
  - 功能特性
    - 每根线的功能
  - 时间特性
    - 信号与时序
- 猝发传输
  - 在【一个总线周期】内传输存储地址连续的多个数据字 --- 猝发传送
    - 例如：一个总线带宽为32bit，传输一次数据的时间是10ns，支持猝发，则传输128bit数据最少需要：10（传地址） + 10 \* 4（四个数据） = 50
      - 如果没有猝发，则时间最少是(10 + 10)\*4
- 总线的分类
  - 片内总线
    - 芯片内部的总线，是CPU内部：寄存器与寄存器之间、寄存器与ALU之间的线
      - 这里面所有的线

        <a href="/images/408-mind-maps/co-0094.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0094.svg" alt="这里面所有的线" width="240" height="101" loading="lazy" /></a>

  - 系统总线
    - 数据总线 DB
      - 传输各功能部件之间的【数据信息】
      - 可以进行双向数据传输，其位数与机器字长、存储字长有关
    - 地址总线 AB
      - 传输源数据、目的数据、IO端口的【地址】
      - AB的根数（总位数）和主存地址空间大小有关
        - 小心：IO和内存统一编址
    - 控制总线 CB
      - 传输【控制信息】
      - CPU送出控制命令和主存返回CPU的反馈信息
  - 通信总线/外部总线
    - 计算机系统之间的、计算机与其他系统的的总线，例如网线
  - 并行/串行总线
    - 并行总线的传输速度不一定比串行高，因为并行总线间的码间串扰现象很严重
- 总线结构
  - 单总线结构
    - CPU、主存、IO全都挂载到一组总线上

      <a href="/images/408-mind-maps/co-0164.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0164.svg" alt="CPU、主存、IO全都挂载到一组总线上" width="240" height="103" loading="lazy" /></a>

    - 优点：
      - 结构简单、成本低、容易接入新设备
    - 缺点：
      - 带宽低、负载重、多部件争用唯一总线
      - 不支持并发传送操作
        - 这里的并发其实指 “并行”
  - 双总线结构
    - 一条是主存总线，另一条是IO总线

      <a href="/images/408-mind-maps/co-0056.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0056.svg" alt="一条是主存总线，另一条是IO总线" width="240" height="182" loading="lazy" /></a>

      - 主存总线在CPU、主存、通道之间传送数据，IO设备通过IO总线和通道进行数据交互
    - 优点：
      - 将低速IO设备从单总线上分离出来了，实现了IO和存储器的分离
    - 缺点：
      - 需要增加通道硬件
  - 三总线结构
    - 一条主存总线、一条IO总线、一条DMA

      <a href="/images/408-mind-maps/co-0053.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0053.svg" alt="一条主存总线、一条IO总线、一条DMA" width="240" height="155" loading="lazy" /></a>

      - CPU通过IO总线和低速外设进行数据交互，主存通过DMA总线和高速外设进行数据交互
    - 优点：
      - 提高IO设备的性能，使其更快的响应命令，提高吞吐量
    - 缺点：
      - 系统工作效率较低
- 总线性能指标
  - 总线传输周期
    - 一次总线操作需要的时间：申请阶段 + 寻址阶段 + 传输阶段 + 结束阶段
  - 总线时钟周期
    - 总线的时钟周期 = 机器时钟周期
  - 工作频率
    - 各种操作的频率，是总线周期的倒数（即 1s 之内能够传送几次数据）
  - 时钟频率
    - 机器的时钟频率，是时钟周期的倒数
  - 宽度
    - 总线位宽，一次总线传输数据的位数
  - 带宽

    - 又：总线数据传输率。即单位时间内总线上可传输数据的总bit数（也可以以Byte作为单位）
  - 总线复用
    - 分时传输技术。一种信号线在不同时间传输不同信息
      - vs. CO 地址复用：DRAM采用的行列存储模式
        [查看关联主题](#topic-33897a397eaa697900dd48c3d8)

      - vs. CN 地址复用：通过NAT技术实现局域网IP地址到广域网IP地址
  - 信号线数
    - 所有总线的线数总和：例如有32位地址线、32位数据线、100位控制线，则信号线数位164根
  - 概要：故一次总线传输周期 = 多个机器周期
    概要范围：[总线传输周期](#topic-d08f2735-10d4-4fac-bd60-e892edfa1010)、[总线时钟周期](#topic-642daf39-bf2f-4e98-9aad-eea132d8c3cd)

- 考频：超高
  - 09-11、12\*2、13、14\*2、15-20

  概要范围：[特性：](#topic-71050445-d452-4a97-bb7a-1164a64977d3)



  **接口标准的四类特性**

  1. **机械特性**：规定连接的规格、接口形状、引线数目和引脚数量等。
  2. **电气特性**：电压范围、阻抗匹配、传输速率、距离限制等，通常与数字有关。
  3. **功能特性**：某条线上出现某一电平表示何种意义，例如说明“高电平”或“低电平”代表什么。
  4. **规程特性**：物理线路的工作规程和时序关系。



## 总线事务和定时

- 考频：低
  - 21
- 总线仲裁
  - 作用：解决多个主设备同时竞争总线控制权的问题，使用某种方式选择一个主设备有限获得控制权
- 总线事务
  - 请求操作：
    - 主设备（CPU、DMA）发出总线传输请求，获得总线控制权
  - 仲裁阶段：
    - 总线仲裁机构决定将下一传输周期的总线使用权授子某一申请者。
  - 寻址阶段：
    - 主设备通过总线给出要访问的从设备地址及有关命令，启动从模块。
  - 传输阶段：
    - 主模块和从模块进行数据交换，可单向或双向进行数据传送。
  - 释放阶段：
    - 主模块的有关信息均从系统总线上撤除，让出总线使用权。
  - 批注：22
- 总线周期<br>四大阶段
  - 申请分配阶段
    - 传输请求 + 总线仲裁
  - 寻址阶段
    - 【获得了使用权的主模块】通过主线发出【本次要访问的从模块】的【地址】的命令
  - 传输阶段
    - 主从模块进行【数据交换】
  - 结束阶段
    - 主模块有关【信息从系统总线上撤除】，【让出总线使用权】
  - 批注：(旧)
- 总线定时
  - 同步定时
    - CPU采用完全统一的时钟，适用于总线长度短、总线所接部件的存取时间很接近的系统
    - 配图

      <a href="/images/408-mind-maps/co-0194.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0194.svg" alt="同步定时" width="240" height="211" loading="lazy" /></a>

      - T1: CPU给出地址信息
      - T2: CPU给出读命令（低电平有效），与地址信息相符合的输入设备按命令进行一系列的内部操作。
        - 且必须在读命令T3的上升之前将CPU所需的数据送到数据总线上
      - T3: CPU把数据线上的数据送到内部寄存器中。
      - T4: CPU在T4撤销读命令，输入设备不再向数据总线上传送数据，撤销它对数据总线的驱动。
    - 优点：
      - 传送速度快，具有较高的传输速率，逻辑简单
    - 缺点：
      - 主从设备强制性同步，不能及时进行【有效性、可靠性】检测
  - 异步定时
    - 主从设备通过应答进行协商确定时钟
    - 请求回答的互锁
      - 发送的例子：
        - 请求：
          - 地址信息、读命令
        - 回答：
          - 要读出的数据
      - 不互锁方式
        - 配图

          <a href="/images/408-mind-maps/co-0087.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0087.svg" alt="不互锁方式" width="240" height="161" loading="lazy" /></a>

          - 最快、最不可靠
          - 主设备发出【请求】，不用等到从设备的【回答】，经过一段时间自行撒销【请求】。
          - 从设备收到【请求】后，发出【回答】信号，经过一段时间自动撒销【回答】。
          - 双方不存在互锁关系
      - 半互锁方式
        - 配图

          <a href="/images/408-mind-maps/co-0289.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0289.svg" alt="半互锁方式" width="240" height="165" loading="lazy" /></a>

          - 主设备发出【请求】，等到从设备的【回答】，后撤销【请求】。
            - 主设备有互锁关系
          - 从设备收到【请求】，发送【回答】，过一段时间自行撤销【回答】。
            - 从设备不存在互锁
      - 全互锁方式
        - 配图

          <a href="/images/408-mind-maps/co-0265.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0265.svg" alt="全互锁方式" width="240" height="161" loading="lazy" /></a>

          - 最慢、最可靠
          - 主设备发出【请求】，等到从设备的【回答】，后撤销【请求】。
            - 主设备有互锁关系
          - 从设备收到【请求】，发送【回答】，等到获知主设备【请求】撤销过后，才可以撤销【回答】。
            - 从设备有互锁关系
    - 优点：
      - 总线周期可变，能保证两个速度相差很大的设备可以可靠的进行通信
    - 缺点：
      - 比同步复杂，速度比同步慢
    - 概要：异步总线的传送设备是按需分配的
      概要范围：[主从设备通过应答进行协商确定时钟](#topic-50ab48ba-84f3-4e62-91ce-c8b76577d40d)

- 半同步通信
  - 同步 + 异步
    - 配图

      <a href="/images/408-mind-maps/co-0089.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0089.svg" alt="同步 + 异步" width="240" height="177" loading="lazy" /></a>

      - 在同步方式中，如果主设备在T2发出了读，但是从设备知道自己无法在T3给出数据，就会在T3发出WAIT命令
- 分离式通信
  - 在从设备准备数据的时候，总线是空闲的，故可以采用其他操作
  - 分为两个周期
    - 周期一：主模块申请占用总线，使用完后放弃总线使用权
    - 周期二：从模块申请占用总线，将各种信息放上总线
  - 特点：
    - 1\. 每个模块都有权利申请占用总线
    - 2\. 总线利用率高

          **6.3.2 中断处理程序**

          当一个进程请求 I/O 操作时，该进程将被挂起，直到 I/O 设备完成 I/O 操作后，设备控制器便向 CPU 发送一个中断请求。CPU 响应后便转向中断处理程序，由中断处理程序执行相应处理；处理完成后解除相应进程的阻塞状态。

          中断处理程序的处理过程可分为以下几个步骤：

          1. **测定是否有未响应的中断信号。**每当设备完成一个字符（字或数据块）的读入或输出，设备控制器便向处理机发送中断请求，请求处理机将已读入的数据传送到内存缓冲区，或将要输出的数据传送给设备控制器。程序每执行完当前指令后，处理机都要测试是否有未响应的中断信号。没有则继续执行下一条指令；有则停止原进程的执行，准备转去执行中断处理程序。
          2. **保护被中断进程的 CPU 环境。**在转交控制权之前，需要保存以后恢复进程运行所需的信息。通常由硬件自动将处理机状态字 **PSW**，以及程序计数器 **PC** 中保存的下一条指令地址，保存到中断保留区（栈）中；然后保存被中断进程的 CPU 现场信息。

- DMA传送过程
  - 预处理：<br>（CPU设置）<br>主存起始地址 -&gt; AR<br>I/O设备地址 -&gt; DAR<br>传送数据个数 -&gt; WC<br>启动I/O设备
  - 数据传输：<br>继续执行主程序<br>同时完成一批数据的传送
    - 1\. DMA把数据放入到DR中
    - 2\. DR写满后设备向DMA请求触发器置为 1
    - 3\. 控制/状态逻辑收到DMA请求触发器的信号，向CPU发送一个HRQ信号
    - 4\. CPU如果此时系统总线空闲，就发送一个HLDA信号给DMAC
    - 5\. 此时DMAC开始接管总线
    - 6\. DMAC不断向总线上发出数据传送，每次发送一个字，不断地修改AR、WC、DAR的值
    - 7\. 当WC的值溢出时，WC向中断机构发出溢出信号，中断机构给CPU发送中断请求，指明已经完成传输
  - 后处理：<br>中断服务程序<br>做DMA结束处理
  - 内存 -&gt; 数据总线 -&gt; DMAC -&gt; 外设
    - 叫做：数据通路

    - 不需要总线使用权的申请、建立和归还过程
    - 硬件逻辑更为复杂
    - 交替轮着来

    - DMA访问主存的三种可能：
      - CPU不访存
        - 不冲突
      - CPU正在访存
        - 存取周期结束让出总线
      - CPU和DMA同时请求
        - I/O访存优先
    - IO优先就完事了
- DMA与中断的对比：
  - 配图



    |比较项|中断方式|DMA 方式|
    |---|---|---|
    |数据传送|程序控制：程序切换、保护和恢复现场|硬件控制：CPU 只在预处理和后处理时参与|
    |中断请求时机|传送数据|后处理|
    |响应|指令执行周期结束后响应中断|每个机器周期结束均可，总线空闲时即可响应 DMA 请求|
    |场景|CPU 控制，低速设备|DMA 控制器控制，高速设备|
    |优先级|低于 DMA|高于中断|
    |异常处理|能够处理异常事件|仅传送数据|



    - 适用范围
      - 中断低速
        - 因为如果是高速设备一直请求程序中断，最后会占用大量的CPU时间
      - DMA高速
    - 数据传输
      - 中断程序
      - DMA硬件
    - 概要：通道是一种硬件 + 程序的数据传输方式
      概要范围：[数据传输](#topic-f1dc4c6e-1b5c-44b3-88fe-6b938a2e2069)

  - 何时检测中断
    - DMA：
      - 在【存取周期】末尾检测
        - 例如：取指指令的后半部分不涉及访问Cache/主存，则可以用来进行DMA
    - 程序中断：
      - 在指令周期末尾
