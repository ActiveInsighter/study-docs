````mindmap
## 算法复杂度

- 考频：高
  - 11、12、13、14、17、19、22
- 时间复杂度
  - 计算：
    - 1\. 找到基本操作（最深层的循环）
    - 2\. 分析该基本操作的执行次数 x 和问题的规模 n 的数学形式关系



      $x = f(n)$

    - 3\. x 的数量级 O(x) 是算法时间复杂度 T(n)
  - 常用技巧：
    - 加法规则



      $O(f(n)) + O(g(n)) = O(max(f(n), g(n)))$

    - 乘法规则



      $O(f(n)) \times O(g(n)) = O(f(n) \times g(n))$

    - 咸鱼口诀：“常对幂指阶”



      $O(1) < O(log_2n) < O(n) < O(nlog_2n)<O(n^2)<O(n^3)<O(2^n) > O(n!) < O(n^n)$

  - 三种复杂度：
    - 最坏时间复杂度：考虑输入数据“最坏”的情况
    - 平均时间复杂度：考虑所有输入数据等概率出现的情况
    - 最好时间复杂度：考虑输入数据“最好”的情况
- 空间复杂度
  - 如何计算
    - 1\. 算法空间大小和问题规模的关系
    - 2\. 数学形式分析：空间x，问题规模n



      $x = f(n)$

    - 3\. x 的数量级 O(x) 就是算法的空间复杂度S(n)
    - 注：如果是递归程序，则各层算法所需存储空间不同，分析方法有所区别
  - 常用技巧：
    - 同上 ↑
  - 原地工作
    - 空间复杂度O(1)
      - 程序消耗的空间和问题规模没有相关性

    - 地址译码器

- 考频：低
````

````mindmap
## 顺序表

- 考频：中
  - 10大、11大、13大、18大、20大
- 定义
  - 顺序存储的线性表
    - 逻辑结构+物理结构
- 特点
  - 随机访问
    - 查找数组O(1)
  - 存储密度高
    - 相比较链表
  - 拓展容量不方便
    - 重新开辟新空间进行拷贝
- 创建
  - 静态分配
    - data\[MaxSize\]
  - 动态分配
    - \*data = malloc(sizeof(ElemType) \* length)
    - 释放：free(data)
    - 增加动态数组的长度
      - 配图



        ```cpp
        // 增加动态顺序表的长度
        void IncreaseSize(SeqList &L, int len) {
            int *p = L.data;
            L.data = (int *)malloc((L.MaxSize + len) * sizeof(int));
            for (int i = 0; i < L.length; i++)
                L.data[i] = p[i];     // 将数据复制到新区域
            L.MaxSize += len;        // 更新顺序表最大长度
            free(p);                // 释放原来的内存空间
        }
        ```



- 插入
  - 代码：注意代码的健壮性
    - 配图



      ```cpp
      bool ListInsert(SqList &L, int i, int e) {
          if (i < 1 || i > L.length + 1)  // 判断 i 的范围是否有效
              return false;
          if (L.length >= MaxSize)       // 当前存储空间满，不能插入
              return false;
          for (int j = L.length; j >= i; j--)  // 将第 i 个及之后的元素后移
              L.data[j] = L.data[j - 1];
          L.data[i - 1] = e;             // 在位置 i 处放入 e
          L.length++;                   // 表长增加 1
          return true;
      }
      ```



  - 时间复杂度
    - 最好
      - O(1)
    - 最坏
      - O(n)
    - 平均
      - O(n/2) = O(n)
- 删除
  - 代码
    - 配图



      ```cpp
      bool ListDelete(SqList &L, int i, int &e) {
          if (i < 1 || i > L.length)  // 判断 i 的范围是否有效
              return false;
          e = L.data[i - 1];         // 将被删除元素赋给 e
          for (int j = i; j < L.length; j++)
              L.data[j - 1] = L.data[j];
          L.length--;               // 表长减 1
          return true;
      }
      ```



  - 时间复杂度
    - 最好
      - O(1)
    - 最坏
      - O(n)
    - 平均
      - O(n/2) = O(n)
- 查找
  - 代码：
    - 配图



      ```cpp
      int LocateElem(SqList L, ElemType e) {
          int i;
          for (i = 0; i < L.length; i++)
              if (L.data[i] == e)
                  return i + 1;  // 下标为 i 的元素值为 e，返回其位序 i+1
          return 0;
      }
      ```



  - 按位查找
    - 获得表L中的第i个位置的元素的值
    - 时间复杂度
      - O(1)
  - 按值查找
    - 搜索即可
    - 时间复杂度
      - O(n)
- 概要：注意length需要修改，传入是引用
  概要范围：[插入](#topic-ffc91e3496cb355b7668d97b90)、[删除](#topic-5d6adf312ecbc5e17958aa7a32)

## 链表

- 单链表
  - 定义
    - 线性表的链式存储
      - 逻辑+物理
  - 链表类型
    - 带头节点
      - 头节点即第0个元素
    - 不带头节点
      - 元素从第一个开始
  - 优缺点
    - 优点：不要求大片存储空间
    - 缺点：不支持随机存取
  - 代码规范
    - typedef
      - 使用 LNode\* 来表示使用的是一个节点
      - 使用 LinkList 来表示使用的是一个链表
    - malloc
      - 配图



        ```cpp
        (LNode *)malloc(sizeof(LNode))
        ```



    - 结构体
      - 配图



        ```cpp
        typedef struct LNode {
            ElemType data;
            struct LNode *next;
        } LNode, *LinkList;
        ```



  - 按位序插入
    - 按位序插入（带头节点插入法）
      - 找到第i - 1 个节点
      - 然后插入一个新的节点
    - 按位序插入（不带头节点插入法）
      - 不带头节点的链表，处理第1个节点的时候需要特殊处理
  - 插入
    - 后插节点
      - 比较简单，直接malloc然后赋值、更新指针
    - 前插节点
      - 需要用一个小的巧方法
        - 对节点p后面插入一个后继节点s
        - 把节点p的数据移动到节点s里面去
        - 把新的数据放到p里面
  - 删除
    - 按位序删除
      - ListDelete(LinkList &amp;L, int i, ElemType &amp;e)
      - 其中的e需要返回删除的数据
    - 指定节点删除
  - 查找
    - 按位查找
      - O(n)
    - 按值查找
      - O(n)
  - 建立
    - 尾插法
    - 头插法
- 双链表
  - 双链表在单链表的基础上添加了前驱节点
  - 插入：需要修改前节点的next和后节点的prior，后设置新节点的next和prior
  - 删除：先设置前节点的next=next-&gt;next，再设置后节点的prior = prior-&gt;prior，删除中间
- 循环链表
  - 链表中最后一个节点指向头结点
  - 循环单链表
  - 循环双链表
- 静态链表
  - 线性结构+顺序存储
  - 用顺序表的形式进行存储空间开辟
- 考频：高
  - 16\*2、21、09大、12大、15大、19大
````

````mindmap
## 队列

- 一种操作受限的线性表，可顺序可链式
  - 只允许在线性表的一端进行插入，另一端进行删除
- 性质
  - 队头删除元素，队尾插入元素（头删尾插）
    - 所以是队尾先行，然后队头紧跟
  - 尾部向后扩展的线性结构
  - front -= 1; rear += 1
- 普通队列
  - 配图

    <a href="/images/408-mind-maps/ds-0107.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/ds-0107.svg" alt="普通队列" width="240" height="80" loading="lazy" /></a>

    - 判断队空
      - Q.front == Q.rear == 0
    - 判断队满
      - Q.rear == MaxSize &amp;&amp; Q.front == 0
      - Q.rear == MaxSize 代表队列不可再插入元素
    - 批注：顺序存储
- 循环队列
  - 如果队列没有使用“循环功能”，rear &gt; front
  - 如果队列使用了“循环功能”, front &gt; rear
  - 判断队空和队满
    分组说明：最常考；对应：[1. 牺牲一个存储单元](#topic-b5e9129d44780c4c40c5493bac)

    - 1\. 牺牲一个存储单元
      - 队满：Q.front == (Q.rear+1)%MaxSize
      - 队空：Q.front == Q.rear
      - 队列长度：(Q.rear - Q.front + MaxSize)%MaxSize
    - 2\. 记录长度
      - 队满：Q.front == Q.rear &amp;&amp; len == n
      - 队空：Q.front == Q.rear &amp;&amp; len == 0
    - 3\. 增加tag
      - 队满：Q.front == Q.rear &amp;&amp; tag == 1
      - 队空：Q.front == Q.rear &amp;&amp; tag == 0
  - 基本操作
    - 初始化：Q.front = Q.rear = 0
    - 插入元素：Q.rear == (Q.rear + 1)%MaxSize
    - 删除元素：Q.front == (Q.front + 1)%MaxSize
    - 队列长度：(Q.rear - Q.front + MaxSize)%MaxSize
  - 配图
````

````mindmap
      // 求模式串 T 的 next 数组，串下标从 1 开始
      void get_next(SString T, int next[]) {
          int i = 1, j = 0;
          next[1] = 0;
          while (i < T.length) {
              if (j == 0 || T.ch[i] == T.ch[j]) {
                  ++i;
                  ++j;
                  // 匹配时将相等前后缀的长度增加 1
                  next[i] = j;
              } else {
                  // 否则令 j = next[j]，继续比较
                  j = next[j];
              }
          }
      }
      ```
````

````mindmap
## 二叉数的应用

- 二叉排序树<br>（BST）
  - 每个结点：左节点值 &lt; 根节点值 &lt; 右节点值
  - 作用：
    - 用来进行搜索，”排序“体现在建树的过程
  - 算法：
    - 搜索
      - 进行比较，确定向左 or 向右

      - 树不为空

      - 从零开始一个一个插
    - 删除

      - 如果只有单子树，则把子树移动上来
      - 既有左子树又有右子树
        - 用直接前驱
          - 左子树的最右
        - 用直接后继
          - 右子树的最左

      #define SIZE 100
      int UFSets[SIZE];

      // 并查集初始化：每个自成单元素集合

  - 查找：
    - 配图



      ```cpp
      // 查找 x 所属集合；根结点的 S[x] 小于 0
      int Find(int S[], int x) {
          while (S[x] >= 0)
              x = S[x];
          return x;
      }
      ```



      - 优化：路径合并
        - 把集合最后变成类似“菊花树”的样子



          ```cpp
          // 并查集的查找：路径压缩
          int find(int x) {
              if (x == fa[x])
                  return x;
              else {
                  fa[x] = find(fa[x]);  // 父节点改为根节点
                  return fa[x];       // 返回父节点
              }
          }

          // 同一操作的简写
          int find(int x) {
              return x == fa[x] ? x : (fa[x] = find(fa[x]));
          }
          ```



  - 合并：
    - 配图



      ```cpp
      // 合并两个不相交集合。Root1、Root2 是不同集合的根。
      void Union(int S[], int Root1, int Root2) {
          S[Root2] = Root1;  // 将 Root2 连接到 Root1 下
      }
      ```



- 优化：
  - 查找的时间复杂度和树高一样，所以要控制树高
  - 每次并查集的合并都是小树并到大树里面



    $时间复杂度O(log_2n)$

    - 用根节点的”绝对值“来表示当前结点个数，例如-3即为这个树里面有3个节点
    - 合并后树高不会超过 ⌊log2n⌋+1
      - 证明：数学归纳法
    - 实现代码



      ```cpp
      void Union_2(int S[], int Root1, int Root2) {
          if (Root1 == Root2) return;
          if (S[Root2] > S[Root1]) {
              // Root2 中的节点数量少，Root2 合并到 Root1
              S[Root1] += S[Root2];
              S[Root2] = Root1;
          } else {
              // Root1 中的节点数量少，Root1 合并到 Root2
              S[Root2] += S[Root1];
              S[Root1] = Root2;
          }
      }
      ```



- 并查集的究极优化
  - 压缩路径
    - 代码
      - 配图

        <a href="/images/408-mind-maps/ds-0079.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/ds-0079.svg" alt="代码" width="240" height="130" loading="lazy" /></a>

    - 时间复杂度
      - 在常见的n的取值范围内是O(4)



        每次 Find 操作先找根，再“压缩路径”，可使树的高度不超过 $O(\alpha(n))$。$\alpha(n)$ 是一个增长很慢的函数；对常见的 $n$ 值，通常有 $\alpha(n)\le4$。因此优化后并查集的 Find、Union 操作的均摊时间开销很低。



  - 优化的总结
    - 初始版本：
      - 用数组、双亲表示法来描述元素之间的集合关系。根节点为-1，非根节点指向父节点下标。
    - Union优化后：
      - 用根节点的负值表示一棵树的节点总数，每次Union的时候是用小树合并到大树根节点下面
    - Find优化后：
      - 使用了压缩路径的策略，每次Find操作先找到了x所属的根节点，再将查找路径上的所有节点都直接挂载到根节点下面。
    - 最坏时间复杂度比较
      - Find操作 = 最坏树高
        - 公式
          标签：初始版本



          $O(n)$

        - 公式
          标签：Union优化后



          $O(log_2n)$

        - 公式
          标签：Find优化后



          $O(\alpha(n))$

      - 将n个独立元素经过<br>Union合并为一个集合
        - 公式
          标签：初始版本



          $O(n^2)$

        - 公式
          标签：Union优化后



          $O(nlog_2n)$

        - 公式
          标签：Find优化后



          $O(n\alpha(n))$
````

````mindmap
## 图的遍历

- BFS
  - 队列
    - 邻接表 O(v + e)
    - 邻接矩阵 O(v^2)
  - 广度优先生成树
    分组说明：如果给定的是邻接矩阵，则生成树唯一，如果是邻接表，则生成树不唯一；对应：[只针对无权图进行BFS即可得到最小生成树](#topic-a25a5b68625a4cc0e07cbbac28)

    - 只针对无权图进行BFS即可得到最小生成树
      - 时间复杂度：O(v^2)/O(v+e)
  - 要求掌握代码（队列实现）
    - 配图



      ```cpp
      void BFS_MIN_Distance(Graph G, int u) {
          // d[i] 表示从 u 到 i 的最短路径
          for (int i = 0; i < G.vexnum; i++)
              d[i] = INF;
          visited[u] = true;
          d[u] = 0;
          EnQueue(Q, u);
          while (!IsEmpty(Q)) {
              DeQueue(Q, u);
              for (int w = FirstNeighbor(G, u); w >= 0; w = NextNeighbor(G, u, w)) {
                  if (!visited[w]) {
                      visited[w] = true;
                      d[w] = d[u] + 1;
                      EnQueue(Q, w);
                  }
              }
          }
      }
      ```



- DFS
  - 递归/堆栈
    - 邻接表 O(v + e)
    - 邻接矩阵 O(v^2)
  - 深度优先生成树
    分组说明：如果给定的是邻接矩阵，则生成树唯一，如果是邻接表，则生成树不唯一；对应：[只针对无权图进行DFS即可得到最小生成树](#topic-0ef991c3521844025fba6ae74d)

    - 只针对无权图进行DFS即可得到最小生成树
      - 时间复杂度：O(v^2)/O(v+e)
  - 要求掌握代码（递归实现）
    - 配图



      ```cpp
      bool visited[MAX_VERTEX_NUM];  // 访问标记数组

      void DFSTraverse(Graph G) {
          for (int v = 0; v < G.vexnum; v++)
              visited[v] = false;
          for (int v = 0; v < G.vexnum; v++)
              if (!visited[v])
                  DFS(G, v);
      }

      void DFS(Graph G, int v) {
          visit(v);
          visited[v] = true;
          for (int w = FirstNeighbor(G, v); w >= 0; w = NextNeighbor(G, v, w))
              if (!visited[w])
                  DFS(G, w);
      }
      ```

          void Prim(G, T) {
              T.V = {w};  // 添加任意一个顶点 w 到顶点集
              while (G.V - T.V != {}) {

                  T.V = T.V ∪ {v};

          }

          void Kruskal(V, T) {
              T.V = V;  // 初始时每个顶点都是一个独立连通分量
              while (compute_connect(T) > 1) {
                  // compute_connect(T) 返回生成树的连通分量个数
                  (u, v) = find_min_weight(T);
                  // 选择连接不同连通分量的最小权值边 (u, v)
                  T.E = T.E ∪ {(u, v)};
              }
          }
````

````mindmap
  - 定义
    - B 树，又称多路平衡查找树，B 树中所有结点的孩子个数的最大值称为 B 树的阶，通常用 m 表示。一棵 m 阶 B 树要么是空树，要么满足这些特性：

      <a href="/images/408-mind-maps/ds-0031.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/ds-0031.svg" alt="B 树，又称多路平衡查找树，B 树中所有结点的孩子个数的最大值称为 B 树的阶，通常用 m 表示。一棵 m 阶 B 树要么是空树，要么满足这些特性：" width="240" height="91" loading="lazy" /></a>

- B树的高度
  - n个关键字的m阶B树，最大最小高度
    - 注：B树的高度不包括叶子结点（失败节点）
  - 最小：
    - 节点填满：(m-1)(1+m+m^2+...+m^h-1) &gt;= n



      $h \ge log_m(n+1)$

      - 每层最多m个指针P，每个P指向的非叶结点最多有(m-1)个关键字K。第i层关键字最多有 ↑。



        $(m-1)*m^{i-1}$

  - 最大：
    - 根节点2个分叉，其他节点只有⌈m/2⌉个指针
      - 每层最少⌈m/2⌉个指针P，每个P指向的非叶结点最少有⌈m/2⌉-1个关键字K，因此第i层的关键字最少有 ↑。



        $(⌈m/2⌉-1)*⌈m/2⌉^{i-1}$

    - 算法一（会用此方法推算）

      <a href="/images/408-mind-maps/ds-0200.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/ds-0200.svg" alt="算法一（会用此方法推算）" width="240" height="193" loading="lazy" /></a>

      $log_m(n+1) \le h \le log_{⌈m/2⌉}\frac{n+1}{2} + 1$

## B+树

- 是分块查找的一种升级优化，作用是查某个对应关键字的记录信息
- 配图

  <a href="/images/408-mind-maps/ds-0184.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/ds-0184.svg" alt="B+树" width="240" height="108" loading="lazy" /></a>

  - 里面的分支、叶子结点都是包含有多个数据项的一个总结点
  - B树的指针是在结点数据之间的，B+树的指针就是结点数据的一个部分
- m阶B+树的性质
  - 1\. 每个结点最多有m个子树
  - 2\. 非叶根节点至少有两颗子树，其他每个分支至少有⌈m/2⌉颗子树

    <a href="/images/408-mind-maps/ds-0039.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/ds-0039.svg" alt="2. 非叶根节点至少有两颗子树，其他每个分支至少有⌈m/2⌉颗子树" width="240" height="103" loading="lazy" /></a>

    - B树的叶子结点是最后那一层空的结点，树的最低层的结点是终端结点
    - B+树的叶子结点就是最底层的节点
  - 3\. B+树有多少个结点就有多少个分支
  - 4\. 叶子结点包含有全部的关键字，以及【对应着相应记录的指针】。相邻叶子会被互相连接起来

    <a href="/images/408-mind-maps/ds-0104.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/ds-0104.svg" alt="4. 叶子结点包含有全部的关键字，以及【对应着相应记录的指针】。相邻叶子会被互相连接起来" width="240" height="48" loading="lazy" /></a>

    - 可以顺序查找，可以树形分块查找
  - 5\. 分支节点只包含对应分支的【最大值】
- B+的查找
  - 多路查找
    - 一定需要找到最下一层才可以
      - B树可能在任何一层查找成功，只能在其叶子结点查找失败
  - 顺序查找
    - 可以最后一行全部进行二分查找吗？不行
- B树和B+树的对比
  - 配图



    |比较项|$m$ 阶 B 树|$m$ 阶 B+ 树|
    |---|---|---|
    |类比|二叉查找树的进化：$m$ 叉查找树|分块查找的进化：多级分块查找|
    |关键字与分叉|$n$ 个关键字对应 $n+1$ 个分叉（子树）|$n$ 个关键字对应 $n$ 个分叉|
    |结点包含的信息|所有结点都包含记录的信息|只有最下层叶子结点包含记录的信息，可使树更矮|
    |查找方式|不支持顺序查找；查找成功可能停在任一层，速度“不稳定”|支持顺序查找；查找成功或失败都会到最下一层，速度“稳定”|

    共同点（按原图表述）：除根结点外，最少 $\lceil m/2\rceil$ 个分叉，避免结点太“空”；任一结点的子树一样高，保证平衡。



- B+的增删操作和B树类似
- 与OS的联系
  - B+树可以用来进行磁盘块的管理
    - 磁盘中的磁盘块号就是B+树中的一个结点编号，磁盘块中的数据就是结点记录
  - 访问：
    - 计算机去访问根节点的磁盘块，然后逐层往下去进行结点的访问
      - 每个结点都是存在一个磁盘块中，例如磁盘块的大小为1KB，一个结点指针为1B，一个块中有1024个节点指针，故为1024叉B+树
- 拓展：公司的数据库真正实现的时候，为什么不用红黑树，而是用B+树？
  - 索引的数据结构会被存储在磁盘中，每次查询都需要到磁盘中访问，对于红黑树，树的高度可能会非常的高，会进行很多次的磁盘IO，效率会非常低，B+树的高度一般为2-4，也就是说在最坏的条件下，也最多进行2到4次磁盘IO，这在实际中性能时非常不错的

## 哈希/散列表

- 考频：中
  - 11、14、18、19、22
- 哈希表是一种典型的拿空间换时间的数据结构
- 概念
  分组说明：是针对【开放定址法】的概念；对应：[聚集（堆积）](#topic-eea81cfb80c8446845957825d3)

  - 散列函数：
    - H(key)= Hash(key) = Addr
  - 同义词
    - 通过一次哈希函数映射到同一地址上的关键词
      - H(key1) = H(key2)
  - 非同义词
    - 通过一次哈希函数映射到不同地址上的关键词
      - H(key1) != H(key2)
  - 冲突
    - 同义词引起的，两个或多个同义词关键字想要的地址已经被占用
  - 聚集（堆积）
    - 经过Hash后找到了地址，但是还需要【探测】才能找到真正的值
      - 线性探测：
        - 很大情况会聚集
      - 再散列、平方、伪随机探测：都可以避免聚集
- 哈希函数
  - 直接定址法
    - H(key) = key 或 H(key) = a \* key + b
    - 不会出现冲突，但是空位多，浪费空间
  - 除留余数法
    - H(key) = key % p
    - 把p选好，可以减少冲突的概率
      - 哈希表的冲突率：由哈希函数的好坏决定
    - 概要：一般p是取一个最接近表长的素数
      概要范围：[H(key) = key % p](#topic-fb5ae80d198889fd83d629c9f4)

  - 数字分析法
    - 根据出现概率分布情况进行分析得出的方法
  - 平方取中法
    - 取关键字的平方的中间某几位数作为Hash值
- 处理冲突
  - 开放定址法
    - 递推式：
      - Hi = (H(key) +di)%m
    - 增量序列di：
      - 线性探测(再散列)法
        - di = 1, 2, 3 .... m-1
      - 平方探测(再散列)法
        - di = 0, 1, -1, 4, -4, 9, -9, ..., k^2, -k^2
        - k一定要 &lt;= m/2 (m为表长)
        - 表长必须是4k+3的素数
      - 再/双散列法
        - Hi = RHash(Hi)
          - 使用另一个哈希函数来进行hash值的确定
            - 批注：题目一定会给出另一个Hash函数
      - 伪随机序列(再散列)法
        - di = \{一个伪随机序列\}
          - di是定义好的，所以每次探测的步长是可以知的
          - 例如：di = \{rand(0, 100), rand(0, 100), rand(0, 100), rand(0, 100)\}
    - 问题：
      - 在开放定址法的哈希表中，删除一个元素是把其标记位Tag改为TRUE
        - 不可直接删除，例如线性探测法a\[3\]，有0, 3, 6，hash结果都为 0，此时如果把a\[0\] = 0删掉，搜a\[1\] = 3的时候，搜到a\[0\]发现没有值，就判断没有
  - 拉链法
    分组说明：直接解决了堆积的问题，不会出现堆积；对应：[遇到冲突了就形成链式结构](#topic-c44912f6c1e908c3797449060d)

    - 遇到冲突了就形成链式结构
      - 解决的是同义词的冲突问题
    - 删除就可以直接物理删除了
- 性能分析
  - ASL
    - 成功失败分别计算即可（算法就是模拟插入过程，手算，求和平均）
  - 装填因子
    - 公式



      $\alpha = \frac{表中记录数n}{散列表长度m}$

      - 装填因子越大，表示装的越满，冲突的可能更大
      - 越小表示发生冲突的可能性更小
  - 会受到冲突影响的是：
    - ASL
      - ✅
    - 装填因子
      - ❎
        - n、m和冲突都没有关系，反而是装填因子可以影响冲突的概率
- 冲突的探讨
````

````mindmap
## 折半插入

- 思路：
  - 对插入排序的改进
    - 插入边比较边移动
      - 所以单个元素一次比较和移动的总复杂度为O(n) + O(n)
  - 折半插入把移动中的比较和插入分开了
    - 比较用二分查找O(logn)，插入就可以直接移动了O(n)
- 代码：
  - 配图



    ```cpp
    // 折半插入排序，A[0] 用作哨兵
    void HalfInsertSort(ElemType A[], int n) {
        int i, j, low, high, mid;
        for (i = 2; i <= n; i++) {
            A[0] = A[i];
            low = 1;
            high = i - 1;
            while (low <= high) {
                mid = (low + high) / 2;
                if (A[mid] > A[0]) high = mid - 1;
                else low = mid + 1;
            }
            for (j = i - 1; j >= high + 1; j--)
                A[j + 1] = A[j];
            A[high + 1] = A[0];
        }
    }
    ```

    > 整理说明：原图函数形参写为 nt，但循环使用 n；统一为 n。



    - 找完、再换位置
- 分析&amp;特点
  - 空间复杂度
    - O(1)
  - 时间复杂度
    - 最好O(n)
    - 平均O(n^2)
      - 比普通的插入好，折半是O(nlogn)+ O(n^2)
    - 最坏O(n^2)
  - 稳定性

    // 希尔排序：缩小增量排序
    void ShellSort(ElemType A[], int n) {
        for (int dk = n / 2; dk >= 1; dk /= 2) {
            for (int i = dk + 1; i <= n; i++) {
                if (A[i] < A[i - dk]) {
                    A[0] = A[i];
                    int j;
                    for (j = i - dk; j > 0 && A[0] < A[j]; j -= dk)

    // 冒泡排序
    void BubbleSort(ElemType A[], int n) {
        for (int i = 0; i < n - 1; i++) {
            bool flag = false;
            for (int j = n - 1; j > i; j--) {
                if (A[j] < A[j - 1]) {

                }
            }
            // 完成最后一位的确定；若未交换，说明序列已有序
            if (flag == false) return;
        }
    }
    ```



- 分析&amp;特点
  - 空间复杂度
    - O(1)
  - 时间复杂度
    - 最好O(n)
      - 因为有那个剪枝操作
    - 平均O(n^2)
    - 最坏O(n^2)
  - 稳定性
    - ✅
  - 特点：
    - 可以用于链表
- 考频：低

## 快速排序

- 考频：中
  - 10、14、19、涉及排序的大题
- 思路：
  - 每次快排，选择一个值为pivot，把比其小的放在左边，比其大的放在右边。然后再对pivot左右的数组进行快排
    - 默认pivot选择最左边的元素
- 示意图：
  - 配图

    <a href="/images/408-mind-maps/ds-0148.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/ds-0148.svg" alt="示意图：" width="186" height="220" loading="lazy" /></a>

- 代码：
  - 配图



    ```cpp
    // 快速排序（包括划分操作）
    void start(ElemType A[], int n) {
        QuickSort(A, 1, n);
    }

    void QuickSort(ElemType A[], int low, int high) {
        if (low < high) {
            int mid = Partition(A, low, high);
            QuickSort(A, low, mid - 1);
            QuickSort(A, mid + 1, high);
        }
    }

    int Partition(ElemType A[], int low, int high) {
        ElemType pivot = A[low];  // 默认选第一个元素作为枢轴
        while (low < high) {
            while (low < high && A[high] >= pivot) high--;
            A[low] = A[high];    // 比枢轴小的元素移到左端
            while (low < high && A[low] <= pivot) low++;
            A[high] = A[low];    // 比枢轴大的元素移到右端
        }
        A[low] = pivot;
        return low;
    }
    ```



- 分析&amp;特点
  - 空间复杂度
    - 最好O(log2n)
    - 平均O(log2n)
    - 最坏O(n)
  - 时间复杂度
    - 最好O(nlog2n)
      - 因为每次都要遍历，所以最好情况就是每次pivot都正好在最中间
    - 平均O(nlog2n)
      - 递归调用栈的深度为O(log2n)，每层递归调用都是O(n)的复杂度
    - 最坏O(n^2)
  - 稳定性
    - ❎
  - 特点：
    - 快排是所有排序中平均性能最佳的排序算法
  - 概要：即递归栈的深度
    概要范围：[空间复杂度](#topic-3699c4fe6a685ce1013fc9ef99)

- 考频：高

- 建大根堆：
  - 思路：
    - 从倒数第一个非叶子结点开始，调整其下属的堆，使得自己是这个堆中的最大值
  - 示意图：
    - 配图

      <a href="/images/408-mind-maps/ds-0062.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/ds-0062.svg" alt="示意图：" width="240" height="158" loading="lazy" /></a>

  - 代码：
    - 配图



      ```cpp
      // 建立大顶堆：数组下标从 1 开始
      void BuildMaxHeap(ElemType A[], int len) {
          for (int i = len / 2; i > 0; i--)
              AdjustHeap(A, i, len);
      }

      // 从 p 开始向下调整
      void AdjustHeap(ElemType A[], int p, int len) {
          A[0] = A[p];  // 暂存待调整元素
          for (int i = 2 * p; i <= len; i *= 2) {
              if (i < len && A[i + 1] > A[i])
                  i++;  // 两个子结点中取较大者
              if (A[0] >= A[i]) break;
              A[p] = A[i];
              p = i;
          }
          A[p] = A[0];
      }
      ```

      > 整理说明：原截图混用了 n/len、k/p，且向下更新写为 p=p*2；整理为统一参数 len、p，并用实际选中的较大孩子 i 更新 p。

    - 空间复杂度：
      - O(1)
    - 时间复杂度：
      - 一个元素的调整：
        - O(h)
          - h是树高度
      - 总的元素调整：
        - O(n)
          - 总的元素比较次数不会超过4n
          - 概要：记住就行
            概要范围：[总的元素比较次数不会超过4n](#topic-48d9d240829ad263b4c40812c0)

- 堆排序算法

  - 递归
    - 配图



      ```cpp
      // 归并排序：辅助数组需要容纳 A[1..len]
      ElemType *B;

      void start(ElemType A[], int len) {
          B = (ElemType *)malloc((len + 1) * sizeof(ElemType));
          MergeSort(A, 1, len);
      }

      void MergeSort(ElemType A[], int low, int high) {
          if (low < high) {
              int mid = (low + high) / 2;
              MergeSort(A, low, mid);
              MergeSort(A, mid + 1, high);
              Merge(A, low, mid, high);
          }
      }
      ```

      ```cpp
      void Merge(ElemType A[], int low, int mid, int high) {
          // A[low..mid] 和 A[mid+1..high] 都有序；B 为辅助数组
          int i, j, k;
          for (i = low; i <= high; i++)
              B[i] = A[i];
          i = low;
          k = i;
          j = mid + 1;
          while (i <= mid && j <= high) {
              if (B[i] <= B[j])
                  A[k++] = B[i++];
              else
                  A[k++] = B[j++];
          }
          while (i <= mid) A[k++] = B[i++];
          while (j <= high) A[k++] = B[j++];
      }
      ```



- 分析：
  - 空间复杂度：
    - O(n)
      - 递归也有O(log2n)可以忽略
  - 时间复杂度：
    - 递归O(log2n)，归并O(n)
      - 总共为O(nlog2n)
  - 稳定性：
    - ✅
- 可以用来给外部排序用，10TB数据请用归并排序
- 考频：低
  - 16、17、22
````
