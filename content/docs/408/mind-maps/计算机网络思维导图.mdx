## 性能指标

<a href="/images/408-mind-maps/cn-0085.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0085.svg" alt="性能指标" width="48" height="48" loading="lazy" /></a>

- 速率
  - 数据传输速率
- 带宽
  - 原本指：
    - 最高频率和最低频率之差
  - 计算机网络指：
    - 在单位时间内从网络中某点到另一点能通过的“最高数据率”
    - 即网络设备支持的最高速度
- 吞吐量
  - 单位时间内通过某网络的数据量
  - 吞吐量一般 &lt; 链路带宽
- 时延
  - 发送时延、传播时延、处理时延、排队时延
  - 发送时延：
    - 又称：
      - 传输时延
    - 把数据包从节点发送到网络上所需要的时间
    - 计算：
      - 使用 “数据/信道带宽“ 来计算



        $\text{发送时延}=\frac{\text{分组长度（数据长度）}}{\text{信道宽度（发送速率）}}$

  - 排队时延：
    - 分组在进入路由器之后在输入队列中排队等待的时间
- 时延带宽积：
  - 指：
    - 发送端发送第一个bit到达终点时，发送端又发送了多少个bit
  - 又称：
    - 以bit为单位的链路长度
  - 公式：
    - 信道带宽 \* 传播时延
- 往返时延
  - 英文：
    - RTT
  - 概念：
    - 从发送方发数据到发送方收到接受方确认，所经历的时延
- 信道利用率
  - 有数据通过的时间占整个时间的百分数
- 考频：低
  - 无

## 计网分层

<a href="/images/408-mind-maps/cn-0062.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0062.svg" alt="计网分层" width="48" height="48" loading="lazy" /></a>

- 概念
  - 实体：
    - 第n层，就是第n层实体
    - 同层为对等实体
  - 协议：
    - 概念：
      - 为了进行网络中对等实体数据交换而建设的规则
    - 三大特点：
      - 语法：
        - 规定传输数据的格式
        - “要怎么做”
      - 语义：
        - 规定要完成的功能
        - ”要做什么”
      - 同步：
        - 规定各个操作的顺序
        - ”是什么时候做”
    - 概要：中文语境：你好，厕所在哪里？
      概要范围：[三大特点：](#topic-fd3ad2eb9cb9a1799f850b496f)

  - 接口：
    - 又称：
      - 访问服务SAP
    - 作用：
      - 上层使用下层服务的入口
  - 服务：
    - 注意：
      - 在一层内完成的全部功能并非都称之为服务
      - 只有那些能够被高一层实体“看得见”的功能才能称为服务。
        - 才能够被使用
    - 作用：
      - 下层为相邻上层提供功能调用
    - 四类：
      - 请求：
        - 用户-&gt;服务器，请求某项工作
      - 指示：
        - 服务器-&gt;用户，指示发生了是么事情
      - 证实：
        - 服务器 -&gt; 用户，对请求的证实
      - 响应：
        - 用户-&gt;服务器，对指示的响应
      - 楼楼举例：n+1去存钱，n是银行服务人员：
        - 存钱的人要去柜台存钱，他会说出他的请求给柜台服务人员，然后服务人员知道后，需要你的银行卡和存款金额现金等证件，指示你把银行卡和现金等证件给她，然后存钱的人根据柜台人员的指示，进行响应，把银行卡和现金等证件给柜台人员，最后柜台人员对你的请求进行处理，帮你存钱，给你一张凭据，证实我帮你处理了存钱操作等一些信息。
      - 概要：无应答服务只有这两个
        概要范围：[请求：](#topic-f97a3497d1cb82b70b1fc820ac)、[指示：](#topic-59cbb13462fb62dacb68da79d3)

  - SDU、PCI、PDU：
    - 配图

      <a href="/images/408-mind-maps/cn-0001.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0001.svg" alt="SDU、PCI、PDU：" width="240" height="59" loading="lazy" /></a>

      - 数据链路层还要加尾部
    - SDU：上层来的数据
    - PCI：本层的协议
    - PDU：本层的数据
  - 协议、接口、服务的关系
    - 相邻两层之间的关系

      <a href="/images/408-mind-maps/cn-0024.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0024.svg" alt="相邻两层之间的关系" width="240" height="88" loading="lazy" /></a>

- OSI模型：
  - 流程：
    - 应用层点击程序，表示层数据格式修改，会话层进行会话，传输层生成数据报找到port，网络层找到IP进行分组转发，数据链路层组装成帧，物理层进行透明bit传输。
  - 应用层
    - 作用：
      - 所有可以和用户交互产生流量的程序
      - 用户和网络交互的界面
      - 提供OSI环境
    - 协议：
      - FTP、SMTP、HTTP
  - 表示层
    - 作用：
      - 处理两个相同通信系统的交换信息表示方式
        - 语法和语义
      - 数据格式变化
      - 数据加密解密
      - 数据压缩和恢复
    - 协议：
      - JPEG、ASCII
  - 会话层
    - 作用：
      - 允许不同主机上的各个进程进行会话
      - 增值服务：在表示层进程上建立连接，并在连接上有序的传输数据
    - 功能：
      - 建立、管理、终止会话
      - 使用校验点会使会话从校验点、同步点继续恢复通信
    - 协议：
      - ADSP、ASP
  - 传输层
    - 作用：
      - 负责两个进程的通信，即端到端通信。
        - Port
    - 传输单位：
      - 报文段、用户数据报
    - 功能：
      - 1\. 可靠传输、不可靠传输
      - 2\. 差错控制
      - 3\. 流量控制
      - 4\. 复用分用
    - 协议：
      - TCP、UDP
  - 网络层
    - 作用：
      - 点到点传输，把分组（数据报）传到目的端
        - IP
    - 功能：
      - 1\. 路由选择
      - 2\. 流量控制
      - 3\. 差错控制
      - 4\. 拥塞控制
    - 协议：
      - IP、IPX、ICMP、IGMP、ARP、RARP、OSPF
  - 数据链路层
    - 作用：
      - 把网络层的数据组装成帧
    - 功能：
      - 1\. 成帧
      - 2\. 流量控制
      - 3\. 差错控制
      - 4\. 访问（接入）控制
    - 协议：
      - PPP、SDLC、HDLC、STP
  - 物理层
    - 作用：
      - 在物理媒体上实现透明传输，传输bit
    - 功能：
      - 1\. 定义接口特性
      - 2\. 定义传输模式
      - 3\. 定义传输速率
      - 4\. 比特同步
      - 5\. 比特编码
    - 协议：
      - Rj45、802.3

## 概念

<a href="/images/408-mind-maps/os-0150.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0150.svg" alt="概念" width="48" height="48" loading="lazy" /></a>

- 定义标准
  - 1\. 机械特性
    - 规定连接时候的规格、接口形状、引线数目、引脚数量等
    - 跟机械规格相关
  - 2\. 电气特性
    - 电压范围、阻抗匹配、传输速率、距离限制等
    - 通常都跟数字有关
  - 3\. 功能特性
    - 某条线上出现的某一电平表示何种意义
    - 说明“高电平” / “低电平”什么的
  - 4\. 规程特性
    - 也叫做过程特性。物理线路的工作规程和时序关系
  - 概要：语法
    概要范围：[1. 机械特性](#topic-83c871ee132a3632b8f65b68da)、[2. 电气特性](#topic-16482616d3c93016917b3a27f7)

  - 概要：语义
    概要范围：[3. 功能特性](#topic-ec6814add169b589f67dda7c7a)

  - 概要：同步
    概要范围：[4. 规程特性](#topic-73cbaabf9e4b61c71bc8cafbd3)

- 一个典型的数据通信模型
  - 配图

    <a href="/images/408-mind-maps/cn-0046.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0046.svg" alt="一个典型的数据通信模型" width="240" height="90" loading="lazy" /></a>

- 数据通信的相关术语
  - 数据、信号、信源、信宿、信道
    - 配图



      通信的目的是传送信息，包括语音、文字、图像、视频等。

      - **数据（data）**：传送信息的实体，通常是有意义的符号序列。
      - **信号**：数据的电气／电磁表现，是数据在传输过程中的存在形式。
      - **数字信号／离散信号**：代表消息的参数取值是离散的。
      - **模拟信号／连续信号**：代表消息的参数取值是连续的。
      - **信源**：产生和发送数据的源头。
      - **信宿**：接收数据的终点。
      - **信道**：信号的传输媒介，一般表示向一个方向传送信息的介质；一条通信线路往往包含一条发送信道和一条接收信道。

      信道的分类：按传输信号分为模拟信道和数字信道；按传输介质分为无线信道和有线信道。

      数据通信：不同计算机之间传输表示信息的二进制数 0、1 序列的过程。



- 三种通信方式
  - 1\. 单工通信
    - 只有一个方向的通信，仅需要一条信道<br>（广播）
  - 2\. 半双工通信/双向交替通信
    - 通信双方都可以发送/接受信息，但不可同时发送+接受，需要两条信道（对讲机）
  - 3\. 全双工/双向同时通信
    - 通信双方可以同时发送+接受信息，需要两条信道。（打电话）

- 传输速率
  - 码元传输速率
    - 单位时间内数字通信系统传输的码元个数（单位：波特Baud）
      - 码元个数又称：脉冲个数/信号变化次数
        - 注意电平如果从0跳到0，也算传输信号变化了一次变换
      - 注意：码元速率与进制无关，只与码元个数T有关
        - 码元速率是码元个数，和一个码元存了多少个bit信息是无关的。
      - 例：在2秒内传4800个码元，码元的传输速率是多少？
        - 答：2400B(Baud)
  - 信息传输速率
    - = 码元传输速率 \* 码元携带的bit数
    - 单位时间传输的bit的个数（单位b/s, bps）
  - 例题
    - 1\.
      - 注意算bit/Baud的时候需要先log2一下



        **例 1**：某数字通信系统传输四进制码元，4 s 传输了 8000 个码元。

        - 码元传输速率：$8000/4=2000\ \mathrm{Baud}$。
        - 信息传输速率：$2000\log_2 4=4000\ \mathrm{b/s}$。

        **例 2**：另一通信系统传输十六进制码元，6 s 传输了 7200 个码元。

        - 码元传输速率：$7200/6=1200\ \mathrm{Baud}$。
        - 信息传输速率：$1200\log_2 16=4800\ \mathrm{b/s}$。

        比较：十六进制系统的信息传输速率更快。



    - 2\.
      - 已知八进制数字信号的传输速率为1600B。 试问变换成二进制数字信号时的传输速率是多少？
        - 4800b/s
        - 数字信号变成不同的进制，波特率变化，传输速率不会发生变化
      - 已知二进制数字信号的传输速率为2400b/s。试问交换成四进制数字信号时，传输速率为多少波特？
        - 1200B

## 奈氏准则 &amp; 香农定理

<a href="/images/408-mind-maps/cn-0085.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0085.svg" alt="奈氏准则 &amp;amp; 香农定理" width="48" height="48" loading="lazy" /></a>

- 考频：中
  - 09、11、17
- 失真
  - 何为失真：
    - 产生误差就是失真（失真可以分为仍可识别和不可识别）
  - 影响失真的因素
    - 码元传输速率（越快越严重）
    - 信号传输距离（越远越严重）
    - 噪声干扰
    - 传输媒体质量
  - 码间串扰
    - 信道带宽
      - 模拟信号的带宽：最高频率 - 最低频率

        <a href="/images/408-mind-maps/cn-0139.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0139.svg" alt="模拟信号的带宽：最高频率 - 最低频率" width="240" height="139" loading="lazy" /></a>

        - 200Hz无法通过：
          - 频率太低，可能会衰减没掉
        - 4000Hz无法通过：
          - 震动太快了，区分不出波形差异（码间串扰）
    - 概念：接受端收到的信号波形失去了码元之间清晰界限的现象
- 奈氏准则<br>（码元）

  - 相位、振幅
    - 故数据可能情况为： 相位 \* 振幅



      $x=A\sin(\omega t+\varphi),\qquad \omega=\frac{2\pi}{T}=2\pi f$

      - $A$：振幅。
      - $\omega$：圆频率。
      - $\varphi$：初相位。
      - $\omega t+\varphi$：相位。



  - 前提：
    - 理想低通 + 无噪
  - 概念：
    - 在理想（无噪声）低通（带宽受限）条件下，为避免码间串扰，极限码元传输速率是2W Baud，W是信道带宽，单位是Hz
      - 考试中：会强调说带宽是多少Hz（那就说明是模拟信号，而不是数字信号 - bps）
  - 公式：
    - 奈氏定理，注意⚠️一定要在【理想低通/无噪声情况下的】



      $极限传输率 = 2Wlog_2V(b/s)$

      - 引申： 奈氏 &amp; 最大采样的 关系



        **原图中的疑问**：如果把最大数据传输速率与采样速率直接比较，为什么带宽为 $W$、码元有 $V$ 种变化时，奈氏公式会出现 $2W\log_2V$？

        区分单位即可：

        - 采样频率／码元速率涉及每秒样本数／码元数。
        - 信息传输速率涉及每秒比特数。
        - 理想低通信道的奈氏码元速率上限为 $2W$ Baud；每个码元携带 $\log_2V$ bit，所以信息速率上限为 $2W\log_2V$ bit/s。

        原图回复的核心是区分这些速率。还应区分采样定理的最低采样频率要求与奈氏准则的码元速率上限，不能把它们当成同一个上限。



      - 批注：V是码元是进制数
  - 采样率 &amp; 带宽：
    - 采样率是带宽的两倍
  - 推论/考点
    - 1\. 奈氏准则规定的在已知W和V的情况下得知的码元传输速率，其中W、V是可以调整的。<br>2. 信道的频率带宽（即W）越高，奈氏依然是2W，不过换算到bit过后就变高了。



      1. 在任何信道中，码元传输速率都有上限；超过上限会发生严重的码间串扰，使接收端对码元的正确识别成为不可能。
      2. 信道频带越宽，即能通过的高频分量越多，就可以用更高速率有效传输码元。
      3. 奈氏准则给出了码元传输速率的限制，但没有直接限制信息传输速率。
      4. 若要求码元传输速率超过奈氏准则给出的上限，需要改善信道条件；若要在给定码元速率下提高信息传输速率，可使每个码元携带更多比特，并采用多元调制。

      > 整理说明：原图第4条把提高信息传输速率与突破码元速率上限混写；明确区分二者。



  - 练习题 09真题
    - 信号携带的信号量 = 相位数 \* 振幅数



      **例题**：在无噪声情况下，某通信链路带宽为 3 kHz，采用 4 个相位、每个相位有 4 种振幅的 QAM 调制，问最大数据传输率。

      信号状态数：$4\times4=16$。

      $R_{\max}=2\times3\,\mathrm{kHz}\times\log_2 16=24\,\mathrm{kb/s}$

- 香农定理<br>（bps）

  - 信噪比
    - S/N是信号平均功率/噪声的平均功率，用分贝（dB）作为度量单位



      $信噪比(dB) = 10log_{10}(S/N)$

      - 考试说S/N和dB都是信噪比
  - 概念
    - 在带宽受限(W)其有噪声(S/N)，为了不产生误差，数据传输速率的上限(bps)



      **香农定理**：在带宽受限且有噪声的信道中，为避免误差，信息的数据传输速率存在上限。

      $C=W\log_2(1+S/N)\quad(\mathrm{b/s})$

      - 一般考试会告诉你dB，需要自己算S/N
  - 推论/考点
    - 配图



      1. 信道带宽或信噪比越大，信息的极限传输速率越高。
      2. 对于一定的传输带宽和一定的信噪比，信息传输速率的上限是确定的。
      3. 只要信息传输速率低于信道的极限传输速率，就存在实现低差错率传输的编码方法。
      4. 若实际信道带宽有限而信噪比可无限提高，理论上的极限传输速率可不受限。
      5. 从香农定理可看出，带宽 $W$ 或信噪比 $S/N$ 不变时，对应条件下的极限信息传输速率不会因单纯换编码而突破。



      - 如何提高
      - 无差错传输
      - 实际信道传输速率
- ‘Nice’ vs ‘香浓’
  - V = 2, S/N = 127, W = 4k



    |比较项|奈氏准则|香农定理|
    |---|---|---|
    |条件|带宽受限、理想无噪声信道|带宽受限且有噪声的信道|
    |码元速率限制|理想低通信道为 $2W$ Baud|不直接用此式给出码元速率限制|
    |极限信息速率|$2W\log_2V$|$W\log_2(1+S/N)$|
    |提高信息速率的方向|增加带宽或每码元状态数|增加带宽或信噪比|

    **例题**：二进制信号在信噪比为 127、带宽为 4 kHz 的信道上传输，最大数据速率是多少？

    - 奈氏准则：$2\times4000\times\log_2 2=8000\ \mathrm{b/s}$。
    - 香农上限：$4000\times\log_2(1+127)=28000\ \mathrm{b/s}$。
    - 两个条件同时成立时取更严格限制：**8000 b/s**。

      典型例子是对音频信号进行编码的脉码调制（PCM）。原图说明 PCM 被广泛应用于音乐 CD、DVD 以及 WAV 文件等场景，主要包括**抽样、量化、编码**。



  - 步骤：
    - 配图



      PCM 的三个步骤：

      1. **抽样**：按信号周期性扫描，把时间连续、幅度连续的信号转换为时间离散、幅度仍连续的信号。为使所得离散信号无失真地代表模拟数据，采样频率满足 $f_{\text{采}}>2f_{\max}$。
      2. **量化**：把抽样所得电平按一定分级标度转换成对应数字值并取整数，把连续电平幅度转换为离散数字量。
      3. **编码**：把量化结果转换为相应的二进制编码。



      - 为何要？



        $f_{采} > 2f_{max}$

## 数据的交换方式

<a href="/images/408-mind-maps/os-0021.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0021.svg" alt="数据的交换方式" width="48" height="48" loading="lazy" /></a>

- 考频：中
  - 10、13、17
- 三大数据交换方式
  - 电路交换<br>(Circuit)
    - 步骤
      - 1\. 建立连接<br>（呼叫/电路建立）
        - 1\. 在交换设备中使用【路由选择算法】去找是发个【下一个交换设备】还是发给【下一个路由器】<br>2. A发送呼叫后，B如果接受到了请求，会原路返回去应答主机A

          <a href="/images/408-mind-maps/cn-0140.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0140.svg" alt="1. 在交换设备中使用【路由选择算法】去找是发个【下一个交换设备】还是发给【下一个路由器】 2. A发送呼叫后，B如果接受到了请求，会原路返回去应答主机A" width="240" height="64" loading="lazy" /></a>

      - 2\. 通信<br>（数据传输）
      - 3\.  释放连接<br>（拆除电路）
        - 与建立连接类似，最后【不返回】

          <a href="/images/408-mind-maps/cn-0054.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0054.svg" alt="与建立连接类似，最后【不返回】" width="240" height="62" loading="lazy" /></a>

    - 特点
      - 【独占资源】，占用端到端的固定传输带宽。适用于远程处理信息系统或者系统间【实时性要求】高的【大量数据】的传输的情况。
    - 优缺点
      - 配图



        **电路交换的优点**

        - 传输时延小。
        - 数据顺序传送，无失序问题。
        - 实时性强：双方一旦建立物理通路即可实时通信，适合交互式会话。
        - 全双工通信，双方使用不同信道，不争用物理信道。
        - 适用于模拟信号和数字信号。
        - 控制简单，交换设备及控制较简单。

        **电路交换的缺点**

        - 建立连接时间长。
        - 线路独占，即便空闲也不能供其他用户使用，信道使用效率低。
        - 灵活性差：连接路径任一点故障后需要重新建立连接，不适合突发通信。
        - 无数据存储能力，难以平滑通信量。
        - 数据直达，不同类型、规格和速率的终端难以互通。
        - 难以在传输过程中进行差错发现与纠正。



  - 报文交换<br>(Message)
    - 报文定义：
      - 报文：网络中交换和传输的数据单元，即站点【一次性要发送的数据块】，长度不一致
    - 报文格式：
      - 报头 + 信息
        - 报头中有：原IP地址+目的IP地址+封装信息 等
    - 基本原理：
      - 存储转发
    - 发送流程
      - 配图

        <a href="/images/408-mind-maps/cn-0020.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0020.svg" alt="发送流程" width="240" height="138" loading="lazy" /></a>

    - 优缺点
      - 配图



        **报文交换的优点**

        - 无需建立连接，无建立连接时延，用户可随时发送报文。
        - 动态分配线路、动态选择报文通过的最佳路径，可以平滑通信量。
        - 提高线路可靠性：某条路径发生故障时，可以重新选择另一条路径。
        - 提高线路利用率：通信双方在不同时间一段一段地部分占有物理通道，多个报文可共享信道。
        - 提供多目标服务：一个报文可以同时发往多个目的地址。
        - 存储转发中容易实现代码转换和速率匹配，甚至收发双方可以不同时处于可用状态，便于不同类型、规格和速度的计算机之间通信。

        **报文交换的缺点**

        - 实时性差，不适合实时或交互式业务。数据进入交换结点后经历存储转发过程，引起转发时延。
        - 只适用于数字信号。
        - 报文长度不受限制，每个中间结点都要完整接收整个报文；输出线路忙时还可能要缓存多个完整报文，因此要求较大的缓冲区。为了降低成本、减少缓冲存储器容量，有时把等待转发的报文存入磁盘，进一步增加传送时延。



  - 分组交换<br>(Packet)
    - 分组的大小：
      - 分组交换和报文交换很类似，分组交换网中【限制了所传输的数据单位的长度】，一般是128B
    - 分组的组成部分：
      - 分组 = 小数据块 + 控制信息（源、目的地址、编号）
    - 优缺点
      - 配图



        **分组交换的优点**

        - 数据报服务无需预先建立专用通信线路，用户可随时发送分组。
        - 线路利用率高：通信双方在不同时间部分占用物理通道，多个分组可共享信道。
        - 简化存储管理：教材模型采用定长分组时，缓冲区大小固定，存储器管理可简化为缓冲区管理。
        - 加速传输：后一个分组的存储可以与前一个分组的转发并行；单个分组需要的缓冲空间比完整报文小，减少等待发送时间。
        - 减少一次出错所涉及的重发数据量，提高可靠性并减少传输时延。
        - 分组短小，适合计算机间突发式数据通信。

        **分组交换的缺点**

        - 仍有存储转发时延，结点交换机需要较强处理能力。
        - 每个分组携带控制信息，降低有效载荷占比并增加处理时间。
        - 数据报服务可能出现失序、丢失或重复，目的结点需要按编号整理；虚电路服务通常保持有序，但有连接建立、数据传输和释放三个过程。

        注：原图把“分组交换无建立时延”和“分组长度固定”笼统用于所有分组交换；此处明确其服务类型及教材模型前提。



- 数据交换方式的选择
  - 配图

    <a href="/images/408-mind-maps/cn-0154.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0154.svg" alt="数据交换方式的选择" width="240" height="179" loading="lazy" /></a>

    - 1\. 数据量大，传输时间远大于呼叫时间：
      - 电路
    - 2\. 端到端的通路有很多段的链路组成：
      - 分组
    - 3\. 要信道利用率高：
      - 分组&amp;报文 &gt; 电路
        - 回顾什么是信道利用率
    - 4\. 传输时延最小
      - 电路
    - 5\. 传输通信效率高（报文短）
      - 电路

  - 数据报方式

    <a href="/images/408-mind-maps/cn-0118.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0118.svg" alt="数据报方式" width="240" height="93" loading="lazy" /></a>

    - 步骤
      - 1\. 源主机把报文分成多个分组
      - 2\. 结点收到分组后，会进行【差错检测】和【路由选择】
      - 3\. 【差错检测】返回ACK信息给上一个结点，如果正确，上一个结点就把分组【副本丢弃】
    - 特点
      - 和分组交换一样
  - 虚电路方式

    <a href="/images/408-mind-maps/cn-0034.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0034.svg" alt="虚电路方式" width="240" height="203" loading="lazy" /></a>

    - 步骤：
      - 1\. 在发送方和接收方建立一条逻辑上连接的虚电路，【一旦建立，就固定了对应的物理路径】
      - 2\. 进行数据的传输
      - 3\. 发送方接受到接收方的ACK后，对虚电路进行拆除
    - 虚电路的数据格式：
      - 分组号、校验、etc
      - 概要：一定要指明虚电路号
        概要范围：[分组号、校验、etc](#topic-b09aa7d4-c566-4952-adaa-eceeea445f62)

    - 特点：
      - 建立链路需要时间
      - 路由选择体现在连接建立阶段
      - 提供可靠的通信功能，分组可以有序到达，也可以对两个数据端点进行流量控制
      - 致命的弱点：一旦有一个节点或某条链路故障失效，所有经过该节点/链路会被破坏
    - 超纲：
      - 虚电路的链接分为永久性和交换性的（王道课后）



        虚电路连接可以是**永久虚电路（PVC）**，也可以是**交换虚电路（SVC）**。原图以电话业务作类比：前者相当于一直提前约定好的连接，后者类似一次呼叫期间建立的临时连接，在请求建立连接时建立、会话结束或取消连接时释放。

        原图以电话类比虚电路的生命周期；虚电路本身是逻辑连接，不能据此理解为独占物理线路。



  - 对比



    |比较项|数据报服务|虚电路服务|
    |---|---|---|
    |连接的建立|不需要|必须建立|
    |目的地址|每个分组都有完整目的地址|建立连接时使用目的地址，之后分组使用较短虚电路号|
    |路由选择|每个分组独立选择路由和转发|同一虚电路中的分组沿同一路由转发|
    |分组顺序|不保证有序到达|保证有序到达|
    |可靠性|不保证可靠通信，由用户主机保证可靠性|教材虚电路模型由网络保证可靠性|
    |对网络故障的适应性|故障结点丢失分组，后续分组可改选路径继续传输|经过故障结点的虚电路不能正常工作|
    |差错处理与流量控制|用户主机负责，不保证数据报可靠性|可由分组交换网或用户主机负责|

## 流量控制（算）

- 考频：超高

  - 都是发完一帧开启一个计时器

  - 滑动窗口如何算完美：

      - 此时接收方收到0怎么办

  - 只有帧的序号落入接收窗口范围内才可以接受，否则就抛弃
- 停止等待协议
  - 信道利用率极低
    - 发送、接受窗口数 = 1
  - ACK0 + ACK1 就足够了
  - 发送方和接受方都需要设置一个帧缓冲区
    - 作用：发送方发送完帧后，必须在缓存中保留此数据的帧副本，只有收到ACK时才可以丢弃
- GBN协议<br>(累计确认)
  - 总窗口数：N，发送窗口数：N-1，接受窗口数 ： 1
  - 帧序列号n位，则发送窗口大小 &lt;= 2^n - 1
    - 为什么呢：例如窗口大小为4编号从0~3，则第一批0~3成功发送，接收方也返回了ACK3，那么下一轮发送的就应该是0~3。可是，如果这个ACK3丢失了，那么接收方就不知道发送方又发一遍了吗
  - 收到 ACK n，说明 n 帧以前的都收到了
    - 期待收到seq = n+1，也有可能n+1 = seq = 0
  - 若信道传输质量差 + 误码率大时， GBN还不如停等协议
- SR协议
  - 总窗口数：N，接受窗口数可以&gt;1。当发送窗口数 = 接受窗口数时效率最高
  - 帧序列号n，则发送窗口大小 &lt;= 2^(n-1)
    - 原因：考虑到接受的所有ACK都丢失了 -&gt; 发送窗口不动，接受窗口已经移动了一组，所以这两个相邻的帧必须不存在任何重复的编号
  - 收到 ACK n，说明只有第n帧都收到了
  - 如果接受方怀疑帧出错，就返回一个NAK n给发送端，发送端重传
    - NAK会指定要重传哪个帧

## 介质访问（算）

- 信道划分（静态）
  - FDM 频分多路复用（模拟信号）
    - 是将基带信号（数字信号）调制到模拟信号进行传输的
    - 共享时间
    - 相邻信道间加入”保护频段”
  - TDM 时分多路复用（数字信号）
    - 共享空间，把时间段的某个固定位置分配给固定的帧
      - 如果不用就会很浪费
    - STDM---统计时分复用，动态分配时隙（不停的问，来就上车）
  - WDM
    - 光的频分多路复用
  - CDM
    - 采用不同的编码方式来进行区分原始信号的一种复用方式
    - CDMA
      - 采用补码方式进行码片序列的设置
      - 例：一共有4个站点，使用8位数据来设置码片序列
        - 如果有n个站点，则码片序列位数应该&gt;=n
        - n维空间，最多有n个线性无关的向量
      - 步骤：
        - 发送
          - 1\. 每个站点都有一个相互正交的码片序列
            - 空间中多个相互正交的向量
          - 2\. 站点如果想要发送1，就发送(+序列)，如果想要发送0就发送(-序列)
            - 用投影后为1、-1的向量来表示数据
          - 3\. 公共信道将所有的站点数据累加在一起
            - 将多个正交向量相加，其投影性质不会发生变化
          - 4\. ....发送中....
        - 接受
          - 1\. 公共信道收到一个码片序列
            - 收到一个向量
          - 2\. 码片序列和每一个站点的码片序列做点乘
            - 使用投影对向量进行每个向量轴的分解
          - 3\. 如果点乘结果是1，就说明发送了1给该站点。如果点乘结果是-1，就说明发送了0给该站点。如果点乘结果是0，说明没有发送给该站点的数据。
            - 根据投影结果得知数据
- 随机访问（动态）
  - ALOHA
    - 收到就发

    - 发送策略：
      - 拿到就发
    - 冲突策略：
      - 发现冲突，等待一个随机时间在重发，重次往复
    - 最大吞吐量：0.184



      $S = Ge^{-2G}, G = 0.5$

  - 时隙ALOHA
    - 收到等一会就发

    - 发送策略：
      - 固定有一个时隙T0，帧到达后在缓存中等待一个&lt;T0的时间，然后等到下一个时隙开始再发
    - 冲突策略：
      - 和ALOHA一样
    - 最大吞吐量：0.368



      $S = Ge^{-G}, G = 1.0$

  - CSMA
    - 先听再发，发完不管

    - Carrier Sense Multiple Access<br>载波侦听多路访问
    - 策略
      - 三种坚持CSMA
        - 1-坚持
        - 非坚持
        - p坚持
      - 监听策略：
        - 忙就一直听
        - 忙就放弃听，过一会再来
        - 忙就一直听
      - 发送策略：
        - 空闲就发
        - 空闲就发
        - 空闲有p的概率发送，有1-p继续监听
      - 冲突策略：
        - 都和ALOHA一样
    - 特点：
      - 发送时，仍有可能会冲突
  - CSMA/CD
    - 全程都听

    - 记一个重要公式
      - 最小帧长 = 2 \* 传播时延 \* 传输速率
        - 其中 传播时延 = 总线长度 / 电磁波的发送速率
      - 公式



        $L_帧 = 2* v_传 * t_线\ (t_线 = \frac{L_线}{v_{电磁波}})$

    - 先听后发，边听边发，冲突停发，随机重发
      - 争议期（冲突窗口、碰撞窗口）：最远两端点之间的往返时延
      - 如果第一个分组没有发生碰撞，就说明抢占信道成功了。
    - 计算最短帧长
      - 要在发送完前检测到碰撞信号
    - 重发算法：
      - 使用二进制指数退避算法
        - 从 1-10，最多16次，等待时间为2t\*k，k为 0~2^n - 1（n从1-10，后一直为10）的数
          - t即为争议期
          - 超过16次，抛弃该数据帧，向上层汇报
    - 用于有线网，如：以太网的数据
      - 51.2us是征用期
      - 速度10Mb/s
      - 64B是最短帧长
    - 概要：记住
      概要范围：[用于有线网，如：以太网的数据](#topic-dc2892d8f7c89502105e490fc0)

    - 发送前预约信道

- 令牌环网
  - 轮询邀请 + 令牌传递
  - 步骤：

      - 令牌只有一个，令牌一直询问
    - 2\. 站点想要发送数据，必须先收到令牌。
      - 发送含有目的地址等数据的一个帧
    - 3\. 帧在环上传送时，所有站点都会进行转发。
      - 如果目的站点收到了，就先在帧尾部设置一个“响应比特”来指示收到了。然后再转发（所以目的站点会先接受帧，然后创建一个帧+尾部的副本进行转发）

## 广域网

- 因特网是世界上范围最大的广域网
- 特点：
  - 广域网是连接众多局域网的网络

    <a href="/images/408-mind-maps/cn-0049.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0049.svg" alt="广域网是连接众多局域网的网络" width="240" height="78" loading="lazy" /></a>

  - != 互联网，互联网=广域网+局域网
  - 广域网采用【结点交换机】在单个网络中转发分组，功能很类似路由器
  - 采用存储转发
    - 局域网是广播
- 广域网和局域网的区别：
  - 连接到同一个广域网的主机只需要使用【物理地址】进行通信（互联网需要IP）



    |比较项|广域网|局域网|
    |---|---|---|
    |覆盖范围|很广，通常跨区域|较小，通常在一个区域内|
    |连接方式|结点之间为点到点连接；为提高可靠性，一个结点交换机往往与多个结点交换机相连|普遍采用多点接入技术|
    |OSI 参考模型层次|物理层、数据链路层、网络层|物理层、数据链路层|
    |着重点|强调资源共享|强调数据传输|

    联系与相似点（原图表述）：

    1. 广域网和局域网都是互联网的重要组成构件；从互联网角度看，二者平等，不是包含关系。
    2. 连接到一个广域网或一个局域网的主机在该网内通信时，只需要使用其网络的物理地址。



- 广域网的数据链路层协议：
  - PPP和HDLC
- PPP协议
  - 应用在直连的两个节点的链路上，目的是通过拨号 or 专线方式进行点对点的传输
  - PPP帧和以太网帧、HDLC帧都是不一样的，只有信息部分是一样的
    - PCI不一样
  - 位置：
    - 两个路由器之间的帧数据可以是PPP帧

      <a href="/images/408-mind-maps/cn-0086.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0086.svg" alt="两个路由器之间的帧数据可以是PPP帧" width="240" height="63" loading="lazy" /></a>

      - 但如果两个路由器之间有一个交换机，则一定不是PPP帧而是以太网帧

        <a href="/images/408-mind-maps/cn-0038.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0038.svg" alt="但如果两个路由器之间有一个交换机，则一定不是PPP帧而是以太网帧" width="240" height="91" loading="lazy" /></a>

  - 特点：
    - 简单！

    - 数据链路层的帧：不提供纠错，只保证无差错接受（用CRC），不可靠即报告上层
      - 无需纠错、无需序号、无需流量控制
    - 只支持全双工
    - 点到点式传输
    - 面向字节的协议：
      - 1\. 帧格式以一个Byte作为最小单位
      - 2\. 定界符（转义字符）保护也是通过加一个Byte的7D
    - 两端可以用不同的网络层协议，但仍然可以同一PPP
    - 概要：面向字节即不可使用奇偶校验、零比特填充法等
      概要范围：[面向字节的协议：](#topic-1524bf6d-60df-4848-a664-41854f4f3e26)

  - PPP帧格式
    - 配图

      <a href="/images/408-mind-maps/cn-0089.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0089.svg" alt="PPP帧格式" width="240" height="76" loading="lazy" /></a>

      - A字段是Address，但是PPP帧是点对点的，不需要说明地址信息，所以A字段就是无用字段
      - 例如协议是0x21，就是IP数据报
      - FCS是只有16bit，检验【F、A、C、协议、信息】
  - 组成部分：
    - LCP：链路控制协议
      - 用于身份验证，建立配置测试管理链路等
        - 等于是建立了物理连接
    - NCP：网络控制协议
      - 因为PPP协议可以支持非常多的网络层协议，所以每一个网络层协议都应该有一个NCP来进行负责
        - 等于是建立了逻辑连接
    - 把IP数据报封装为PPP帧发到串行链路上
  - PPP协议的工作流程：
    - 配图

      <a href="/images/408-mind-maps/cn-0002.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0002.svg" alt="PPP协议的工作流程：" width="240" height="142" loading="lazy" /></a>

      - 简单来讲就是：你点击上网，最开始是没有链路的。
      - 1\. 在物理层上建立连接，此时还不算完全连接成功
      - 2\. 在连接的基础上建立LCP链路
      - 3\. 在LCP链路的基础上建立NCP链路
- HDLC协议
  - HDLC协议的站
    - 主站、从站、复合站
    - 主站：
      - 负责控制链路的制作，主站的帧是命令帧
    - 从站：
      - 受控于主站，按主站命令进行操作，可以发出响应帧
    - 复合站：
      - 可以发出命令帧和响应帧
    - 概要：+ = 复合站
      概要范围：[主站：](#topic-f196dd21-0104-45e5-a4ab-13e29ee8a436)、[从站：](#topic-6d2e9b6e-de22-4a8c-9ed3-d08d14aa0fe9)

  - 特点：
    - 面向比特
      - 使用5110的“0比特插入法”
    - 全双工
    - 所有信息帧都采用CRC校验，要编号，可以防止漏发重发，支持可靠传输
  - 两种配置：
    - 非平衡配置
      - 由一个主站来控制整个链路
    - 平衡配置
      - 链路两端的两个站都是复合站，每个复合站都可以平等地发起数据传输
  - 三种操作：
    - 正常响应方式：
      - 非平衡，主站传输，从站响应
    - 异步平衡方式：
      - 每个复合站都可以传输
    - 异步响应方式：
      - 非平衡，从站未受主站允许也可以传输
  - HDLC帧格式：
    - 配图

      <a href="/images/408-mind-maps/cn-0136.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0136.svg" alt="HDLC帧格式：" width="240" height="85" loading="lazy" /></a>

      - 控制C：
        - 无编号帧（U)
          - 第1、2位为1，用于建立、拆除链路
        - 监督帧（S)
          - 第1、2位为1、0，用于流量控制等等
        - 信息帧（I)
          - 第一位为0，用来传输数据信息
            - 或者使用捎带技术对信息进行确认
      - 监督帧说明是不是确认帧、应答帧
      - 信息帧说明是不是数据帧（也可以捎带确认）

- 网桥
  - 把两个或多个以太网通过网桥连接
    - 多个以太网内的物理协议可以不同
    - 不同MAC子层的网段连接在一起，需要进行帧格式的转化
  - 网桥工作在MAC子层，可以使以太网各网段成为隔离开的碰撞域
  - 使用网桥可以提高整个网络的数据率
  - 优点：
    - 可以过滤通信量
      - 可以连接不同类型的局域网
  - 缺点：
    - 增大了时延
      - MAC没有流量控制
        - 传播过多的信息可能引起广播风暴
- 网桥路径<br>选择算法
  - 透明网桥
    - 即插即用，自学习算法
      - 选择的不是最佳路由
    - 算法：
      - 转发表内容
        - 源地址、进入的端口、进入时间
      - 算法步骤
        - 接受一切广播到该网桥的数据帧
        - 工作原理
          - 接受到的帧如果
          - 1\. 源地址和目的地址一样，丢弃
          - 2\. 目的地址转发表中有，则从对应端口转发
          - 3\. 目的地址没有，则扩散本帧
        - 1\. 初始时刻转发表为空
        - 2\. 记录本帧的（源地址 + 进入的端口 + 时间）到转发表中
        - 3\. 如果帧的目的地址有了，就可以发送了
        - 定期清理里面的地址，时间过长的就清理
      - 问题：
        - 可能存在“兜圈子”情况，透明网桥采用了一种无环的生成树算法，以保证不会成环
  - 源路由网桥
    - 选择的是最佳路由
    - 算法：
      - 源站向目的站广播一个【发现帧】，目的站收到后，进行原路径返回，返回途经的网桥都把自己标记在应答帧中。
        - 源节点根据众多返回的帧来确定最佳路由
    - 发现帧可以帮助源站确定整个网络可以通过的最大帧长
    - 问题：
      - 如果发现帧太多了，会导致网络拥塞
- 局域网交换机
  - 又称：以太网交换机
  - 特点：
    - 使用VLAN来进行冲突域和广播域的隔离
    - 直接连主机，全双工
    - 即插即用
    - 有许多对端口，相互通信的主机可以无碰撞的传输数据
    - 有专用的传输芯片
    - 独占传输媒体带宽
  - 两种交换模式：
    - 1\. 直通式
      - 只检测目的地址，接受后立马传出去
      - 延迟小、可靠性低、无法支持不同速率的端口交换
    - 2\. 存储转发式
      - 先将帧存储在高速缓存器中，进行数据正确性检测，发现无误后传输，否则丢弃
      - 延迟大、可靠性高、支持不同速率的端口交换

  - 网络互联
    - 把两个以上的计算机网络相互连接起来，通过多个中间设备（中继系统）构成更大的网络
      - 批注：网络层可以把不同广播域的网络连起来

      - 网络层
        - 路由器
      - 网络层以上
        - 网关
      - 概要：在网络层的视角中，这两种只是把一个网络给扩大了
        概要范围：[物理层](#topic-13ff990d-6e98-42fa-80c3-6e86fc77fb28)、[数据链路层](#topic-693431b0-d3db-49a0-8461-a07bea169748)

  - 虚拟互联网络

    - 网络中出现了过量的分组导致网络性能下降
  - 判断拥塞的方法：
    - 轻度拥塞
      - 网络负载增加，网络的吞吐量【明显小于】正常的吞吐量
    - 拥塞状态
      - 吞吐量【随着负载增大而下降】
    - 死锁状态

      - 事先不考虑各种因素，用检测网络去监视，及时检测

  - 单位总结：
    - 一种首饰八片
    - 总长度：1B

  - MF：More Fragment 还有分片
    - DF：Dont Fragment 不分片
  - 标识：
    - 源主机在发送数据报时设定的“ID”，来一个数据报，标识++（数据报分片后，每个数据报都是相同的标识）
  - 片偏移的单位是8B，所有分片长度都是8B的整数
    - 首部20B，1480/8=185，刚好可以够分
    - 最后一片可以不是8B整数
  - TTL生存时间
    - 是一直在减少的，减到0就丢弃
    - 每次转发TTL都要 -1，当TTL = 0，丢弃
  - 这里的FCS只有16bit（因为只检查首部）

    - 概要：此处显得IPv4的检错功能不那么重要了（IPv6删去了该内容）

## 路由转发

<a href="/images/408-mind-maps/cn-0032.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0032.svg" alt="路由转发" width="48" height="48" loading="lazy" /></a>

- 考频：超高
  - 10\*2、11、12\*3、15、16-18\*2、19、21-22\*2、15大、18大、20大、22大
- 路由器本身可以有多个IP地址+多个MAC地址
- 路由器的分组转发算法
  - 已知：目的网络N，目的主机IP地址D
  - NAT的路由分组转发步骤
    - 1\. NAT路由器会维护一个LAN中IP和Port同样对应着WAN中的一个IP和Port
    - 2\. 数据帧封装好自己LAN的IP、端口以及目的网络中WAN对应的IP、端口，发送到NAT路由器
    - 3\. NAT路由器转为WAN的IP，转发
    - 如果接受到WAN的，NAT就把WAN的转为LAN的，然后放到LAN中传输
      - 如何传输，请看ARP
        查看关联主题（原图链接目标缺失：`xmind:#b3b4e1fb-b3fc-4dd5-96b9-ce72e4452bd5`）

  - 对于同一个网段内的主机（子网的掩码相同），一般情况下都是可以进行IP通信的，与其默认网关无关
    - 默认网关：
      - 如果一台主机找不到正确的网关，就把数据报发给默认网关
      - 配置默认网关
        - 手动配置
          - 考试喜欢考
        - DHCP配置
          - 详情看下面
    - 一个主机的默认网关没有正确填写：<br> 1. 无法进入互联网进行信息交流<br>2. 可以和在同一个网关的主机进行IP交换（局域网广播）
  - 概要：NAT中涉及到了port端口，故NAT是工作在传输层的
    概要范围：[NAT的路由分组转发步骤](#topic-bc4b1924dee8f554ee3a9a2a7e)

- 路由分组转发算法（子网掩码）

  - 获得IP -&gt; 对比子网集 -&gt; 查路由表特殊通道 -&gt; 查路由表其他IP -&gt; 发给默认网关 -&gt; TTL = 0就丢弃并返回ICMP
  - 1\. 路由器【提取】出目的IP地址（从IP报文段中提取）
  - 2\. 路由器【按位与查看】自己的全部子网，看能不能直接【直接交付】
    - 就是查看是不是对应的那个子网
  - 3\. 路由器【按位与查看】自己路由表是否存在这个IP的【特定主机】
    - 看能不能走特殊通道
  - 4\. 路由器【按位与查看】自己的路由表中的所有其他IP路径，看能不能【发给对应的路由器】处理
  - 5\. 路由器发现上面的步骤都行不通，那就发给自己的【默认网关】处理
  - 6\. 如果TTL=0，或者默认网关出错，就丢弃该数据，直接返回ICMP回去
- ARP
  查看关联主题（原图链接目标缺失：`xmind:#980af23a-a8e3-48da-92b8-04d2ed7f38fc`）

  - Address Resolution Protocol 地址解析协议
    - 记住英文可以知道协议的作用
  - 每个主机都会存有一个高速缓存ARP表
    - ARP表：IP地址 --- MAC地址的映射表
  - 若A向B发送信息，工作流程：
    - 查找A的ARP是否有B的IP地址（有了IP就也硬件MAC地址）
      - 如果【有】IP地址，那么就把B的硬件地址写入到MAC帧里面，然后使用局域网把该MAC帧发给B。

      - 如果【没有】IP地址，那么就广播一个【ARP请求分组】（其中MAC地址为【FF-FF-FF-FF-FF-FF】），让局域网内的所有其他主机都收到ARP请求，然后主机继续转发

        - 如果B收到了ARP请求，就单播返还一个【ARP响应分组】回去，告诉主机A自己的IP和MAC地址
          - 其他主机收到【ARP响应】后，也会把B的IP和MAC建立在ARP高速缓存中。
        - 批注：MAC广播地址：FF-FF-FF-FF-FF-FF
    - 主机A收到响应分组后，写入到自己的ARP片中，然后发送MAC帧
    - 配图

      <a href="/images/408-mind-maps/cn-0077.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0077.svg" alt="若A向B发送信息，工作流程：" width="240" height="97" loading="lazy" /></a>

  - 所以ARP请求是广播的，ARP响应的单播的
  - 总结四种情况
    - 主机➡️本网内主机
      - 用ARP找目的主机地址
    - 主机➡️外网主机
      - 用ARP找本网的路由器硬件地址
        - 一定是NAT路由器
        - 这个路由器的IP地址就是本主机的默认网关
    - 路由器➡️本网内主机
      - 用ARP找目的主机地址
    - 路由器➡️外网主机
      - 用ARP找本网的另一个路由器的硬件地址
  - RARP
    - 通过MAC逆查找IP
      - DHCP中已经有这个技术了
- DHCP
  - Dynamic Host Configuration Protocol
    - 动态主机配置协议
  - 处于应用层，基于UDP，动态的给每个主机分配IP地址，即插即用
  - 使用客户/服务端方式工作
  - 工作原理
    - 广播【DHCP发现】问所有服务器
      - 可以存在多个DHCP服务器
    - 所有收到【DHCP发现】的服务器都广播一个<br>【DHCP提供】里面有IP+相关的配置信息
      - 多个DHCP服务器都会回复，先到先得
    - 客户机收到【DHCP提供】，广播一个【DHCP请求】
    - 对应服务器收到【DHCP请求】后，将IP地址分给客户机
  - 为什么使用UDP，不使用TCP
    - 因为客户端连IP都没有，只能广播，也无法建立TCP连接
- ICMP
  - Internet control message protocol<br>网络控制信息协议
  - 差错报文
    - 五种类型
      - 无法交付（终点不可达）
      - 拥塞数据丢弃（源点抑制）
        - 现在基本用不到了
      - TTL=0/残缺
      - 首部出错
      - 值得更好的路由
        - 反馈给源主机一个更优解
    - 不发送ICMP的情况
      - ICMP出错了
      - 第一个分片后的数据报片后续的不发送ICMP
      - 组播地址
      - 特殊地址
  - 询问报文
    - （PING）回送请求和回答报文
    - （时间戳）时间戳请求和回单报文
    - 掩码地址和回答报文
    - 通告报文
    - 概要：现在不用了
      概要范围：[掩码地址和回答报文](#topic-2f0b2402e75b0447f9107b2fcd)、[通告报文](#topic-8bf8a380dd8b4bf0d08918ff95)

  - 应用：
    - 分组网间探测PING
      - 测试两台主机之间的连通性
      - 使用了 ICMP 回送请求和回答报文
    - TraceRoute
      - 用来跟踪分组经过的路由
      - 使用了 ICMP 时间超过报文

## IPv6

<a href="/images/408-mind-maps/os-0062.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0062.svg" alt="IPv6" width="48" height="48" loading="lazy" /></a>

- 真正解决IPv4耗尽的问题，NAT、子网等只是缓解手段
- IPv6，一共128bit（8组 \* 4个16进制数 =  8 \* 4 \* 4 bit)，用冒号分隔
  - 对比：
    - MAC
      - FF-FF-FF-FF-FF-FF
    - IPv4
      - 127.0.0.2
    - IPv6
      - 0000:0000:0000:0000:0000:0000:0000:0001<br>【即 ::1 】
  - 有相继的0时可以用 :: 直接缩写，但只能有一次

<a href="/images/408-mind-maps/cn-0032.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0032.svg" alt="路由协议" width="48" height="48" loading="lazy" /></a>

  - 简便可靠，负荷稳定，拓扑变化不大
- 动态路由：<br><br>域内路由（内部网关协议IGP）

  <a href="/images/408-mind-maps/os-0062.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0062.svg" alt="动态路由： 域内路由（内部网关协议IGP）" width="48" height="48" loading="lazy" /></a>

  - 路由信息协议RIP

    - 全程：
      - Routing Information Protocol<br>路由信息协议
        - 应用最广泛的协议，简单
    - 路由表信息：
      - 每个路由器只维护他到每个【目的网络】的【距离向量】
      - 路由表信息：&lt;目的网络N，距离d，下一跳路由器R&gt;
    - 性质
      - 【应用层协议】，把自己封装到UDP报文中（UDP是传输层，但他的数据来自于应用层，在【传输层传输】），使用端口520的UDP
      - 跳数
        - 从一个路由器到一个连接网络要中转的路由器数（跳数 - 1）
        - 最大跳数为15，如果跳数&gt;=16，即说明网络不可达
          - 对比记忆：CSMA/CD的二进制回退算法
      - 最短广播时间
        - 30s广播一次RIP路由信息
    - 特点
      - RIP中每个网络的子网掩码必须相同，但是新的RIP2协议中，支持变长子网掩码和CIDR
      - 开销小、收敛快、实现简单
      - 适用于小型的互联网
      - 存在慢收敛情况
        - 例如：R1连接的N1出现了故障，表从&lt;1, 1, - &gt; 变成了 &lt;1, 16, -&gt;
        - R2原来是&lt;1,2,R1&gt;，现在R1收到R2的交换信息，自己变成&lt;1,3,R2&gt;。&lt;1, 16, -&gt; 这个真实的信息丢了。
        - 最后经过数轮过后，R1、R2都变成了&lt;1, 16, R2&gt;和&lt;1, 16, R1&gt;
    - RIP的算法步骤
      - 1\. 与相邻路由器
      - 2\. 路由器交换的信息是当前路由器所知道的全部信息，就是自己的路由表
      - 3\. 30s更新一次
      - 4\. 收到信息后的步骤
        - 路由表信息：&lt;目的网络N，距离d，下一跳路由器R&gt;
        - 1\. 收到来自路由器Rx的信息，【N不变，d++，R = Rx】
        - 2\. 查看自己的路由表，【如果没有N的信息】，则直接添加进去
        - 3\. 查看自己路由表，【如果有N，R相同】，那么直接改d为新的（不论大小）
        - 4\. 查看自己路由表，【如果有N，R不同，d更小】，则改成新的（新的d比旧的d要小，就改成新的）
      - 如果180s还没有收到相邻路由器的RIP，则判定其不可达（设置d为16）
    - 优点：
      - 简单、开销小、收敛快
  - 开放最短路径优先OSPF
    - Opening Short Path First
      - 开放最短路径优先
    - 每个路由器维护【全网的拓扑结构图】
      - 即：DD链路状态数据库的同步
    - 性质
      - 【网络层】协议，使用IP数据包传送，在网络层传输
      - 洪泛法发送数据给【所有路由器】，⚠️  这里实际洪泛法是只发给相邻的路由器，然后一层一层传出去
      - 交换信息为【本路由相邻的所有路由器的链路状态】
        - 与RIP相比不一样的：RIP是发自己知道的全部东西
          查看关联主题（原图链接目标缺失：`xmind:#fbf903b1-8017-4bb2-84ee-28fbf61d8250`）

        - 链路状态
          - 本路由器与哪些路由器相邻
          - 链路的“度量”（或代价）
      - 只有链路状态发生变化的时候才会使用洪泛法发送信息
        - 与RIP相比不一样的：RIP是每30s就发一次
        - OSPF规定每隔30min更新一次链路状态
    - 特点
      - OSPF的代价可自行调节，针对不同类型业务可计算出不同的路由，【十分灵活】
      - OSPF算法会把【大型网络划分为数个区域】，区域内的路由器只会存储每个区域内的链路数据库
        - 适用于大型网络
        - 主干区域为0.0.0.0，除了主干区域，其他为自治系统边界路由器
        - 四种路由器
          - 主干路由器
            - 主干区域内的
          - 区域边界路由器
            - 主干区域 ↔️  边界区域
          - 区域内部路由器
            - 边界区域内部
          - 自治系统边界路由器
            - AS1 ↔️  AS2
      - 收敛过程快，不会出现“慢收敛现象”
      - 四个楼楼没讲的功能
        - 1）如果到同一个目的网络有多条相同代价的路径，那么可以将通信量分配给这几条路径。这称为多路径间的【负载平衡】。
        - 2）所有在OSPF路由器之间交换的分组都具有鉴别功能，因而保证了仅在可信赖的路由器之间交换链路状态信息。
        - 3）支持可变长度的子网划分和无分类编址CIDR。
        - 4）每个链路状态都带上一个32位的序号，序号越大，状态就越新。
    - OSPF算法步骤
      - 目的：每个路由器都建立一个全网的链路状态数据库，即全网拓扑结构图
        - 然后每个路由器在结束链路交换后，使用Dijikstra算法计算最优路径
          - 在路由器的存储中，存的仍然是下一跳的地址，因为Dijikstra对每个顶点也可以只存下一跳的地址
      - 五种OSPF
        - HELLO问候分组
        - （metric每个邻居的成本度量）
        - 数据库描述分组
          - 向邻站发送自己链路状态数据库中所有链路状态项目的摘要信息
        - LSR链路状态请求分组
          - 向对方请求某些链路状态的详细信息
        - LSU链路状态更新分组
          - 洪泛式更新链路状态
        - LSAck链路状态确认分组
          - 对收到的更新分组进行去人
      - 步骤
        - 1\. 有一个路由器发生了路由变化
        - 2\. 该路由器洪泛式发送LSU
        - 3\. 其他路由器收到后更新DD链路数据库，返回LSAck
        - 4\. 所有其它的路由器，重新跑一次Dijikstra
- 动态路由：<br>域间路由（外部网关协议EGP）

## IP组播

<a href="/images/408-mind-maps/cn-0062.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0062.svg" alt="IP组播" width="48" height="48" loading="lazy" /></a>

- 只用于UDP，点对多点。把一个报文分组发送给多个目的地主机，只会在接受的前一个路由器处进行复制
  - UDP，不提供可靠交付
  - 组播地址只能是目的地址
  - 组播信息不产生ICMP报文，PING后+组播地址，无法接收到响应
- 使用IGMP协议才可以加入组播组
- 组播地址：224.0.0.0 ～ 239.255.255.255
  - 不是所有D类地址可作为组播地址，有许多已经被作为永久组播地址，不允许使用
- 两种组播
  - 在因特网范围内组播 IGMP<br>(internet group message protocol)
    - 路由器维护【成员关系】
      - 是否有成员在组播组中
    - 第一阶段：若【主机】申请加入新的组播组，那么主机向【组播组的组播地址】发送IGMP报文说自己要进来。
      - 【本地的组播路由器】收到后，把组的成员关系转发给【其他组播路由器】
    - 第二阶段：本地的组播路由器会周期性询问LAN的主机
      - 只要有一台主机回应，就认为本组活跃
      - 如果【经过几次】都没回应，就不把这个组的成员关系转给其他组播路由器
    - 概要：所以，组播必须要路由器才可以实现
      概要范围：[路由器维护【成员关系】](#topic-71ca3177369b019726dfb88ba7)

    - 批注：维护成员关系
  - 在因特网和硬件间组播<br>（组播IP地址与组播MAC地址的对应关系）
    - 01005E是固定的组播MAC前缀，而IP有组播地址范围（前4bit是1110）
    - IP和MAC地址的最后23位一定一摸一样，一一对应
    - 概要：所以一个组播IP地址可以对应很多个MAC地址，故会有多个主机接受到组播地址，需要在IP层利用软件进行过滤，把不是给本主机的组播信息丢弃掉
      概要范围：[01005E是固定的组播MAC前缀，而IP有组播地址范围（前4bit是1110）](#topic-86d8a0becdb85b104d469bb33c)、[IP和MAC地址的最后23位一定一摸一样，一一对应](#topic-1c6ae3457a1939c183f0e8a6bf)

    - 批注：进行组播
- 组播路由选择
  - 通过IGMP使路由器获得组播成员信息
    - 找到组播转发树（因为每个分组只转发一次，所以使用树形结构。根节点不同，树也会不同）
  - IGMP是TCP/IP的一个部分
  - 三种路由算法
    - OSPF
    - RIP
    - PIM（协议无关组播，了解即可）
- 考频：低
  - 无

## 移动IP

- 考频：低
  - 无
- 定义
  - 移动IP
    - 支持移动性的因特网结构与协议的IP
  - 移动结点
    - 具有永久IP地址的移动结点
  - 移动代理
    - 外埠代理/外部代理
    - 本地代理/归属代理/归属网络
- 处理流程
  - 1\. 如果在本地网络内，就使用普通的TCP/IP通信
  - 2\. 移动节点移动到外网，仍然使用本地IP。需要向本地代理注册当前的位置地址
  - 3\. 本地代理接受到注册后，会构建一条通往移动代理的隧道，然后截获发给本地的IP分组通过隧道传到代理网络处
  - 4\. 代理网络处解除隧道的封装，恢复原始的IP分组，最后送过去
  - 5\. 在外网通过外网的路由器或外埠代理发送IP数据包
  - 6\. 来到新的网络就新注册
  - 7\. 回去就注销
- 移动节点以固定IP来实现跨网的漫游

## UDP

- 特色
  - 实现了传输层协议最少的工作，只在IP的基础上增加了两个服务：【复用分用和差错检测】
- 优点：

    - 也不会有建立连接的时延
      - 即：
        - DHCP可以用UDP要IP地址
        - DNS使用UDP可以更快的查找IP
        - HTTP不能使用UDP，因为HTTP需要文本数据的可靠性
  - 无连接状态
    - UDP不维护连接状态也就不需要跟踪参数，所以应用服务器使用UDP时一般可以支持更多的【活动客户机】
  - 分组首部开销小
    - TCP首部有20B，UDP只有8B
      - vs
        - MAC帧首部 6+6+2 B，FCS为 4 B
        - PPP帧 F+A+C+协议+FCS+F
          - 1+1+1+2+2+1 B
          - 配图

            <a href="/images/408-mind-maps/cn-0033.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0033.svg" alt="PPP帧 F+A+C+协议+FCS+F" width="240" height="77" loading="lazy" /></a>

        - DHCP帧 F+A+C+FCS+F
          - 1+1+1+2+1 B
        - IPv4首部为4\*(5~15)B
        - IPv6首部为40B
  - 应用层可以更好的控制发送的数据和发送的时间
    - UDP没有拥塞控制，所以网络拥塞不会影响发送效率
      - 但是网络拥塞会影响丢包率等等，UDP只是不会向TCP那样进行流量控制
    - 应用可以接受部分信息的丢失、但不允许有较大时延，就使用UDP
  - 支持一对一、一对多、多对一、多对多
- 特点：
  - UDP是面向报文的
    - 应用层应该自己设计好该让UDP发多大的数据报
      - 因为UDP只负责加个头部就给IP了，其他啥也不做，如果到了IP层发现太大了网络层会自己分片，如果发现太小了，又会发现头部太长了，两者都不划算
  - UDP常用于一次传输较少的数据
    - 例如DNS、SNMP
  - UDP不保证可靠交付
    - 所以应用层需要自行进行传输可靠性的维护

## TCP

- 考频：超高
  - 09\*2、10、11\*2、13-15、17、19-20\*2、21\*3、22\*2、12大、16大
- 目的：
  - 建立可靠、有序、无丢失、不重复传输
- 特点：
  - 面向连接的传输层协议

  - 只支持一对一传输（端对端）

  - 可靠的传输

  - 提供全双工，所以发送端和接受端都设置有发送和接受缓存

    - 【发送缓存】存 1. 应用程序准备发送的数据 2. TCP已发送但还没收到确认的数据
    - 【接受缓存】存 1. 按序到达的但是没有被应用程序接受的数据 2. 未按序到达的数据
  - TCP的传输是面向字节流的（Byte Stream）

    - 应用程序每次和TCP交换一个数据块的大小，但TCP把其视为无结构的字节流
- 发送报文采用的方式
  - UDP --- 应用程序要发多少就发多少
  - TCP --- 根据接受窗口和拥塞情况决定
- TCP首部

  - 配图

    - 数据偏移
      - = IP首部的”长度”
        - 单位为4B，占4bit，所以范围为5~15
      - != IP首部的”片偏移“
    - 各bool变量
      - 紧急位 URG
        - URG=1时，表明紧急指针字段有效。它告诉系统此报文段中有紧急数据， 应尽快传送（相当于高优先级的数据）。
          - 但 URG 需要和紧急指针配合使用，即数据从第一个字节到紧急指针所指字节就是紧急数据。
      - 确认位 ACK
        - 仅当 ACK = 1 时确认号字段才有效。当ACK = 0时，确认号无效。
          - TCP 规定，在连接建立后所有传送的报文段都必须把 ACK 置 1。
      - 推送位 PSH (Push）
        - 接收方 TCP 收到 PSH=1 的报文段，就尽快地交付给接收应用进程， 而不再等到整个缓存都填满后再向上交付。
      - 复位位 RST (Reset)
        - RST=1 时，表明 TCP 连接中出现严重差错(如主机崩溃或其他原因），必须释放连接，然后再重新建立运输连接。
      - 同步位 SYN
        - 同步SYN=1表示这是一个连接请求或连接接受服文。
          - 当SYN = 1, ACK = 0时，表明这是一个连接请求报文，对方若同意建立连接，则应在响应报文中使用 SYN = 1，ACK = 1。
      - 终止位 FIN (Finish)
        - 用来释放一个连接。当FIN=1时，表明此报文段的发送方的数据已发送完毕，并要求释放传输连接。
    - 校验和添加字段：
      - 源IP + 目的IP + 0 + 6 + TCP总长度

- TCP可靠传输
  - 序号
    - TCP给自己传输的每个【字节流】都编上了序号
      - 即：一个Byte一个序号
      - 注意：TCP不是把报文段/数据报/帧给标上的记号，而是给自己的【字节流】
    - 例如：TCP发送了三个报文段，第一个有5B，第二个有3B，第三个有2B
      - 则他们的seq分别为 seq = 0, seq = 5, seq = 8
  - 确认
    - TCP默认采用累计确认（类似GBN），对ack = 下一个我想要的序号
      - 例如：TCP发送了三个报文段，第一个有5B，第二个有3B，第三个有2B
        - 则他们发送后对应的的ack分别为 ack = 5(seq = 0), ack = 8(seq = 5), ack = 10(seq = 8)
  - 重传
    - 超时
      - TCP每发送一个报文段就设置一个计时器，计时器时间到头还没收到ACK，就重发
      - 优化：
        - TCP采用了自适应算法来计算加权往返时间RTTs，其会随着RTT变化而变化
    - 冗余ACK
      - 当TCP同时收到了3个冗余ACK的时候，可以认为该报文已经丢失
        - 例如：TCP发送了五个报文段，序号为0，1，2，3，4
          - 其中 1 丢失了，则发送方会收到3个 ack = 1（接收方在收到2、3、4的时候返回的）
      - 出现冗余ACK时，采用快速重传
- TCP拥塞控制
  - 目的：
    - 防止过多的数据注入网络，保证网络中的路由器或者链路不会过载
  - vs 流量控制
    - 相同：都是控制发送方的发送速率来达到控制效果
    - 区别：
      - 拥塞控制是全局性的过程，涉及所有网络的所有设备
      - 流量控制是点对点的，接收端控制发送端，抑制发送数据的速率
  - 窗口：
    - rwnd 接受窗口
      - 是【接收端】发的帧中的窗口大小
    - cwnd 拥塞窗口
      - 是发送端根据【当前网络】的拥塞情况设置的窗口值
    - 发送窗口大小 = min(rwnd, cwnd)
  - 慢开始+拥塞避免：
    - 【每个RTT】会发送【MSS个数据】，每个RTT中可能会有【多个序号】的数据报

          - 把cwnd重新归到 1，重新开始慢开始

    - 批注：网络拥塞

    - 【快开始+快恢复】是在”慢开始+拥塞避免“的一种对冗余ACK的优化，【快开始】就是检测到3个重复ACK后不用等计时器，直接重传。【快恢复】就是把cwnd和ssthresh直接减到cwnd的一半，开始【拥塞避免】

## 域名系统(DNS)

<a href="/images/408-mind-maps/os-0004.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0004.svg" alt="域名系统(DNS)" width="48" height="48" loading="lazy" /></a>

- 考频：中
  - 10、16、18、20
- DNS采用C/S模型，建立在UDP在，使用53号端口
- 域名标准
  - 硬性规则
    - 不区分大小写、不使用' - '以外的符号、每个标号不超过63B一共不超255B、级别越高越靠右
  - 顶级域名<br>(TLD)
    - 国家顶级域名nTLD，.cn .us
    - 通用顶级域名gTLD, .com .net .org .gov .int .aero .museum .travel
    - 基础结构域名
      - .arpa，反向域名解析
  - 二级域名
    - 类别域名
      - ac.am.edu.gov.mil.net.org
    - 行政域名
      - bj.js
    - 自行注册域名
      - cctv. bilibili.
  - 三级、四级域名
    - www1. www. mail. hust. .hit.
    - 与二级域名差不多
  - 概要：都由授权域名服务器管辖
    概要范围：[二级域名](#topic-fb185f36c4fa73bbc3ca286825)、[三级、四级域名](#topic-8c2a1f2812bba98933c53ae476)

- 域名服务器
  - IP到域名解析的过程是由众多域名服务器中的应用程序完成的
  - 本地域名服务器
    - 一个网络服务提供商ISP、一个大学、一个系，都拥有一个本地域名服务器
    - 主机发送DNS请求，第一个就是发送给本地域名服务器
    - 本地域名服务器会存有一个本地缓存，直接有IP
      - 其他服务器很多都有高速缓存，直接有IP
  - 根域名服务器
    - 为：a-m.rootservers.net
      - 一共13个
    - 本地域名服务器第一求助对象
    - 用来管辖顶级域
      - 返回下一个顶级域名服务器的IP地址
  - 顶级域名服务器
    - 管辖所有二级域名
      - 已经可以返回最后结果了，也可能是返回下一个域名服务器的IP地址
  - 授权域名服务器
    - 每台主机都会在此处登记
      - 很多域名服务器又是本地又是授权的
    - 返回最后结果
- 域名解析
  - 递归查询
  - 递归+迭代
  - 概要：配图
    概要范围：[递归查询](#topic-b06a12b0d9bbf442a47f4a9db0)、[递归+迭代](#topic-e97ad54a42191875dfa5989ec9)

    <a href="/images/408-mind-maps/cn-0037.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0037.svg" alt="域名解析" width="240" height="105" loading="lazy" /></a>

- 域名解析的步骤
  - 1\. 客户机向本地域名服务器发送DNS请求
    - y.abc.com
    - 概要：只有这一步是需要解析软件实现的，后续都自动完成
      概要范围：[y.abc.com](#topic-c15f5a0a-161b-403d-9e14-fc7229f5e9c3)

  - 2\. 本地域名服务器收到请求后，查询高速缓存，若没有则以DNS客户的身份向根域名服务器(就是dns.)请求
    - 如果有，就返回，下同
  - 3\. 根域名服务器收到请求后，判断域名属于.com，将dns.com的IP返回给本地域名服务器
  - 4\. 本地服务器向dns.com发送DNS请求
  - 5\. dns.com域名服务器收到请求后，判断域名属于abc.com，将dns.abc.com的IP返回给本地域名服务器
  - 6\. 本地服务器向dns.abc.com发送DNS请求
  - 7\. dns.abc.com域名服务器收到请求后，返回IP
  - 客户机把IP和DNS写入到本地缓存中

## FTP传输

<a href="/images/408-mind-maps/cn-0027.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0027.svg" alt="FTP传输" width="48" height="48" loading="lazy" /></a>

- 配图

  <a href="/images/408-mind-maps/cn-0128.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0128.svg" alt="FTP传输" width="240" height="105" loading="lazy" /></a>

- 采用C/S模型、先建立TCP连接，连接端口 21，数据端口 20
  - 数据端口（主动情况20，被动情况 1024 ~ 65535）
  - 使用TCP可靠传输服务
  - 控制进程、数据进程同时两个TCP连接
- FTP提供
  - 不同种类主机系统（软硬件都可不同）之间的文件传输
  - 以用户权限管理方式提供用户对远程FTP服务器的文件管理能力
  - 以匿名FTP方式提供文件共享
- 服务器进程
  - 主进程
    - 负责接受请求
  - 从属进程
    - 负责处理单个请求，处理完毕终止
- 连接方式
  - 控制连接
    - 监听21号端口
    - 使用7位ASCII码做控制信息
  - 数据连接
    - PORT模式（主动
      - 客户端发送请求到21，服务器开20给客户端，客户端随机开一个端口来接受服务器的20的数据
    - PASV模式（被动
      - 客户端发送请求到21，服务器随机开一个端口给客户端，客户端后面自己连接
  - 概要：只有控制+数据两个连接，没有其他连接
    概要范围：[控制连接](#topic-86a8365ebf9bd6dc28e0fb0b5d)、[数据连接](#topic-66ead9af593b3eff63c3390a52)

- 数据连接<br>（FTP与NFS）
  - FTP是分离控制，是带外传输(Out-of-band)
    - 如果要修改文件就很麻烦，需要读文件所有信息，改了过后再发回去
  - NFS可以只读获得一个文件的一个部分
- 数据传输模式
  - 文本模式 ASCII码
  - 二进制模式
- 匿名FTP访问：
  - 用户名：annoymous
- 考频：低

## SMTP传输

<a href="/images/408-mind-maps/co-0015.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0015.svg" alt="SMTP传输" width="48" height="48" loading="lazy" /></a>

- 考频：中
  - 12、13、15、18
- 基于TCP连接的应用层协议
- 组成结构
  - 用户代理（User Agent）
    - 用户与电子邮件系统的接口，例如：Outlook、Foxmail
    - 概要：如qq邮箱、Gmail，用户使用浏览器操作这类邮件服务器【发送和接受】使用的HTTP，仅在【不同邮件服务器之间传送邮件】用的SMTP
      概要范围：[用户与电子邮件系统的接口，例如：Outlook、Foxmail](#topic-f1478118-890a-44b7-97e5-4a657497f781)

  - 邮件服务器
    - 接受和发送邮件，报告发信人邮件传送情况
    - 例如：A向B发送邮件，A就是SMTP客户，B就是SMTP服务器
  - 电子邮件协议
    - 发送协议
      - SMTP（Push)
    - 接受协议
      - POP3（Pull）、IMAP
- 收发过程：
  - 1\. 发信人调用用户代理来撰写和编辑要发送邮件。
  - 2\. 发送端的邮件服务器将邮件放入邮件缓存队列
  - 3\. 运行发送端的SMTP客户进程，如果有缓存中的等待邮件，则向接受方的SMTP服务器建立TCP连接
  - 4\. TCP建立完成后，SMTP客户进程向SMTP服务器发送邮件。所有邮件发完后。关闭TCP连接
  - 5\. 运行在接受端的SMTP服务器收到邮件后，将邮件放入收信人邮箱，待收信人方便时读取
  - 6\. 收件人打算收信时，调用用户代理，启用POP3/IMAP来取回邮件
- SMTP的<br>电子邮件格式
  - 信封
    - From:
      - 例:xxx@bytedance.com
    - To:
      - 例：xxx@tecent.com
    - Subject:
      - 主题，可以有可无
  - 内容
    - 主体内容
      - 只能传输一定长度的ASCII码
- SMTP &amp; MIME<br>和<br>POP3 &amp; IMAP
  分组说明：只用于读取邮件；对应：[POP3](#topic-e7e4343c-459d-4fd4-890e-0808f17028d8)、[IMAP](#topic-6f016e84-6d7a-4b3e-aae8-073bd94ac0f3)

  分组说明：只用于发送邮件；对应：[SMTP简单邮件传输协议](#topic-53964648-f6e2-439c-9422-478baeed4e09)、[MIME](#topic-816840db-9aef-46a0-9346-0b3f16c019aa)

  - SMTP简单邮件传输协议
    - 使用CS模式
      - 发送方即SMTP客户
      - 接收方即SMTP服务器
    - TCP连接，端口25
    - 三个阶段
      - 1\. 连接建立
        - SMTP客户扫描缓存时发现有邮件，就使用25号端口与接收方服务器的SMTP建立TCP连接。
        - 建立后，服务器发送“220 Service Ready”，然后SMTP客户向SMTP服务器发送HELO命令，附上发送方主机名
          - 如果发来的邮件服务器可以接受，返回"250 OK"，否则返回"421 Services not available"
        - （SMTP不使用中间服务器，故TCP连接总是在发送方和接收方这两个邮件服务器直接建立）
      - 2\. 邮件传送
        - 客户端先发送MAIL命令开始，MAIL FROM：&lt;...&gt;
        - 服务器收到MAIL命令后，如果准备好接受，就返回250 OK
        - 客户端根据接收方的email号，发送数个RCPT命令
        - 服务器收到RCPT后，返回250 OK或550 No such user here
          - 如果收到550，说明不可发送
        - 如果收到了OK，客户端就使用DATA命令，表示要发送的内容
          - 此时服务器返回354 Start mail input; end with &lt;CRLF&gt;&lt;CRLF&gt;
      - 3\. 连接释放
        - 发送QUIT命令
          - 服务器返回221（服务器关闭），则表明同一TCP连接释放
  - MIME
    - 多用途网际邮件扩充(MIME)
    - 并未改动SMTP，而是继续使用SMTP的结构，增加了新的内容
    - 新增：
      - 1\. 新的邮件首部，包括MIME版本、内容描述、内容标识、传送编码、内容类型
      - 2\. 定义了许多邮件内容格式，对多媒体电子邮件表示方法进行了标准化
      - 3\. 定义了传送编码，可以对任何内容格式进行转换，不会被邮件系统改变
  - POP3
    - 邮局协议
    - 端口号110，使用TCP
    - 两种工作方式：
      - 下载保存
      - 下载删除
  - IMAP
    - 因特网报文协议
    - 提供了创建文件夹、在不同文件夹之间移动邮件和在远程文件夹中查询邮件的联机命令
    - 可以允许用户只读取邮件中的一个视频/音频而不用全部
      - 和FTP的NFS模式很像
        [查看关联主题](#topic-d309489ea4ca171a20c46a6714)

## 万维网和HTTP

<a href="/images/408-mind-maps/cn-0056.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0056.svg" alt="万维网和HTTP" width="48" height="48" loading="lazy" /></a>

- WWW的三个部分
  - 1\. URL
    - &lt;协议&gt;://&lt;主机&gt;:&lt;端口&gt;/&lt;路径&gt;
      - 例：http://172.0.0.1:8080/index.html
  - 2\. HTTP
    - 使用TCP，是WWW中客户程序和服务器程序交互必须遵守的协议
  - 3\. HTML
    - 文档结构语言，使用约定的标记对页面的各种信息、格式进行描述
- HTTP协议
  - 连接步骤
    - 1\. 浏览器进行DNS解析指向页面的URL，返回IP地址
      [查看关联主题](#topic-cd5848e0d6b94d7ebc6f4a7659)

    - 2\. 浏览器与IP地址服务器进行TCP连接（端口80）
    - 3\. 连接完毕后，发送HTTP请求(GET/POST/PUT ... )
    - 4\. 服务器返回HTTP响应，把文件发回给浏览器
    - 5\. 释放TCP，浏览器解析文件，展示Web页面
    - 概要：举例：
      概要范围：[1. 浏览器进行DNS解析指向页面的URL，返回IP地址](#topic-9f9b007a536b28dcfa11397b64)、[2. 浏览器与IP地址服务器进行TCP连接（端口80）](#topic-c489ca74bf4b840da4fe9a8c0b)、[3. 连接完毕后，发送HTTP请求(GET/POST/PUT ... )](#topic-88382ea35bca80358883aab55d)、[4. 服务器返回HTTP响应，把文件发回给浏览器](#topic-5a89f5a4cff9968b4f5a19be37)、[5. 释放TCP，浏览器解析文件，展示Web页面](#topic-c5c830339918243bc2eb9b923d)



      **用户单击链接后发生的事件顺序**（原图以访问清华大学网站为例）：

      1. 浏览器分析链接指向页面的 URL：`http://www.tsinghua.edu.cn/chn/index.htm`。
      2. 浏览器向 DNS 请求解析 `www.tsinghua.edu.cn` 的 IP 地址。
      3. DNS 系统解析该域名，返回服务器 IP 地址。
      4. 浏览器与服务器建立 TCP 连接，默认服务端端口为 80。
      5. 浏览器发出 HTTP 请求：`GET /chn/index.htm`。
      6. 服务器通过 HTTP 响应把 `index.htm` 文件发送给浏览器。
      7. 释放 TCP 连接。
      8. 浏览器解释 `index.htm`，将 Web 页面显示给用户。

      原图旁注：浏览器可以不必等一次完整响应后再发出其他对象请求。上述为教材中的 HTTP/TCP 过程，不代表所有 HTTP 版本都采用相同连接流程。



  - 特点
    - HTTP本身是无连接的
      - 使用了TCP连接后，HTTP便可直接发送数据，而不用像FTP、SMTP那样建立FTP连接和SMTP连接
    - 无状态
      - 无状态：
        - HTTP服务器不存储HTTP客户的访问记录
      - 使用Cookie去优化 '无状态' 的特点
        - 服务器给用户的响应报文中添加set-cookie:123456
        - 用户再次访问这个网页时，会取出cookie标识符，写入到请求报文中：cookie:123456
        - 存在用户主机中
    - 连接特性
      - 非持久连接
        - HTTP/1.0的默认方式，1.1也可以使用这种
        - 每次请求网页元素的时候都需要进行一次TCP连接
        - 概要：进行N次访问要2N个RTT
          概要范围：[HTTP/1.0的默认方式，1.1也可以使用这种](#topic-e538c06c75f8e5de8aded9a725)、[每次请求网页元素的时候都需要进行一次TCP连接](#topic-8cca9b071859aecf9ec33b9f22)

          - 例：读取一个有100个图片的Web页面，需要经历202个RTT
      - 持久连接
        - 非流水线
          - 类似停等协议的请求/接受方式
          - 概要：进行N次访问要N+1次RTT
            概要范围：[类似停等协议的请求/接受方式](#topic-f0fa6a6e73e96d8d853c788360)

        - 流水线
          - HTTP/1.1的默认方式
          - 类似GBN+SR的请求/接受方式
        - 概要：进行N次可能只用2次RTT
          概要范围：[流水线](#topic-ad2a482102e854dba4aa8abed6)
