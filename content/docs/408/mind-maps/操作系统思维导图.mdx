## 操作系统基本概念

<a href="/images/408-mind-maps/co-0085.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0085.svg" alt="操作系统基本概念" width="48" height="48" loading="lazy" /></a>

- 操作系统概念
  - 操作系统（operating system，简称OS）是管理【计算机硬件】与【软件资源】的【计算机程序】。操作系统需要处理如管理与配置内存、决定系统资源供需的优先次序、控制输入设备与输出设备、操作网络与管理文件系统等基本事务。操作系统也提供一个让用户与系统交互的操作界面。
- 四大特征
  - 并发
    - 两个或多个事件在同一时间间隔发生
    - 并行
      - 多流水线或者多CPU可以实现并行
      - 在同一时间同一时刻
    - 引入进程目的就是让程序可以并发
    - 【宏观并行，微观并发】
      - 并发：两个程序一个CPU，依次轮询使用1ms，宏观上看是同时处理了两个程序
    - 并发是资源共享的基础，若OS不支持并发，则不存在共享
      - A在使用资源，此时A还没有结束进程，B就想来使用，A让给了B：【能并发、有共享】
    - 概要：单核CPU基本都是并发，多核CPU/多CPU基本都是并行+并发
      概要范围：[并行](#topic-e8282e433279fe30cd90290694)

  - 共享
    - 指资源共享
    - 互斥资源共享
      - 在一段时间内，无论宏观微观都不可以同时访问
      - 如打印机、磁带机
      - 互斥式共享
        - 进程A访问完才可以释放，才允许另一进程访问
      - 独占资源/临界资源
        - 一段时间内只允许一个进程访问的
    - 同时访问方式
      - 在一段时间内，宏观上同时访问微观上分时访问
    - OS对共享资源的管理会影响到并发执行的情况
  - 虚拟
    - 把一个物理实体变为若干逻辑上的对应物
    - 虚拟处理器
      - 利用多道程序设计技术把一个物理上的CPU虚拟为多个逻辑上的CPU
        - 通过并发
    - 虚拟内存
      - 虚拟存储器
      - 把物理存储器转变为虚拟存储器，以从逻辑上扩充存储器容量
    - 虚拟外部设备
      - 将一台物理IO设备虚拟为多台逻辑IO设备
        - Spooling技术
  - 异步
    - 进程是以不可预知的速度向前推进的，这就是进程的异步性
  - 概要：两个最基本的特征
    概要范围：[并发](#topic-7df861f92789c992d40a5be279)、[共享](#topic-10eaab2d04693eb909bf59f42c)

- 目标和功能
  - 系统资源的管理者
    - 处理机管理
      - 进程
    - 存储器管理
      - 内存
    - 文件管理
      - 文件
    - 设备管理
      - IO
  - 用户和硬件的接口
    - 命令接口
      - 联机
      - 脱机
    - 程序接口
      - 使用GUI
  - 用作扩充机器
    - 没有任何软件支持的计算机称为裸机
    - 覆盖了软件的机器为扩充机器、虚拟机
- 考频：低
  - 09、10、13、22

## 操作系统运行环境

<a href="/images/408-mind-maps/co-0017.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0017.svg" alt="操作系统运行环境" width="48" height="48" loading="lazy" /></a>

- 处理器运行模式
  - 特权指令/非特权指令
    - 特权指令：是指不允许用户直接使用的指令，如I/O指令、置中断指令
    - 非特权指令：是指允许用户直接使用的指令，它不能直接访问系统中的软硬件资源，仅限于访问用户的地址空间，这也是为了防止用户程序对系统造成破坏
  - 内核态和用户态
    - PSW = 1，即在内核态（管态）
    - PSW = 0，即在用户态（目态）
    - 广义指令 = 系统调用
      - 广义指令在用户态下调用，内核态下执行
- 4方面内容：
  - 时钟管理
    - 功能：计时、切换进程
  - 中断机制
    - 引入中断提高CPU利用率，提高外部设备利用率
  - 原语
    - 处于操作系统最底层
    - 具有原子性，一气呵成
    - 运行时间短，调用频繁
  - 系统控制的数据结构和处理
    - 进程管理
    - 存储器管理
    - 设备管理
- 中断和异常
  - 中断
    - 内中断
      - 来自CPU内部的
      - 故障 fault
        - fault是可以被修复的异常
        - 非法操作码、缺页、除数为0、溢出
      - 自陷 trap
        - trap指令
        - 安排好的时间，在用户态下调用操作系统内核程序
      - 终止 abort
        - abort是十分严重的异常
        - 使CPU无法执行的硬件故障，例如控制器出错了、存储器校验错等
      - 概要：软件中断
        概要范围：[故障 fault](#topic-9d2a7ff2be499b282bd5dbaac4)、[自陷 trap](#topic-8ab808cdfdcbb861f190f98fe8)

      - 概要：硬件中断
        概要范围：[终止 abort](#topic-b859ccb2e218d898d9b09a0a57)

      - 批注：异常
    - 外中断
      - 通常处理IO
      - 可屏蔽中断 INTR
        - 通过改变屏蔽字实现多重中断
      - 不可屏蔽中断 NMI
        - 紧急的硬件故障
  - 中断处理：
    - OS检测到中断后，就会查询系统中断向量表，找到应该执行的中断处理程序
      - 通过中断向量地址 ---&gt;  中断向量 ---&gt; 处理程序
        - 批注：计组重难点
  - 中断处理过程：
    - 中断隐指令
      - 1\. 关中断
      - 2\. 保存断点
        - 即PC寄存器的内容
      - 3\. 中断服务程序寻址
      - 批注：纯硬件
    - 中断程序
      - 4\. 保护现场和屏蔽字
        - 现场信息：
          - PSW程序状态字寄存器
          - 通用寄存器内容
        - 屏蔽字：
          - 硬件实现、软件实现（计组）
      - 5\. 开中断
        - 如果不支持多重中断，则没有这里的开关中断（计组）
      - 6\. 执行中断处理程序
      - 7\. 关中断
      - 8\. 恢复现场屏蔽字
      - 9\. 开中断
      - 10\. 中断返回
      - 批注：软件
    - 概要：结合计组
      概要范围：[中断隐指令](#topic-be8a748f718a13fc2871ea0c7c)、[中断程序](#topic-2f5a6b5823fabbed30fb7a782b)

- 系统调用
  - 系统调用可视为特殊的公共子程序
  - 分为五类
    - 设备管理、文件管理、进程控制、进程通信、内存管理
- 考频：高
  - 11、12\*2、13、14、15\*2、16-22

  - 优点
    - 1\. 简化了系统设计和实现，编程方便，便于调试 2. 便于扩充和维护
  - 缺点
    - 1\. 定义各层比较困难 2. 效率差
- 模块化
  - 配图

    <a href="/images/408-mind-maps/os-0089.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0089.svg" alt="模块化" width="240" height="103" loading="lazy" /></a>

    - 分块标准
      - 高内聚低耦合

        <a href="/images/408-mind-maps/os-0121.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0121.svg" alt="高内聚低耦合" width="240" height="124" loading="lazy" /></a>

      - 模块内紧密度要高，模块间的联系影响要小
  - 优点
    - 1\. 提高了OS的正确性、可理解性、可维护性 2. 可适应性高 3， 加速的开发过程（可以不同模块不同团队同时开发）
  - 缺点
    - 1\. 【模块间】的接口规定很难满足对接口的需求 2. 各模块开发者难以找到一个可靠的决定顺序
- 宏内核
  - 单内核、大内核
  - OS的所有功能模块全都在内核态
  - 优点：
    - 速度快
  - 缺点：
    - 一个模块奔溃导致整个核崩溃

      <a href="/images/408-mind-maps/os-0053.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0053.svg" alt="一个模块奔溃导致整个核崩溃" width="240" height="139" loading="lazy" /></a>

  - 在桌面OS中宏内核取得很大成功
    - 例如Windows、MacOS、Linux、iOS、Android等等
  - 概要：OS服务越来越复杂，OS面临着”软件危机“
    概要范围：[OS的所有功能模块全都在内核态](#topic-a334a572-990e-42f0-954a-139689842995)

- 微内核
  - 把部分内核OS代码移出内核，采用C/S模式进行执行

    <a href="/images/408-mind-maps/os-0161.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0161.svg" alt="把部分内核OS代码移出内核，采用C/S模式进行执行" width="240" height="79" loading="lazy" /></a>

  - 内核代码：
    - 1\. 与硬件紧密相连的 2. 一些较为基本的功能 3. 客户服务器的通信功能
  - 用户的服务器：
    - 这些服务器本质上就是一个进程，借助微内核的消息传递机制进行交互的
  - 基本功能：
    - 线程管理、低级存储器管理、中断和陷入处理
  - 优点
    - 1\. 扩展+灵活（新增内容加个服务器就好）
    - 2\. 可靠+安全（一个模块崩溃就重启那个模块就好）
    - 3\. 可移植性好（服务器的具体细节与硬件无关）
    - 4\. 分布式计算，可以很好的支持分布式系统和网络系统
  - 缺点
    - 慢
    - 概要：解决办法之一：把用的频繁的服务器加到内核
      概要范围：[慢](#topic-715b79f8-7c94-4d5e-a549-997eb549541c)

  - 在实时、工业、军事、航空等特别流行
    - 谷歌的Fuchsia、鸿蒙OS
- 外核
  - 外核是提高'虚拟机’效率的
    - 外核可以使一个应用进程直接获得访问内核的权利
  - 优点
    - 1\. 减少了映射层
      - 磁盘的一个部分的盘块就直接分配给了这个虚拟机，这样虚拟机间就不会发生冲突了
      - 如果不采用外核：那么多个虚拟机使用同一个内存，每个虚拟机进程需要维护一个映射表格
    - 2\. 把多道程序（外核外）与OS代码（用户空间）加以分离

    - MBR中的标志信息位：
      - 告诉主机这个磁盘是不是引导盘（分区中至少有一个分区是活动分区、有操作系统）
    - CPU读ROM进行自检、找OS的
    - 引导块：
      - 如果该磁盘分区有OS，则引导块不为空；如果没有OS，则为引导块内没有实际内容
- 步骤：
  - ① CPU读ROM
    - 激活CPU
      - CPU读取ROM里的boot程序，IR置为BIOS的第一条指令（开始运行BIOS）
    - 硬件自检
      - 启动BIOS程序，硬件开始自检，检查是否有故障
    - 带有OS的硬盘
      - BIOS读取Boot Sequence
        - Boot Sequence是一个在CMOS中的设置启动顺序的元件
      - BIOS找到了设置的第一顺序的存储设备，然后把这个设备的【引导扇区内容（MBR）】加载入内存
  - ② RAM读MBR
    - 加载主引导记录MBR
      - 硬盘以特定标识符来区分引导和非引导盘。遍历每一个，直到发现引导盘
        - MBR作用：告诉CPU去哪个主分区找操作系统
    - 加载硬件分区表
      - 找哪个磁盘分区中装有操作系统，所以需要扫描MBR中的硬件分区表
  - ③ RAM读活动分区
    - 加载磁盘活动分区
      - 活动分区：装有OS的分区就是活动分区
      - MBR找到了对应的OS分区后，把这分区读入RAM
    - 加载分区引导记录PBR
      - PBR：引导块
      - 寻找并激活根目录
    - 加载启动管理器

## 进程的概念

<a href="/images/408-mind-maps/os-0040.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0040.svg" alt="进程的概念" width="48" height="48" loading="lazy" /></a>

- 临界资源：
  - 一次只能由一个进程使用的资源，例如：打印机
- 临界区：
  - 临界区是一段访问共用资源（例如：共用设备或是共用存储器）的【程序片段】
- 程序与进程
  - 程序是静态的（就是一段代码块）
  - 进程是动态的
  - 进程实体是进程某一个时刻的“快照”，静态的
- PCB
  - PCB是进程存在的唯一标识（像身份证那样，PID像身份证号）
  - PCB中有【PID + 资源分配清单 + 进程控制/管理信息】
    - 其中UID为---哪一个用户在使用
    - 其中PID为---进程的身份证
- 进程是进程实体的运行过程，是系统进行【资源】分配和调度的基本单位
  - 线程是CPU调度的最小单位
- 进程的特征
  - 动态性
    - 进程是动态地产生、变化和消亡的。动态性是进程的【最基本特征】
  - 并发性
    - 引入进程就是为了使进程可以与其他进程并发执行
  - 独立性
    - 进程实体，独立获得资源，独立接受调度
  - 异步性
    - 进程间相互制约，具有执行的间断性，进程间以独立的、不可预知的速度向前推进
  - 结构性
    - 每个进程都配置了一个PCB
- 其他特性
  - 封闭性
    - 进程的运行结果只取决于进程本身，于进程执行的速度无关
  - 进程是【一个】程序在【一个】数据集上运行的过程
    - 如果这两个【一个】发生改变，则进程为不同进程
- 考频：低
  - 11、19、20

## 进程操作：

<a href="/images/408-mind-maps/co-0152.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0152.svg" alt="进程操作：" width="48" height="48" loading="lazy" /></a>

分组说明：题目中出现，找最对最错，都要考虑；对应：[广义狭义的进程调度](#topic-1cd264b9-f199-4db9-8160-c038603de537)

- 考频：中

- 进程的七状态模型：
  - 配图

    <a href="/images/408-mind-maps/os-0160.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0160.svg" alt="进程的七状态模型：" width="240" height="108" loading="lazy" /></a>

    - 配图

      <a href="/images/408-mind-maps/os-0036.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0036.svg" alt="进程的七状态模型：" width="240" height="109" loading="lazy" /></a>

    - 由运行结束或者发生异常到终止态：撤销
    - 图中还有可能从运行态到就绪挂起（当运行的程序在内存中的空间被抢占后）
    - 如果在运行过程中自己发生了缺页，那就是到阻塞态
- 广义狭义的进程调度
  - 狭义的进程调度
    - 从就绪态到运行态
  - 狭义的进程切换
    - 一个进程从运行态到就绪态，另一个进程从就绪态到运行态
  - 广义的进程调度
    - 上面两个之和
- 进程的创建：
  - 内容
    - 创建者为父进程，被创建者为子进程
    - 终端用户登录系统、作业调度、系统提供服务、打开应用程序都会创建进程
  - 步骤
    - 1\. 给新进程分配一个标识符PID，申请一个空白PCB
      - PCB申请失败，创建失败
    - 2\. 给进程分配内存资源（为程序、数据、用户栈分配必要内存空间）
      - 资源不足则进入阻塞态
    - 3\. 初始化PCB
      - 初始化标识信息
      - 初始化处理机控制信息
      - 设置进程优先级
    - 4\. 待就绪队列可以接纳新进程，将新进程插入就绪队列
- 进程的终止：
  - 1\. 通过PCB找到该进程的状态
  - 2\. 终止进程执行
  - 3\. 终止所有子孙进程
  - 4\. 把所有资源都归还给父进程或操作系统
  - 5\. 把PCB删除
- 进程的阻塞：
  - 又称：睡眠等待状态
  - 1\. 找到对应PCB
  - 2\. 若进程在运行态，则保护现场，将其转为阻塞态，停止运行
  - 3\. PCB插入【相应事件】的等待队列
- 进程的唤醒：
  - 1\. 找到对应PCB
  - 2\. 将其从等待队列中移出，把状态设置为就绪态
  - 3\. PCB插入就绪队列，等待CPU调度
  - 例子：
    - IO结束
      - IO结束后，等待这个IO的进程会被唤醒
    - 进程退出临界区
      - 进程A想要访问有进程B在访问的的临界区 --- A进入阻塞，进程B访问完临界区 --- A回到就绪
- 进程的切换：
  - 1\. 保存CPU环境
  - 2\. 更新PCB
  - 3\. 把PCB移入到对应队列
  - 4\. 更新数据结构
  - 5\. 恢复CPU环境

## 进程组织

<a href="/images/408-mind-maps/co-0015.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0015.svg" alt="进程组织" width="48" height="48" loading="lazy" /></a>

- 进程控制块（PCB）
  - PCB创建后常驻内存，任意时刻都可以存取，进程结束时删除
  - 需要访问PCB的情况
    - 1\. OS想要调度某进程运行
      - 调度
    - 2\. 调度到某进程后，根据PCB所保存的处理机状态信息恢复现场
      - 恢复
    - 3\. 运行过程中，当需要与之合作的进程实现同步、通信时要访问PCB
      - 合作
    - 4\. 进程由于某些原因暂停时，会将其断点处的处理机环境保存在PCB中
      - 暂停
  - 在整个生命期中，系统总是通过PCB来对进程进行控制，系统唯有通过PCB才能感知进程存在
  - 配图



    |进程描述信息|进程控制和管理信息|资源分配清单|处理机相关信息|
    |---|---|---|---|
    |进程标识符 PID|进程当前状态|代码段指针|通用寄存器值|
    |用户标识符 UID|进程优先级|数据段指针|地址寄存器值|
    |—|代码运行入口地址|堆栈段指针|控制寄存器值|
    |—|程序的外存地址|文件描述符|标志寄存器值|
    |—|进入内存时间|键盘|状态字|
    |—|处理机占用时间|鼠标|—|
    |—|信号量使用|—|—|



    - 1\. PID标志各个进程，UID标志进程归属的用户
    - 2\. 描述进程的状态信息，描述进程抢占处理机的优先级
    - 3\. 有关内存地址、虚拟内存地址有关的内容、打开文件列表、IO设备信息
    - 4\. 处理机中的各种寄存器的值
  - 各进程PCB结构的数据结构
    - 链接方式
      - 把不同状态的PCB链接成一个链表
    - 索引方式
      - 把不同状态的PCB组成一个索引表
- 程序段
  - 程序段可以被多个进程共享
  - 多个进程运行同一个程序
- 数据段
  - 数据段是进程的数据段
- 概要：故同一程序不同进程：其PCB不同、程序段相同、数据段不同
  概要范围：[程序段](#topic-abe77592-128f-403a-a55b-2638ce72c108)、[数据段](#topic-8a8d797b-a99a-40b2-8111-bf83c243a0f8)

  - 例：父子进程，代码段相同，地址段不同（不可以共享同一片虚拟地址空间）

## 进程通信：

<a href="/images/408-mind-maps/os-0023.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0023.svg" alt="进程通信：" width="48" height="48" loading="lazy" /></a>

- 考频：低
  - 14
- 共享存储
  - 通过一块可以直接访问的共享空间，通过对这片空间的读写来实现信息交换
  - 低级方式
    - 基于数据结构
  - 高级方式
    - 基于存储块
- 消息传递
  - 数据交换以格式化信息为单位，若通信进程无可直接访问的空间，则OS会通过发送原语和接受原语来传递数据
  - 直接通信
    - 通过共享空间（缓冲区，输入输出队列）来进行直接通信
  - 间接通信
    - 把信息发到某个中间实体
    - 又称：
      - 信箱通信、电子邮件系统
- 管道通信
  - 使用pipe文件来进行信息传递，属于半双工通信
  - 两个特点：
    - 1\. 管道写满，write()阻塞；管道变空，read()阻塞。
    - 2\. 数据一旦被读出，就会被抛弃，故只能有一个读进程
- 通道、管道、管程
  - 通道：硬件IO技术，用来进行快速的、多个块的IO传输
    - 比DMA牛逼
  - 管道：pipe文件，信息传递用，半双工
    - 信息传输
  - 管程：在进程互斥机制中对PV操作进行管理的数据结构
    - 信号量、PV
  - 概要：通：硬件
    概要范围：[通道：硬件IO技术，用来进行快速的、多个块的IO传输](#topic-8190baca-c6f2-43fd-b2e4-26c2024533f7)

  - 概要：管：软件
    概要范围：[管道：pipe文件，信息传递用，半双工](#topic-060312c8-a732-4f61-a97c-8fe0d1e0d52d)、[管程：在进程互斥机制中对PV操作进行管理的数据结构](#topic-b29ed31f-2d3e-4d02-8943-60177eff362a)

## 线程：

<a href="/images/408-mind-maps/os-0065.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0065.svg" alt="线程：" width="48" height="48" loading="lazy" /></a>

- 轻量级进程，CPU的最小执行单位
- 进程作为CPU外资源的最小调度单位，线程作为CPU的最小调度单位
  - 也称为程序执行流的最小单元
  - 进程 --- 资源调度和分派
  - 线程 --- 处理机调度和分派
- 进程和线程的区别
  - 1\. 进程仍是资源分配的最小单位，线程不拥有系统资源，线程可以访问隶属进程的系统资源
    - 线程也可以分配资源，但是仅仅是CPU资源的情况
  - 2\. 在引入线程的OS中，多进程、多线程都可以并发执行
  - 3\. 创建、撤销、切换进程时都会有较大的消耗，而对于线程就不会有较大的消耗
  - 4\. 进程空间相互独立，进程内的线程对其他进程不可见
- 内核级线程：
  - 只有内核有线程管理的代码
- 用户级线程：
  - 用户自行进行线程管理
- 线程实现方式：
  - OS会给每一个内核线程分配一个TCB（Thread Control Block)

    <a href="/images/408-mind-maps/os-0097.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0097.svg" alt="OS会给每一个内核线程分配一个TCB（Thread Control Block)" width="240" height="118" loading="lazy" /></a>

    - 用户级方式
      - 用户级线程 ULT
      - 一个系统进程多个用户线程
      - 一个线程被阻塞，整个进程被阻塞
    - 内核级方式
      - 内核级线程 KLT
      - 一个系统进程一个用户线程
      - 资源浪费大
    - 组合方式
      - 组合模式
      - 多个系统进程多个用户线程
  - 批注：进程与线程
- 多线程模型：
  - 考虑红框部分

    <a href="/images/408-mind-maps/os-0114.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0114.svg" alt="考虑红框部分" width="240" height="121" loading="lazy" /></a>

    - 一对一模型
      - 一个用户级线程
        - 对应
          - 一个内核级线程
          - 概要：1:1
            概要范围：[一个内核级线程](#topic-25434aeb-3f2b-4fdd-80a3-f3366da88afd)

      - 优点：
        - 一个线程阻塞，可以调度另一个线程，并发能力强
      - 缺点：
        - 每来一个用户级线程都要创建一个内核级线程
          - 开销大
    - 多对一模型
      - 多个用户级线程
        - 对应
          - 一个内核级线程
          - 概要：N:1
            概要范围：[一个内核级线程](#topic-803f2660-4d7a-4e78-9990-eeb5344a3ebf)

      - 优点：
        - 线程管理在用户空间，效率高
      - 缺点：
        - 一个线程阻塞，整个进程阻塞
        - 每个进程同时只能有一个线程访问内核
          - 并发度不高
    - 多对多模型
      - 多个用户级线程
        - 对应
          - 多个内核级线程
          - 概要：N:M (N&gt;=M)

## 处理机调度

<a href="/images/408-mind-maps/os-0144.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0144.svg" alt="处理机调度" width="48" height="48" loading="lazy" /></a>

- 处理机调度是多道程序操作系统的基础
- 三种调度：
  - 作业调度
    - 高级调度
      - 把外存上处于后备状态的作业中挑选一个，给他们分配内存、输入/输出设备等资源，并建立相应的进程
    - 外存 -&gt; 内存
    - 调度的频率低，一般几分钟一次
  - 内存调度
    - 中级调度
      - 把暂时无法执行的进程放到【外存的挂起队列中】，但是其PCB亦然保留在内存
    - 挂起态 -&gt; 内存 / 内存 -&gt; 挂起态
    - 例如：
      - 进程在内存中，出现了其他进程来抢占内存资源，导致进程被移出内存，就会变成挂起态
      - 内存有了空间，就会把挂起态中的进程调入内存
  - 进程调度
    - 低级调度
      - 按照某种方法和策略从【就绪队列】中选一个进程，将处理机分配给它
    - 内存 -&gt; CPU
    - 频率高，几十ms一次
    - 批注：最关键，不可或缺
  - 三种调度的联系：
    - 【进程调度】使进程正常活动起来
    - 【作业调度】为进程活动做准备
    - 【中级调度】将暂时不能运行的进程挂起
- 调度的时机、切换、过程
  - 什么时候不可调度
    - 处理中断
      - 多重中断中间可以调度
    - 进程在内核程序临界区
      - 因为临界区只能有一个进程访问，所以访问时一定要加锁。解锁前不应切换到其他进程运行，以加快共享数据的释放
    - 完全屏蔽中断的原子操作
  - 什么时候可以调度
    - 进程处在非内核程序临界区
    - 发生了引起调度条件且当前进程无法运行下去时
      - 可以马上进行调度和切换
      - 为非剥夺方式
    - 中断处理结束/trap处理结束，返回前请求调度，可以马上进行进程调度切换
      - 剥夺方式
- 调度基本准则
  - CPU利用率
  - 系统吞吐量
  - 周转时间
    - 周转时间：
      - 公式



        $t_{周转} = t_{完成} - t_{提交}$

    - 平均周转时间：
      - 公式



        $t_{平均周转} = \frac{\sum t_{周转}}{n}$

    - 带权周转时间：
      - 公式



        $t_{带权周转} = \frac{t_{周转}}{t_{实际运行}}$

        - 带权周转 &gt;= 1.0
    - 平均带权周转时间：
      - 公式



        $t_{平均带权周转} = \frac{\sum t_{带权周转}}{n}$

  - 等待时间
    - 等待处理机状态的时间之和
  - 响应时间
    - 从用户提交到系统首次产生响应所用的时间
- 调度的实现
  - 配图

    <a href="/images/408-mind-maps/os-0051.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0051.svg" alt="调度的实现" width="240" height="116" loading="lazy" /></a>

    - 排队器：
      - 将系统中的所有就绪进程按照一定的策略排成一个或多个队列，以便于调度程序选择。
      - （变为就绪态就插入到就绪队列中）
    - 分派器：
      - 调度程序选择进程，分派器从就绪队列中取出
    - 上下文切换器：
      - 1\. 将当前进程的上下文保存到其PCB中，再装入分派程序的上下文，以便分派程序运行
      - 2\. 移出分派程序的上下文，将新选进程的CPU现场信息装入处理机的各个相应寄存器
- 调度算法：
  - FCFS
    - 先来先服务
      - FIFO队列
    - 有利于CPU繁忙型，不利于IO繁忙型

    - 饥饿，对长作业不利
    - 通过计算得出的进程所需的时间，不一定准确
  - 优先级：
    - 剥夺式/非剥夺式
    - 静态优先级/动态优先级
      - 静态：
        - 创建进程时确定的
      - 动态：
        - 运行时确定的
    - 优先级：
      - 系统 &gt; 用户
      - 交互 &gt; 非交互
      - I/O &gt; 计算
  - 高响应比：
    - 响应比越高，优先级越高



      $响应比R_p = \frac{t_{等待} + t_{要求服务}}{t_{要求服务}}$

      - 永远 &gt; 1
  - 时间片轮转：

## 同步与互斥

<a href="/images/408-mind-maps/os-0054.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0054.svg" alt="同步与互斥" width="48" height="48" loading="lazy" /></a>

- 同步的基本概念
  - 临界资源：
    - 一次只能有一个进程所用的资源
    - 访问过程
      - 进入区
        - 上锁
      - 临界区、<br>临界(代码)段
        - 进程中访问临界资源的那一段代码
      - 退出区
        - 解锁
      - 剩余区
    - 例如：
      - 公用队列
    - 反例：
      - 磁盘、内存、私有数据、可重入程序代码
  - 同步：
    - 破坏异步性，进程间的制约关系，用来协调进程的工作次序
    - 批注：制约关系
  - 互斥：
    - 四大原则
      - 空闲让进
        - 临界区空闲时，可以允许一个请求进入临界区使用临界资源
      - 忙则等待
        - 有进程在临界区其他进程必须等待
      - 有限等待
        - 保证有限时间内可以进入临界区
      - 让权等待
        - 当进程不能进入临界区时，应该释放处理机，防止忙等
          - 不是按次序进入哦
- 临界区互斥：
  - 软件实现
    - 单标志法：
      - 共享一个整形变量turn，turn = 0 则A进程使用，turn = 1 则B进程使用
        - 等turn = 0后，A进行运行，运行后turn = 1，但是B不运行，则A无法进行下次的运行
      - 违背空闲让进，如果一个不运行，另一个永远无法运行
    - 双标志先检查：
      - 设置一个flag\[\]来进行标明哪个进程正在临界区中
        - Pi:<br>while(flag\[j\]);<br>flag\[i\] = TRUE;<br>do ... ;<br>flag\[i\] = FALSE;<br>remainder section;
          - Pj:<br>while(flag\[i\]);<br>flag\[j\] = TRUE;<br>do ... ;<br>flag\[j\] = FALSE;<br>remainder section;
        - AB可能同时进入临界区（A设置了flag\[j\]后B立马就进入）
      - 违背忙则等待，可能同时进入临界区
      - 使用原语来完成检查+处理
    - 双标志后检查：
      - 相比较双标志先检测，把设置flag\[\]改到前面
        - Pi:<br>flag\[i\] = TRUE;<br>while(flag\[j\]);<br>do ... ;<br>flag\[i\] = FALSE
          - Pj:<br>flag\[j\] = TRUE;<br>while(flag\[i\]);<br>do ... ;<br>flag\[j\] = FALSE
        - AB若同时设置flag，则谁也进不了do
      - 会引发饥饿，两个进程同时设置了flag，导致双方都无法进入
    - Peterson算法：

      - 一个flag，一个turn
        - Pi:<br>flag\[i\] = TRUE; turn = j;<br>while(flag\[j\] &amp;&amp; turn == j);<br>do ... ;<br>flag\[i\] = FALSE
          - Pj:<br>flag\[j\] = TRUE; turn = i;<br>while(flag\[i\] &amp;&amp; turn == i);<br>do ... ;<br>flag\[j\] = FALSE
      - 主动争取 + 主动谦让 + 检测
        - 无法解决让权等待(不停的while，累死cpu)
  - 硬件实现
    - 中断屏蔽方法：
      - 使用关中断+临界区+开中断
      - 优缺点：
        - 优点
          - 简单高效
        - 缺点
          - 只适用单系统，只能用于内核程序
    - 硬件指令方法：
      - TestAndSet：先检测后上锁（原语）
        - 原语中查看之前的lock，并修改为自己的
        - bool TestAndSet(bool \*lock)\{<br>     bool old;<br>     old = \*lock;<br>     \*lock = true;<br>     return old;<br>\}
          - while(TestAndSet(&amp;lock));<br>执行;<br>lock = false;<br>其他代码;
        - 将双标志后检查法，进行原语实现
          - 无法解决让权等待
      - Swap：交换两个字内容（原语）
        - lock是全局的false，key是局部的true。在原语中，交换lock和key。
        - Swap(bool \*a, bool \*b)\{<br>// 交换AB<br>\}
          - key = true;<br>while(key != false)<br>    Swap(&amp;lock, &amp;key);<br>do....<br>lock = false;<br>...
        - 原理和TestAndSet一个样子
          - 无法解决让权等待
      - 优缺点：
        - 优点
          - 简单容易、支持进程内有多个临界区，只需要给每一个临界区设置一个bool就可以
        - 缺点
          - 进程等待的时候饥饿，无法解决让权等待
      - 信号量机制
- 互斥锁：
  - 这个的缺点就是【忙等】，会一直占用处理机进行循环



    ```text
    acquire() {
        while (!available)
            ;                    // 忙等
        available = false;       // 获得锁
    }

    release() {
        available = true;        // 释放锁
    }
    ```

    > 校注：原图为锁的概念伪代码；实际多线程实现需要原子操作，普通变量的检查和赋值并不保证互斥。



    - acquire()和release()都是原子操作
    - 单处理器：
      - 很蠢的方法，会一直占用CPU又无法解决
    - 多处理器：
      - 不错的方法，因为可能在自己这个时间片另一个CPU上的进程把锁release了

## 信号量：

<a href="/images/408-mind-maps/os-0124.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0124.svg" alt="信号量：" width="48" height="48" loading="lazy" /></a>

分组说明：题目不说，默认是对记录型信号量处理；对应：[记录性信号量：](#topic-5effe7ee-ece4-44f6-a83d-537e78f39865)

- 信号量可以用于解决互斥和同步问题，只能被Wait和Signal访问
  - Wait --- P，Signal --- V
  - Wait：等待S大于零的时候执行；可执行时S--
    - Signal：S++
  - PV操作是一种【低级进程通信原语】
    - 而不是系统调用命令
- 整形信号量：
  - wait(S) 和 signal(S)，<br>其中S是一个int数。
    - wait：S -= 1
    - signal：S += 1
  - 优点：
    - 解决了同步互斥
  - 缺点：
    - 不满足让权等待
- 记录性信号量：
  - int + 链表
    - wait: S -= 1; 把进程加入等待队列; 阻塞进程
    - signal: S += 1; 把进程从等待队列中移出; 唤醒进程

- Swait和Ssignal
  - 格式为：Swait(Si, ti, di; ...)
    - 对于信号量Si， 每次分配di（即Si = Si - di），如果Si &lt; ti了就不予以分配

## 管程：

<a href="/images/408-mind-maps/os-0109.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0109.svg" alt="管程：" width="48" height="48" loading="lazy" /></a>

- 管程最开始是在Pascal语言中引入的
  - 管程就像是一种语法，就像C里面类似static、const等，可以使用也可以不使用，但不可以创建和撤销
- 作用：
  - 大量的PV操作给OS的管理带来了麻烦，同步操作不当非常容易死锁。
  - 管程的特性保证了进程互斥，而无须程序员自己实现互斥，从而降低了死锁的可能性
  - 通过入口才能访问数据
  - 每次仅允许一个进程在管程内执行
- 定义：
  - 1\. 管程名称
  - 2\. 共享数据结构
  - 3\. 对该数据结构进行操作的一组过程
  - 4\. 对局部于管程内部的共享数据设置初始值
- 类似class数据结构，管程的变量全是private类型
- 未命名主题
- 未命名主题
- 未命名主题
- 设置条件变量：
  - 配图



    ```text
    monitor Demo {
        共享数据结构 S;
        condition x;  // 条件变量
        init_code() { ... }

        take_away() {
            if (S <= 0) x.wait();  // 资源不足，在条件变量上阻塞等待
            资源足够，分配资源，做一系列相应处理;
        }

        give_back() {
            归还资源，做一系列相应处理;
            if (有进程在等待) x.signal();  // 唤醒一个阻塞进程
        }
    }
    ```



  - 使用x来对阻塞队列进行挂载
    - x.wait()
      - 当x对应的条件不满足时，正在调用管程的进程调用x.wait将自己插入x条件的等待队列，并释放管程。此时其他进程可以使用该管程。
    - x.signal()
      - x对应的条件发生了变化，则调用x.signal,唤醒一个因x条件而阻塞的进程。
  - 注意管程的wait、signal和PV操作的区别：
    - PV操作一定会使信号量++或者--（不论是记录型还是整形）
    - 而管程的signal和wait只负责唤醒、阻塞进程（从阻塞队列中进行唤醒或插入到阻塞队列），不一定会有++--
  - 可以有多个condition x
    - 可以在一个管程中，管理多个共享资源
- 管程对于生产者<br>消费者问题的改进：

  - 配图

    monitor ProducerConsumer {

        int count = 0;         // 缓冲区中的产品数

        void insert(Item item) {
            if (count == n) wait(full);
            count++;
            insert_item(item);
            if (count == 1) signal(empty);
        }

        Item remove() {
            if (count == 0) wait(empty);
            count--;
            if (count == n - 1) signal(full);

    producer() {

        }
    }

- 生产者消费者
  - 问题描述：一组生产者进程和一组消费者进程共享一个初始为空、大小为n的缓冲区，只有 缓冲区没满时，生产者才能把消息放入缓冲区，否则必须等待；只有缓冲区不空时，消费者才能 从中取出消息，否则必须等待。由于缓冲区是临界资源；它只允许一个生产者放入消息，或一个消费者从中取出消息。
  - 生产者和消费者是合作协作的关系、同时生产者和消费者对缓冲区是互斥关系
  - 思路：使用两个信号量控制empty和full，一个信号量控制mutex互斥关系即可，缓冲区大小 &gt; 1
  - 配图



    ```text
    semaphore mutex = 1;  // 互斥访问缓冲区
    semaphore empty = n;  // 空缓冲区数，n 为缓冲区容量
    semaphore full = 0;   // 非空缓冲区数

    producer() {
        while (1) {
            produce an item in nextp;
            P(empty);
            P(mutex);
            add nextp to buffer;
            V(mutex);
            V(full);
        }
    }

    consumer() {
        while (1) {
            P(full);
            P(mutex);
            remove an item from buffer;
            V(mutex);
            V(empty);
            consume the item;
        }
    }
    ```

- 读写者问题
  分组说明：读写公平法；对应：[问题：可能会出现写者饿死的情况](#topic-0dbd0d4f-6f20-415b-b163-37958501ba8e)、[解决办法：写者申请写入后，读者便不可申请读](#topic-2f893505-1497-47b8-8bf0-b9bafce1802a)

  - 问题描述：有读者写者两个进程，共享文件。多个读者可以同时读文件。只能又一个写者写文件。存在有读者读文件时，不允许写者写。必须写者写完后才可以读。
  - 思路：写者比较简单，写者两两互斥，待读者全退出后写。读者两两不互斥，待写者写毕后进行读取
    - 1\. 使用 int 计数器来记录当前读者情况
    - 2\. 使用 信号量 来互斥访问计数器
    - 3\. 使用 信号量 来控制写者能否写入
  - 配图



    ```text
    int count = 0;        // 记录当前读者数
    semaphore mutex = 1;  // 保护共享变量 count
    semaphore rw = 1;     // 控制对共享文件的互斥访问

    writer() {
        while (1) {
            P(rw);
            writing;
            V(rw);
        }
    }

    reader() {
        while (1) {
            P(mutex);
            if (count == 0) P(rw);  // 第一个读者阻止写者
            count++;
            V(mutex);
            reading;
            P(mutex);
            count--;
            if (count == 0) V(rw);  // 最后一个读者允许写者进入
            V(mutex);
        }
    }
    ```

    - 不停的有读者到来
  - 解决办法：写者申请写入后，读者便不可申请读
    - 配图



      ```text
      int count = 0;
      semaphore mutex = 1;
      semaphore rw = 1;
      semaphore w = 1;  // 控制读、写请求进入次序

      writer() {
          while (1) {
              P(w);
              P(rw);
              writing;
              V(rw);
              V(w);
          }
      }

      reader() {
          while (1) {
              P(w);
              P(mutex);
              if (count == 0) P(rw);
              count++;
              V(mutex);
              V(w);
              reading;
              P(mutex);
              count--;
              if (count == 0) V(rw);
              V(mutex);
          }
      }
      ```

- 吸烟者
  - 问题描述：假设一个系统有三个抽烟者进程和一个供应者进程。每个抽烟者不停地卷烟并抽掉它，但要卷起并抽掉一支烟，抽烟者需要有三种材料：烟草、纸和胶水。三个抽烟者中，第一个拥有烟草，第二个拥有纸，第三个拥有胶水。供应者进程无限地提供三种材料，供应者每次将两种材料放到桌子上，拥有剩下那种材料的抽烟者卷一根烟并抽掉它，并给供应者一个信号告诉已完成，此时供应者就会将另外两种材料放到桌上，如此重复(让三个抽烟者轮流地抽烟)。
  - 分析：
    - 三种消费者分别只持有A, B, C三种资源，当有任意两种资源可使用时，哪个消费者应该去获得资源
  - 生产者：轮流产生（也可以使用random()来随机)



    ```text
    int num = 0;           // 当前轮换序号
    semaphore offer1 = 0;  // 烟草和纸
    semaphore offer2 = 0;  // 烟草和胶水
    semaphore offer3 = 0;  // 纸和胶水
    semaphore finish = 0;  // 是否抽完

    process P1() {  // 供应者
        while (1) {
            num++;
            num = num % 3;
            if (num == 0) {
                将烟草和纸放在桌子上;
                V(offer1);
            } else if (num == 1) {
                将烟草和胶水放在桌子上;
                V(offer2);
            } else {
                将纸和胶水放在桌子上;
                V(offer3);
            }
            P(finish);
        }
    }
    ```

    > 整理说明：原图把发出 offer 信号写在放置材料之前；改为先放好相应两种材料，再发对应信号，避免消费者提前被唤醒。

## 死锁

<a href="/images/408-mind-maps/os-0110.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0110.svg" alt="死锁" width="48" height="48" loading="lazy" /></a>

  - 09、11-16、18-22
- 死锁概念：
  分组说明：都是OS分配资源不合理导致；对应：[两个或两个以上的进程争夺资源](#topic-739900e7-784b-4ed0-a1fe-7a9fd417c333)、[两大原因：](#topic-ded8062f-d776-45d2-a219-1f5a65949843)

  - 两个或两个以上的进程争夺资源
    - 饥饿只是一个进程得不到资源
  - 两大原因：
    - 资源分配不合理
    - 进程推进顺序非法
- 产生的必要条件：<br>（死锁一定满足这四个，<br>这四个不可反推死锁）
  - 互斥条件
    - 资源不可同时被访问
      - 反例：扬声器、内存
  - 不剥夺
    - 未使用完时，不能被抢走
  - 请求+保持
    - 如果P1持有了A，P1也想要B；此时P1堵塞，也不释放A
  - 循环等待
    - 在资源分配途中，存在资源循环链
- 四种处理策略
  - 死锁预防
    - 破坏互斥：
      - SPOOLing技术
      - 缺点：
        - 有些资源根本不可以共享
    - 破坏不剥夺：
      - 可以进行剥夺
        - 自己堵塞，全部释放
        - 自己想要，强行抢占
      - 缺点：
        - 实现复杂，反复的申请和释放资源会增加系统开销
      - 特点：
        - 这种方法适用于【状态易于保护和恢复的资源】，例如CPU、内存等等
    - 破坏请求保持：
      - 一次申请完。不够就不要，够就直接运行
      - 缺点：
        - 系统资源容易被浪费，有些资源可能只有进程最开始用一下，后续也不释放
        - 导致饥饿
    - 破坏循环等待：
      - 给系统资源编号
      - 缺点：
        - 编号必须相对稳定
        - 经常会发生作业使用资源顺序和系统规定顺序不同，造成浪费
        - 按规定次序申请，会很难coding
    - 批注：事先预防(事先破坏)
  - 死锁避免
    - 银行家算法

  - 死锁解除
    - 资源剥夺法
      - 挂起某些死锁进程，剥夺资源分配给其他死锁进程。注意防止被挂起进程饥饿
    - 撤销进程法
      - 强制撤销部分/全部死锁进程并剥夺这些进程的资源。代价大，撤销按进程优先级进行
    - 进程回退法
      - 让一个或多个进程回退到足以避免的时刻。系统需要保持进程的历史情况
    - 批注：解除手段
  - 感觉死锁避免和检测的灵活性不够，银行家算法这种算法完全可以检测到死锁的，资源有向图这种数据结构也是完全可以提供进程使用资源的顺序的
  - 概要：系统只是提供检测和解除手段，不会有任何实质上的措施
    概要范围：[死锁检测](#topic-64234ada-7387-44ff-affc-629166437286)、[死锁解除](#topic-f056f7e4-3589-4d51-aa73-6e55a7c31103)

- 死锁与不安全态：
  - 不安全态 &gt; 死锁，如果系统中现在有些进程持有了很多资源正在运行，而且现在系统中的资源无法进行正常分配（不安全）。但是这些进程运行完毕释放资源后，就可以正常分配资源了（非死锁）

- 链接
  - 概念
    - 由链接程序把库函数和目标模块连着一起
      - 库代码也需要新分配空间
  - 静态链接
    - 程序运行前，把目标模块、库文件链接成同一个完整的装配模块，后不再拆开
  - 装入时动态链接
    - 程序在装入内存时，边进行装入边链接
    - 易于修改和更新，便于共享
  - 运行时动态链接
    - 程序装入时不进行链接，运行时才链接（动态链接库DLL）
    - 在执行过程中未被用到的目标模块，都不会被调入内存和被链接到装入模块上
    - 优点是能加快程序的装入过程， 还可节省大量的内存空间。
- 装入
  - 概念
    - 从逻辑地址更改到物理地址
  - 绝对装入
    - 代码中的逻辑地址与物理地址相同，编译时装入（只适用单道程序）
  - 可重定位装入<br>（静态重定位）
    - 程序执行之前，完成逻辑地址和物理地址的转换，运行时内存不移动也不再申请空间。
  - 动态运行时装入<br>（动态重定位）
    - 运行时才进行逻辑地址到物理地址的转化
    - 整个系统中只设计一个重定位寄存器，所有进程共享使用
  - 概要：只有装入到连续地址空间中，不能修改
    概要范围：[绝对装入](#topic-13eb999960da13f08e91693e86)、[可重定位装入<br>（静态重定位）](#topic-31baf3afe8794c8ee93928cac0)

  - 概要：不连续空间，装入部分代码即可运行，动态分配内存
    概要范围：[动态运行时装入<br>（动态重定位）](#topic-7118cccc0d293adf5ddf392232)

## 覆盖和交换

<a href="/images/408-mind-maps/os-0156.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0156.svg" alt="覆盖和交换" width="48" height="48" loading="lazy" /></a>

- 覆盖和交换
  - 覆盖：
    - 把内存分为固定区 + 覆盖区
      - 经常活跃的部分放在固定区中
      - 即将访问的段放在覆盖区中，其他放在外存
    - 固定区就是不可被覆盖的
    - 用于单一连续存储管理
  - 交换：
    - 换出：把处于等待状态的程序从内存移到辅存，就可以把内存空间腾出来
    - 换入：把准备好竞争CPU进程从辅存移动到内存
      - 中级调度
        [查看关联主题](#topic-68d33468-7769-4d76-927b-20546a7810ef)

    - 不同状态的进程<br>能否交换：
      - 创建态，可以
        - 即创建态 -&gt; 挂起态
      - 死锁，可以
        - 非常好
      - 处于临界区，不行
        - 因为这片临界区的访问会一直阻塞，直到该被挂起的进程重新恢复
      - 正在IO操作，不行
        - 如果是A进程Input阶段，则可能造成新的B进程交换后，输入设备覆盖掉了B进程的指令
- 可重入程序：
  - 法一：共享使用同一块存储空间
  - 法二：通过动态链接的方式将所需的程序段映射到相关的进程中
    - 最大的优点：减少了程序段的调入调出

## 连续分配

<a href="/images/408-mind-maps/os-0048.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0048.svg" alt="连续分配" width="48" height="48" loading="lazy" /></a>

- 连续分配和非连续分配：装入
- 内部、外部碎片
  - 程序使用的空间、程序申请的空间、内存总空间
  - 内部碎片：程序申请空间 - 程序使用的空间
  - 外部碎片：内存总空间 - 程序申请空间
- 单一连续分配
  - 一个内存空间只给一个进程使用
  - 优点：
    - 简单、无外部碎片、采用覆盖技术
  - 缺点：
    - 单用户、单任务、有内部碎片、利用率低
- 固定分区分配
  - 分区大小相同
    - 将内存空间划分为若干固定大小的区域
  - 分区大小不同
    - 划分为多个小分区、适中中分区、少量大分区
  - 分区说明表
    - （分区号） \| 大小/KB 、始址/KB、状态



      **分区使用表**

      |分区号|大小 / KB|起址 / KB|状态|
      |---:|---:|---:|---|
      |1|12|20|已分配|
      |2|32|32|已分配|
      |3|64|64|已分配|
      |4|128|128|未分配|

      **空间分配情况（地址向下递增）**：OS 从 0 开始；作业 A 从 20 开始；作业 B 从 32 开始；作业 C 从 64 开始；128～256 为未分配区。



  - 优点：
    - 多道程序设计、无外部碎片
  - 缺点：
    - 程序太大，分区装不下
    - 主存利用率低，很多内部碎片
    - 没有内存共享能力
- 动态分区分配
  - 配图

    <a href="/images/408-mind-maps/os-0061.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0061.svg" alt="动态分区分配" width="240" height="74" loading="lazy" /></a>

  - 记录存储内存使用情况
    - 内存分区链、内存分区块
    - 分区表
      - (分区号) \| 大小/KB、始址/KB、状态
  - 分配回收
    - 动态分区分配算法
      - 首次适应
        - 找到第一个满足的就行
          - 最好的
      - 最佳适应
        - 找到最小满足的一个（排序）
      - 最坏适应
        - 找到最大满足的一个（排序）
      - 邻近适应
        - 首次适应 + 指针不回溯
    - 回收（4种）
      - 紧凑技术
      - 分区前面有一块
        - 改前一块的大小
      - 分区后面有一块
        - 改后一块的大小 + 始址
      - 分区前后都有
        - 合并前后两块，改大小
      - 分区前后都无
        - 新增一块
  - 分配流程：
    - 系统在初始化后除操作系统占据一部分内存外，其余部分都是【自由空间】。作业申请内存时候，OS分配一个大小相当的内存过去，将作业创建为进程，在作业运行完毕后，在释放内存
      - 申请内存阶段就是装入阶段

      - 页表项结构

## 虚拟内存

<a href="/images/408-mind-maps/os-0124.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0124.svg" alt="虚拟内存" width="48" height="48" loading="lazy" /></a>

- 考频：超高
  - 11\*2、12、13、14\*2、15\*2、16\*2、19、20、21\*2、22\*2、09大、10大、12大、15大、17大、18大、20大
- 为什么使用虚拟内存
  - 若同时运行的进程太多，则需要很多的内存，当一个程序没有内存空间可用时，那么它甚至无法运行。 所以，在物理上扩展内存相对有限的条件下，应尝试以一些其他可行的方式在逻辑上扩充内存。
- 虚拟内存的空间大小约束
  - 实际容量 ≤ 内存+外存
    - 硬件硬性要求
  - 最大容量 ≤ 计算机地址位数容纳的最大容量
    - 例如32位地址系统，虚存最大为2^\{32\} B
  - 概要：需要两种都满足
    概要范围：[实际容量 ≤ 内存+外存](#topic-ff647a53-943f-42f7-bef9-5e4ebfaa9a4c)、[最大容量 ≤ 计算机地址位数容纳的最大容量](#topic-33082e69-32db-4335-b31e-0ad239f87215)

- 虚存的好处和缺点
  - 好处：使用了外存空间扩充了内存空间，通过一定程度的换入换出使得整个系统在逻辑上能够使用一个远远超出其物理内存大小的内存容量
  - 缺点：虚拟内存技术调换页面时需要访问外存，会导致平均访存时间增加，若使用了不合适的替换算法，则会大大降低系统性能
- 虚拟内存的基本概念
  - 传统存储管理方式
    - 一次性
      - 程序一次性全部装入内存
        - 程序大，运行不了
        - 程序多，并发度低
    - 驻留性
      - 程序直至运行结束才会被换出内存
  - 局部性原理
    - 时间局部性
      - 某条指令被执行，不久会再被执行
    - 空间局部性
      - 访问了某条指令，其相邻的代码/指令也会很快被访问
  - 虚拟存储器的定义和特征
    - 特点：
      - 分内余外
        - 部分装入内存，其余留在外存
      - 内需调入
        - 程序执行过程中，所访问的信息不在内存，需要OS把信息调入到内存中
      - 空闲调出
        - OS将内存中暂时不需要的内容换出到外存
    - 多次性
      - 作业无须运行时全部装入内存，可以分多次完成装入
    - 对换性
      - 作业无须常驻内存，可以在运行过程中换入换出
    - 虚拟性
      - 逻辑上扩充内存的容量
  - 虚拟内存技术的实现
    - 要建立在
      - 非连续分配的情况下
    - 三大虚拟内存实现方式
      - 请求分页存储
      - 请求分段存储
      - 请求段页式存储
      - 概要：与非请求模式的区别：采用了虚拟内存的技术，不需要把页/页面全部都先放入内存中，而是在运行中检测到缺页再去外存中读取
        概要范围：[请求分页存储](#topic-8c060148-60be-4d71-8573-4c881b912511)、[请求分段存储](#topic-3c80ad87-deb3-4973-8b0b-3f7e62485a72)、[请求段页式存储](#topic-4612f6a1-880c-4e10-bf77-9906dbc04f13)

    - 需要的四个硬件支持
      - 一定的内外存
      - 页表/段表数据结构
      - 中断机制
      - 地址变换
- 请求分页管理
  - 页表机制
    分组说明：在非虚拟存储的页表、段表是基本固定的，而虚拟存储的页表要实时记得要不要修改页表项；对应：[配图／公式](#topic-af16649f-b034-473f-b1b3-ded2b016ba09)

    - 配图

      <a href="/images/408-mind-maps/os-0120.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0120.svg" alt="页表机制" width="240" height="41" loading="lazy" /></a>

  - 缺页中断机构
    - 内存有空闲块
      - 直接分配空闲块给缺页部分，修改【页表】
    - 内存无空闲块
      - 通过算法淘汰某页
        分组说明：容易忘；对应：[【若被修改了，写回外存】](#topic-085c5da7-4fb5-4fe6-8f57-897773b17273)、[【若该页也存在于快表中，一并删除】](#topic-e9641430-9227-4b12-b98b-871677a4a9ee)

        - 【若被修改了，写回外存】
        - 【若该页也存在于快表中，一并删除】
  - 地址变化机构

- 页面分配策略
  - 调入页面的时机
    - 预调页
      - 根据局部性原理，一次调入若干相邻的页
      - 成功率不高，进程首次调入时，由程序员指定预调页
    - 请求调页
      - 运行时进行调页
  - 从何处调用页面
    - 外存结构
      - 对换区 + 文件区
        - 对换区是连续分配
        - 文件区是离散分配
    - 系统有足够对换区
      - 直接 内存 ↔ 对换区
    - 系统没有足够对换区
      - 不会被修改的：文件区 → 内存
      - 会被修改的：对换区 ↔ 内存
    - Unix方式
      - 首次都是 文件区 → 内存
      - 其余 对换区 ↔ 内存
      - 配图

        <a href="/images/408-mind-maps/os-0116.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0116.svg" alt="Unix方式" width="240" height="175" loading="lazy" /></a>

  - 驻留集大小
    - 驻留集：
      - 分配给进程的物理块大小（OS概念）
    - 固定分配 VS 可变分配
      - 固定：每个进程的驻留集刚开始就确定
      - 可变：每个进驻留集是可变的
    - 局部置换 VS 全局置换
      - 局部：缺页时，进程先自己进行页面置换，OS不干预。根据进程的缺页率，OS再进行空闲块分配的
      - 全局：进程缺页，OS直接送一块
        - 如果没有空闲块，就选择”未锁定”的页面置出外存
    - 联合：
      - 固定分配局部置换
        - 驻留集大小不变，自己内部置换
      - 可变分配全局置换
        - 驻留集大小可变，缺页就给你新的
      - 可变分配局部置换
        - 最好，灵活调配，缺页率高就给新的，低就拿走
  - 批注：页框分配
- 页面置换算法
  - OPT
    - 最佳置换算法
    - 无法实现、找最长时间不被访问的块置换（作为算法的评价标准）
  - FIFO
    - 先进先出
      - 队列类算法
        - 会出现Belady异常：总分配的内存物理块（内存块）数增加，导致缺页率也会增加
    - 实现简单，性能差
    - 与首次适应进行区分
      [查看关联主题](#topic-5513bb3e-fa4a-4526-bb99-427df688483e)

    - LAST RECENTLY USED

          - 批注：底层实现
        - 批注：考试做法
  - CLOCK
    - 简单CLOCK（NRU算法）
      - 只使用访问位
        - 第一轮扫描的时候，把访问位为0的换出，边扫描边把访问位全部置为0。进行第二轮扫描
    - 改进CLOCK置换算法
      - 使用访问位 + 修改位
        - 优先淘汰没有被修改过的页面
        - 四级访问：
          - （书中的P用的A来表示）
          - P = 0，M = 0
            - 未访问，未修改
          - P = 0，M = 1
            - 未访问，有修改
              - 本次扫描结束后把所有的P都改为0，然后重复扫描
          - P = 1，M = 0
            - 访问过，未修改
          - P = 1， M = 1
            - 访问过，修改过
          - 概要：如果会搜到这里，P其实已经更改为0了
            概要范围：[P = 1，M = 0](#topic-7b4cb26b-b605-4358-a1cc-6320e4c7b82e)、[P = 1， M = 1](#topic-d71be280-7338-491d-a3c5-386c8821fea1)

- 抖动 &amp; 工作集
  - 抖动定义
    - 刚换出的马上要换入主存，刚换入的马上要换出
    - 产生原因：
      - 某个进程频繁访问的页面数目高于可用的物理页面帧数
    - 解决办法：
      - 工作集
  - 工作集W和时间t和工作窗口大小delta
    - 基于局部性原理，OS实时跟踪进程，用最近访问过的页面来确定工作集。例如在t1时刻，工作集窗口大小为5，窗口内的页面是2, 3, 5, 3, 2，此时工作集为\{2, 3, 5\}
      - 随后操作系统为进程分配【 &gt; 工作集的驻留集】大小，就会保证不抖动
      - 拓展：
        - 有些OS会根据工作集来设计页面置换算法，根据进程近期访问的页面来确定换什么页面
  - 工作集和驻留集关系
    - 工作集  &lt; 驻留集
- 内存共享、内存映射文件
  - 页框分配：
    - 即页面分配策略，连续、非连续分配
  - 内存映射文件：
    - mmp, Memory-Mapped File
    - 通过内存映射，使得多个进程的某一个虚拟进程地址区域对应内存中同一个物理地址区域
  - 虚存性能因素：
    - 缺页率是影响虚存性能的最主要因素
    - 提高性能的办法
      - 设置好页面大小
        - 太大会增加内部碎片
        - 太小会使得缺页率高、页表过长
      - 设置好工作集、驻留集
      - 设置好LRU、CLOCK置换算法
      - 提高程序的局部性
    - 概要：TLB、Cache命中率都没有这么主要
      概要范围：[缺页率是影响虚存性能的最主要因素](#topic-293f8f1f-3303-4081-9c62-ed1f0732435e)

      - 保存在内存中，很不安全
  - 加密保护
    - 优点：
      - 保密性强
    - 缺点：
      - 编码、译码需要一定时间
  - 访问控制
    - 访问控制列表：
      - 英文：
        - ACL
      - 根据用户身份进行控制，给每个文件和目录增加ACL，规定了不同的用户的访问类型。
      - 【精简】的访问控制列表：
        - 拥有者
          - 创建文件的用户
        - 组
          - 需要共享文件且具有类似访问的用户
        - 其他
          - 系统内的所有其他用户
    - 缺点：
      - 内容太多，使用精简可以解决问题
    - 相比加密保护保密性更差，但更灵活
    - 访问文件的限制因素：
      - 用户访问权限 + 文件属性
      - 用户优先级与能否访问文件无关
  - 系统级安全管理：
    - 登录注册

- 创建
  - 从外存中找到文件对应大小的【磁盘空间】
  - 创建该文件对应的【目录项】

  - 如果存在其他硬链接：
    - 修改FCB的文件链接数
  - 不存在硬链接：
    - 删除文件的目录项
    - 删除该文件的FCB
    - 释放与此文件相关的内存缓冲区
    - 回收文件磁盘空间
- 打开(目录)文件
  - 主要工作：
    - 1\. 找到文件对应的目录项
    - 2\. 把目录项复制到内存中的打开文件表中

      <a href="/images/408-mind-maps/os-0145.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0145.svg" alt="2. 把目录项复制到内存中的打开文件表中" width="240" height="139" loading="lazy" /></a>

    - 3\. 随后用户就可以使用打开文件表中的编号来指明要操作的文件
    - 把文件目录调入到内存中（调入 --- 复制到内存中）
  - 指令：
    - open(char\* path, char\* fname, int access) -&gt; int
      - path：文件路径
      - fname：文件名
      - access：指明了是只读、只写、读和写
      - 返回的int：文件唯一标识符fd
- 关闭
  - 回收分配给文件的【内存空间】
  - 系统中的“打开文件表“中count - 1。如果count == 0，则删除对应表项
- 读文件
  - 通过文件的目录结构，如果找到了文件的逻辑地址（即已经在内存中了），直接访问内存
  - 通过文件的目录结构，发现数据不在内存中，则进程进入到阻塞态，请求调页。
  - 指令：
    - read(int fd, int\* buf, int n)
      - fd：文件唯一标识符
      - buf：缓冲区始址
      - n：读入的字节数
- 写
  - 找到文件、打开文件、读取文件（记事本需要显示已记录的内容）
  - 在内存区域中修改了文件数据后，使用write系统调用写入到磁盘中
- 复制
  - 文件在同一个OS中复制时，应保证逻辑结构不变，但物理结构可变
- 重定位
  - 按某条件搜索目录，将当前文件位置设为给定值，并且不会读、 写文件。
- 截断
  - 允许文件所有属性不变，并删除文件内容，即将其长度设为0并释放其空间。
- 提高文件访问速度
  - 下列优化方法中，可以提高文件访问速度的
  - 提前读
    - 提前读是指在读当前盘块时，将下一个可能要 访问的盘块数据读入缓冲区，以便需要时直接从缓冲区中读取，提高了文件的访问速度
  - 为文件分配连续的簇
    - ✅
  - 延迟写
    - 延迟写是指先将数据写入缓冲区，并置上“延迟写"标志，以备不久之后访问，当缓冲区需要再次 被分配出去时，才将缓冲区数据写入磁盘，减少了访问磁盘的次数，提高了文件的访问速度
  - 采用磁盘高速缓存
    - ✅

## 文件分配方式（物理结构）

<a href="/images/408-mind-maps/co-0152.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0152.svg" alt="文件分配方式（物理结构）" width="48" height="48" loading="lazy" /></a>

- 连续分配
  - 配图

    <a href="/images/408-mind-maps/os-0140.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0140.svg" alt="连续分配" width="240" height="198" loading="lazy" /></a>

  - 原理：
    - 每个文件在磁盘上占有一组连续的块，在外存中是【连续分配】
  - 目录表：
    - &lt;文件名、起始盘块号、长度&gt;
  - 支持的访问类型：
    - 顺序访问、直接访问
  - 优点：
    - 寻道数、寻道时间最短
      - 磁盘章节
  - 缺点：
    - 文件长度不可动态增加
    - 只适用于长度固定的文件
  - 只有连续分配会出现碎片
    - 谈速度时，连续分配不管是顺序存取还是随机存取都是最快的
- 链接分配
  - 原理：
    - 从起始盘块号开始访问，一块一块的找，采用离散分配的思路查找文件
  - 支持的访问类型：
    - 顺序访问
      - 不能直接访问
  - 隐式链接
    - 在每一个盘块的末尾都存有一个【指向下一个盘块】的指针

      <a href="/images/408-mind-maps/os-0152.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0152.svg" alt="在每一个盘块的末尾都存有一个【指向下一个盘块】的指针" width="240" height="197" loading="lazy" /></a>

    - 目录表：
      - &lt;文件名、起始盘块号、末尾盘块号&gt;
    - 缺点：
      - 稳定性不够，容易丢失数据
      - 指针会消耗空间
      - 只能顺序访问，有大量的IO，很费事
  - 显式链接
    - FAT表

      <a href="/images/408-mind-maps/os-0136.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0136.svg" alt="FAT表" width="240" height="209" loading="lazy" /></a>

    - 目录表：
      - 文件名、起始盘块号
    - 文件分配表：
      - 英文：
        - FAT
      - 内容：
        - 下一块的号码
          - 不存有盘块号
        - 如果是最后一块就是-1，如果没有被分配就是-2
    - FAT在启动时：
      - 和文件目录表一样，刚启动就被导入内存，所以很明显的提高了检索速度
    - 缺点：
      - 每次启动的时候都要把FAT读入内存，若FAT很大，则会占用大量的内存
    - 身兼数职，还可以负责管理磁盘的空闲空间
      - 磁盘章节，-2就是空闲盘块
- 索引分配
  [查看关联主题](#topic-3fd88bd47d2a95e31c3d0969c2)

  - 配图

    <a href="/images/408-mind-maps/os-0135.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0135.svg" alt="索引分配" width="240" height="183" loading="lazy" /></a>

  - 原理：
    - 【每个文件对应有一个索引表】，内存中的文件目录表存的是每个文件对应的索引表块号，当要访问一个文件的时候，首先把该文件【的索引表从外存读入内存】
  - 目录表：
    - &lt;文件名、索引表块号&gt;
  - 索引表：
    - 顺序地存有文件的块号
  - 优缺点：
    - 优点：
      - 支持随机、顺序存取
      - 文件拓展很方便
      - 比起显示链接，不需要把索引表同时存入到内存中
    - 缺点：
      - 如果程序很大的话，一个块大小的索引表不够用
  - 缺点优化：
    - 链接方案：
      - 如果一个块大小的索引表存不够，那么索引表最后就指向下一个索引表的块
    - 多层索引：
      - 和多级页表一样，首先访问一级索引表，然后再访问二级索引表
    - 混合索引
- 混合索引：
  - 配图

    <a href="/images/408-mind-maps/os-0003.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0003.svg" alt="混合索引：" width="240" height="218" loading="lazy" /></a>

    - 一个索引表中，存在
    - 1\. 直接地址（直接指向一个块）
      - i.addr(0) ~ i.addr(9)
    - 2\. 一级间接（指向一个索引表）
      - i.addr(10)
    - 3\. 二级间接（指向一个二级索引表）
  - 批注：inode
- 如果访问一个文件中第n块中的记录：
  - 连续分配
    - 只需访问一次磁盘
  - 链接分配
    - 隐性
      - 需要访问n次磁盘
    - 显性
      - 需要访问1次磁盘
  - 索引分配
    - 访问两次磁盘（一次读索引表，一次读文件）
    - 可能存在超过两次访问（如果索引表一块磁盘装不下）

  - 字符设备接口

  - 块设备接口

    - 由图可知：
    - 1\. 一个I/O控制器，管理多个IO设备
      - 一个I/O设备中，也可以连接多个I/O控制器（多通路IO系统）
    - 2\. 每个I/O控制器中可以有多个(相同或不同的)寄存器。

    - 向CPU报告设备状态
      - 【状态寄存器】，表示空闲忙碌
    - 数据交换
      - 读写数据都放到【数据寄存器】
    - 地址识别
      - 把逻辑IO寄存器地址翻译为物理地址，通过【地址线】进行传输
    - 概要：【数据寄存器】<br>【控制寄存器】<br>【状态寄存器】<br>【地址线】<br>【控制线】
      概要范围：[接受和识别CPU命令](#topic-426a34e02c986d127e5ce9ec71)、[向CPU报告设备状态](#topic-9e788de5a589482d30aac821c4)、[数据交换](#topic-fcf9829b6d8b5405f30f7a92b0)、[地址识别](#topic-f599b47a60f8f4e996b48a775c)

      - 四个寄存器的作用：
      - DR：
        - Data Register，用于暂存设备和内存交换的数据
      - MAR：
        - Memory Address Register，指明内存的起始地址

- 总结：中断时机
  - 程序直接控制方式
    - 没有中断：CPU定期轮询检查I/O操作是否完成
  - 中断控制方式
    - 中断发生的时机：每完成一个字的读写（CPU完成的读写），I/O控制器向CPU发出一个中断信号
  - DMA控制方式
    - 中断发生的时机：CPU向DMA控制器指明读写操作相关参数，每完成一整块数据的读写（DMA完成的读写），DMA控制器向CPU发出中断信号
  - 通道控制方式
    - 中断发生的时机：CPU向通道指明通道程序在内存中的地址，通道执行完通道程序后，通道向CPU发出中断信号

## 高速缓存和缓冲区

<a href="/images/408-mind-maps/co-0033.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0033.svg" alt="高速缓存和缓冲区" width="48" height="48" loading="lazy" /></a>

- 磁盘高速缓存
  - Disk Cache
  - 概念：
    - 将一个指令又存在内存中，又存在磁盘中
  - 作用：
    - 提高I/O的速度，访问更高效
      - 例如进程的指令既在磁盘中，也在内存中，同时还在CPU一级二级cache中
  - 形式：
    - 1\. 在内存中【单独开辟空间】，大小固定
    - 2\. 把未利用的内存空间作为【缓冲池】，供请求分页和IO共享
- 缓冲区
  - 目的：
    - 1\. 缓和CPU和I/O的速度矛盾
    - 2\. 减少CPU中断频率
    - 3\. 解决数据粒度不同
      - 例如CPU一次产生一个块，I/O一次只能读一次char
    - 4\. 提供CPU和I/O的并行
  - 实现方法：
    - 使用硬件缓冲区，成本太高，一般不用
    - 采用内存缓冲区
      - 采用缓冲技术
  - 需要缓冲的例子：
    - 鼠标、键盘
      - 若有更高优先级的进程到来，鼠标点击事件不应被丢失，则放在buffer中
    - 多任务的磁盘驱动器、磁带驱动器
    - 图形卡
      - 图形学开篇，使用双缓冲来实现图像更换
  - 若无特殊说明，缓冲区大小为一个块
  - 高速缓存和缓冲区的对比

    - 滞后写：在需要把A写回时，先不写回，先挂载到buffer中，直到这块buffer需要使用再写回

## 设备的分配和回收

<a href="/images/408-mind-maps/co-0017.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0017.svg" alt="设备的分配和回收" width="48" height="48" loading="lazy" /></a>

- 三种分类：
  - 独占
    - 打印机
  - 共享
    - 磁盘
  - 虚拟
    - SPOOLing技术
- 数据结构：
  - DCT：
    - 一个DCT表就表征一个设备，表中内容就是设备的各个属性
    - 称为：
      - Device Control Table 设备控制表
    - 内容：
      - 设备类型type
      - 设备标识符: deviceid
        - 唯一id
      - 设备状态：等待/空闲
      - 指向控制器的指针
        - 用来找该设备对应的I/O控制器
          - 父级指针
      - 重复执行次数或时间
        - I/O设备会在自己发现执行失败了很多次以后才会认定为I/O失败
      - 设备队列的队首指针
        - 指向正在等待该设备的【进程队列】
          - 如果一个进程想要使用这个设备，那么就把该进程的PCB插入到该设备对应的DCT的设备队列中
  - COCT：
    - 用来管理众多DCT，因为【一个控制器会管理多个设备】
    - 称为：
      - Controller Control Table 控制器控制表
    - 内容：
      - 设备标识符: controllerid
      - 设备状态：等待/空闲
      - 指向通道的指针
        - 父级指针
      - 控制器队列的队首指针
      - 控制器队列的队尾指针
      - 概要：指向正在等待该控制器的【进程队列】
        概要范围：[控制器队列的队首指针](#topic-c4a865d716a932a8c2beea7671)、[控制器队列的队尾指针](#topic-d5fb12b89b193509c6137b4481)

        - 如何插入的不做深究
  - CHCT：
    - 用来管理众多COCH的，一个通道管理很多个控制器
    - 称为：
      - Channel Control Table 通道控制表
    - 内容：
      - 设备标识符: channelid
      - 设备状态：等待/空闲
      - 控制器队列的首地址
        - 孩子节点，找到第一个相连的控制器
      - 通道队列的队首指针
      - 通道队列的队尾指针
  - SDT：
    - 整个系统只有一个SDT表，管理所有物理设备
    - 称为：
      - System Device Table 系统设备表
    - SDT是一个表，每一个设备就占一个表项（前面的同理）
    - 内容：
      - 设备类型
      - 设备标识符
        - 物理设备名
      - DCT
      - 驱动程序入口
  - 设备分配的步骤：
    - 1\. 根据进程请求的【物理设备号】去查SDT的【设备标识符】，获得对应DCT
      - 如果请求的是【逻辑设备号】，就去查SDT的【设备类型】
    - 2\. 找到DCT，如果设备忙碌(【设备状态】)就挂到等待队列，如果不忙碌就获得该设备
      - 将该逻辑设备的&lt;逻辑设备名、物理设备名、驱动程序入口地址&gt;加入到LUT表中
    - 3\. 根据DCT去找【父指针】，找到COCT，控制器忙碌就挂，不忙就用
    - 4\. 根据COCT去找【父指针】，找到CHCT，忙挂闲用
    - 只有上述四个步骤都分配完成才算成功
      - 使用【物理设备号】请求不如【逻辑设备号】好
  - 概要：配图
    概要范围：[SDT：](#topic-85e992bb1488ab7eb20dda63ec)

    <a href="/images/408-mind-maps/os-0082.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0082.svg" alt="数据结构：" width="240" height="160" loading="lazy" /></a>

- 设备分配策略：
  - 设备分配方式：
    - 静态分配
      - 作用：
        - OS一次性分配该作业需要的所有设备、控制器、通道信息
      - 死锁：
        - 不会”死锁“，破坏了”请求保持“
    - 动态分配
      - 作用：
        - 通过进程需求来提供设备
      - 死锁：
        - 有可能”死锁”
  - 设备分配算法：
    - 先请求先分配
    - 优先级高优先
- 逻辑名到物理名的映射：
  - LUT：
    - 名称：
      - 逻辑设备表
    - 表项：
      - 逻辑设备名、物理设备名、驱动程序入口
    - 单用户：
      - 每个设备都在这个LUT中，不运行出现相同的逻辑设备名
    - 多用户：
      - 每个用户在登录时，系统会给用户【创建一个进程和一个LUT】，这个LUT会放入到PCB中

    - spooling技术本质上是添加了一个消息队列+异步执行+完成回调，可以让一个独占资源变成共享资源的一个功能

  - vs 请求分页系统：时间换空间

  - 概念：
    - 计算机启动时会从引导块中读入一个初始化程序（自举程序）
  - 初始化程序作用：
    - 初始化程序可以初始CPU、寄存器、设备控制器、内存etc，然后可以启动操作系统
  - 自举程序存储位置：
    - 【自举程序】存在ROM中<br> 或：<br>【自举装入程序】在ROM中，完整的自举程序在磁盘启动块（引导块）上，一般是在一个固定的位置
  - 拓展
    - 引导控制块
      - 包含OS从该分区引导OS所需要的信息
      - UFS中称为引导块，NTFS中称为分区引导扇区
    - 分区控制块
      - 包含分区信息（分区块数、块大小、空闲块情况）、空闲FCB数量、指针
      - UFS称为超级块、NTFS称为主控文件表
- 坏块
  - 简单磁盘
    - 在FAT中标明，程序不会使用它
  - 复杂磁盘
    - 磁盘控制器维护一个磁盘坏块链表，同时会有一些块用来作为备用（扇区备用）

- 可以优化的
  - 延迟时间
    - 平均：
      - 1/2r
    - 有关：
      - 磁盘空闲空间分配程序
        - 是否错位编号
          - 程序规定的分配方式是直接分配相邻块（每次读取的旋转时延为一整圈）
          - 若是相邻一个分配（每次读取的旋转时延为一个簇）
      - 物理结构
        - 是连续分配还是链接分配
        - 连续分配：可以只转圈
        - 链接分配：可能需要换柱换盘块
    - 数据处理时间的影响：
      - 会影响间隙大小，其实影响不大
  - 寻道时间
    - 有关：
      - 磁盘调度算法
- 调度算法
  - FCFS算法
    - 根据进程请求访问磁盘的先后顺序进行调度
    - 优点
      - 公平、简单
    - 缺点
      - 平均寻道距离大，I/O较少可以使用
  - SSTF算法
    - 调度处理的磁道是与当前磁头所在磁道距离最近的磁道
    - 优点
      - 性能比FCFS好（贪心算法）
    - 缺点
      - 可能出现“饥饿”现象
  - SCAN算法
    - （电梯调度算法）
    - 磁头【当前移动方向】上选择与当前磁头所在磁道距离最近的请求作为下一次服务的对象
    - 优点
      - 性能好，不会有“饥饿”
    - 缺点
      - 不利于远离磁头一端的访问
    - LOOK调度
      - 不用扫到两端，扫到最左/最右的磁盘请求就行
  - C-SCAN算法
    - 回返时直接快速移动至起始端而不服务任何请求
    - 优点
      - 磁道请求公平
    - C-LOOK调度
      - 同理
  - 磁臂黏着
    - 只有FCFS没有，如果在算法访问某个磁道时，这个磁道又进行了请求，就会一直被访问
      - 很诡异，记住就行
  - 概要：若无特殊说明，默认采用LOOK而不是SCAN（C-LOOK / C-SCAN）
    概要范围：[SCAN算法](#topic-31475d43-cff5-4838-aedf-ea7aacf767ce)、[C-SCAN算法](#topic-af51976e-c5c8-4747-bc67-b862affcc446)

- 错位编号
  - 同一盘面
    - 同一盘面，物理地址相邻的扇区，在磁盘中应交错存放（留一些处理时间给磁头）
  - 不同盘面
    - 同柱面不同盘面的扇区错位编号，可以缩短连续读写两个相邻盘面的时间

## 固态硬盘SSD

<a href="/images/408-mind-maps/os-0070.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0070.svg" alt="固态硬盘SSD" width="45" height="46" loading="lazy" /></a>

- 基于闪存的存储器
  - 存储介质：NAND颗粒
- 读写速度比较：
  - 配图

    <a href="/images/408-mind-maps/co-0101.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0101.svg" alt="读写速度比较：" width="240" height="99" loading="lazy" /></a>

    - （硬件茶谈）
- 组成：
  - 闪存翻译层 + 多个闪存芯片

    <a href="/images/408-mind-maps/os-0033.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0033.svg" alt="闪存翻译层 + 多个闪存芯片" width="240" height="142" loading="lazy" /></a>

    - 读写单位
      - CPU下令要读取一个块的内容
      - SSD的读取单位：一个页
        - SSD接受到这个块的地址
        - SSD的闪存翻译层把它翻译为SSD中对应的数个页的地址
        - SSD把这些页的数据发到IO总线上，返回CPU
      - 具体大小：机械磁盘的一个块大小可能在1KB；SSD的一个页大小是512B~4KB，一个块中有32~128个页
    - 批注：市面上的厂家的SSD都有一个缓存
- 读写原则：
  - 读：以一个页为单位来读 ✅
  - 写：以一个页为单位来写
    - 擦除：以一个块的单位来擦除
    - 擦除方法：先把要写那页的整块复制到另一块，然后再擦除原来那块
      - 复制过后，在闪存翻译层中会建立新的： ‘逻辑地址’ —— ‘物理地址’ 的转换关系
    - 擦除的缺点：
      - 擦除多了会造成磨损
- 平均磨损
  - 静态平均：
    - SSD在进行擦除后的数据迁移的时候，会让寿命比较老的闪存块担任“读”的责任，让新的闪存块担任“写”的责任
  - 动态平均：
    - 在SSD写入新数据的时候，会优先选择磨损次数少的块进行写入
  - 概要：静态平均的效果比动态平均效果更好
    概要范围：[静态平均：](#topic-4cb781e0-0e11-4194-a174-fd1081dd0f1a)

- 考频：低
  - 无
