# 6.6 总线事务：阶段与突发

## 一次共享总线事务的典型阶段
- **申请与分配**：发起方请求总线；仲裁器/协议决定使用者
- **寻址与命令**：输出目标地址和读/写/长度等控制
- **传输数据**：读事务由目标方返回数据；写事务由发起方送数据
- **结束与释放**：完成确认/撤消控制/释放共享通路
- 不是所有协议都严格按这四阶段**独占一整段总线**
  - 某些事务可流水化；地址与数据相位可拆开
  - 接收方也可能通过握手控制传输节拍

## 总线读 vs 总线写
- 读：发起方提供地址 → 目标方提供数据
- 写：发起方提供地址与要写入的数据 → 目标方接收并可能应答
- “读总线”并非地址线的数据方向反过来

## 突发传输 burst
- 只描述一次事务中多个连续数据节拍的发送方式
  - 通常只需发送一次首地址/启动信息，按协议递增目标地址
  - 连续数据**依然占用多个节拍**；不是“一时钟送完整块”
- <img src="/images/408-mind-maps/co-06-burst-comparison.svg" alt="非突发四次独立地址数据事务，对比一次突发首地址加四个连续数据节拍" width="760" height="310">
- 在相同带宽、相同延迟前提下省去重复的地址/启动开销
- 具体是否也节约等待周期由内存系统和题目约束决定

## 连续事务流水与突发的不同
- 连续事务：多次独立事务也可能地址/数据交叠
- 突发：一次事务包含多个顺序数据beat
- **不能**仅根据“突发”推断总线时钟频率提高

## 分离事务 split transaction
- 请求方发出请求、释放总线；目标处理完成后再竞争/使用总线返回结果
- 高延迟设备准备数据期间，其他设备可以占用共享通路
- 侧重点：**释放等待中的总线使用权**，提高利用率
- 与burst关系：两者可并存，关注的开销不同

## 一眼辨析
- 地址/数据分时复用 → **节省引脚**，可能增加时间成本
- 突发传输 → **减少连续数据块的重复启动/地址开销**
- 分离事务 → **减少等待期间的总线占用**
- 事务流水 → **重叠不同事务的相位**
