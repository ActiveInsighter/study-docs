# 3.12 Cache 替换策略

## 发生替换的条件
- 不命中后需要分配块，**目标组满且已有有效行**，才必须决定淘汰哪一行
  - 直接映射不存在策略选择，目标只有1行
  - 全相联/组相联由指定替换算法在可选行中选择受害者
- 如果旧行是dirty且采用写回，则必须将其修改内容下传至下一级

## RAND / FIFO / LRU / LFU
- RAND：随机选取候选行；简单，但对局部性没有确定的利用
- FIFO：最早**装入**的先淘汰，命中通常不改变其进队次序
  - FIFO理论上可能出现Belady异常；实际固定配置Cache命中数仍需逐序列推算
- LRU：淘汰距离上次**访问**最久的行；命中也要更新最近使用顺序
  - 真LRU可用栈/顺序记录或计数器实现；并非任意$2^n$路都“每行只需n bit”
  - 理论编码至少区分s!个顺序状态，$\lceil\log_2(s!)\rceil$位是理论信息下界
  - 工程常用树形PLRU近似：它与精确LRU在特定序列上可能不同
- LFU：淘汰访问次数较少的行；需要明确计数溢出、衰减和并列时的规则

## 可复算LRU轨迹
- 4行全相联、初始空；访问 `1,2,3,4,1,2,5,1,2,3,4,5`
  - 前4次都是强制缺失；访问1、2分别命中
  - 访问5时淘汰最久未用的3；随后1、2均命中
  - 访问3淘汰4，访问4淘汰5，访问5淘汰1 → **共4次命中、8次缺失**
- 判断时维护“从最近到最久”的队列：每次命中移至队首，缺失换出队尾
- 区分“装入顺序”“最近访问顺序”，是FIFO与LRU最常见混淆

## 408误区清单
- 页框LRU与Cache LRU原理类似，但缺页触发磁盘IO，代价和具体硬件支持不同
- Cache替换策略**不直接控制**缺页置换；TLB也有独立的替换和有效位管理
- 一次不命中未必触发真正的主存读：写不分配可绕过Cache；某些预取也会触发装入
