# 4.12 CALL与RET：函数控制流与栈

## 调用/返回必须成对理解
- 在经典32位x86近调用中，`CALL target`通常把**下一条指令地址**压入栈，再将EIP设为target
- `RET`从栈中取返回地址作为新的EIP；返回值一般依调用约定放在EAX
- **调用约定不属于CALL机器指令本身**：参数从哪里来、谁清理栈、哪些寄存器需保存随ABI变化
  - 常见IA-32 `cdecl`：参数由调用者从右至左压栈，返回后调用者清理参数
  - 不能把所有x86函数都画成固定`[ebp+8]`取首参数（优化后可省略帧指针）

## 相对CALL机器码例
- 地址`0x00401025`有5B指令：`E8 D6 FF FF FF`
  - Opcode `E8` + 4B有符号相对位移，按小端存储为`0xFFFFFFD6` = −42
  - 下一条指令地址=$0x00401025+5=0x0040102A$
  - 目标=$0x0040102A-0x2A=0x00401000$
- <img src="/images/408-mind-maps/co-04-call-rel32-clean.svg" alt="x86 call rel32以下一指令地址为基准，负42字节跳转到函数入口" width="1040" height="440">

## 一次典型帧建立（教学模型）
- `push ebp`保存旧帧指针；`mov ebp,esp`设置本函数帧基
- `sub esp,K`预留局部变量区；`leave`恢复典型栈帧；`ret`返回
  - 参数/局部变量地址随布局和ABI改变；不能机械把ebp±偏移套到任何函数

## 与C语言递归联系
- `f(n)=n*f(n-1)`且`n<=1`返回1：每次调用都会新增栈帧，直到触底
  - 若从n=4起，进入f(4),f(3),f(2),f(1)，共4层；乘法3次
- 32位有符号整数：$12!=479001600$可表示；$13!=6227020800>2^{31}-1$
  - C语言有符号整数溢出是**未定义行为**，不能把某个机器运行结果当语言保证
  - 硬件二操作数IMUL的CF/OF可指示低32位截断，具体需看所用指令

## 综合追踪步骤
- 标注每条指令首地址与长度 → 计算顺序PC → 相对位移符号扩展
- `CALL`另写“压栈返回地址”和“转到目标”；`RET`明确读栈并回到调用点
- 分析递归时区分**函数调用次数/最大栈深/乘法次数**
