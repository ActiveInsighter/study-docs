# 4.14 CISC与RISC：架构风格而非硬性标签

## CISC倾向（复杂指令集）
- 指令功能和寻址方式丰富；某些指令可以访问内存并同时运算
- 经典x86指令**变长编码**，前缀、寻址字段、位移等组合多
- 一条复杂指令内部可分解为若干微操作，现代处理器仍可高度流水化

## RISC倾向（精简指令集）
- 典型设计更规则，常规算术运算使用寄存器操作数
- 典型**Load/Store结构**：专门的Load/Store访存，其余算术只在寄存器间运算
- 易于译码/流水化与编译器寄存器分配，但不是“所有RISC指令必定一个周期”
- 典型MIPS、RISC-V、ARM相关设计存在变长/压缩编码等实现或扩展，不宜一刀切

## 比较维度
- **编码**：CISC更常见变长；传统RISC更倾向规则定长，但压缩指令是重要例外
- **访存**：CISC可能允许内存直接参与算术；Load/Store架构一般只由加载/存储访存
- **寄存器**：传统RISC倾向更多通用寄存器；数量并非绝对分类依据
- **译码控制**：微程序/硬布线是实现选择，不能简单按ISA二分
- **流水线**：两类处理器都能流水化；RISC风格在规则译码上有优势

## 一个相同的计算任务
- 目标：`c = a + b`，a/b/c在内存
- 典型Load/Store示意：`LOAD R1,[a]`、`LOAD R2,[b]`、`ADD R3,R1,R2`、`STORE R3,[c]`
- 可支持内存运算的ISA可能用较少的架构指令表达，但内部微操作数并不等同于架构指令数

## 考试答题原则
- 先说**教科书典型特征**，再识别题目是否对特定处理器作出明确规定
- 不把“CISC＞200条、RISC＜100条”当必要条件
- 不把“RISC必须流水线、CISC不能流水线”“CISC全部微程序控制”当定义
