## 数制和编码

- 进位计数制
  - 基数：
    - N进制的基数为 0 ~ N-1
- 为何选择二进制
  - 使用有两个稳定状态的物理器件就可以表示二进制的每一位了
  - 逻辑运算方便
  - 逻辑门电路设计方便
- 二进制、八进制、十六进制、十进制相互转化
  - 例：十进制 18.375 的转换
    - 二进制：$18 = 16 + 2 = 2^4 + 2^1$，$0.375 = 0.25 + 0.125 = 2^{-2} + 2^{-3}$ ⇒ $(10010.011)_2$
    - 八进制：从小数点向两边每 3 位一组，不足补 0：010 010 . 011 ⇒ $(22.3)_8$
    - 十六进制：每 4 位一组，不足补 0：0001 0010 . 0110 ⇒ $(12.6)_{16}$

  - 注意八进制和十六进制要补位
- 真值、机器数
  - 真值：
    - 符合人类习惯的数字
  - 机器数：
    - 数字在机器中代表的意思
- BCD码
  - \*
  - 8421、2421、余3码
- 概要：例如：真值 +5 即机器数 0,101
  概要范围：[真值、机器数](#focus=%E7%9C%9F%E5%80%BC%E3%80%81%E6%9C%BA%E5%99%A8%E6%95%B0)

## 定点数的表示

- 考频：低
  - 15、18、21、22
- 无符号数
  - unsigned int、 unsigned long
    - 无符号数没有小数
  - 【没有符号位】，有n个bit，则数的表示范围为：( 0 ~ 2^n - 1 ) <img src="/images/408-mind-maps/co-0123.svg" alt="【没有符号位】，有n个bit，则数的表示范围为：( 0 ~ 2^n - 1 )" width="300" height="91">

    - 指针、表示地址
- 定点数
  - 小数点位置是固定的
    - 即小数点前面和后面的位数是固定的
  - 定点小数
    - <img src="/images/408-mind-maps/co-0032.svg" alt="定点小数" width="300" height="92">

      - 只表示正的、负的小数
  - 定点整数
    - <img src="/images/408-mind-maps/co-0244.svg" alt="定点整数" width="300" height="92">

      - 只表示正的、负的整数
- 浮点数 --- 小数点位置是不固定的
- 有符号数
  - 原码
    - 形式
      - 第一位为符号位，其余位为数值位，要么表示小数要么表示整数
    - 表示范围
      - 整数
        - 整数
          - 存在 +0 和 -0，所以正负数对半分 $-(2^n-1) \leq x \leq (2^n - 1)$

      - 小数
        - 纯小数
          - 小数的表示是离散的，正负对半分 $-(1-2^{-n}) \leq x \leq (1 - 2^{-n})$

    - 作用
      - 最容易理解的表示方式
      - 原码相加运算不成立哦
    - 举例：
      - 整数
        - x1  = +1110
          - \[x1\]原 = 0, 0001110
        - x2 = -1110
          - \[x2\]原 = 1, 0001110
      - 小数
        - x1  = +0.1101
          - \[x1\]原 = 0.1101000
        - x2 = -0.1101
          - \[x2\]原 = 1.1101000
  - 反码
    - 形式
      - 从原码转化而来，如果原码为正，反码不变。如果原码为负，则反码的数值位是原码的取反
    - 表示范围
      - 和原码完全一致
    - 作用
      - 作为”原码 -&gt; 补码“的中间态
      - 若是想通过反码得出十进制，则先转为原码再转为十进制
    - 举例：
      - 整数
        - x1  = +1110
          - \[x1\]反 = 0, 0001110
            - \[x1\]原 = 0, 0001110
        - x2 = -1110
          - \[x2\]反 = 1, 1110001
            - \[x2\]原 = 1, 0001110
      - 小数
        - x1  = +0.1101
          - \[x1\]反 = 0.1101000
            - \[x1\]原 = 0.1101000
        - x2 = -0.1101
          - \[x2\]反 = 1.0010111
            - \[x2\]原 = 1.1101000
  - 补码

    - 形式
      - 正数的补码：不变 负数的补码：反码 + 1
        - 负数：原码转为补码的技巧是【尾数】取反再+1
      - 注意：
        - 补码中只存在一个 0
          - +0 的补码： 0 0000 000
            - -0 的补码：【 1 0000 000按位取反再+1 】 -&gt; 【0 0000 000】和+0 一致了
          - 1 0000 000是无法通过原码变化获得的，故规定在整数中表示 -2^n，在小数中表示 -1
          - 概要：因为1 0000 000 = 0 0000 000按位取反 + 1，但是 +0 是正数，没有这个运算规则
            概要范围：[1 0000 000是无法通过原码变化获得的，故规定在整数中表示 -2^n，在小数中表示](#focus=1%200000%20000%E6%98%AF%E6%97%A0%E6%B3%95%E9%80%9A%E8%BF%87%E5%8E%9F%E7%A0%81%E5%8F%98%E5%8C%96%E8%8E%B7%E5%BE%97%E7%9A%84%EF%BC%8C%E6%95%85%E8%A7%84%E5%AE%9A%E5%9C%A8%E6%95%B4%E6%95%B0%E4%B8%AD%E8%A1%A8%E7%A4%BA%20-2%5En%EF%BC%8C%E5%9C%A8%E5%B0%8F%E6%95%B0%E4%B8%AD%E8%A1%A8%E7%A4%BA)

        - 原码 -&gt; 补码：（负）按位取反 + 1 补码 -&gt; 原码：（负）按位取反 + 1
          - 为什么：
            [参考链接](<https://blog.csdn.net/m0_37433111/article/details/107938663?utm_medium=distribute.pc_relevant.none-task-blog-2%7Edefault%7EBlogCommendFromMachineLearnPai2%7Edefault-1.essearch_pc_relevant&depth_1-utm_source=distribute.pc_relevant.none-task-blog-2%7Edefault%7EBlogCommendFromMachineLearnPai2%7Edefault-1.essearch_pc_relevant>)

          - 按位取反 + 1 的快速做法：从右往左，遇到第一个 1 右边的所有bit不动，把这个1左边的全部数值位bit取反
    - 表示范围
      - 整数
        - 没有 -0 了，负数可以到 -2^n 了 $-2^n \leq x \leq 2^n - 1$

          - 原码范围：
            - 存在 +0 和 -0，所以正负数对半分 $-(2^n-1) \leq x \leq (2^n - 1)$

      - 小数
        - 没有 -0 了，负数可以到 -1 了 $-1 \leq x \leq 1 - 2^{-n}$

          - 原码范围：
            - 小数的表示是离散的，正负对半分 $-(1-2^{-n}) \leq x \leq (1 - 2^{-n})$

    - 作用

      - 补码相加减的运算是成立的
        - 所以在现代语言(例如C++)中都是采用的补码来表示数
      - 一切加减法都可以写作两个补码数相加
    - 举例：
      - 整数
        - x1  = +1110
          - \[x1\]补 = 0, 0001110
            - \[x1\]原 = 0, 0001110
        - x2 = -1110
          - \[x2\]补 = 1, 1110010
            - \[x2\]原 = 1, 0001110
      - 小数
        - x1  = +0.1101
          - \[x1\]补 = 0.1101000
            - \[x1\]原 = 0.1101000
        - x2 = -0.1101
          - \[x2\]补 = 1.0011000
            - \[x2\]原 = 1.1101000
  - 移码
    - 形式
      - 移码 = 补码首位取反
    - 表示范围
      - 和补码一致
    - 作用

      - 使用移码计算机可以直接通过【按位比较的方式】来比较两个数的大小

        |真值（十进制）|8 位补码|8 位移码|
        |---:|---|---|
        |-128|10000000|00000000|
        |-127|10000001|00000001|
        |-126|10000010|00000010|
        |-3|11111101|01111101|
        |-2|11111110|01111110|
        |-1|11111111|01111111|
        |0|00000000|10000000|
        |1|00000001|10000001|
        |2|00000010|10000010|
        |3|00000011|10000011|
        |124|01111100|11111100|
        |125|01111101|11111101|
        |126|01111110|11111110|
        |127|01111111|11111111|

        省略号表示原图略去的中间数值。移码表示的数较便于按编码大小比较；其编码由 8 位补码的符号位取反得到。

    - 小端模式

## 定点数的移位运算

- 逻辑运算
  - 与、或、非三大基本运算
- 逻辑移位
  - 不管数的类型，一律添 0
  - 作用：
    - 用于拆分和定位一个二进制中对应区间bit的数值，例如可以通过逻辑移位获得24bit RGB二进制数的R、G、B分别的数值
- 算术移位
  - 原码
    - 正数负数，一律添 0
  - 反码
    - 正数全 0，负数全 1
  - 补码
    - 正数全 0，负数左 1 右 0
    - 概要：注意：是左边添 1，右边添 0
      概要范围：[正数全 0，负数左 1 右 0](#focus=%E6%AD%A3%E6%95%B0%E5%85%A8%200%EF%BC%8C%E8%B4%9F%E6%95%B0%E5%B7%A6%201%20%E5%8F%B3%200)

      - 王道：左移（在右边）添0，右移（在左边）添1
  - 算术移位的精度：
    - 往右移动会丢失精度
      - 例：0011(3) 右移一次 0001(1)，而 3 ÷ 2 = 1.5
    - 往左移动可能出现严重误差
      - 例： 1000(-8)  左移一次 0000 (0), 出现严重误差
  - 作用：
    - 算术位移可以模拟乘法运算

      ```text
      -2 × 7：使用 8 位补码进行示意
      1111 1110 × 0000 0111
      → -2 左移 0 次（×1）、1 次（×2）、2 次（×4）再相加
        1111 1110 + 1111 1100 + 1111 1000
      = 1111 1010 + 1111 1000
      = 1111 0010
      = -14
      ```

- 【加减法】
  - 运算规则：
    - 1\. 使用补码来进行加法，符号位参与运算
    - 2\. 如果是 A - B，改为补码形式的 A + (-B)来进行计算
  - 运算电路：
    - <img src="/images/408-mind-maps/co-0245.svg" alt="运算电路：" width="300" height="133">

      - ZF、OF、SF、CF的意义
        - zero flag，overflow flag，signal flag，carry flag
  - 溢出判断：
    - 正负溢出
      - 正 + 正
        - 可能导致正溢出
      - 负 + 负
        - 可能导致负溢出
      - 正负相加
        - 一定没有溢出
    - 溢出的含义：
      - 原码、反码、补码计算器
        [参考链接](<https://chenwenhang.github.io/code-switch/>)

      - 例：1 位符号 + 7 位数值（表示范围 −128 ~ +127）
        - ① 15 + 124：0,0001111 + 0,1111100 = 1,0001011 = −117
          - 真实结果 139 > +127，越过上界回绕到负数：上溢（正溢出）
        - ② −97 + (−63)：1,0011111 + 1,1000001 = 0,1100000 = +96
          - 真实结果 −160 < −128，越过下界回绕到正数：下溢（负溢出）

    - 检测手段
      - 单符号位
        - 计算出结果后进行检测，可以检测出异常
          - 一位符号位：A + B = S，A_s、B_s、S_s 分别为两数和结果的符号位
            - $V = A_sB_s\overline{S_s} + \overline{A_s}\,\overline{B_s}S_s$，V = 1 溢出，V = 0 不溢出

              |A_s|B_s|S_s|V|
              |---|---|---|---|
              |0|0|0|0|
              |0|0|1|**1**（上溢）|
              |0|1|0|0|
              |0|1|1|0|
              |1|0|0|0|
              |1|0|1|0|
              |1|1|0|**1**（下溢）|
              |1|1|1|0|

            - 正负相加（A_s ≠ B_s）永不溢出

          - 无法检测是正溢出还是负溢出
      - 符号位 + 进制位
        - ( 正溢出 -&gt; 0,1 ) ；( 负溢出 -&gt; 1,0 )
          - 符号位 + 进位位：C_s 为符号位产生的进位，C_1 为最高数值位产生的进位
            - C_s = 0、C_1 = 1 ⇒ 上溢；C_s = 1、C_1 = 0 ⇒ 下溢；$V = C_s \oplus C_1$
            - 例 ①：0,0001111 (+15) + 0,1111100 (+124) = 1,0001011：C_s = 0、C_1 = 1 ⇒ 上溢
            - 例 ②：1,0011111 (−97) + 1,1000001 (−63) = (1) 0,1100000：C_s = 1、C_1 = 0 ⇒ 下溢

      - 双符号位
        - ( 正溢出 -&gt; 0,1 ) ；( 负溢出 -&gt; 1,0 )
          - 双符号位（模 4 补码）：S_s1 S_s2 中 S_s1 为真正的符号，S_s2 为实际结果的符号
            - 00 正；01 上溢（真正为正、结果为负）；10 下溢（真正为负、结果为正）；11 负
            - $V = S_{s1} \oplus S_{s2}$
            - 例 ①：00,0001111 (+15) + 00,1111100 (+124) = 01,0001011 ⇒ 上溢
            - 例 ②：11,0011111 (−97) + 11,1000001 (−63) = (1) 10,1100000 ⇒ 下溢

          - 存储的时候是单符号位，运算时扩展成了双符号位。
      - 拓展
        - 双符号位补码：
          - 模4补码
        - 单符号位补码：
          - 模2补码
    - 解决办法
      - 通过符号扩展来进行溢出控制，例如 int (4B) -&gt; long(8B)，扩展方法和算术位移一致
- 【乘法运算】
  - <img src="/images/408-mind-maps/co-0080.svg" alt="【乘法运算】" width="300" height="300">

    - ACC：乘积高位
    - MQ：乘数、乘积低位
    - X：被乘数
    - 概要：X \* MQ = ( ACC, MQ )
      概要范围：[ACC：乘积高位](#focus=ACC%EF%BC%9A%E4%B9%98%E7%A7%AF%E9%AB%98%E4%BD%8D)、[MQ：乘数、乘积低位](#focus=MQ%EF%BC%9A%E4%B9%98%E6%95%B0%E3%80%81%E4%B9%98%E7%A7%AF%E4%BD%8E%E4%BD%8D)、[X：被乘数](#focus=X%EF%BC%9A%E8%A2%AB%E4%B9%98%E6%95%B0)

      - 最开始ACC是0，然后通过多次加法+移位把低位移动到了MQ中，ACC中存放的是高位。
  - X \* MQ
    - X是被乘数，MQ是乘数
      - 前放X，后放MQ
        - （X\*Y）
  - 【原码乘法】 符号另算。多次累加，通过MQ最后一位来判断是否让ACC加X，每次都让右移，最后结果ACC为高位，MQ为低位
    - 硬件构成
      - <img src="/images/408-mind-maps/co-0229.svg" alt="硬件构成" width="300" height="124">

        - ACC有n+1位，MQ也有n+1位
    - 加法规则：
      - MQ的最低位为0，则ACC = ACC + 0
      - MQ的最低位为1，则ACC = ACC + X
    - 移位规则：
      - 统一采用逻辑移位（只补0）
        - 因为是原码，所以逻辑算术移位没区别
    - 运算流程：
      - 已知运算 x \* y，x为负，y为正
        - 其中x和y的符号位为一位，数值位为n位
      - 0\. 确定最终符号位为 1，把【x的符号改为0】
        - 符号位的计算：对两个数的符号位进行异或运算即可
      - 1\. 把x存入X寄存器中，把y存入到MQ寄存器中，清空ACC
        - 此时，MQ的最低位就应该是被乘数X应该进行操作
      - 2\. 进行加法，进行移位
        - 此时的右移有两个作用：
          - A. 使得MQ的最低位指明了下一次需要进行操作 B. 下次一次的加法是和上一次的结果“错位”相加
      - 3\. 重复 1~2 的步骤 n 次。 最后的结果就是(ACC, MQ)中，其中MQ的最末位舍弃，ACC的第一位改为符号位
        - ACC的全部 + MQ的前n位
        - x \* y 最后的结果最多为 2n 位，MQ和ACC都是n+1位寄存器，MQ的最末位舍去
    - 采用的是原码一位乘法，还有二位乘法，不拓展了
    - 概要：配图
      概要范围：[运算流程：](#focus=%E8%BF%90%E7%AE%97%E6%B5%81%E7%A8%8B%EF%BC%9A)

      - 原码一位乘法手算模拟：机器字长 5 位（含 1 位符号位，n = 4），x = −0.1101，y = +0.1011
        - 解：|x| = 00.1101，|y| = 00.1011；每轮看 MQ 最低位 C₄：为 1 则 ACC + |x|，为 0 则 ACC + 0，然后 ACC、MQ 一起逻辑右移

          |步骤|ACC（高位部分积）|MQ（低位部分积 / 乘数）|说明|
          |---|---|---|---|
          |起始|00.0000|1011|C₄ = 1，+\|x\||
          |+\|x\||00.1101||部分积 00.1101|
          |右移|00.0110|1101|C₄ = 1，+\|x\||
          |+\|x\||01.0011||部分积 01.0011|
          |右移|00.1001|1110|C₄ = 0，+0|
          |+0|00.1001||部分积 00.1001|
          |右移|00.0100|1111|C₄ = 1，+\|x\||
          |+\|x\||01.0001||部分积 01.0001|
          |右移|00.1000|1111|乘数全部移出|

        - 结果绝对值 |x·y| = 0.10001111；符号 $P_s = x_s \oplus y_s = 1 \oplus 0 = 1$，得 x·y = −0.10001111
        - 要点：符号位不参与运算；累加 n 次、右移 n 次；部分积用双符号位（模 4）防止加法时溢出

    - 批注：n次位移，n次运算
  - 【补码乘法】 符号参与运算，双符号位，MQ多一个辅助位，ACC是+/- X或者不变看MQ后两位之差，然后位移。【最后还有一次加法】

      - <img src="/images/408-mind-maps/co-0173.svg" alt="硬件构成" width="300" height="120">

        分组说明：MQ有辅助位，ACC、X均为双符号位；对应：[MQ为 n+2 位（因为多了一位辅助位）](#focus=MQ%E4%B8%BA%20n%2B2%20%E4%BD%8D%EF%BC%88%E5%9B%A0%E4%B8%BA%E5%A4%9A%E4%BA%86%E4%B8%80%E4%BD%8D%E8%BE%85%E5%8A%A9%E4%BD%8D%EF%BC%89)、[同样ACC和X都是n+2位（因为CPU要保证寄存器长度一致），那么就可以采用双符号位了](#focus=%E5%90%8C%E6%A0%B7ACC%E5%92%8CX%E9%83%BD%E6%98%AFn%2B2%E4%BD%8D%EF%BC%88%E5%9B%A0%E4%B8%BACPU%E8%A6%81%E4%BF%9D%E8%AF%81%E5%AF%84%E5%AD%98%E5%99%A8%E9%95%BF%E5%BA%A6%E4%B8%80%E8%87%B4%EF%BC%89%EF%BC%8C%E9%82%A3%E4%B9%88%E5%B0%B1%E5%8F%AF%E4%BB%A5%E9%87%87%E7%94%A8%E5%8F%8C%E7%AC%A6%E5%8F%B7%E4%BD%8D%E4%BA%86)

        - MQ为 n+2 位（因为多了一位辅助位）
        - 同样ACC和X都是n+2位（因为CPU要保证寄存器长度一致），那么就可以采用双符号位了
    - 加法规则：
      - 根据MQ的最低位和MQ的辅助位（在硬件中MQ的最低位为MQ的倒数第二位，辅助位为MQ的倒数第一位）
      - 辅助位 - 最低位 = 1 ， ACC = ACC + x
      - 辅助位 - 最低位 = 0 ， ACC = ACC + 0
      - 辅助位 - 最低位 = -1， ACC = ACC + (-x)
        - x的补码到-x的补码是由另外的辅助电路完成的
    - 移位规则：
      - 采用算术移位
        - 正的补0，负的补 1
    - 运算流程：
      - 已知运算 x \* y，x为负，y为正
        - 其中x和y的符号位为一位，数值位为n位
      - 1\. x扩展为双符号直接存入X，y不扩展符号存入MQ中，清空ACC（MQ辅助位初始为0）
      - 2\. 根据加法和移位的规则进行加法运算
      - 3\. 重复 1~2 的步骤n次
      - 4\. 对3的结果再进行一次加法运算
      - 5\. 最后的结果就是(ACC, MQ)
        - ACC的全部 + MQ的前n位
    - 概要：配图

        - $[x]_补 = 11.0011$，$[-x]_补 = 00.1101$，$[y]_补 = 0.1011$；MQ 末尾加辅助位 $Y_5 = 0$
        - 规则：看 $Y_5 - Y_4$（辅助位 − MQ 最低位）：1 则 $+[x]_补$，0 则 +0，−1 则 $+[-x]_补$；之后算术右移；共 n 轮加法与移位，最后再多做一次加法（不移位）

          |起始|00.0000|0.1011 0|Y₄Y₅ = 10，$+[-x]_补$|

          |加|11.0110|||

          |最后一次加（不移位）|11.0111|0001|结果|

        - $[x\cdot y]_补 = 11.01110001$，即 $x \cdot y = -0.10001111$
        - 符号位参与运算；部分积和被乘数用双符号位；算术右移时正数补 0、负数补 1

    - 批注：n次位移，n+1次运算

    - MQ：商
    - X：除数
    - 概要：ACC ÷ X = MQ ... ACC
      概要范围：[ACC：被除数、余数](#focus=ACC%EF%BC%9A%E8%A2%AB%E9%99%A4%E6%95%B0%E3%80%81%E4%BD%99%E6%95%B0)、[MQ：商](#focus=MQ%EF%BC%9A%E5%95%86)、[X：除数](#focus=X%EF%BC%9A%E9%99%A4%E6%95%B0)

  - 【原码除法】 先商一，然后相减后发现是负数了，再处理，逐渐左移，最后MQ是商，ACC是余数
    - 恢复余数法
      - 硬件构成
        - <img src="/images/408-mind-maps/co-0276.svg" alt="硬件构成" width="300" height="124">

          - ACC有n+1位，MQ也有n+1位
      - 运算流程：
        - 单独处理符号位
        - 已知运算 x ÷ y
          - ACC ÷ X
        - 0\. 把 y 写入到X，把 x 写入到ACC，MQ清零
        - 1\. 算法默认商 1，MQ的最低位置为 1，进行减法操作：ACC = ACC + (-X)
          - 如果最后的ACC的结果为负，则说明此时商0，则把MQ的最低位改为 0，同时ACC = ACC + X
            - 批注：“恢复余数法”
        - 2\. 把(ACC, MQ)的值全部左移一位
          - 此时的左移有两个作用：
            - A. 使得ACC被除数\*2 B. 有一位商已经确定在MQ中了
        - 3\. 如果x和y的数值位都为n，那么需要经过【n + 1】次减法运算，n 次移位运算
          - 如果最后一次商 1 还是负数，则应该再恢复余数一次
        - MQ最后存放了商，ACC存放了余数，【修改MQ的符号位】
      - 概要：配图
        概要范围：[运算流程：](#focus=%E8%BF%90%E7%AE%97%E6%B5%81%E7%A8%8B%EF%BC%9A)

        - 原码恢复余数法（手算）：n = 4，x = 0.1011，y = 0.1101；$[|y|]_补 = 0.1101$，$[-|y|]_补 = 1.0011$
          - 每步：余数 −|除数| = 新余数；新余数为负则商 0 并 +|y| 恢复，为正则商 1；然后余数逻辑左移

            |操作|被除数 / 余数|商|说明|
            |---|---|---|---|
            |$+[-\lvert y\rvert]_补$|0.1011 + 1.0011 = 1.1110||余数为负|
            |$+[\lvert y\rvert]_补$|1.1110 + 0.1101 = 0.1011|0|商 0，恢复余数|
            |左移，$+[-\lvert y\rvert]_补$|1.0110 + 1.0011 = 0.1001|01|余数为正，商 1|
            |左移，$+[-\lvert y\rvert]_补$|1.0010 + 1.0011 = 0.0101|011|商 1|
            |左移，$+[-\lvert y\rvert]_补$|0.1010 + 1.0011 = 1.1101||余数为负|
            |$+[\lvert y\rvert]_补$|1.1101 + 0.1101 = 0.1010|0110|商 0，恢复余数|
            |左移，$+[-\lvert y\rvert]_补$|1.0100 + 1.0011 = 0.0111|01101|商 1|

          - 左移 n 次，上商 n + 1 次；最后一次上商后余数不左移
          - 结果：商 $Q = +0.1101$，余数 $R = 0.0111 \times 2^{-4}$

    - 加减交替法
      - 优化思路：
        - 设某步余数 a 为负：恢复余数法先恢复 b = a + |y|，再左移并减 |y|：$(a + |y|) \times 2 - |y| = 2a + |y|$
          - 所以余数为负时，可直接商 0，并让余数左移一位再加上 |除数|，省去“恢复”这一步 —— 这就是加减交替法

        - 不进行恢复余数的操作，将操作更改如下
          - 计算机每次都默认商 1，然后进行补码减法，对于减法后的结果，如果结果为正，则移位进行下一次商操作。
          - 如果商 1 结果为负，则将 (ACC, MQ) 的值左移一位，在加上X的值（此处的X是ACC,MQ,X的那个X）
            - 把 (a + b) x 2 - b
              - 简化为了 2 x a + b
              - 批注：首先恢复余数(+b)，然后向左移位一次(x2)，然后进行下一次的商 1 相减设置(-b)
      - 其他特点：
        - 最后算完MQ和ACC的时候如果ACC的内容是负数，还是要 +X 恢复一下
        - 加法进行了 n + 1/n + 2 次，而左移进行了 n 次
      - 概要：配图
        概要范围：[优化思路：](#focus=%E4%BC%98%E5%8C%96%E6%80%9D%E8%B7%AF%EF%BC%9A)、[其他特点：](#focus=%E5%85%B6%E4%BB%96%E7%89%B9%E7%82%B9%EF%BC%9A)

        - 原码加减交替法（不恢复余数法）：n = 4，x = 0.1011，y = 0.1101
          - 余数为正：商 1，余数左移一位再减 |除数|；余数为负：商 0，余数左移一位再加 |除数|

            |操作|被除数 / 余数|商|ACC|MQ|
            |---|---|---|---|---|
            |起始|0.1011||01011|00000|
            |$+[-\lvert y\rvert]_补$|1.1110|0|11110|00000|
            |左移，$+[\lvert y\rvert]_补$|1.1100 + 0.1101 = 0.1001|01|01001|00001|
            |左移，$+[-\lvert y\rvert]_补$|1.0010 + 1.0011 = 0.0101|011|00101|00011|
            |左移，$+[-\lvert y\rvert]_补$|0.1010 + 1.0011 = 1.1101|0110|11101|00110|
            |左移，$+[\lvert y\rvert]_补$|1.1010 + 0.1101 = 0.0111|01101|00111|01101|

          - 若最后余数为负，还需 +|y| 得到正确余数
          - 结果：$Q_s = 0 \oplus 0 = 0$，$x / y = +0.1101$，余数 $0.0111 \times 2^{-4}$

  - 【补码除法】 符号位参与运算，如果X和ACC异号，则左移后相加，如果X和ACC同号，则左移后相减
    - 补码加减交替法：n = 4，x = +0.1000，y = −0.1011
      - $[x]_补 = 00.1000$，$[y]_补 = 11.0101$，$[-y]_补 = 00.1011$；符号位参与运算，被除数/余数、除数用双符号位
      - 第一步：被除数与除数同号则减除数，异号则加除数
      - 之后：余数与除数同号，商 1，余数左移一位减除数；异号，商 0，余数左移一位加除数；重复 n 次，末位商恒置 1（精度误差不超过 $2^{-n}$）

        |操作|被除数 / 余数|商（MQ）|
        |---|---|---|
        |异号，$+[y]_补$|00.1000 + 11.0101 = 11.1101|00001（同号，商 1）|
        |左移，$+[-y]_补$|11.1010 + 00.1011 = 00.0101|00010（异号，商 0）|
        |左移，$+[y]_补$|00.1010 + 11.0101 = 11.1111|00101（同号，商 1）|
        |左移，$+[-y]_补$|11.1110 + 00.1011 = 00.1001|01010（异号，商 0）|
        |左移，$+[y]_补$|01.0010 + 11.0101 = 00.0111|10101（末位恒置 1）|

      - 结果：$[x/y]_补 = 1.0101$，即商 −0.1011，余数 $0.0111 \times 2^{-4}$

      - 原码除法采用默认商 1
        - 如果结果为正：左移 + X
        - 如果结果为负：左移 - X
        - 概要：随后进行下一次的运算
          概要范围：[如果结果为正：左移 + X](#focus=%E5%A6%82%E6%9E%9C%E7%BB%93%E6%9E%9C%E4%B8%BA%E6%AD%A3%EF%BC%9A%E5%B7%A6%E7%A7%BB%20%2B%20X)、[如果结果为负：左移 - X](#focus=%E5%A6%82%E6%9E%9C%E7%BB%93%E6%9E%9C%E4%B8%BA%E8%B4%9F%EF%BC%9A%E5%B7%A6%E7%A7%BB%20-%20X)

      - 补码除法在商的时候根据ACC和X的符号进行判断
        - 如果ACC和X的符号不同，则商0
          - (ACC, MQ)左移一位，+ X
        - 如果ACC和X的符号同号，则商 1
          - (ACC, MQ)左移一位， - X

## 定点数的转换

- 强制类型转化
  - 原则：不改变具体数值，只改变解释方式
  - 例如：
    - 实验：无符号数与有符号数之间的强制转换

      ```cpp
      #include <iostream>
      int main() {
          unsigned int x = 0x80000001;
          int x1 = x;
          printf("(%lu) - %u", sizeof(unsigned int), x);   // (4) - 2147483649
          printf(" - (%lu) - %d\n", sizeof(int), x1);      // (4) - -2147483647
          unsigned int y = 0xFFFFFFFF;
          int y1 = y;
          printf("(%lu) - %u", sizeof(unsigned int), y);   // (4) - 4294967295
          printf(" - (%lu) - %d\n", sizeof(int), y1);      // (4) - -1
      }
      // 结论：unsigned int 转 int，机器数不变，直接按补码解释
      ```

- 长整数变短整数
  - 高位截断，低位保留
- 短整数变长整数
  - 符号扩展
    - unsigned 就是直接补0
    - short/int/long 就是按正负补0/补 1
  - 由 short 变为 unsigned int 的过程
    - 首先先把short【扩展】为int类型，然后再【转为】unsigned int的【表示方法】
      - 实验：short 变 unsigned int 时先符号扩展为 int，再按无符号解释

        ```c
        #include <stdio.h>
        int main() {
            short x = 0xf000;
            unsigned short num1 = (unsigned short) x;               // 0xf000 = 61440，2B
            int num2 = (int) x;                                     // 0xfffff000 = -4096
            unsigned int num3 = (unsigned int) x;                   // 0xfffff000 = 4294963200
            unsigned int num4 = (unsigned int)((unsigned short) x); // 0xf000 = 61440，4B
        }
        ```

      - 如果自己手动修改转化的方式：先转为unsigned再扩展，就会很系统默认的不一样

    - 记忆口诀：

      - **C 语言本身不规定整数在内存中的字节序**，应按具体实现检查；原图提到某些单片机环境使用大端。
      - Java 的某些跨平台二进制格式和标准数据流使用大端，但不能据此断言所有 Java API 都只有一种端序。
      - 通常所说的网络字节序是大端；仍应以具体协议规定的数据格式为准。

## 浮点数

- 考频：高
  - 09-15、18、20-22、17大
- 通常表示方法
  - 公式 $N =(-1)^S \times R^E \times M$

    - 其中 R为基数（即R进制），E和M都是有符号定点数。E称为阶码，M称为尾码
    - E为定点整数，M为定点小数
    - 其中E和M可以用补码或原码来表示
      - 注意计算十进制值的时候补码为负要转为对应真值在写值
  - 一般格式 <img src="/images/408-mind-maps/co-0004.svg" alt="一般格式" width="300" height="97">

  - 尾数规格化
    - 原码
      - 浮点数的尾数部分的最高位一定是“有效数”位
        - 负数： 1, 1 ....
        - 正数：0, 1....
    - 补码
      - 浮点数的尾数部分最高位和符号位一定不同
        - 负数：1, 0 ...
        - 正数：0, 1....
    - 尾数、阶码规格化
      - 例如 原码 ( M = 1,011 ，E = 0, 000 0010 )，则应该变为：( M = 1,110 ，E = 0, 000 0001），M左移了，E对应减小
        - 尾数左移：左归
        - 尾数右移：右归
  - 计算
    - 在进行加减计算中，采用双符号位进行计算，可以挽救很多溢出
      - 例如：符号位 00 和 符号位 00 相加的结果是 0 1，则可以把尾数右移一位，阶码 +1 来进行挽救
- 浮点数的运算
  - 对阶
    - 首先把两个浮点数的阶码对齐，以小阶向大阶看齐
  - 尾数求和
    - 尾数按定点数的加减法进行运算
  - 规格化
    - 尾数 &gt; 0时，规格化为00.1xxxx 尾数 &lt; 0时，规格化为 11.0xxxx
    - 概要：补码
      概要范围：[尾数 &gt; 0时，规格化为00.1xxxx 尾数 &lt; 0时，规格化为 11.0xxxx](#focus=%E5%B0%BE%E6%95%B0%20%3E%200%E6%97%B6%EF%BC%8C%E8%A7%84%E6%A0%BC%E5%8C%96%E4%B8%BA00.1xxxx%E5%B0%BE%E6%95%B0%20%3C%200%E6%97%B6%EF%BC%8C%E8%A7%84%E6%A0%BC%E5%8C%96%E4%B8%BA%2011.0xxxx)

  - 舍入
    - "0"舍"1"入法：
      - 尾数右移，如果被【移除的最高位】为 0，那么就舍去。如果被【移除的最高位】的是 1，那么就让尾数 + 1
        - 10100
          - 右移3次：
            - 10 + 1 = 11
          - 右移1次：
            - 1010
        - 此时+1后可能还需要进行规格化
    - 恒置为"1"法：
      - 尾数右移，不管如何移动，尾数最末位一定为 1
  - 溢出判断
    - 双符号时
      - 如果阶码出现了“01”，说明出现了上溢，进入中断处理
      - 如果阶码出现了“10”，说明出现了下溢，按 0 处理
  - 一般考试的运算是不会计算IEEE754模式的
    - 计算只有09选择题考了
