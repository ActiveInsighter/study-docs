# 7.9 DMA：谁负责大块数据搬运

## DMA的核心定位
- **DMA = Direct Memory Access**：设备与主存之间的大块数据传输**无需CPU逐个字参与搬运**
- CPU负责配置DMA：方向、内存地址、设备/通道、长度、中断策略
- DMA控制器在传输阶段发起或协调访问内存事务，完成地址与剩余计数更新
- 传输完成后通常以**一次完成中断**通知CPU；也可根据实现采用轮询完成标志
- 现代总线主控设备可直接发起对内存的DMA事务，不必经独立的集中式DMAC数据寄存器；依题设硬件结构判断

## 控制器核心部件
- **AR／内存地址寄存器**：保存当前主存地址，传送过程中按单位自动更新
- **WC／长度或字数计数器**：记录剩余传送单位或已传送计数（计数方向取决于实现）
- **DR／数据缓冲寄存器**：教材典型DMAC模型中暂存传送数据；现代设备也可能采用内部FIFO或总线主控引擎
- **DAR／设备地址寄存器**：若设备端需要寻址，保存设备端地址/端口配置
- **状态与控制逻辑**：控制传送方向、设备请求、时序及结束状态
- **中断机构**：传送结束或错误时发出请求（不一定“必须依赖WC溢出”）

## 总线请求与应答
- 在经典DMA系统中：外设 → DMAC发出设备级DMA请求
- DMAC → CPU/仲裁器：`HRQ` 总线请求
- CPU/仲裁器 → DMAC：`HLDA` 总线允许
- 获得相应总线/主存访问权后，DMAC才可参与共享资源的数据传输
- **优先于CPU访存**是特定仲裁机制的常见设计，不是任何DMA设备在任何体系下的无条件绝对优先级

## 误区纠正
- **DMA仍可能占用主存带宽或总线**；免去CPU指令搬运不代表硬件传输成本为零
- **DMA不用CPU逐字搬运**不等于CPU始终能够无阻塞访存
- **DMA块大小**由配置、控制器能力及协议决定，可能分若干次总线事务完成
