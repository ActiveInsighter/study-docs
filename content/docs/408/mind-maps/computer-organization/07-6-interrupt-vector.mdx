# 7.6 中断：从请求到找到服务程序

## 中断请求与响应条件
- **请求产生**：设备完成数据交换/发生异常状态，向中断控制器或CPU发出请求
- **是否响应**：检查请求是否有效、是否被屏蔽、当前CPU是否可响应
- **多个请求同时到达**：需按硬件仲裁/优先级策略选择允许响应的来源
- 外部中断响应通常安排在适当指令边界；某些不可屏蔽请求或异常另有机制
- CPU可在接受中断前先向设备/中断控制器发出应答，具体握手依体系结构

## 中断判优两种典型方法
- **硬件排队器**：用优先级编码或中断控制器按请求线优先选取
- **软件查询**：CPU/服务程序依次检查各设备状态，找出需要处理的来源
- 硬件判优通常响应快；软件查询实现灵活但消耗额外检查时间
- <img src="/images/408-mind-maps/co-07-interrupt-priority-redrawn.svg" alt="四路中断请求的硬件判优与软件轮询对比" width="760" height="388">

## 中断向量的精确定义
- **中断类型号/向量号**：识别某一种中断的编号
- **向量表项地址**：中断向量表中某个表项的存储地址（可能由基址和编号计算）
- **中断向量**：表项中保存的**处理程序入口地址**或相应入口描述符
- **ISR（中断服务程序）入口**：CPU最终跳转开始执行的代码位置
- 易错顺序：`向量号 → 定位向量表项 → 得到ISR入口`，不是把“向量号”直接当成服务程序地址
- <img src="/images/408-mind-maps/co-0110.svg" alt="硬件向量法：向量表定位与中断服务入口" width="680" height="319">

## 考点自测
- “中断请求一出现CPU就立即停止当前指令”→ **错误**，需要满足响应条件与时机
- “中断向量地址与中断向量含义相同”→ **错误**，前者是表项位置，后者通常是表项内容
- “所有中断都必须进行软件轮询”→ **错误**，存在硬件向量/硬件判优
