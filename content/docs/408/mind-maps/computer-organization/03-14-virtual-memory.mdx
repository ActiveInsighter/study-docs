# 3.14 虚拟存储器与页表

## 为什么需要虚存
- 程序使用**虚拟地址空间**，由MMU与操作系统协作转换为物理地址
  - 不是“一定可以使用磁盘大小那么多的虚拟空间”；还受进程位数、映射限制等影响
  - 缓解物理内存容量压力、支持隔离/保护、按需装入和共享映射
- 虚存对**应用程序**常表现透明；对内核、异常处理和系统开发不完全透明
- 页表保存映射和权限；缺页处理由OS调入或分配页框

- <img src="/images/408-mind-maps/co-0268.svg" alt="虚拟存储器的三个地址空间：主存（实地址）、程序（虚地址）、辅存" width="760" height="330">

## 页地址划分
- 页大小$2^k$字节，字节编址的虚拟地址 = `虚页号VPN | 页内偏移k位`
  - 有效PTE中提供物理页框号PFN；`PFN | 原偏移`组成物理地址
  - 页内偏移在转换前后**保持不变**，没有“翻译页内地址”这一步
- 例32位虚址、4KiB页：偏移12位、VPN20位
  - 访虚址 `0x12345678` → VPN `0x12345`、偏移 `0x678`
  - 若PFN=`0x89ABC`，物理地址为 `0x89ABC678`
- <img src="/images/408-mind-maps/co-03-page-translation-clean.svg" alt="虚拟页号与物理页框号拼接相同12位偏移" width="920" height="379">

## 页表项PTE不等于固定四元组
- 常包含：存在/有效位、页框号、权限位、访问位/引用位、脏位等
  - **PTE无效时存放磁盘块号只是可能的一种实现**：真实系统也可能是空洞、交换信息或非法映射
  - 有效位=0时不一定能据该PTE取得外存地址
- 访问已映射但未驻留页：触发缺页异常，OS分配页框/置换旧页/加载内容/更新页表
  - 写回旧页仅在旧页脏且策略要求时发生；新页可能来自文件或零页
- 区分缺页异常、越界/权限异常、TLB缺失，它们不是同一故障

- <img src="/images/408-mind-maps/co-0062.svg" alt="主存中的页表：有效位、脏位、引用位、物理页号或磁盘地址" width="760" height="400">

## 多级页表
- 当页表很大时，用页目录逐层指向下级页表，只分配实际需要的部分
  - 假设32位虚址、4KiB页、PTE 4B → 一个页表页能放1024个PTE
  - VPN20位分为一级10位+二级10位；虚址 = `10 | 10 | 12`
- TLB未命中且页驻留：需执行页表遍历，可能需要多次物理内存访问
  - 原图：<img src="/images/408-mind-maps/co-0107.svg" alt="页表地址转换与页框映射示意" width="820" height="469">
- 页表通常由硬件遍历器或内核协作，具体步骤依架构
