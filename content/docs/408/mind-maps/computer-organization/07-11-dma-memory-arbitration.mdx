# 7.11 DMA与CPU：争抢主存的三种方法

## 冲突产生的条件
- CPU与DMA需要同时使用**同一单端口主存资源或共享互连**时，必须仲裁
- 多总线拓扑可减少部分竞争，**不能自动消除对同一单端口内存的冲突**
- 争用“主存周期/总线使用权”与“CPU是否仍在执行寄存器内部指令”应区别对待
- <img src="/images/408-mind-maps/co-0227.svg" alt="DMA独立I/O侧互连仍共享主存访问资源" width="610" height="218">

## 方法一：停止CPU访存（突发成组）
- 允许DMA在一段连续时间内占用相关主存/总线资源，搬完一批数据再归还
- 优势：DMA块传输效率高、仲裁开销少
- 代价：CPU在需要受争用的访存资源时会被持续阻塞
- <img src="/images/408-mind-maps/co-0006.svg" alt="DMA连续占用资源期间CPU访存停止" width="650" height="227">

## 方法二：DMA与CPU交替访问
- 将访存时间槽按固定规则分配给CPU和DMA
- 优势：时间关系可预测，按固定分时设计可减少逐次争用仲裁
- 代价：硬件时序要求更强；某一方没有传输需求时会出现浪费，除非机制允许复用
- <img src="/images/408-mind-maps/co-0113.svg" alt="CPU和DMA固定交替使用主存时间槽" width="650" height="227">

## 方法三：周期窃取（Cycle Stealing）
- DMA在需要访问内存时请求一个或若干访存周期
- CPU当前访存尚未完成则等待合适的让出点；若二者争用，按仲裁规则决定
- CPU仅在实际冲突的相应访问时隙受影响，其他时间可继续运行
- **不能将DMA周期窃取理解为CPU程序计数器每次都停止一个完整指令周期**
- <img src="/images/408-mind-maps/co-0277.svg" alt="DMA按需窃取内存周期的时间线" width="650" height="227">

## 抢占开销的简单模型
- 传输块大小 $S\,\mathrm B$，一次DMA访存搬运 $w\,\mathrm B$
- 如每次访存占用一个主存周期，最少DMA访存次数（不考虑额外协议）：$N=\lceil S/w\rceil$
- 如果一次DMA访存令CPU等待 $t_m$，CPU的**最坏无重叠停顿估计**为 $N\,t_m$
- 实际停顿要扣除本来不需要相关存储资源的时刻，并考虑主存/总线竞争与批量传输
