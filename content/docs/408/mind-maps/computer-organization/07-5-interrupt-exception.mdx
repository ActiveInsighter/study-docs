# 7.5 中断与异常：来源和性质

## 外部中断（异步事件）
- 通常由**当前正在执行的指令流之外**的硬件事件引起
- 常见：I/O完成、定时器、外部设备请求、电源或硬件故障告警
- **可屏蔽中断**：受中断允许位及屏蔽机制控制；`INTR`是一些教材/ISA的示意信号名
- **不可屏蔽中断 NMI**：不能被普通可屏蔽中断的屏蔽位屏蔽，常用于高优先级异常硬件事件
- 经典顺序执行模型：通常在**当前指令完成的边界**检查并响应外中断；精确响应时机由ISA及CPU实现规定

## 内部异常（同步事件）
- 由**当前指令的执行**触发：缺页、非法操作码、算术异常、陷入指令等
- **故障 fault**：一般报告导致故障的指令，以便处理后重试；例如可修复的缺页
- **自陷 trap**：通常在指令执行后将控制交给处理程序，典型是显式系统调用/断点；返回点依架构而定
- **终止 abort**：不可保证可精确恢复，常伴随严重错误；不是“所有硬件错误都属于abort”
- **不能硬编码**：除零、溢出、非法指令在不同ISA/语言或异常配置中的具体语义可能不同

## 判断一件事的三把尺子
- **来源**：CPU执行当前指令触发，还是外部设备独立产生？
- **可恢复性**：异常处理后能否重试指令、从下一指令继续，或难以恢复？
- **可屏蔽性**：仅对适用的外部请求讨论“可屏蔽/不可屏蔽”更清楚
- “异常都是软件中断”是概念混用；硬件检测的内部异常同样可能由CPU直接报告

## 处理路径的共性
- 识别原因 → 保存必要处理器状态 → 切换至特权处理程序 → 服务 → 恢复/终止
- 操作系统、异常控制器和ISA共同定义向量与处理步骤；“软件查询”不是内部异常识别的通用必要步骤
