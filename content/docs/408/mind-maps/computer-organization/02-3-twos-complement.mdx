# 2.3 补码的数学本质与边界

## 将整数映射到模 $2^w$
- 把整数 $x$ 映射成 $w$ 位模式：$x\bmod 2^w$
  - 负数取非负余数；−14在8位上 $256-14=242=\mathrm{F2_H}$
- 有符号解释：把模式当无符号数 $u$
  - 若最高位为0，则真值 $u$；若最高位为1，则真值 $u-2^w$
- 加法在机器上按模 $2^w$ 运算；**数学真值溢出**需另外检测
  - 例如 8位 `01111111`+`00000001`→`10000000`，真值127+1溢出

## 负数求补与“从右向左”技巧
- 求 $[-x]_{\mathrm{补}}$：把 $[x]_{\mathrm{补}}$ **所有 $w$ 位**取反再加1
  - 包含符号位；与“仅对原码数值位取反”是不同操作
- 快捷：从最低位向高位，保留右边最先出现的1及其右侧位，对其左侧位取反
  - 例 `00001110` → `11110010`，得到−14
- 最小负数有例外：8位 `10000000` 的补码取负仍 `10000000`
  - 数学上的 +128 超出 int8 范围，不表示“−128等于+128”

## 符号扩展与零扩展
- 从 $w$ 位补码扩为更宽补码：复制原符号位到左侧新高位
  - `10010110`（−106）→ `11111111 10010110`（16位依然−106）
- 无符号扩宽：高位补0
  - `10010110`（150）→ `00000000 10010110`（仍150）
- 缩窄时保留低位、丢掉高位，可能改变真值
  - 原值是否能够用目标位宽表示决定是否可无损

## 双符号位（模4补码的教学模型）
- 计算时把单符号位扩展为两位，有利于观察结果溢出方向
  - `00`：非负；`11`：负数；`01`：正溢出；`10`：负溢出
- 上述 `01/10` 为**扩展后算术结果**的符号模式，不能直接据此判定IEEE754异常
- 双符号位并不扩大原始存储类型的合法真值范围

## 考点区分
- **进位**：最高位之外产生的进位；**溢出**：有符号数学结果超出真值区间
- “移码=补码首位取反”针对教材指定的同位宽偏置；IEEE754通常用$2^{k-1}-1$
- 源码层面：C有符号溢出可能是未定义行为，不能把硬件回绕解释当语言保证
