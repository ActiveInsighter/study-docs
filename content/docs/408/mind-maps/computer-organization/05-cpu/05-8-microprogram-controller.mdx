# 5.8 微程序控制的核心机制

## 从机器指令到微指令
- **机器指令**：ISA定义的软件可见指令，例如LOAD、ADD、JMP
- **微程序**：为实现某类机器指令/公共阶段而执行的一段微指令序列
- **微指令**：存于控制存储器的一条控制字，通常包括**操作控制字段+顺序/下地址字段**
- **微命令**：控制ALU、寄存器、总线等执行微操作的信号
  - 微指令可能在同一节拍同时发出**多个兼容微命令**
- **微操作**：被硬件实际执行的寄存器传送或算术动作

## 控制器四大部件
- **CM**（Control Memory）控制存储器：存放微程序，可使用ROM/可更新控制存储等实现
- **CMAR**（微地址寄存器，也可称μPC）：保存本次要从CM读取的微指令地址
- **CMDR**（微指令寄存器，也可称μIR）：锁存当前微指令，分发控制字段
- **下地址形成逻辑**：结合当前微指令、OP(IR)、条件信号生成下一微地址

## 取出一条微指令的流程
- ①根据当前微地址`CMAR`访问控制存储器`CM`
- ②`CMDR ← CM[CMAR]`
- ③CMDR的控制字段形成微命令，驱动数据通路
- ④在顺序逻辑/条件测试控制下，产生下一微地址`CMAR ← next`，循环进行
- **入口选择**：取指入口可以固定；机器指令译码决定该指令执行微程序入口

## 共享阶段与“至少N+1”结论的边界
- 教学模型可让所有N条机器指令共享一段取指微程序，再各有执行微程序
  - 若无其他共享，常写至少N+1段微程序**作为特定设计假设**
- 实际微码可能共享更多子程序，带异常/中断入口，也可能硬布线完成部分功能
- 所以“N条指令一定恰好N+1条微程序”不是普适定理

## 机器指令与微地址位宽
- 机器指令长度由ISA编码决定；**微指令字长由控制字段+顺序字段决定**
- 控存有M个可寻址微指令字，一般至少需`ceil(log2 M)`位CMAR（定长编址假设）
