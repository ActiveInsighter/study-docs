# 5.12 经典RISC五级流水线

## 五段各做什么
- **IF**：按PC取指、计算/选择顺序PC
- **ID**：译码、读寄存器、扩展立即数
- **EX**：ALU算术或求Load/Store有效地址；分支比较/目标计算视设计
- **MEM**：Load读数据存储器，Store写数据存储器；其余指令可空过
- **WB**：写回通用寄存器（ALU结果或Load数据）；Store/很多分支无通用寄存器写回
- 各级之间有流水寄存器；数据和控制位**一起向前传递**
- <img src="/images/408-mind-maps/co-05-readable-0045.svg" alt="IF、ID、EX、MEM、WB五级流水线框图" width="990" height="440">

## 典型ALU寄存器运算 `ADD R3,R1,R2`
- IF取指 → ID读取R1/R2 → EX计算R1+R2 → MEM空过 → WB写R3
- 同一条指令虽然MEM没有数据访存，**仍占用流水时序位置**（在固定5段模型）
- 不要把“所有RISC运算类指令都只需1个周期”作为延迟结论

- <img src="/images/408-mind-maps/co-0119.svg" alt="运算类指令：M 段空过" width="720" height="320">

## `LOAD R2, 8(R1)`
- IF → ID读基址R1与立即数8 → EX算EA=R1+8 → **MEM读取M[EA]** → WB写R2
- 基址与位移如何解释（字节单位/对齐）须遵守ISA

## `STORE R2, 8(R1)`
- IF → ID读取基址R1与要写的数据R2 → EX算EA → **MEM写入M[EA]←R2** → WB空过
- 原图笔记把STORE的MEM误写为“从Cache中取数据”，应改为**写数据缓存/主存**
- Store并不会自动回写通用寄存器R2
- <img src="/images/408-mind-maps/co-05-readable-0155.svg" alt="STORE指令在MEM阶段写数据而WB阶段为空" width="1000" height="444">

## `BEQ R1,R2,offset`
- IF → ID读R1/R2 → 预定阶段比较并求目标 → 若成立更新PC
  - 在某些教学图中EX判定，某些在ID阶段；**分支罚时由决策阶段决定**
- 偏移尺度不固定：例如经典MIPS按4B指令寻址时可表示$PC_{seq}+(signext(off)\ll2)$
  - RISC-V分支、x86等又各有编码规则，**必须按题设而不是套公式**

- <img src="/images/408-mind-maps/co-0196.svg" alt="条件转移指令：M 段把目标 PC 写回 PC，WB 为空段" width="720" height="340">

## `JMP`或无条件跳转
- 也可能在ID/EX计算和更新PC；不必经过数据MEM/WB阶段
- “越早知道目标越容易减少冲刷流水线成本”是关键
