# 5.14 流水线冒险（二）：控制流

## 控制冒险的根源
- 条件分支、间接跳转、异常等使**下一条PC**不能立即确定
- 如果流水线已经取入错误路径指令，需要清除(flush)或使其失效
- <img src="/images/408-mind-maps/co-05-readable-0133.svg" alt="遇到分支后的错误路径指令冲刷及目标路径重新取指" width="1090" height="395">

## 典型解决手段
- 尽早计算分支条件和目标PC（在ID而非EX判定可降低典型损失）
- 静态预测：恒预测不跳/跳；按编译器提示或转移方向给规则
- 动态预测：结合历史结果、分支目标缓冲BTB、预测器
- 预测执行：在预测路径上取指；**预测错则清空受影响的年轻指令**
  - 错误路径的架构状态必须不产生可见副作用，需回滚或延迟提交
- 延迟分支：某些旧ISA规定执行分支延迟槽指令；现代ISA并非普遍如此

## 用罚时模型计算CPI
- 理想CPI为1，分支指令比例b，错误预测率p，每次错预测损失q个周期
  - 近似$CPI=1+b\cdot p\cdot q$，前提其他冒险与开销忽略
- 算例：b=20%、p=10%、q=3
  - $CPI=1+0.2\times0.1\times3=1.06$
- 若题目说**每次分支均停顿2拍**，则应使用b×2，而不是误用p

## 分支目标地址容易算错
- 下一顺序PC的基准是否已更新？立即数有符号吗？是否隐含左移？
- 例如题设明确PC已指向下条指令，位移为-4字节：`target=PC-4`
- 不能把x86相对位移和经典MIPS字对齐偏移混成一种规则

## 对异常/中断的额外说明
- 异常需要保持**精确的架构状态**：较早指令完成、故障指令及其后续按规则处理
- 中断/异常会改变控制流，但保存现场的内容和检查点受架构规定
