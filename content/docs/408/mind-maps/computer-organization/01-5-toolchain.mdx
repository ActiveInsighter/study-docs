# 1.5 从源代码到可执行程序

## 典型C编译工具链（以常见GCC流程为例）
- 源文件 `hello.c` → **预处理** → `hello.i`
- `hello.i` → **编译** → 汇编文本 `hello.s`
- `hello.s` → **汇编** → 可重定位目标文件 `hello.o`
- `hello.o` + 所需库/其他目标模块 → **链接** → 可执行文件
- **装载**：由OS加载器建立进程映像、映射必要代码/数据后开始执行
- <img src="/images/408-mind-maps/co-0073.svg" alt="C程序预处理、编译、汇编、链接的典型流水线" width="860" height="220">
- 以上扩展名和中间结果是常见示例，**不代表所有工具链必须生成磁盘上的.s文件**

## 预处理器做什么
- 展开宏、处理条件编译、按包含规则展开头文件的文本内容
- `#include <stdio.h>` 在通常C工具链中于**编译前**处理
  - 运行可执行程序时无需再从磁盘读取这个头文件并“补编译”
- 头文件包含声明与宏，不等于把全部库函数机器码复制到源码

## 编译、汇编与链接各做什么
- 编译器进行语法/语义检查和中间表示优化，输出低级表示或机器码
- 汇编器翻译汇编指令与伪指令，生成目标模块
- 可重定位目标文件常包含符号表、重定位记录及代码/数据节
- 链接器解析跨模块符号、重定位与组织输出文件
  - 静态链接：将所需对象/库代码合入输出（具体机制视工具链）
  - 动态链接：执行前/执行时由加载器或动态链接器完成共享库关联
- **链接后的可执行文件不等于已经装载在内存中的运行进程**

## 翻译路径辨析
- **编译**：把源程序转化为另一种表示，可为汇编、机器码、字节码
- **解释**：由解释执行器逐步处理源代码或字节码语义
- **JIT即时编译**：运行时将热点代码转换为本机机器码
- 这些模式可组合使用；不要把Python/Java概括成“绝对只解释、不编译”

## 实际执行时的时间顺序
- 编辑源程序 → 构建产物 → shell启动可执行程序
- OS加载程序、设置虚拟地址空间和运行时上下文
- CPU按PC的控制流执行**机器指令**；函数调用可能触发系统调用/I/O
- 输出由程序经系统服务/设备驱动到达终端或其他设备
