# 3.7 后退N帧GBN

## GBN机制
- **发送窗口Ws可以大于1**：允许流水式发送多个未确认帧
- **接收窗口Wr=1**：只能按序接收下一个期望帧
- 收到失序帧通常丢弃，可再次确认最近连续收到的帧
- **累计确认**：本章约定`ACK n`代表序号不晚于n的连续已接收帧

## 出错时为什么“回退N帧”
- 例如发送0、1、2、3；帧1丢失
- 接收端收0后期待1，收到2、3也不交付/缓存（典型GBN）
- 发送端在最早未确认帧1超时后，**从1开始重传全部尚未确认帧**
- 缺点：误码率高时即使后续帧已到达，也可能白白重发

## 序号空间与窗口上界
- k位序号，共$M=2^k$种取值，**GBN要求 $1\le W_s\le M-1$**
- 若$W_s=M$，旧一轮与新一轮同序号帧在ACK丢失情形下可能无法判别
- 例：3位序号0~7 → `Ws`最大7；4位序号 → 最大15
- **最大窗口不是固定“所有协议总窗口N=…”**：接收窗口是否缓存、确认方式才是关键

## 计时器与重发
- 典型实现只针对**最早未确认帧**启动定时/调整定时器
- ACK移动窗口时，可将新窗口起点对应的最早未确认帧作为定时对象
- 不是“每发一帧都必须开独立计时器”：那更接近SR

## 例题：4bit序号
- $M=16$，$W_s\le 15$；若题设窗口为10，GBN合法
- 若序号共3bit、发送窗口为8 → **不合法**（须≤7）
- 对比SR：相同3bit且对称窗口最大只有4
