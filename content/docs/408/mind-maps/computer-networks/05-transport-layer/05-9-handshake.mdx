# 5.9 三次握手、SYN序号与连接建立

## 标准三次握手（以初始序号x、y表示）
- <img src="/images/408-mind-maps/cn-05-handshake-clean.svg" alt="三次握手带序号、确认号和状态转换" width="1000" height="472">
- ① 客户端 `SYN=1, seq=x`：`CLOSED → SYN-SENT`；SYN消耗一个序号
- ② 服务器 `SYN=1, ACK=1, seq=y, ack=x+1`：`LISTEN → SYN-RCVD`
- ③ 客户端 `ACK=1, seq=x+1, ack=y+1`：客户端进入`ESTABLISHED`；服务器收到确认后进入`ESTABLISHED`
- 第③次纯ACK一般**不消耗序号**，可携带数据时才按照数据长度推进序号

## 为什么不是两次
- 服务端要确认**客户端有接收服务端SYN的能力**，双方交换初始序号并确认
- 防止旧的失效连接请求使服务端误以为创建了新连接；第三次ACK使握手完整
- 建连语义不等于把网络改造成可靠的链路；丢失仍靠后续TCP机制处理

## SYN与ACK易错
- 大写`ACK`为1比特**确认标志**；小写`ack`是32比特**确认号字段**
- `seq=x`是该TCP段第一个数据字节的序号；不含数据的SYN仍占一个序号
- 服务器在`SYN-RCVD`为半连接维护状态；可采用SYN Cookie减轻资源消耗
- **不要求第三次ACK到达之前客户端一直不能发送应用数据**：建立确认段可携带数据，按具体语义解释
