# 5.17 拥塞窗口、阈值与四种经典算法

## 拥塞与流量控制不是一回事
- **拥塞控制**：防止发送方注入过多数据造成网络中的排队、丢包和吞吐下降
- **流量控制**：避免接收方来不及读取而溢出接收缓存
- `cwnd`：发送端基于网络反馈维护的拥塞窗口；`ssthresh`：慢开始阈值
- `rwnd`：接收端通告；简化发送限制为`FlightSize≤min(cwnd,rwnd)`

## 经典Reno教学框架
- **慢开始**：`cwnd`每收到确认新数据的ACK通常增大约1 MSS（经典模型），在一个RTT近似翻倍
- **拥塞避免**：`cwnd`一个RTT约增大1 MSS，近似线性增长（AIMD中的加性增）
- **快速重传**：通常3个重复ACK触发疑似丢失段的立即重传
- **快速恢复**：Reno在重复ACK事件后降低阈值、暂时调整窗口，通常避免直接回到1 MSS

## 算法版本差异
- 考研典型图题常将慢开始初值设为`1 MSS`；**真实TCP实现可能初始窗口大于1 MSS**
- 超时RTO通常视为严重拥塞：更新阈值、窗口降至初始值（按题设常取1 MSS）
- 三重复ACK的Reno处理与Tahoe不同：Tahoe也可能把窗口回到1 MSS；按题设算法区分
- CUBIC、BBR等现代控制不必套用Reno每RTT一格的线性增长图

## 公式与单位
- 题图纵轴若是MSS个数，则`cwnd=16`表示**16 MSS**，不是16字节
- MSS是TCP**数据载荷**上限；IP首部/选项均不计入MSS
- 窗口数变化的“每收到ACK+1”需要说明以**确认了新数据**和教材简化为前提
