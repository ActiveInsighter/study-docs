# 4.7 路由转发算法与最长前缀匹配

## 查表逻辑
- 目的IP与每条路由网络前缀匹配，**选中前缀最长的有效可用条目**
- 本机接口直连路由、静态路由、动态学到的路由可能共同存在；路由协议先确定候选优劣，再形成FIB
- `/32`主机路由比`/24`更具体；`0.0.0.0/0`是**匹配所有IPv4目的地**的最后兜底
- **路由器不必先机械地“直连→主机→默认”逐一按固定优先级结束**；转发关键是LPM

## 一道高频查表题
- 路由1：`192.168.0.0/16 → A`
- 路由2：`192.168.1.0/24 → B`
- 路由3：`192.168.1.128/25 → C`
- 默认：`0.0.0.0/0 → D`
- 目的`192.168.1.130`命中全部四项，但**选C**（/25最长）
- 目的`192.168.1.50`选B；`192.168.2.2`选A；`8.8.8.8`选D

## 真正发送时发生什么
- 取得下一跳IP和出口接口；以太网接口通常先ARP解析下一跳MAC
- 链路帧的MAC地址**逐跳重写**，IP源/目的地址在无NAT情况下通常保持不变
- 每次IP路由转发使IPv4 TTL减1，必要时更新首部校验和
- 若无匹配可用路由且没有默认路由→丢弃，可能回ICMP目的不可达

## 易错区分
- 下一跳IP ≠ 下一跳MAC；路由表常记录目的前缀、下一跳、出口、度量等
- **本地交付**是终点主机或目的地址属于本路由器接口；**直接交付**是出接口直连网段，无需再经其他路由器
- 不能把IP广播当作每跳的ARP广播
