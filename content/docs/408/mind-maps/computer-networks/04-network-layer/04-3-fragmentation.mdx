# 4.3 IPv4分片、MTU与偏移计算

## 什么时候分片
- 以太网常见MTU=1500 B（指以太网帧承载的IP包，**不是含MAC首部/FCS的帧长**）
- IPv4数据报超过下一跳MTU，且`DF=0`时允许按需要分片；`DF=1`则丢弃并可返回“需要分片”ICMP信息
- **只在最终目的IP主机重组**；中间路由器不会先拼成完整数据报再转发
- IPv6路由器**不分片**，由源点依据路径MTU处理

## 计算模板（假定20 B首部）
- 每个非末片最大载荷：$P=8\left\lfloor\frac{\mathrm{MTU}-20}{8}\right\rfloor$
- 片偏移：$\mathrm{offset}_i=\frac{\text{之前各片载荷字节之和}}8$
- 每片总长度=该片载荷+20 B；**非最后一片**载荷必须为8 B整数倍
- 最后一片载荷可不足8 B整数倍；重组靠源地址/目的地址/协议/标识等识别

## 例题：4000 B载荷、MTU=1500 B
- 原IPv4数据报总长4020 B；每个满片最多1480 B
- 第1片：载荷1480 B，总长1500 B，偏移0，`MF=1`
- 第2片：载荷1480 B，总长1500 B，偏移185，`MF=1`
- 第3片：载荷1040 B，总长1060 B，偏移370，`MF=0`
- 三片标识相同；分片数据总字节$1480+1480+1040=4000$

## 常见陷阱
- **片偏移单位是8 B**，不是8 bit；首部长度单位4 B；总长度单位1 B
- 分片各自有IPv4首部，**不能用完整IP总长度直接除以MTU**
- DF=0不意味着一定已分片；MF=0可能代表未分片数据报或最后一个分片
- IPv4固定首部校验和**逐片计算**；中途分片会产生新的IP首部
