## 总结！

- 网络层全整理：

  - 总流程
    - 网络层总流程示例：AS1 中有主机 A、B、C 与路由器 R1、R2、R3（R3 为 BGP 发言人），AS2 中有 R4（BGP 发言人）、R5 与主机 D、E、F
      - ① A 刚接入：A 用 DHCP 获取 IP（由 B 帮忙转发也可）
      - ② A → B：A 查 ARP 缓存，有则直接发；没有则广播 ARP 请求，B 收到后单播 ARP 响应告知自己的 MAC
      - ③ A → F：A 查 ARP 得到默认网关 R1 的 MAC，经 R1 → R2 → R3 → R4 → R5 → F
        - 经过 NAT 时需要转换地址
        - AS 内部用 OSPF 或 RIP 维护路由表；AS 之间 R3、R4 用 BGP 交换（BGP-4）
        - 每一跳都要用 ARP 找下一跳的 MAC 地址

  - 同一局域网内两主机数据交流
    - 同一子网内两主机交流：A 想发给 B
      - ① A 先检查目的 IP 与自己是否在同一网络（网络号、子网号相同）：同网则查 ARP 高速缓存，有则直接发
      - 没有就广播 ARP 请求报文，B 收到后回复自己的 MAC 地址，然后 A 再发送
      - ② 若 A 发现目的主机在外网，用 ARP 找到默认网关（默认路由器，路由表中目的为 0.0.0.0 的项）的 MAC 地址，把帧发给它转发

  - NAT转发流程（蓝字举例为：接受了一个来自WAN的帧）
    - NAT 转发：LAN 侧 `172.16.3.1:8080` ⇄ WAN 侧 `176.1.1.1:1010`
      - 收到一个数据帧，若是局域网内的，就把 LAN 的 IP:Port 转为 WAN 的 IP:Port 发出；若是 WAN 发来的，则按转换表把 WAN 的 IP:Port 换回 LAN 的
      - 注 ①：私有地址范围 A `10.x.x.x`，B `172.16.0.0 ~ 172.31.255.255`，C `192.168.x.x`
      - 注 ②：NAT 的 LAN / WAN 主机号不是全 0；NAT 中的每个 LAN 是一个主机（看作一个 port）
      - 注 ③：涉及端口，是传输层的内容（NAPT）

  - 子网掩码转发
    - 子网掩码转发（路由器收到 IP 数据报后）
      - ① 提取目的 IP 地址
      - ② 检查是否直接交付：用本路由器各网络的子网掩码与目的 IP 相与，看是否属于直连网络
      - ③ 是否为“特定主机”路由（主机路由）
      - ④ 查找所有其他 IP 路径：对路由表中每一项，用其子网掩码与目的 IP 相与，与目的网络地址比较（最长前缀匹配）
      - ⑤ 都没有则交付给默认路由
      - ⑥ TTL = 0 时丢弃

  - ARP转发
    - ARP 转发：IP 和自己在同一子网 / 不在同一子网分别如何处理（A、B 在同一子网，C 在 R2 之后）
      - 在同一子网（A 发 B）
        - ① A 发给 B：若 A 的 ARP 表中有 B 的 MAC，则直接封装到链路层进行发送；若没有，则广播 ARP 请求：`IP A | IP B | MAC A | FF-FF-FF-FF-FF-FF`
        - ② B 收到请求后，回送一个单播响应：`IP B | MAC B`
        - ③ A 把帧组成发送到物理层：`FCS | IP 报 | MAC A | MAC B | IP A | IP B`
      - 不在同一子网（A 发 C）
        - ① 使用同样步骤获得默认网关的 MAC（即 MAC1）
        - ② R1 收到后，转发数据：IP A → WAN 的 IP A′，IP C 不变，源 MAC 是 MAC2；若 R1 和 R2 是 PPP，则目的 MAC 为全 1，否则为 MAC3（新的 ARP 请求）
        - ③ R2 发现主机 C 在同一网内，则使用同样的步骤
        - ④ 主机 C 收到后返回 `IP C | MAC C`

  - DHCP
    - DHCP：自己刚上网，如何获得 IP？
      - ① 刚到的主机：不知道服务器在哪里，广播“DHCP 发现”报文（基于 UDP）
      - ② 服务器收到，回复“提供”报文（给出可用 IP）
      - ③ 主机选择一个服务器，广播“DHCP 请求”报文
      - ④ 服务器收到后确认，分配 IP：你的 IP 是 x.x.x.x（DHCP 确认），可能还需要中继代理转发

  - IGP
    - IGP：用于生成本 AS 内的路由表
      - 方法 1：RIP，路由表形如 ⟨目的 IP，下一跳 MAC，跳数⟩，基于 UDP
      - 方法 2：OSPF，路由器中存有全网拓扑图，基于 IP

  - AS、BGP、IGP（如果使用OSPF，那大型网络还可以被划分）
    - AS、BGP、IGP：不同内部协议的网络怎么互联？
      - 每个 AS 内部使用自己的 IGP（如 AS1 用 OSPF，AS2 用 RIP），OSPF 时大型网络还可以划分区域
      - 各 AS 选出 BGP 发言人，发言人之间基于 TCP 交换 BGP 路由信息
      - BGP 路由表：⟨网络前缀，下一跳，所经 AS 序列⟩

    - 拥塞状态
      - 吞吐量【随着负载增大而下降】
    - 死锁状态
      - 网络【负载增大】，吞吐量【下降到 0 】
  - 拥塞后果

  - 实现方法

  - 拥塞控制的方法

      - 在设计网络时预先将发生拥塞的因素考虑周到，力求不会产生拥塞
      - 是一种静态的拥塞预防，启动后不需更改
    - 闭环
      - 事先不考虑各种因素，用检测网络去监视，及时检测
      - 基于【反馈环路】，是动态方法

## IPv4、子网划分

- IPv4 数据报格式 <img src="/images/408-mind-maps/cn-0109.svg" alt="IPv4 数据报格式" width="300" height="154">

  - 单位总结：
    - 一种首饰八片
    - 总长度：1B
      - 首部长度：4B
        - 片偏移：8B
  - MF：More Fragment 还有分片
    - DF：Dont Fragment 不分片
  - 标识：
    - 源主机在发送数据报时设定的“ID”，来一个数据报，标识++（数据报分片后，每个数据报都是相同的标识）
  - 片偏移的单位是8B，所有分片长度都是8B的整数
    - 首部20B，1480/8=185，刚好可以够分
    - 最后一片可以不是8B整数
  - TTL生存时间
    - 是一直在减少的，减到0就丢弃
    - 每次转发TTL都要 -1，当TTL = 0，丢弃
  - 这里的FCS只有16bit（因为只检查首部）
    - 而数据链路层的FCS有32bit，需要检查全部内容
    - TCP和UDP的FCS也是16bit，但需要检查全部内容
    - 概要：此处显得IPv4的检错功能不那么重要了（IPv6删去了该内容）

    - 对主机号进行了划分，划分为了【子网号 + 主机号】
      - 划分过后每个子网中的主机号全0和全1都应该保留下来
      - 在RFC950中规定子网号不可以为全0或者全1，而CIDR是可以支持全0、全1的
    - 网络号+子网号+主机号
  - CIDR （无分类阈间路由选择）
    - 网络前缀 + 主机号 / 前缀长
    - CIDR不使用子网，仍使用“掩码”
    - CIDR地址块：网络前缀相同的IP地址
    - 划分子网
      - 在网络号后的主机号中，仍可以把几位主机号抽取出来作为子网号，继续划分
        - 这样划分前缀长不变，子网掩码发生变化
    - 路由聚合/构成超网
      - 把同一路由表中的不同网络项取交集，聚合成一个前缀长更小的网络
      - 每一个CIDR地址块都可以表示很多地址，也是路由聚合/构成超网的一种表现
    - 最长前缀匹配
      - 在路由表中选择下一跳的地址，找到匹配前缀最长的下一跳
      - 如果找不到，就跳到0.0.0.0去
      - CIDR查找路由表的算法是二叉线索树来查找

## 路由转发

- 考频：超高
  - 10\*2、11、12\*3、15、16-18\*2、19、21-22\*2、15大、18大、20大、22大
- 路由器本身可以有多个IP地址+多个MAC地址
- 路由器的分组转发算法
  - 已知：目的网络N，目的主机IP地址D
  - NAT的路由分组转发步骤
    - 1\. NAT路由器会维护一个LAN中IP和Port同样对应着WAN中的一个IP和Port
    - 2\. 数据帧封装好自己LAN的IP、端口以及目的网络中WAN对应的IP、端口，发送到NAT路由器
    - 3\. NAT路由器转为WAN的IP，转发
    - 如果接受到WAN的，NAT就把WAN的转为LAN的，然后放到LAN中传输
      - 如何传输，请看ARP
        查看关联主题（原图链接目标缺失：`xmind:#b3b4e1fb-b3fc-4dd5-96b9-ce72e4452bd5`）

  - 对于同一个网段内的主机（子网的掩码相同），一般情况下都是可以进行IP通信的，与其默认网关无关
    - 默认网关：
      - 如果一台主机找不到正确的网关，就把数据报发给默认网关
      - 配置默认网关
        - 手动配置
          - 考试喜欢考
        - DHCP配置
          - 详情看下面
    - 一个主机的默认网关没有正确填写： 1. 无法进入互联网进行信息交流 2. 可以和在同一个网关的主机进行IP交换（局域网广播）
  - 概要：NAT中涉及到了port端口，故NAT是工作在传输层的
    概要范围：[NAT的路由分组转发步骤](#focus=NAT%E7%9A%84%E8%B7%AF%E7%94%B1%E5%88%86%E7%BB%84%E8%BD%AC%E5%8F%91%E6%AD%A5%E9%AA%A4)

- 路由分组转发算法（子网掩码）

  - 获得IP -&gt; 对比子网集 -&gt; 查路由表特殊通道 -&gt; 查路由表其他IP -&gt; 发给默认网关 -&gt; TTL = 0就丢弃并返回ICMP
  - 1\. 路由器【提取】出目的IP地址（从IP报文段中提取）
  - 2\. 路由器【按位与查看】自己的全部子网，看能不能直接【直接交付】
    - 就是查看是不是对应的那个子网
  - 3\. 路由器【按位与查看】自己路由表是否存在这个IP的【特定主机】
    - 看能不能走特殊通道
  - 4\. 路由器【按位与查看】自己的路由表中的所有其他IP路径，看能不能【发给对应的路由器】处理
  - 5\. 路由器发现上面的步骤都行不通，那就发给自己的【默认网关】处理
  - 6\. 如果TTL=0，或者默认网关出错，就丢弃该数据，直接返回ICMP回去
- ARP
  查看关联主题（原图链接目标缺失：`xmind:#980af23a-a8e3-48da-92b8-04d2ed7f38fc`）

  - Address Resolution Protocol 地址解析协议
    - 记住英文可以知道协议的作用
  - 每个主机都会存有一个高速缓存ARP表
    - ARP表：IP地址 --- MAC地址的映射表
  - 若A向B发送信息，工作流程：
    - 查找A的ARP是否有B的IP地址（有了IP就也硬件MAC地址）
      - 如果【有】IP地址，那么就把B的硬件地址写入到MAC帧里面，然后使用局域网把该MAC帧发给B。

      - 如果【没有】IP地址，那么就广播一个【ARP请求分组】（其中MAC地址为【FF-FF-FF-FF-FF-FF】），让局域网内的所有其他主机都收到ARP请求，然后主机继续转发

        - 如果B收到了ARP请求，就单播返还一个【ARP响应分组】回去，告诉主机A自己的IP和MAC地址
          - 其他主机收到【ARP响应】后，也会把B的IP和MAC建立在ARP高速缓存中。
        - 批注：MAC广播地址：FF-FF-FF-FF-FF-FF
    - 主机A收到响应分组后，写入到自己的ARP片中，然后发送MAC帧
    - <img src="/images/408-mind-maps/cn-0077.svg" alt="若A向B发送信息，工作流程：" width="300" height="139">

  - 所以ARP请求是广播的，ARP响应的单播的
  - 总结四种情况
    - 主机➡️本网内主机
      - 用ARP找目的主机地址
    - 主机➡️外网主机
      - 用ARP找本网的路由器硬件地址
        - 一定是NAT路由器
        - 这个路由器的IP地址就是本主机的默认网关
    - 路由器➡️本网内主机
      - 用ARP找目的主机地址
    - 路由器➡️外网主机
      - 用ARP找本网的另一个路由器的硬件地址
  - RARP
    - 通过MAC逆查找IP
      - DHCP中已经有这个技术了
- DHCP
  - Dynamic Host Configuration Protocol
    - 动态主机配置协议
  - 处于应用层，基于UDP，动态的给每个主机分配IP地址，即插即用
  - 使用客户/服务端方式工作
  - 工作原理
    - 广播【DHCP发现】问所有服务器
      - 可以存在多个DHCP服务器
    - 所有收到【DHCP发现】的服务器都广播一个 【DHCP提供】里面有IP+相关的配置信息
      - 多个DHCP服务器都会回复，先到先得
    - 客户机收到【DHCP提供】，广播一个【DHCP请求】
    - 对应服务器收到【DHCP请求】后，将IP地址分给客户机
  - 为什么使用UDP，不使用TCP
    - 因为客户端连IP都没有，只能广播，也无法建立TCP连接
- ICMP
  - Internet control message protocol 网络控制信息协议
  - 差错报文

      - TTL=0/残缺
      - 首部出错

    - 不发送ICMP的情况
      - ICMP出错了
      - 第一个分片后的数据报片后续的不发送ICMP
      - 组播地址
      - 特殊地址
  - 询问报文
    - （PING）回送请求和回答报文
    - （时间戳）时间戳请求和回单报文
    - 掩码地址和回答报文
    - 通告报文
    - 概要：现在不用了
      概要范围：[掩码地址和回答报文](#focus=%E6%8E%A9%E7%A0%81%E5%9C%B0%E5%9D%80%E5%92%8C%E5%9B%9E%E7%AD%94%E6%8A%A5%E6%96%87)、[通告报文](#focus=%E9%80%9A%E5%91%8A%E6%8A%A5%E6%96%87)

## IPv6

- 真正解决IPv4耗尽的问题，NAT、子网等只是缓解手段
- IPv6，一共128bit（8组 \* 4个16进制数 =  8 \* 4 \* 4 bit)，用冒号分隔
  - 对比：
    - MAC
      - FF-FF-FF-FF-FF-FF
    - IPv4
      - 127.0.0.2
    - IPv6
      - 0000:0000:0000:0000:0000:0000:0000:0001 【即 ::1 】
  - 有相继的0时可以用 :: 直接缩写，但只能有一次
    - 例：F:F:F:F:F:0:0:3 可以写为F:F:F:F:F::3
- IPv6的优势
  - 提供QoS保障（Quality of Service，服务质量）

  - 更大的地址空间，首部是8B的整数倍

    - 扩展的地址层次格式
      - 改进的选项
  - 允许协议继续扩充

    - 支持即插即用（自动配置）
      - 支持资源预分配
  - 只有在包的源点分片，路由器不允许分片

    - 如果超了，就丢弃掉然后返回一个ICMPv6，只有在目的才能重新组装
  - 增大的安全性，有身份验证和保密功能

- IPv6头部 <img src="/images/408-mind-maps/cn-0044.svg" alt="IPv6头部" width="300" height="150">

- IPv6的三种传播形式
  - 单播
    - 点对点通信
  - 多播
    - 点对多通信（可以用来实现IPv4的广播）
  - 任播
    - 点对多中的一个，发给一组主机，如果有一个接受了，就不发了。
- IPv4和IPv6的过渡
  - 双栈协议
    - 一台计算机：同时拥有IPv4地址和IPv6地址
    - 一台设备上：同时装有IPv4和IPv6协议，可以和IPv4通信也可以和IPv6通信
    - 一台路由器上：在不同接口上分别配置了IPv4和IPv6的地址
  - 隧道技术
    - 可以把IPv6的数据报封装到IPv4数据报的数据部分里面

  - 无

## 路由协议

- 考频：高
  - 10、16、17、21、13大、14大
- 自治系统AS
  - autonomous system
  - 单一技术管理下的一组路由器，这些路由器使用一种AS内部的路由选择协议
    - 内部网关协议IGP，如ARP、OSPF
  - 同时还使用一种AS之间的路由选择协议
    - 外部网关协议EGP，如BGP-4
- 静态路由（手动配置）

  - 简便可靠，负荷稳定，拓扑变化不大
- 动态路由：  域内路由（内部网关协议IGP）

  - 路由信息协议RIP

    - 全程：
      - Routing Information Protocol 路由信息协议
        - 应用最广泛的协议，简单
    - 路由表信息：
      - 每个路由器只维护他到每个【目的网络】的【距离向量】
      - 路由表信息：&lt;目的网络N，距离d，下一跳路由器R&gt;
    - 性质
      - 【应用层协议】，把自己封装到UDP报文中（UDP是传输层，但他的数据来自于应用层，在【传输层传输】），使用端口520的UDP
      - 跳数
        - 从一个路由器到一个连接网络要中转的路由器数（跳数 - 1）
        - 最大跳数为15，如果跳数&gt;=16，即说明网络不可达
          - 对比记忆：CSMA/CD的二进制回退算法
      - 最短广播时间
        - 30s广播一次RIP路由信息
    - 特点
      - RIP中每个网络的子网掩码必须相同，但是新的RIP2协议中，支持变长子网掩码和CIDR
      - 开销小、收敛快、实现简单
      - 适用于小型的互联网
      - 存在慢收敛情况
        - 例如：R1连接的N1出现了故障，表从&lt;1, 1, - &gt; 变成了 &lt;1, 16, -&gt;
        - R2原来是&lt;1,2,R1&gt;，现在R1收到R2的交换信息，自己变成&lt;1,3,R2&gt;。&lt;1, 16, -&gt; 这个真实的信息丢了。
        - 最后经过数轮过后，R1、R2都变成了&lt;1, 16, R2&gt;和&lt;1, 16, R1&gt;
    - RIP的算法步骤
      - 1\. 与相邻路由器
      - 2\. 路由器交换的信息是当前路由器所知道的全部信息，就是自己的路由表
      - 3\. 30s更新一次
      - 4\. 收到信息后的步骤
        - 路由表信息：&lt;目的网络N，距离d，下一跳路由器R&gt;
        - 1\. 收到来自路由器Rx的信息，【N不变，d++，R = Rx】
        - 2\. 查看自己的路由表，【如果没有N的信息】，则直接添加进去
        - 3\. 查看自己路由表，【如果有N，R相同】，那么直接改d为新的（不论大小）
        - 4\. 查看自己路由表，【如果有N，R不同，d更小】，则改成新的（新的d比旧的d要小，就改成新的）
      - 如果180s还没有收到相邻路由器的RIP，则判定其不可达（设置d为16）
    - 优点：
      - 简单、开销小、收敛快
  - 开放最短路径优先OSPF
    - Opening Short Path First
      - 开放最短路径优先
    - 每个路由器维护【全网的拓扑结构图】
      - 即：DD链路状态数据库的同步
    - 性质
      - 【网络层】协议，使用IP数据包传送，在网络层传输
      - 洪泛法发送数据给【所有路由器】，⚠️  这里实际洪泛法是只发给相邻的路由器，然后一层一层传出去
      - 交换信息为【本路由相邻的所有路由器的链路状态】
        - 与RIP相比不一样的：RIP是发自己知道的全部东西
          查看关联主题（原图链接目标缺失：`xmind:#fbf903b1-8017-4bb2-84ee-28fbf61d8250`）

        - 链路状态
          - 本路由器与哪些路由器相邻
          - 链路的“度量”（或代价）
      - 只有链路状态发生变化的时候才会使用洪泛法发送信息
        - 与RIP相比不一样的：RIP是每30s就发一次
        - OSPF规定每隔30min更新一次链路状态
    - 特点
      - OSPF的代价可自行调节，针对不同类型业务可计算出不同的路由，【十分灵活】
      - OSPF算法会把【大型网络划分为数个区域】，区域内的路由器只会存储每个区域内的链路数据库
        - 适用于大型网络
        - 主干区域为0.0.0.0，除了主干区域，其他为自治系统边界路由器
        - 四种路由器
          - 主干路由器
            - 主干区域内的
          - 区域边界路由器
            - 主干区域 ↔️  边界区域
          - 区域内部路由器
            - 边界区域内部
          - 自治系统边界路由器
            - AS1 ↔️  AS2
      - 收敛过程快，不会出现“慢收敛现象”
      - 四个楼楼没讲的功能
        - 1）如果到同一个目的网络有多条相同代价的路径，那么可以将通信量分配给这几条路径。这称为多路径间的【负载平衡】。
        - 2）所有在OSPF路由器之间交换的分组都具有鉴别功能，因而保证了仅在可信赖的路由器之间交换链路状态信息。
        - 3）支持可变长度的子网划分和无分类编址CIDR。
        - 4）每个链路状态都带上一个32位的序号，序号越大，状态就越新。
    - OSPF算法步骤
      - 目的：每个路由器都建立一个全网的链路状态数据库，即全网拓扑结构图
        - 然后每个路由器在结束链路交换后，使用Dijikstra算法计算最优路径
          - 在路由器的存储中，存的仍然是下一跳的地址，因为Dijikstra对每个顶点也可以只存下一跳的地址
      - 五种OSPF
        - HELLO问候分组
        - （metric每个邻居的成本度量）
        - 数据库描述分组
          - 向邻站发送自己链路状态数据库中所有链路状态项目的摘要信息
        - LSR链路状态请求分组
          - 向对方请求某些链路状态的详细信息
        - LSU链路状态更新分组
          - 洪泛式更新链路状态
        - LSAck链路状态确认分组
          - 对收到的更新分组进行去人
      - 步骤
        - 1\. 有一个路由器发生了路由变化
        - 2\. 该路由器洪泛式发送LSU
        - 3\. 其他路由器收到后更新DD链路数据库，返回LSAck
        - 4\. 所有其它的路由器，重新跑一次Dijikstra
- 动态路由： 域间路由（外部网关协议EGP）

  - BGP-4
    - 特点
      - 应用层，基于TCP
        - 为什么使用TCP
          - TCP有更稳定的服务，可以简化路由协议
    - 性质
      - 不同AS之间进行交换的协议
      - 每个AS中至少有一个BGP发言人
        - BGP发言人与其他AS中的BGP发言人进行路由信息交换
        - 交换的信息是【路径向量】
      - BGP支持CIDR，路由表为 &lt; 网络前缀、下一跳路由器、所经过的AS序列 &gt;
      - 在刚开始运行的时候，所有发言人都与相邻路由器交换整个BGP路由表，以后只在有更新变化的时候再更新有变化的部分
    - 四种报文
      - 打开(Open)
        - 与相邻BGP发言人建立关系
      - 更新(Update)
        - 用来发送某一路由信息，以及要删除的信息
      - 保活(KeepAlive)
        - 周期性的证实临站的存在
      - 通知(Notification)
        - 发送检测到的差错
- 动态路由三种对比

  - 配图

## IP组播

- 只用于UDP，点对多点。把一个报文分组发送给多个目的地主机，只会在接受的前一个路由器处进行复制
  - UDP，不提供可靠交付
  - 组播地址只能是目的地址
  - 组播信息不产生ICMP报文，PING后+组播地址，无法接收到响应
- 使用IGMP协议才可以加入组播组
- 组播地址：224.0.0.0 ～ 239.255.255.255
  - 不是所有D类地址可作为组播地址，有许多已经被作为永久组播地址，不允许使用
- 两种组播
  - 在因特网范围内组播 IGMP (internet group message protocol)
    - 路由器维护【成员关系】
      - 是否有成员在组播组中
    - 第一阶段：若【主机】申请加入新的组播组，那么主机向【组播组的组播地址】发送IGMP报文说自己要进来。
      - 【本地的组播路由器】收到后，把组的成员关系转发给【其他组播路由器】
    - 第二阶段：本地的组播路由器会周期性询问LAN的主机
      - 只要有一台主机回应，就认为本组活跃
      - 如果【经过几次】都没回应，就不把这个组的成员关系转给其他组播路由器
    - 概要：所以，组播必须要路由器才可以实现
      概要范围：[路由器维护【成员关系】](#focus=%E8%B7%AF%E7%94%B1%E5%99%A8%E7%BB%B4%E6%8A%A4%E3%80%90%E6%88%90%E5%91%98%E5%85%B3%E7%B3%BB%E3%80%91)

    - 批注：维护成员关系
  - 在因特网和硬件间组播 （组播IP地址与组播MAC地址的对应关系）
    - 01005E是固定的组播MAC前缀，而IP有组播地址范围（前4bit是1110）
    - IP和MAC地址的最后23位一定一摸一样，一一对应
    - 概要：所以一个组播IP地址可以对应很多个MAC地址，故会有多个主机接受到组播地址，需要在IP层利用软件进行过滤，把不是给本主机的组播信息丢弃掉
      概要范围：[01005E是固定的组播MAC前缀，而IP有组播地址范围（前4bit是1110）](#focus=01005E%E6%98%AF%E5%9B%BA%E5%AE%9A%E7%9A%84%E7%BB%84%E6%92%ADMAC%E5%89%8D%E7%BC%80%EF%BC%8C%E8%80%8CIP%E6%9C%89%E7%BB%84%E6%92%AD%E5%9C%B0%E5%9D%80%E8%8C%83%E5%9B%B4%EF%BC%88%E5%89%8D4bit%E6%98%AF1110%EF%BC%89)、[IP和MAC地址的最后23位一定一摸一样，一一对应](#focus=IP%E5%92%8CMAC%E5%9C%B0%E5%9D%80%E7%9A%84%E6%9C%80%E5%90%8E23%E4%BD%8D%E4%B8%80%E5%AE%9A%E4%B8%80%E6%91%B8%E4%B8%80%E6%A0%B7%EF%BC%8C%E4%B8%80%E4%B8%80%E5%AF%B9%E5%BA%94)

    - 批注：进行组播
- 组播路由选择
  - 通过IGMP使路由器获得组播成员信息
    - 找到组播转发树（因为每个分组只转发一次，所以使用树形结构。根节点不同，树也会不同）
  - IGMP是TCP/IP的一个部分
  - 三种路由算法
    - OSPF
    - RIP
    - PIM（协议无关组播，了解即可）
- 考频：低
  - 无

## 移动IP

- 考频：低
  - 无
- 定义
  - 移动IP
    - 支持移动性的因特网结构与协议的IP
  - 移动结点
    - 具有永久IP地址的移动结点
  - 移动代理
    - 外埠代理/外部代理
    - 本地代理/归属代理/归属网络
- 处理流程
  - 1\. 如果在本地网络内，就使用普通的TCP/IP通信
  - 2\. 移动节点移动到外网，仍然使用本地IP。需要向本地代理注册当前的位置地址
  - 3\. 本地代理接受到注册后，会构建一条通往移动代理的隧道，然后截获发给本地的IP分组通过隧道传到代理网络处
  - 4\. 代理网络处解除隧道的封装，恢复原始的IP分组，最后送过去
  - 5\. 在外网通过外网的路由器或外埠代理发送IP数据包
  - 6\. 来到新的网络就新注册
  - 7\. 回去就注销
- 移动节点以固定IP来实现跨网的漫游

- 控制平面
  - 软件解决
  - 传统方法（每路由器法）：
    - 路由选择算法运行在每一台路由器之中，每个路由器都有转发和路由选择两个功能
    - 所以在传统方法中控制平面和数据平面在一个路由器里面是同时起作用的
      - 每个路由器既要进行对数据帧的转发，也要进行对路由转发表的建立
    - 路由选择处理器：
      - 传统方法：【路由选择处理器执行控制平面功能】。在传统的路由器中，它执行路由选择协议，维护路由选择表于关联链路状态信息，并为该路由器计算转发表。
      - SDN方法： 在SDN路由器中，【路由选择处理器负责与远程控制器通信】，目的是接收远程控制器计算的转发表项。
      - 概要：SDN方法中进行了分离
        概要范围：[传统方法：【路由选择处理器执行控制平面功能】。在传统的路由器中，它执行路由选择协议，维护路](#focus=%E4%BC%A0%E7%BB%9F%E6%96%B9%E6%B3%95%EF%BC%9A%E3%80%90%E8%B7%AF%E7%94%B1%E9%80%89%E6%8B%A9%E5%A4%84%E7%90%86%E5%99%A8%E6%89%A7%E8%A1%8C%E6%8E%A7%E5%88%B6%E5%B9%B3%E9%9D%A2%E5%8A%9F%E8%83%BD%E3%80%91%E3%80%82%E5%9C%A8%E4%BC%A0%E7%BB%9F%E7%9A%84%E8%B7%AF%E7%94%B1%E5%99%A8%E4%B8%AD%EF%BC%8C%E5%AE%83%E6%89%A7%E8%A1%8C%E8%B7%AF%E7%94%B1%E9%80%89%E6%8B%A9%E5%8D%8F%E8%AE%AE%EF%BC%8C%E7%BB%B4%E6%8A%A4%E8%B7%AF)、[SDN方法： 在SDN路由器中，【路由选择处理器负责与远程控制器通信】，目的是接收远程控制](#focus=SDN%E6%96%B9%E6%B3%95%EF%BC%9A%20%E5%9C%A8SDN%E8%B7%AF%E7%94%B1%E5%99%A8%E4%B8%AD%EF%BC%8C%E3%80%90%E8%B7%AF%E7%94%B1%E9%80%89%E6%8B%A9%E5%A4%84%E7%90%86%E5%99%A8%E8%B4%9F%E8%B4%A3%E4%B8%8E%E8%BF%9C%E7%A8%8B%E6%8E%A7%E5%88%B6%E5%99%A8%E9%80%9A%E4%BF%A1%E3%80%91%EF%BC%8C%E7%9B%AE%E7%9A%84%E6%98%AF%E6%8E%A5%E6%94%B6%E8%BF%9C%E7%A8%8B%E6%8E%A7%E5%88%B6)

  - SDN方法：
    - Software-Defined Networking
    - 控制平面从路由器上物理分离，路由器只负责数据平面的转发，而转发表的计算是由【远程控制器】完成的
      - 远程控制器在高可靠性的远程数据中心中，并有ISP或其他第三方管理
    - 具体方法：
      - 路由器通过【交换包含转发表和其他路由选择信息的报文】与【远程控制器】通信
      - 在【远程控制器】中使用软件计算
        - 所以网络是”软件定义的“
    - SDN控制平面
      - <img src="/images/408-mind-maps/cn-0151.svg" alt="SDN控制平面" width="300" height="203">

        - 从上到下
          - 网络控制器应用程序
            - 根据SDN控制器提供的方法，这些应用程序会监视、编程、控制下面的网络设备
          - SDN控制器
            - 为运行在控制平面中的【网络控制应用程序】提供这些信息
              - 可以使这些【网络控制应用程序】逻辑上集中起来
              - 批注：向北
            - 维护网络状态信息（链路、路由器、主机状态）
              - 这里的路由器也可以称为交换机，因为是《自顶向下》这本书说的
              - 批注：向南
          - 交换机
    - 细分【SDN控制器】

        - 网络【应用程序接口层】

          - 允许SDN控制器与【网络控制应用程序】交互
