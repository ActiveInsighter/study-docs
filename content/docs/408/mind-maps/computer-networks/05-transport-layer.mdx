## 功能

- 概念
  - 传输层向它上面的应用层提供通信服务，属于面向通信部分的最高层，也是用户功能的最底层
  - 为运行在不同主机上的进程提供了逻辑通信
    - vs
      - 网络层
        - 为不同链路层的主机提供通信
        - AS系统
          - 为不同IGP的网络提供通信
      - 数据链路层
        - 为不同物理层的主机提供通信
      - 物理层
        - 提供通信
- 功能
  - 提供端到端的通信
  - 复用+分用
    - 复用：
      - 发送方不同进程使用同一个传输层协议传输
    - 分用：
      - 接收方收到这些数据后可以正确交付到目的应用进程
  - 向更高层的用户屏蔽底层的网络
  - 未命名主题
  - 传输层可以对收到的报文进行差错检测（首部+数据）
    - vs
      - 网络层
        - 只检测首部
      - 数据链路层
        - 首部+数据

## 寻址和端口

- 考频：低
  - 无
- 端口作用
  - port
    - 127.0.0.1:8080
  - 用于标识主机的进程，是让计算机知道可以把数据交付给哪一个进程的标志
  - 端口只有本地意义
    - 即不同主机使用相同端口是没有任何联系的
  - vs
    - 物理层MAC
      - 指明物理的主机
    - 网络层IP/CIDR
      - 指明逻辑上的主机、网络
    - 传输层端口
      - 指明主机上进程使用的端口

  - 服务器端口
    - 熟知端口号（0~1023）

      - TELNET
        - 23
      - SMTP
        - 25
      - DNS
        - 53
      - FTFP
        - 69
      - HTTP
        - 80
      - POP3
        - 110
    - 登记端口号（1024~49151）

  - 客户端端口（49152~65535）
    - 又称短暂端口号

## UDP

- 特色
  - 实现了传输层协议最少的工作，只在IP的基础上增加了两个服务：【复用分用和差错检测】
- 优点：
  - 无需建立连接
    - 也不会有建立连接的时延
      - 即：
        - DHCP可以用UDP要IP地址
        - DNS使用UDP可以更快的查找IP
        - HTTP不能使用UDP，因为HTTP需要文本数据的可靠性
  - 无连接状态
    - UDP不维护连接状态也就不需要跟踪参数，所以应用服务器使用UDP时一般可以支持更多的【活动客户机】
  - 分组首部开销小
    - TCP首部有20B，UDP只有8B
      - vs
        - MAC帧首部 6+6+2 B，FCS为 4 B
        - PPP帧 F+A+C+协议+FCS+F
          - 1+1+1+2+2+1 B
          - 配图

            <a href="/images/408-mind-maps/cn-0033.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0033.svg" alt="PPP帧 F+A+C+协议+FCS+F" width="240" height="77" loading="lazy" /></a>

        - DHCP帧 F+A+C+FCS+F
          - 1+1+1+2+1 B
        - IPv4首部为4\*(5~15)B
        - IPv6首部为40B
  - 应用层可以更好的控制发送的数据和发送的时间
    - UDP没有拥塞控制，所以网络拥塞不会影响发送效率
      - 但是网络拥塞会影响丢包率等等，UDP只是不会向TCP那样进行流量控制
    - 应用可以接受部分信息的丢失、但不允许有较大时延，就使用UDP
  - 支持一对一、一对多、多对一、多对多
- 特点：
  - UDP是面向报文的
    - 应用层应该自己设计好该让UDP发多大的数据报
      - 因为UDP只负责加个头部就给IP了，其他啥也不做，如果到了IP层发现太大了网络层会自己分片，如果发现太小了，又会发现头部太长了，两者都不划算
  - UDP常用于一次传输较少的数据
    - 例如DNS、SNMP
  - UDP不保证可靠交付
    - 所以应用层需要自行进行传输可靠性的维护
- UDP首部格式

      - 校验和：检测有没有错，如果有错就直接丢弃掉

    - 计算UDP校验和（注意红色字）

      <a href="/images/408-mind-maps/cn-0047.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0047.svg" alt="计算UDP校验和（注意红色字）" width="240" height="146" loading="lazy" /></a>

      - 发送端：
        - 1\. 加入伪首部
        - 2\. 校验和全0
        - 3\. 填补数据、每行4B
        - 4\. 伪首部、首部、数据一起求二进制反码
        - 5\. 最后取求和结果反码放入校验和中
      - 接受端收到后：
        - 1\. 添加伪首部，数据补0
        - 2\. 伪首部、首部、数据二进制反码求和，若全为1，则说明没有错，否则会丢给应用层差错报告。
  - 特点：
    - 如果UDP校验出来发现是错了，可以直接丢弃，也可以丢给上层处理，但是得附上错误报告，告诉上层哪里错了
      - 连ICMP都不发送
    - UDP这里采用的是直接求和最后求反码的方法

## TCP

- 考频：超高
  - 09\*2、10、11\*2、13-15、17、19-20\*2、21\*3、22\*2、12大、16大
- 目的：
  - 建立可靠、有序、无丢失、不重复传输
- 特点：
  - 面向连接的传输层协议

  - 只支持一对一传输（端对端）

  - 可靠的传输

  - 提供全双工，所以发送端和接受端都设置有发送和接受缓存

    - 【发送缓存】存 1. 应用程序准备发送的数据 2. TCP已发送但还没收到确认的数据
    - 【接受缓存】存 1. 按序到达的但是没有被应用程序接受的数据 2. 未按序到达的数据
  - TCP的传输是面向字节流的（Byte Stream）

    - 应用程序每次和TCP交换一个数据块的大小，但TCP把其视为无结构的字节流
- 发送报文采用的方式
  - UDP --- 应用程序要发多少就发多少
  - TCP --- 根据接受窗口和拥塞情况决定
- TCP首部

  - 配图

    <a href="/images/408-mind-maps/cn-0076.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0076.svg" alt="TCP首部" width="240" height="160" loading="lazy" /></a>

    - 数据偏移
      - = IP首部的”长度”
        - 单位为4B，占4bit，所以范围为5~15
      - != IP首部的”片偏移“
    - 各bool变量
      - 紧急位 URG
        - URG=1时，表明紧急指针字段有效。它告诉系统此报文段中有紧急数据， 应尽快传送（相当于高优先级的数据）。
          - 但 URG 需要和紧急指针配合使用，即数据从第一个字节到紧急指针所指字节就是紧急数据。
      - 确认位 ACK
        - 仅当 ACK = 1 时确认号字段才有效。当ACK = 0时，确认号无效。
          - TCP 规定，在连接建立后所有传送的报文段都必须把 ACK 置 1。
      - 推送位 PSH (Push）
        - 接收方 TCP 收到 PSH=1 的报文段，就尽快地交付给接收应用进程， 而不再等到整个缓存都填满后再向上交付。
      - 复位位 RST (Reset)
        - RST=1 时，表明 TCP 连接中出现严重差错(如主机崩溃或其他原因），必须释放连接，然后再重新建立运输连接。
      - 同步位 SYN
        - 同步SYN=1表示这是一个连接请求或连接接受服文。
          - 当SYN = 1, ACK = 0时，表明这是一个连接请求报文，对方若同意建立连接，则应在响应报文中使用 SYN = 1，ACK = 1。
      - 终止位 FIN (Finish)
        - 用来释放一个连接。当FIN=1时，表明此报文段的发送方的数据已发送完毕，并要求释放传输连接。
    - 校验和添加字段：
      - 源IP + 目的IP + 0 + 6 + TCP总长度
      - 4B + 4B + 1B + 1B + 2B
    - （不是固定首部了）选项：
      - 因为TCP只规定了一种选项，就是MSS（最大报文长度）
        - 选项字段可以like

      - MSL：最大报文生存时间
      - 注意客户机的半关闭状态和等待重传
  - SYN洪泛攻击
    - SYN洪泛攻击发生在OSI第四层，这种方式利用TCP协议的特性，就是三次握手
    - 攻击者发送TCP SYN，SYN是TCP三次握手中的第一个数据包，而当服务器返回ACK后，该攻击者就不对其进行再确认
    - 那这个TCP连接就处于【挂起】状态，也就是所谓的半连接状态，服务器收不到再确认的话 ，还会重复发送ACK给攻击者

      - 在服务器上，这些TCP连接会因为挂起状态而消耗CPU和内存，最后服务器可能死机
- TCP可靠传输
  - 序号
    - TCP给自己传输的每个【字节流】都编上了序号
      - 即：一个Byte一个序号
      - 注意：TCP不是把报文段/数据报/帧给标上的记号，而是给自己的【字节流】
    - 例如：TCP发送了三个报文段，第一个有5B，第二个有3B，第三个有2B
      - 则他们的seq分别为 seq = 0, seq = 5, seq = 8
  - 确认
    - TCP默认采用累计确认（类似GBN），对ack = 下一个我想要的序号
      - 例如：TCP发送了三个报文段，第一个有5B，第二个有3B，第三个有2B
        - 则他们发送后对应的的ack分别为 ack = 5(seq = 0), ack = 8(seq = 5), ack = 10(seq = 8)
  - 重传
    - 超时
      - TCP每发送一个报文段就设置一个计时器，计时器时间到头还没收到ACK，就重发
      - 优化：
        - TCP采用了自适应算法来计算加权往返时间RTTs，其会随着RTT变化而变化
    - 冗余ACK
      - 当TCP同时收到了3个冗余ACK的时候，可以认为该报文已经丢失
        - 例如：TCP发送了五个报文段，序号为0，1，2，3，4
          - 其中 1 丢失了，则发送方会收到3个 ack = 1（接收方在收到2、3、4的时候返回的）
      - 出现冗余ACK时，采用快速重传
- TCP拥塞控制
  - 目的：
    - 防止过多的数据注入网络，保证网络中的路由器或者链路不会过载
  - vs 流量控制
    - 相同：都是控制发送方的发送速率来达到控制效果
    - 区别：
      - 拥塞控制是全局性的过程，涉及所有网络的所有设备
      - 流量控制是点对点的，接收端控制发送端，抑制发送数据的速率
  - 窗口：
    - rwnd 接受窗口
      - 是【接收端】发的帧中的窗口大小
    - cwnd 拥塞窗口
      - 是发送端根据【当前网络】的拥塞情况设置的窗口值
    - 发送窗口大小 = min(rwnd, cwnd)
  - 慢开始+拥塞避免：
    - 【每个RTT】会发送【MSS个数据】，每个RTT中可能会有【多个序号】的数据报

      <a href="/images/408-mind-maps/cn-0053.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0053.svg" alt="【每个RTT】会发送【MSS个数据】，每个RTT中可能会有【多个序号】的数据报" width="240" height="164" loading="lazy" /></a>

      - 最大报文段长度（MSS）
      - 慢开始指数增长的本质：

        - 其中每个RTT每收到一个ACK，cwnd就+1
      - 拥塞避免：

        - 当cwnd达到ssthresh值以后，开始拥塞避免
        - 拥塞避免时，每一个RTT不管MSS中有多少个序号的数据报，其cwnd始终都只+1
      - 网络拥塞处理：

        - 当网络出现了拥塞的时候（例如丢包etc），进行两步操作：
          - 设置ssthresh为当前cwnd的一半

          - 把cwnd重新归到 1，重新开始慢开始

    - 批注：网络拥塞
  - 快重传+快恢复：
    - 【快开始+快恢复】是在”慢开始+拥塞避免“的一种对冗余ACK的优化，【快开始】就是检测到3个重复ACK后不用等计时器，直接重传。【快恢复】就是把cwnd和ssthresh直接减到cwnd的一半，开始【拥塞避免】
