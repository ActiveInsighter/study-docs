## 网络模型

<a href="/images/408-mind-maps/os-0062.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0062.svg" alt="网络模型" width="48" height="48" loading="lazy" /></a>

- C/S模型
  - 服务器
    - 永久提供服务（接入网络）
    - 永久提供访问地址、域名
    - 概要：面向任务
      概要范围：[永久提供服务（接入网络）](#focus=%E6%B0%B8%E4%B9%85%E6%8F%90%E4%BE%9B%E6%9C%8D%E5%8A%A1%EF%BC%88%E6%8E%A5%E5%85%A5%E7%BD%91%E7%BB%9C%EF%BC%89)、[永久提供访问地址、域名](#focus=%E6%B0%B8%E4%B9%85%E6%8F%90%E4%BE%9B%E8%AE%BF%E9%97%AE%E5%9C%B0%E5%9D%80%E3%80%81%E5%9F%9F%E5%90%8D)

  - 客户机
    - 与服务器通信
    - 间歇接入网络
    - 使用动态IP
    - 不与其他客户机通信
    - 概要：面向客户
      概要范围：[与服务器通信](#focus=%E4%B8%8E%E6%9C%8D%E5%8A%A1%E5%99%A8%E9%80%9A%E4%BF%A1)、[间歇接入网络](#focus=%E9%97%B4%E6%AD%87%E6%8E%A5%E5%85%A5%E7%BD%91%E7%BB%9C)、[使用动态IP](#focus=%E4%BD%BF%E7%94%A8%E5%8A%A8%E6%80%81IP)、[不与其他客户机通信](#focus=%E4%B8%8D%E4%B8%8E%E5%85%B6%E4%BB%96%E5%AE%A2%E6%88%B7%E6%9C%BA%E9%80%9A%E4%BF%A1)

  - 常见例子
    - Web
      - FTP
        - 远程登录
          - 电子邮件
  - 特点
    - 网络中计算机地位不平等
    - 客户机之间不可直接通信
    - 可扩展性差
  - 批注：服务器的性能决定了整个网络的性能
- P2P模型
  - P2P网络是一种动态逻辑网络，不是一种具体的物理网络
  - 每个主机都可以
    - 提供服务
    - 请求服务
    - 概要：不存在一直在线的服务器
      概要范围：[提供服务](#focus=%E6%8F%90%E4%BE%9B%E6%9C%8D%E5%8A%A1)、[请求服务](#focus=%E8%AF%B7%E6%B1%82%E6%9C%8D%E5%8A%A1)

  - 任意两个主机之间可以直接通信
  - 节点间歇的进入网络
    - 节点可能改变IP地址
  - 可扩展性强
    - 健壮性强
  - 经常使用P2P会对硬盘造成损伤
  - 常见例子
    - PPlive
      - Bittorent
        - 电驴
    - 流媒体播放对服务器压力过大时，可以使用P2P
  - 概要：可以直接共享文档
    概要范围：[任意两个主机之间可以直接通信](#focus=%E4%BB%BB%E6%84%8F%E4%B8%A4%E4%B8%AA%E4%B8%BB%E6%9C%BA%E4%B9%8B%E9%97%B4%E5%8F%AF%E4%BB%A5%E7%9B%B4%E6%8E%A5%E9%80%9A%E4%BF%A1)

- 混合模式
  - 文件搜索使用C/S，文件传输使用P2P
- 考频：低
  - 19

## 域名系统(DNS)

<a href="/images/408-mind-maps/os-0004.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/os-0004.svg" alt="域名系统(DNS)" width="48" height="48" loading="lazy" /></a>

- 考频：中
  - 10、16、18、20
- DNS采用C/S模型，建立在UDP在，使用53号端口
- 域名标准
  - 硬性规则
    - 不区分大小写、不使用' - '以外的符号、每个标号不超过63B一共不超255B、级别越高越靠右
  - 顶级域名<br>(TLD)
    - 国家顶级域名nTLD，.cn .us
    - 通用顶级域名gTLD, .com .net .org .gov .int .aero .museum .travel
    - 基础结构域名
      - .arpa，反向域名解析
  - 二级域名
    - 类别域名
      - ac.am.edu.gov.mil.net.org
    - 行政域名
      - bj.js
    - 自行注册域名
      - cctv. bilibili.
  - 三级、四级域名
    - www1. www. mail. hust. .hit.
    - 与二级域名差不多
  - 概要：都由授权域名服务器管辖
    概要范围：[二级域名](#focus=%E4%BA%8C%E7%BA%A7%E5%9F%9F%E5%90%8D)、[三级、四级域名](#focus=%E4%B8%89%E7%BA%A7%E3%80%81%E5%9B%9B%E7%BA%A7%E5%9F%9F%E5%90%8D)

- 域名服务器
  - IP到域名解析的过程是由众多域名服务器中的应用程序完成的
  - 本地域名服务器
    - 一个网络服务提供商ISP、一个大学、一个系，都拥有一个本地域名服务器
    - 主机发送DNS请求，第一个就是发送给本地域名服务器
    - 本地域名服务器会存有一个本地缓存，直接有IP
      - 其他服务器很多都有高速缓存，直接有IP
  - 根域名服务器
    - 为：a-m.rootservers.net
      - 一共13个
    - 本地域名服务器第一求助对象
    - 用来管辖顶级域
      - 返回下一个顶级域名服务器的IP地址
  - 顶级域名服务器
    - 管辖所有二级域名
      - 已经可以返回最后结果了，也可能是返回下一个域名服务器的IP地址
  - 授权域名服务器
    - 每台主机都会在此处登记
      - 很多域名服务器又是本地又是授权的
    - 返回最后结果
- 域名解析
  - 递归查询
  - 递归+迭代
  - 概要：配图
    概要范围：[递归查询](#focus=%E9%80%92%E5%BD%92%E6%9F%A5%E8%AF%A2)、[递归+迭代](#focus=%E9%80%92%E5%BD%92%2B%E8%BF%AD%E4%BB%A3)

    <a href="/images/408-mind-maps/cn-0037.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0037.svg" alt="域名解析" width="240" height="105" loading="lazy" /></a>

- 域名解析的步骤
  - 1\. 客户机向本地域名服务器发送DNS请求
    - y.abc.com
    - 概要：只有这一步是需要解析软件实现的，后续都自动完成
      概要范围：[y.abc.com](#focus=y.abc.com)

  - 2\. 本地域名服务器收到请求后，查询高速缓存，若没有则以DNS客户的身份向根域名服务器(就是dns.)请求
    - 如果有，就返回，下同
  - 3\. 根域名服务器收到请求后，判断域名属于.com，将dns.com的IP返回给本地域名服务器
  - 4\. 本地服务器向dns.com发送DNS请求
  - 5\. dns.com域名服务器收到请求后，判断域名属于abc.com，将dns.abc.com的IP返回给本地域名服务器
  - 6\. 本地服务器向dns.abc.com发送DNS请求
  - 7\. dns.abc.com域名服务器收到请求后，返回IP
  - 客户机把IP和DNS写入到本地缓存中

## FTP传输

<a href="/images/408-mind-maps/cn-0027.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0027.svg" alt="FTP传输" width="48" height="48" loading="lazy" /></a>

- 配图

  <a href="/images/408-mind-maps/cn-0128.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0128.svg" alt="FTP传输" width="240" height="105" loading="lazy" /></a>

- 采用C/S模型、先建立TCP连接，连接端口 21，数据端口 20
  - 数据端口（主动情况20，被动情况 1024 ~ 65535）
  - 使用TCP可靠传输服务
  - 控制进程、数据进程同时两个TCP连接
- FTP提供
  - 不同种类主机系统（软硬件都可不同）之间的文件传输
  - 以用户权限管理方式提供用户对远程FTP服务器的文件管理能力
  - 以匿名FTP方式提供文件共享
- 服务器进程
  - 主进程
    - 负责接受请求
  - 从属进程
    - 负责处理单个请求，处理完毕终止
- 连接方式
  - 控制连接
    - 监听21号端口
    - 使用7位ASCII码做控制信息
  - 数据连接
    - PORT模式（主动
      - 客户端发送请求到21，服务器开20给客户端，客户端随机开一个端口来接受服务器的20的数据
    - PASV模式（被动
      - 客户端发送请求到21，服务器随机开一个端口给客户端，客户端后面自己连接
  - 概要：只有控制+数据两个连接，没有其他连接
    概要范围：[控制连接](#focus=%E6%8E%A7%E5%88%B6%E8%BF%9E%E6%8E%A5)、[数据连接](#focus=%E6%95%B0%E6%8D%AE%E8%BF%9E%E6%8E%A5)

- 数据连接<br>（FTP与NFS）
  - FTP是分离控制，是带外传输(Out-of-band)
    - 如果要修改文件就很麻烦，需要读文件所有信息，改了过后再发回去
  - NFS可以只读获得一个文件的一个部分
- 数据传输模式
  - 文本模式 ASCII码
  - 二进制模式
- 匿名FTP访问：
  - 用户名：annoymous
- 考频：低
  - 09、17

## SMTP传输

<a href="/images/408-mind-maps/co-0015.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/co-0015.svg" alt="SMTP传输" width="48" height="48" loading="lazy" /></a>

- 考频：中
  - 12、13、15、18
- 基于TCP连接的应用层协议
- 组成结构
  - 用户代理（User Agent）
    - 用户与电子邮件系统的接口，例如：Outlook、Foxmail
    - 概要：如qq邮箱、Gmail，用户使用浏览器操作这类邮件服务器【发送和接受】使用的HTTP，仅在【不同邮件服务器之间传送邮件】用的SMTP
      概要范围：[用户与电子邮件系统的接口，例如：Outlook、Foxmail](#focus=%E7%94%A8%E6%88%B7%E4%B8%8E%E7%94%B5%E5%AD%90%E9%82%AE%E4%BB%B6%E7%B3%BB%E7%BB%9F%E7%9A%84%E6%8E%A5%E5%8F%A3%EF%BC%8C%E4%BE%8B%E5%A6%82%EF%BC%9AOutlook%E3%80%81Foxmail)

  - 邮件服务器
    - 接受和发送邮件，报告发信人邮件传送情况
    - 例如：A向B发送邮件，A就是SMTP客户，B就是SMTP服务器
  - 电子邮件协议
    - 发送协议
      - SMTP（Push)
    - 接受协议
      - POP3（Pull）、IMAP
- 收发过程：
  - 1\. 发信人调用用户代理来撰写和编辑要发送邮件。
  - 2\. 发送端的邮件服务器将邮件放入邮件缓存队列
  - 3\. 运行发送端的SMTP客户进程，如果有缓存中的等待邮件，则向接受方的SMTP服务器建立TCP连接
  - 4\. TCP建立完成后，SMTP客户进程向SMTP服务器发送邮件。所有邮件发完后。关闭TCP连接
  - 5\. 运行在接受端的SMTP服务器收到邮件后，将邮件放入收信人邮箱，待收信人方便时读取
  - 6\. 收件人打算收信时，调用用户代理，启用POP3/IMAP来取回邮件
- SMTP的<br>电子邮件格式
  - 信封
    - From:
      - 例:xxx@bytedance.com
    - To:
      - 例：xxx@tecent.com
    - Subject:
      - 主题，可以有可无
  - 内容
    - 主体内容
      - 只能传输一定长度的ASCII码
- SMTP &amp; MIME<br>和<br>POP3 &amp; IMAP
  分组说明：只用于读取邮件；对应：[POP3](#focus=POP3)、[IMAP](#focus=IMAP)

  分组说明：只用于发送邮件；对应：[SMTP简单邮件传输协议](#focus=SMTP%E7%AE%80%E5%8D%95%E9%82%AE%E4%BB%B6%E4%BC%A0%E8%BE%93%E5%8D%8F%E8%AE%AE)、[MIME](#focus=MIME)

  - SMTP简单邮件传输协议
    - 使用CS模式
      - 发送方即SMTP客户
      - 接收方即SMTP服务器
    - TCP连接，端口25
    - 三个阶段
      - 1\. 连接建立
        - SMTP客户扫描缓存时发现有邮件，就使用25号端口与接收方服务器的SMTP建立TCP连接。
        - 建立后，服务器发送“220 Service Ready”，然后SMTP客户向SMTP服务器发送HELO命令，附上发送方主机名
          - 如果发来的邮件服务器可以接受，返回"250 OK"，否则返回"421 Services not available"
        - （SMTP不使用中间服务器，故TCP连接总是在发送方和接收方这两个邮件服务器直接建立）
      - 2\. 邮件传送
        - 客户端先发送MAIL命令开始，MAIL FROM：&lt;...&gt;
        - 服务器收到MAIL命令后，如果准备好接受，就返回250 OK
        - 客户端根据接收方的email号，发送数个RCPT命令
        - 服务器收到RCPT后，返回250 OK或550 No such user here
          - 如果收到550，说明不可发送
        - 如果收到了OK，客户端就使用DATA命令，表示要发送的内容
          - 此时服务器返回354 Start mail input; end with &lt;CRLF&gt;&lt;CRLF&gt;
      - 3\. 连接释放
        - 发送QUIT命令
          - 服务器返回221（服务器关闭），则表明同一TCP连接释放
  - MIME
    - 多用途网际邮件扩充(MIME)
    - 并未改动SMTP，而是继续使用SMTP的结构，增加了新的内容
    - 新增：
      - 1\. 新的邮件首部，包括MIME版本、内容描述、内容标识、传送编码、内容类型
      - 2\. 定义了许多邮件内容格式，对多媒体电子邮件表示方法进行了标准化
      - 3\. 定义了传送编码，可以对任何内容格式进行转换，不会被邮件系统改变
  - POP3
    - 邮局协议
    - 端口号110，使用TCP
    - 两种工作方式：
      - 下载保存
      - 下载删除
  - IMAP
    - 因特网报文协议
    - 提供了创建文件夹、在不同文件夹之间移动邮件和在远程文件夹中查询邮件的联机命令
    - 可以允许用户只读取邮件中的一个视频/音频而不用全部
      - 和FTP的NFS模式很像

## 万维网和HTTP

<a href="/images/408-mind-maps/cn-0056.svg" target="_blank" rel="noopener noreferrer"><img src="/images/408-mind-maps/cn-0056.svg" alt="万维网和HTTP" width="48" height="48" loading="lazy" /></a>

- WWW的三个部分
  - 1\. URL
    - &lt;协议&gt;://&lt;主机&gt;:&lt;端口&gt;/&lt;路径&gt;
      - 例：http://172.0.0.1:8080/index.html
  - 2\. HTTP
    - 使用TCP，是WWW中客户程序和服务器程序交互必须遵守的协议
  - 3\. HTML
    - 文档结构语言，使用约定的标记对页面的各种信息、格式进行描述
- HTTP协议
  - 连接步骤
    - 1\. 浏览器进行DNS解析指向页面的URL，返回IP地址

    - 2\. 浏览器与IP地址服务器进行TCP连接（端口80）
    - 3\. 连接完毕后，发送HTTP请求(GET/POST/PUT ... )
    - 4\. 服务器返回HTTP响应，把文件发回给浏览器
    - 5\. 释放TCP，浏览器解析文件，展示Web页面
    - 概要：举例：
      概要范围：[1. 浏览器进行DNS解析指向页面的URL，返回IP地址](#focus=1.%20%E6%B5%8F%E8%A7%88%E5%99%A8%E8%BF%9B%E8%A1%8CDNS%E8%A7%A3%E6%9E%90%E6%8C%87%E5%90%91%E9%A1%B5%E9%9D%A2%E7%9A%84URL%EF%BC%8C%E8%BF%94%E5%9B%9EIP%E5%9C%B0%E5%9D%80)、[2. 浏览器与IP地址服务器进行TCP连接（端口80）](#focus=2.%20%E6%B5%8F%E8%A7%88%E5%99%A8%E4%B8%8EIP%E5%9C%B0%E5%9D%80%E6%9C%8D%E5%8A%A1%E5%99%A8%E8%BF%9B%E8%A1%8CTCP%E8%BF%9E%E6%8E%A5%EF%BC%88%E7%AB%AF%E5%8F%A380%EF%BC%89)、[3. 连接完毕后，发送HTTP请求(GET/POST/PUT ... )](#focus=3.%20%E8%BF%9E%E6%8E%A5%E5%AE%8C%E6%AF%95%E5%90%8E%EF%BC%8C%E5%8F%91%E9%80%81HTTP%E8%AF%B7%E6%B1%82(GET%2FPOST%2FPUT%20...%20))、[4. 服务器返回HTTP响应，把文件发回给浏览器](#focus=4.%20%E6%9C%8D%E5%8A%A1%E5%99%A8%E8%BF%94%E5%9B%9EHTTP%E5%93%8D%E5%BA%94%EF%BC%8C%E6%8A%8A%E6%96%87%E4%BB%B6%E5%8F%91%E5%9B%9E%E7%BB%99%E6%B5%8F%E8%A7%88%E5%99%A8)、[5. 释放TCP，浏览器解析文件，展示Web页面](#focus=5.%20%E9%87%8A%E6%94%BETCP%EF%BC%8C%E6%B5%8F%E8%A7%88%E5%99%A8%E8%A7%A3%E6%9E%90%E6%96%87%E4%BB%B6%EF%BC%8C%E5%B1%95%E7%A4%BAWeb%E9%A1%B5%E9%9D%A2)

      **用户单击链接后发生的事件顺序**（原图以访问清华大学网站为例）：

      1. 浏览器分析链接指向页面的 URL：`http://www.tsinghua.edu.cn/chn/index.htm`。
      2. 浏览器向 DNS 请求解析 `www.tsinghua.edu.cn` 的 IP 地址。
      3. DNS 系统解析该域名，返回服务器 IP 地址。
      4. 浏览器与服务器建立 TCP 连接，默认服务端端口为 80。
      5. 浏览器发出 HTTP 请求：`GET /chn/index.htm`。
      6. 服务器通过 HTTP 响应把 `index.htm` 文件发送给浏览器。
      7. 释放 TCP 连接。
      8. 浏览器解释 `index.htm`，将 Web 页面显示给用户。

      原图旁注：浏览器可以不必等一次完整响应后再发出其他对象请求。上述为教材中的 HTTP/TCP 过程，不代表所有 HTTP 版本都采用相同连接流程。

  - 特点
    - HTTP本身是无连接的
      - 使用了TCP连接后，HTTP便可直接发送数据，而不用像FTP、SMTP那样建立FTP连接和SMTP连接
    - 无状态
      - 无状态：
        - HTTP服务器不存储HTTP客户的访问记录
      - 使用Cookie去优化 '无状态' 的特点
        - 服务器给用户的响应报文中添加set-cookie:123456
        - 用户再次访问这个网页时，会取出cookie标识符，写入到请求报文中：cookie:123456
        - 存在用户主机中
    - 连接特性
      - 非持久连接
        - HTTP/1.0的默认方式，1.1也可以使用这种
        - 每次请求网页元素的时候都需要进行一次TCP连接
        - 概要：进行N次访问要2N个RTT
          概要范围：[HTTP/1.0的默认方式，1.1也可以使用这种](#focus=HTTP%2F1.0%E7%9A%84%E9%BB%98%E8%AE%A4%E6%96%B9%E5%BC%8F%EF%BC%8C1.1%E4%B9%9F%E5%8F%AF%E4%BB%A5%E4%BD%BF%E7%94%A8%E8%BF%99%E7%A7%8D)、[每次请求网页元素的时候都需要进行一次TCP连接](#focus=%E6%AF%8F%E6%AC%A1%E8%AF%B7%E6%B1%82%E7%BD%91%E9%A1%B5%E5%85%83%E7%B4%A0%E7%9A%84%E6%97%B6%E5%80%99%E9%83%BD%E9%9C%80%E8%A6%81%E8%BF%9B%E8%A1%8C%E4%B8%80%E6%AC%A1TCP%E8%BF%9E%E6%8E%A5)

          - 例：读取一个有100个图片的Web页面，需要经历202个RTT
      - 持久连接
        - 非流水线
          - 类似停等协议的请求/接受方式
          - 概要：进行N次访问要N+1次RTT
            概要范围：[类似停等协议的请求/接受方式](#focus=%E7%B1%BB%E4%BC%BC%E5%81%9C%E7%AD%89%E5%8D%8F%E8%AE%AE%E7%9A%84%E8%AF%B7%E6%B1%82%2F%E6%8E%A5%E5%8F%97%E6%96%B9%E5%BC%8F)

        - 流水线
          - HTTP/1.1的默认方式
          - 类似GBN+SR的请求/接受方式
        - 概要：进行N次可能只用2次RTT
          概要范围：[流水线](#focus=%E6%B5%81%E6%B0%B4%E7%BA%BF)
