# 5.12 序号、累计确认与字节级推导

## 核心约定
- TCP给**每一个字节**编号，不是每个报文段编号；32位序号按模`2^32`回绕
- 报文段序号`seq`：此段**第一个数据字节**的序号；`ack`：按序**期望收到的下一个字节序号**
- 发送`L`字节的数据段，则下一个新数据序号通常为`seq+L`
- SYN/FIN各额外占一个序号；**没有数据的普通ACK不占序号**

## 四段示例（已完成握手）
- A发送 `seq=1001, len=500` → 字节序号1001～1500；B按序收到回`ack=1501`
- A随后发 `seq=1501, len=200` → 字节1501～1700；B按序收到回`ack=1701`
- 如果第一段丢失，B先收到第二段：累计确认**仍为1001**（即使可缓存乱序段）
- 若支持SACK，可另告知已收到1501～1700字节，但累计ACK不跳过缺口

## 双向序号空间
- A→B字节序号与B→A序号无须相同；双方分别设置自己的初始序号
- 每个ACK字段针对**对端发来的数据**，所以数据方向与确认方向常相反
- 一条携带数据的ACK段既消耗自己方向的序号（按数据长度）又确认对方

## 计算模板
- `下个seq=本段seq+数据字节数+SYN?1:0+FIN?1:0`
- `ack=对端已连续收到的最后一字节序号+1`
- **不要把帧序号、IP标识符、TCP序号与ACK标志位混为一谈**
