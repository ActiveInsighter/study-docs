# 6.2 C/S、P2P与混合架构

## 客户端/服务器 C/S
- 客户端通常主动请求；服务器通常等待请求并提供持续服务
- 服务器**可以**使用稳定域名、固定地址或负载均衡入口，但并非必须永久保持同一IP
- 常见：Web、DNS递归查询、FTP、邮件提交与收取
- 集中管理、统一认证和维护相对容易；可能存在服务端瓶颈或单点故障

## P2P对等通信
- 一个对等节点可以同时请求和提供资源，结点角色可随会话改变
- P2P是**逻辑组织/应用模式**，不要求特定物理拓扑
- BT/BitTorrent是典型例子：内容可以分块从多个对等端获取
- 易于利用参与者资源，但结点上下线、NAT穿越、一致性和安全管理更加复杂
- “P2P必然没有协调服务器”不准确：可有跟踪器、目录、信令或引导节点

## 混合模式与性能
- 可用C/S发现元数据，P2P传输实际数据；也可混合CDN、缓存和中心控制
- 集中式吞吐不只取决于“服务器性能”，还与链路、缓存、负载均衡和应用负荷有关
- 对等式不是天然更快；节点上行带宽、在线程度和内容副本数量影响效果

## 高频判断
- **错**：C/S客户端绝不能直接互通 → C/S描述某种服务的角色，主机还可运行其他连接
- **错**：P2P必然损坏磁盘 → 大量I/O可能增加磨损，但不能推为架构的固有必然结果
- **错**：P2P中的任何两台主机总能直连 → NAT、防火墙或地址条件可能要求中继
- 看到“永久在线、动态IP、可扩展性”应从典型特征理解，切勿视为协议硬性条件
