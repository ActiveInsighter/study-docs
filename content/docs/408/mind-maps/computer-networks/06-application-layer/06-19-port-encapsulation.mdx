# 6.19 应用层端口、封装字节数与跨层辨错

## 常考服务与默认端口
- DNS UDP/TCP 53；FTP控制TCP 21、主动数据服务器通常TCP 20
- SMTP服务器互传TCP 25、用户提交TCP 587；POP3 TCP 110；IMAP TCP 143
- HTTP TCP 80；HTTPS常见TCP 443；HTTP/3通常UDP 443
- 注意端口号标识**通信端点服务**；它属于传输层字段，不是HTTP首部字段

## 封装字节数的课堂模型
- 以普通以太网II帧、无VLAN、IPv4无选项、TCP无选项且无额外链路标记为前提
- 以太网首部14B（目的MAC6+源MAC6+类型2）+ IP首部20B + TCP首部20B + HTTP数据 + FCS4B
- 对一个HTTP应用消息长$H$字节，未分段且不含填充时：帧长$L=14+20+20+H+4=H+58$字节
- 计算须注意以太网最小载荷与填充、最大MTU、可能的TCP选项和TLS开销

## 原文按字节编号的局限
- 在上述**固定头部且1基序号**时，IPv4报文位于整帧第15～34字节为IP首部
- 源IP位于第27～30字节，目的IP位于第31～34字节；TCP首部第35～54字节
- 若有VLAN标签、IP/TCP选项或封装隧道，上述固定偏移全部可能失效
- FCS长度4B是在以太网上的链路校验字段，通常抓包工具未必显示它

## 跨层易错
- 不应把`Content-Length`算作整个以太网帧长度
- DNS解析和HTTP消息分属不同交互；解析已缓存可能不发DNS查询
- FTP控制21与数据20的关系不是“两个永远固定端口”
