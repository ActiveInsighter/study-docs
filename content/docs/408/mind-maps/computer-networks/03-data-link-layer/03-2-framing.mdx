# 3.2 组帧与透明传输

## 组帧为何必要
- 物理层给出**连续比特流**；链路层须明确每帧**开始/结束**，便于验错和定位
- **透明传输**：载荷中出现与帧定界相同的字节/比特串，也不会被错误当作边界
- 不同协议可采用不同方法；不能把某一种填充规则用于所有帧格式

## 字符计数法
- 头部计数字段记录帧长度，接收方依长度取帧
- 若计数字段损坏，可能**失去后续帧同步**；须结合协议其他约束

## 字节定界+字符填充
- 用**标志字节**定界，数据中出现标志/转义字节时使用转义（ESC）
- 典型异步PPP：`0x7E` 为FLAG，`0x7D` 为ESC
  - 数据中`0x7E` → 发送`0x7D 0x5E`（按PPP异步字节填充规则异或`0x20`）
  - 接收先反填充，再进行相应的帧处理/校验
- 不能把EOH/SOT当作所有协议通用的唯一字符定界符

## 比特定界+零比特填充
- 典型HDLC标志`01111110`（十六进制`0x7E`）
- 发送端：**数据/控制区**每连续出现五个`1`，插入一个`0`
- 接收端：看到连续五个`1`后，识别并去掉后面填入的`0`
- 实例：原始`01111110`若作为帧内数据 → 填充为`011111010`
- 两端定界标志本身**不按数据区零填充规则转义**

## 违规编码法
- 利用物理编码中**不用于正常数据**的信号状态作帧界
- 可与特定物理层编码方案配合；不能笼统说“IEEE 802全部使用违规编码”

## 快速对比
- 字符计数：依长度；长度字段出错风险高
- 字节填充：标志字节+ESC；需要恢复转义
- 比特填充：标志比特串+插0；面向比特
- 违规编码：依物理编码的保留信号
